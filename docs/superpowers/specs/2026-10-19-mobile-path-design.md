# 휴대폰 길: 카톡 링크에서 첫 알림까지

2026-10-19. 다시 만들기(`2026-10-19-rebuild-design.md`)의 첫 덩어리다. 시범 운영의 첫 시험은 학생회 대화와 업무를 카카오톡에서 VADA로 옮기는 것이다(vada-docs RFC-8). 알림이 없으면 대화가 카톡으로 돌아가도 그 이유를 가릴 수 없다. 그런데 이 길은 공식 방법이 없는 곳(카톡의 바깥 브라우저 주소)과 기기마다 다른 동작에 기댄다. 그래서 가장 먼저 만들어 실제 아이폰과 갤럭시로 확인한다(DEC-43).

이 덩어리는 표를 쓰지 않는다. 지금 vada 위에서 만들어 바로 배포하고 확인한다. 다시 만들 표와 상관없이 그대로 남는다.

## 원칙 대조

| 사람이 하는 일 | 새로 생긴 일인가 | 바로 이득 | 판단 |
|---|---|---|---|
| 카톡에서 링크를 누르고 바깥 브라우저로 넘어가기 | 넘어가지 못했을 때만 버튼을 한 번 누른다 | 로그인할 수 있다 | 그대로 |
| 홈 화면에 추가하기(아이폰) | 새로 생긴 일이다. 처음 한 번 | 알림을 받고, 앱처럼 연다 | 시범 운영 첫날 옆에서 같이 한다 |
| 알림 켜기 | 새로 생긴 일이다. 기기마다 한 번 | 새 글과 부름을 놓치지 않는다 | 그대로 |
| 시험 알림 보내기 | 고를 때만 | 알림이 오는지 그 자리에서 안다 | 그대로 |

- **근거 연결, 변경 이력:** 이 덩어리는 기록을 만들지 않는다.
- **개인정보:** 알림 받을 기기의 주소는 이번엔 저장하지 않는다. 시험 알림을 보낼 때만 받고 버린다. 알림 내용은 정해 둔 시험 문구뿐이다.

## 왜 이렇게

- **카카오톡 안 브라우저는 Google 로그인과 웹 푸시를 모두 막는다.**
  - Google은 앱 안 브라우저의 로그인을 막는다(403 `disallowed_useragent`).
  - 앱 안 브라우저는 웹 푸시를 받지 못한다(MDN 호환성 자료).
  - vada는 앱 화면을 열면 `kakaotalk://web/openExternal`로 바깥 브라우저를 연다(`apps/web/src/main.tsx`). 실제 기기로는 확인하지 않았고, 이 주소가 안 된다는 보고도 있다(카카오 데브톡).
- **아이폰은 홈 화면에 추가한 웹 앱만 알림을 받는다(iOS 16.4부터, WebKit).**
  - 허락은 사용자가 버튼을 눌렀을 때만 물을 수 있다.
  - 안드로이드의 Chrome과 삼성 인터넷은 추가하지 않아도 받는다.
- **홈 화면 앱은 사파리와 쿠키를 따로 쓴다(WWDC23).**
  - 그래서 홈 화면 앱 안에서 Google 로그인을 하면 로그인이 사파리 쪽에 남고 앱은 로그인되지 않는다는 보고가 여럿 있다.
  - 그런데 iOS 17.2부터는 홈 화면에 추가하는 순간 사파리의 쿠키가 로그인 상태까지 앱으로 한 번 복사된다(WebKit, Safari 17.2). 그래서 첫 로그인은 사파리에서 하고, 추가는 그다음에 하게 안내한다.
- **홈 화면 앱 안에서 다시 로그인해야 할 때가 남는다.** 로그아웃했거나 세션이 끝났을 때다.
  - Apple은 `window.open`으로 연 창은 홈 화면 앱 안에 머문다고 안내한다(WWDC23).
  - 이 방법으로 고친 사례(GitHub)가 있지만 실제 기기로 확인한 기록은 찾지 못했다.
  - 그래서 길을 둘 넣어 한 번에 시험한다(판단 절차 3).

## 범위

- **넣는다**
  - 카톡에서 못 넘어갔을 때의 로그인 화면. '바깥 브라우저로 열기' 버튼, 주소 복사, 메뉴 안내를 둔다.
  - 홈 화면 설정(`manifest.webmanifest`), 앱 아이콘, 페이지 제목과 메타
  - 서비스 워커(`sw.js`). 알림을 띄우고, 알림을 누르면 앱을 연다.
  - 옆 메뉴 아래 '휴대폰 알림' 대화상자. 알림 켜기, 시험 알림, 홈 화면에 추가하는 법, 꺼졌을 때의 안내를 담는다.
  - 아이폰 홈 화면 앱 안의 로그인. 길 B(앱 안 창)를 기본으로 하고, 길 A(지금처럼 넘기기)를 '다른 방법으로 로그인'으로 둔다.
  - 서버: 알림 열쇠 설정, `GET /api/me/push`, `POST /api/me/push/test`
  - 실제 기기 확인 절차와 기록(`docs/device-checks.md`)
- **넣지 않는다**
  - **알림 받을 기기 저장:** 바탕에서 새 표와 함께 만든다(rebuild-design).
  - **새 글, 부름, 업무, 구매 결과 같은 진짜 알림:** 3~5 덩어리에서 만든다.
  - **앱 안 알림 목록과 방마다 끄기:** 되도록 할 것이다(RFC-7).
  - **오프라인 화면과 파일 캐시:** 얻는 것은 없고, 배포 뒤 옛 화면이 남는 위험만 생긴다.
  - **다른 앱 안 브라우저(인스타그램, 에브리타임 등):** 시범 운영의 링크는 카톡 단톡방으로 나간다.

## 흐름

아이폰:

1. 카톡에서 링크를 누르면 사파리로 넘어간다. 못 넘어가면 카톡 안 로그인 화면이 버튼과 안내를 보여 준다.
2. 사파리에서 Google로 로그인한다.
3. '휴대폰 알림'을 열면 "아이폰은 홈 화면에 추가해야 알림을 받아요"와 추가하는 법이 보인다. 공유 버튼에서 홈 화면에 추가한다.
4. 홈 화면의 VADA로 열면 로그인된 채 열린다. iOS 17.2의 쿠키 복사 덕분이다.
5. '휴대폰 알림'에서 '알림 켜기'를 누르고 허락한다.
6. '시험 알림 보내기'를 누르고 화면을 끈다. 5초 뒤 잠금 화면에 알림이 뜬다. 누르면 VADA가 열린다.
7. 로그아웃한 뒤 홈 화면 앱 안에서 다시 로그인해 본다. 길 B가 기본이고, 안 되면 '다른 방법으로 로그인'(길 A)을 쓴다.

갤럭시:

1. 카톡에서 링크를 누르면 기본 브라우저(Chrome 또는 삼성 인터넷)로 넘어간다.
2. Google로 로그인한다.
3. '휴대폰 알림'에서 '알림 켜기'를 누르고 허락한다.
4. '시험 알림 보내기'를 누르고 홈으로 나간다. 5초 뒤 알림이 뜬다. 누르면 VADA가 열린다.
5. 원하면 홈 화면에 추가한다. 안드로이드는 브라우저와 저장소를 함께 쓰므로 로그인이 그대로다.

## 화면

### 카톡 안 로그인 화면

- 지금의 경고 한 줄(`App.tsx`의 `Alert`)을 다음으로 바꾼다.
  - "카카오톡 안에서는 Google 로그인이 막혀 있어요. 바깥 브라우저로 열어 주세요."
  - **[바깥 브라우저로 열기]:** `openOutsideKakao`를 다시 부른다. 처음 열 때의 자동 시도가 막혔어도 사용자가 누른 동작이면 열릴 수 있다.
  - **[주소 복사]:** 지금 주소를 복사한다. 복사가 막히면 주소를 글자로 보여 길게 눌러 고르게 한다(`AccountInfo`와 같은 방식).
  - **안내 한 줄:** "안 되면 오른쪽 위나 아래의 메뉴(··· 또는 ⋮)에서 '다른 브라우저로 열기'를 눌러 주세요." 실제 메뉴 이름은 기기 확인에서 맞춘다.
- 카톡 안에서는 [Google로 로그인] 버튼을 보이지 않는다. 눌러도 403이 난다.
- 공개 화면(참가 신청, 내 신청)은 지금처럼 카톡 안에서 연다. 로그인이 없다.

### 휴대폰 알림 대화상자

옆 메뉴 아래 사용자 줄의 로그아웃 버튼 옆에 종 모양 '휴대폰 알림' 버튼을 둔다. 대화상자를 열기 전에는 서버를 부르지 않는다. 대화상자는 기기 상태에 따라 한 가지만 보여 준다. 상태는 순수 함수 `pushStateOf`가 정하고, 테스트한다.

| 상태 | 언제 | 보여 주는 것 |
|---|---|---|
| 홈 화면에 추가 필요 | 아이폰이고 홈 화면 앱이 아니다 | 추가하는 법 세 단계(공유 버튼, 홈 화면에 추가, 홈 화면의 VADA로 열기). "로그인한 채로 추가하면 다시 로그인하지 않아도 돼요" |
| 받을 수 없음 | 서비스 워커, `PushManager`, `Notification` 가운데 하나가 없다 | "이 브라우저는 알림을 받을 수 없어요." 아이폰이면 iOS 16.4 이상이 필요하다고 덧붙인다 |
| 서버 꺼짐 | `GET /api/me/push`가 404 | "아직 알림을 쓸 수 없어요" |
| 켜기 전 | 허락을 묻지 않았거나, 허락했지만 구독이 없다 | [알림 켜기] |
| 꺼짐 | 허락을 거절했다 | "알림이 꺼져 있어요." 기기별로 다시 켜는 곳을 보여 준다(아이폰: 설정 → 알림 → VADA, 안드로이드: 브라우저의 사이트 설정) |
| 켜짐 | 허락했고, 지금 서버 열쇠로 만든 구독이 있다 | "이 기기에서 알림을 받아요" [시험 알림 보내기] |
| 불러오지 못함 | 서버 열쇠를 받지 못했거나, 서비스 워커가 10초 안에 준비되지 않았다 | "알림 설정을 불러오지 못했어요." [다시 시도] |

- **알림 켜기:** 대화상자를 열 때 서비스 워커 등록(`navigator.serviceWorker.ready`)과 공개 열쇠를 미리 받아 둔다. 버튼을 누르면 다른 기다림 없이 바로 `pushManager.subscribe({ userVisibleOnly: true, applicationServerKey })`를 부른다. 아이폰은 누른 동작 안에서만 허락을 묻기 때문이다.
  - 이미 있는 구독의 열쇠가 서버 열쇠와 다르면 구독을 지우고 다시 만든다.
- **시험 알림:**
  1. 누르면 구독을 서버로 보낸다.
  2. 그동안 "5초 뒤에 알림이 와요. 화면을 끄거나 홈으로 나가 기다려 보세요."를 보여 준다.
  3. 응답이 오면 결과를 보여 준다.

| 결과 | 문구 |
|---|---|
| `sent` | "보냈어요. 알림이 왔는지 확인해 주세요." |
| `expired` | "이 기기의 알림 등록이 끝났어요. 알림을 다시 켜 주세요." 구독을 지우고 '켜기 전'으로 돌아간다 |
| `rejected` | "알림 서버가 받지 않았어요." |
| `PUSH_SERVICE_UNSUPPORTED` | "이 브라우저의 알림 서버(호스트 이름)는 아직 받지 않아요." 호스트는 화면이 자기 구독에서 읽는다 |
| 요청 실패 | "시험 알림을 보내지 못했어요. 연결을 확인해 주세요." |
| 기다리는 동안 화면을 꺼서 요청이 끊김 | "결과를 받지 못했어요. 알림이 왔다면 잘 된 거예요." iOS는 화면을 끄면 요청을 끊을 수 있다 |

### 아이폰 홈 화면 앱 안의 로그인

- 홈 화면 앱인지는 `navigator.standalone === true`로 가린다. 이 값은 iOS의 홈 화면 앱에서만 참이다.
- **길 B(기본):** [Google로 로그인]을 누르면 다음 순서로 한다. 성공하면 본 창은 세션을 다시 읽는다. 창이 알리지 못해도 본 창이 다시 보일 때 세션을 다시 읽는다.
  1. 누른 순간 `window.open('about:blank', '_blank')`로 앱 안 창을 연다.
  2. `authClient.signIn.social({ provider: 'google', callbackURL: '/auth-done', disableRedirect: true })`로 Google 주소를 받는다. better-auth 1.7.6에 있다.
  3. 연 창을 그 주소로 보낸다.
  4. 로그인이 끝나면 창이 `/auth-done`에 온다. 이 화면은 `BroadcastChannel('vada-auth')`로 본 창에 알리고 스스로 닫는다. 닫히지 않으면 "로그인했어요. 이 창을 닫아 주세요."를 보여 준다.
- **길 A('다른 방법으로 로그인'):** 지금의 `login()` 그대로다.
- **둘 다 안 될 때:** 버튼 아래에 늘 이렇게 안내한다. "로그인이 안 되면 사파리에서 VADA에 로그인한 뒤, 홈 화면의 VADA를 지우고 다시 추가해 주세요." iOS 17.2의 쿠키 복사를 쓰는 길이다.
- 홈 화면 앱이 아닌 곳(사파리, 안드로이드)은 지금처럼 길 A만 쓴다.

## 홈 화면 설정과 서비스 워커

- `apps/web/public/`을 새로 만든다. Vite가 빌드 결과의 맨 위로 복사한다.
- **`manifest.webmanifest`**

| 항목 | 값 |
|---|---|
| `id`, `start_url`, `scope` | `/` |
| `name`, `short_name` | `VADA` |
| `display` | `standalone` |
| `lang` | `ko` |
| `theme_color` | 브랜드 파랑(`primary`, blue-600) |
| `background_color` | 흰색 |
| `icons` | 192px, 512px, 512px 마스크용 |

- **아이콘:** 로고(`BrandMark`)와 같다. 파란 정사각형 안의 흰 V다. 파일은 `icons/icon-192.png`, `icons/icon-512.png`, `icons/maskable-512.png`, `apple-touch-icon.png`(180px)다. 만드는 스크립트를 함께 커밋한다.
- **`index.html`**
  - `<title>`을 'VADA'로 바꾼다.
  - manifest와 `apple-touch-icon`을 잇는다.
  - `theme-color`와 `apple-mobile-web-app-title`을 둔다.
- **`sw.js`(일반 스크립트)**
  - `install`에서 `skipWaiting`, `activate`에서 `clients.claim`을 한다.
  - `push`: 본문 JSON `{ title, body, url }`로 알림을 띄운다. 아이폰은 알림을 띄우지 않는 푸시가 거듭되면 허락을 거둘 수 있으므로 늘 띄운다.
  - `notificationclick`: 알림을 닫는다. 열린 VADA 창이 있으면 그 창을 앞으로 가져와 `url`로 보내고, 없으면 새로 연다.
  - `fetch` 처리기는 두지 않는다(오프라인 없음).
- **등록:** `main.tsx`가 앱 화면에서만 `navigator.serviceWorker.register('/sw.js')`를 부른다. 공개 화면에서는 부르지 않는다.
- **서버가 내주는 파일(`apps/api/src/web.ts`)**
  - `/sw.js`, `/manifest.webmanifest`: 캐시하지 않는다(`no-cache`). 서비스 워커가 바뀌면 바로 받게 한다.
  - `/icons/*`, `/apple-touch-icon.png`
  - 화면 진입점에 `/auth-done`을 더한다.

## API

새 경로는 `/api/me/` 아래에 둔다. `createApp`이 이 경로에도 공통 가드(`mutationGuard`)를 걸고, `boundary.test.ts`의 `guarded`에 더한다. `GET /api/me/memberships`가 이미 이 경로를 쓴다.

```
GET /api/me/push
  200 { publicKey: string }
  401 로그인 안 함
  404 알림 열쇠가 없어 경로가 없음

POST /api/me/push/test
  body PushSubscriptionSchema
  200 { result: 'sent' | 'expired' | 'rejected' }
  400 PUSH_SERVICE_UNSUPPORTED, 입력 오류
  401 로그인 안 함
```

- **`PushSubscriptionSchema`(`packages/contracts/src/push.ts`):** 브라우저의 `PushSubscription.toJSON()` 모양이다.
  - `endpoint`: `token(1024)`, `https:` 주소
  - `expirationTime`: 정수 또는 `null`, 없어도 된다
  - `keys`: `z.strictObject({ p256dh: token(200), auth: token(100) })`
- **보내는 곳 제한:** 서버가 사용자가 준 주소로 요청을 보내므로, 알려진 알림 서버로만 보낸다. 다른 서버를 거쳐 내부 주소를 찌르는 공격을 막기 위해서다.
  - `fcm.googleapis.com`
  - `web.push.apple.com`
  - `updates.push.services.mozilla.com`
  - `.notify.windows.com`으로 끝나는 호스트
  - 삼성 인터넷의 알림 서버는 확인하지 못했다. Chromium 계열이라 FCM일 것으로 본다. 기기 확인에서 막히면 그 호스트를 더한다(판단 절차 3).
- **시험 알림:** 5초 기다린 뒤 한 번 보내고 결과를 돌려준다.
  - 내용은 `{ title: 'VADA', body: '시험 알림이에요. 누르면 VADA가 열려요.', url: '/' }`다.
  - `TTL`은 60초, `urgency`는 `high`다.
  - 알림 서버가 404나 410을 주면 `expired`, 그 밖의 실패는 `rejected`로 돌려준다. 예상한 실패라 5xx로 던지지 않는다.
- **로그:** 알림 주소는 기기를 가리키는 비밀 주소라 로그와 응답에 넣지 않는다. 결과의 종류만 남긴다(AGENTS.md 로그·비밀).

## 서버

- **설정(`apps/api/src/push/config.ts`, `pushConfigFrom(env)`):**
  - `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`(`mailto:` 또는 `https:`) 셋이 모두 있거나 모두 없어야 한다. 하나만 있으면 서버가 시작하지 않는다.
  - 모두 없으면 알림 경로를 만들지 않는다. 영수증 저장소(R2)와 같은 방식이다.
- **보내기(`push/sender.ts`):** `web-push`(3.6.7)를 감싼다. 결과를 `sent | expired | rejected`로 바꾼다. 테스트에서는 가짜로 바꿔 끼운다.
- **경로(`push/routes.ts`, `createPushRoutes`):** `AppOptions`의 `push`로 잇는다. 그래야 경계 테스트가 빠짐없이 검사한다.
- **CI의 운영 모드 시작 검사(`ci.yml`):** 실행할 때마다 임시 열쇠를 만들어 넣고, 알림이 켜진 채로 뜨는지 본다. 열쇠는 형식 검사를 받으므로 아무 글자나 넣을 수 없다.

## 테스트

- **계약:** `PushSubscriptionSchema`에 AGENTS.md의 경우를 모두 넣는다.
  - 필수값 누락, 빈 값과 공백
  - 상한+1
  - NUL과 홀로 쓰인 서러게이트
  - 모르는 키(바깥과 `keys` 안), `https:`가 아닌 주소
- **API:**
  - 열쇠가 없으면 두 경로가 404다.
  - 로그인하지 않으면 401이다.
  - 모르는 알림 서버면 400 `PUSH_SERVICE_UNSUPPORTED`이고, 보내기를 부르지 않는다.
  - 성공하면 정한 내용으로 보내기를 부르고 `sent`를 돌려준다.
  - 410이면 `expired`, 그 밖의 실패면 `rejected`다.
  - 기다리는 시간은 바꿔 끼워 테스트가 5초를 기다리지 않게 한다.
  - 경계 테스트가 `/api/me/`의 변경 경로를 검사한다.
- **설정:** 열쇠 셋 가운데 일부만 있으면 오류다. `VAPID_SUBJECT`가 `mailto:`나 `https:`가 아니면 오류다.
- **화면:**
  - 기기 판별: 아이폰 사파리, 아이폰 홈 화면 앱, 안드로이드 Chrome, 삼성 인터넷, 카톡(아이폰, 안드로이드)의 사용자 에이전트
  - `pushStateOf`의 상태 여섯 가지
  - 알림 켜기: 누른 동작 안에서 기다림 없이 `subscribe`를 부르는지
  - 시험 알림의 결과 문구 네 가지
  - 카톡 안 로그인 화면: 버튼이 `openOutsideKakao`와 복사를 부르는지, 복사가 막혔을 때 주소를 글자로 보이는지
  - 아이폰 홈 화면 앱: 로그인 요청보다 먼저 `window.open`을 부르는지, `/auth-done`이 알리고 닫는지
- **서비스 워커:** 가짜 `self`에 `sw.js`를 불러 확인한다.
  - `push`가 받은 내용으로 알림을 띄운다.
  - `notificationclick`이 열린 창을 앞으로 가져오거나 새로 연다.
- **부품 확인 화면(`/ui.html`):** 대화상자의 상태별 모습을 더한다.

## 실제 기기 확인

- 배포 뒤 사용자가 아이폰과 갤럭시로 위 흐름을 끝까지 해 본다.
- 결과는 `docs/device-checks.md`에 남긴다. 다음 확인(덩어리 3~6, 리허설)도 같은 문서에 이어 쓴다.

| 남길 것 | 예 |
|---|---|
| 날짜, 기기, OS 버전 | 2026-10-21, iPhone 15, iOS 26.1 |
| 카톡 버전, 넘어간 브라우저 | 25.9.1, Safari |
| 단계마다 결과 | 됨 / 안 됨 / 해당 없음 |
| 안 됐을 때 | 무엇이 보였는지. 화면은 찍어 두되 커밋하지 않는다 |

- 확인 결과로 정하는 것은 다음과 같다.

| 결과 | 정하는 것 |
|---|---|
| 카톡에서 못 넘어간다 | 안내 화면을 기본으로 바꾸고 문구를 실제 메뉴 이름에 맞춘다 |
| 로그인이 홈 화면 앱으로 안 옮겨 간다 | 길 B를 첫 로그인에도 쓴다 |
| 길 B가 안 되고 길 A가 된다 | 길 A를 기본으로 바꾼다 |
| 둘 다 안 된다 | '사파리에서 로그인하고 다시 추가' 안내를 기본으로 하고, 세션 기간을 늘릴지 정한다 |
| 알림이 안 온다 | 시작 판단의 조건이므로 원인을 찾을 때까지 다음 덩어리의 알림 작업을 미룬다 |

## 열린 것

- **세션 기간:** better-auth 기본값(7일, 쓰는 날마다 늘어남)을 쓴다. 홈 화면 앱 안의 다시 로그인이 안 되면 늘릴지 정한다.
- **기본 브라우저가 Chrome인 아이폰:** 카톡이 Chrome을 열면 홈 화면에 추가할 때 로그인이 옮겨 가는지 모른다. 확인할 수 있으면 확인한다.
- **웨일:** 알림 지원을 확인하지 못했다. 시범 운영 학생회에 웨일 사용자가 있으면 확인한다.

## 사람이 할 일

1. 배포 전: `npx web-push generate-vapid-keys`를 직접 실행한다. 나온 두 값과 연락 메일(`mailto:...`)을 Render 환경 변수 세 개와 `.env`에 넣는다.
2. 배포: 사용자가 반영하라고 하면 main에 올린다.
3. 배포 뒤: 아이폰과 갤럭시로 확인하고 결과를 알려 준다. `docs/device-checks.md`에는 내가 옮겨 적는다.
