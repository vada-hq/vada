# 학생회 가입·초대 설계

2026-10-07 작성. 정책은 [구매 모델의 정책 결정 1번](../../purchase-model.md#정책-결정-2026-10-07)을 따른다.

## 목표

학생회 사람이 DB 작업 없이 스스로 들어온다. 지금은 `apps/api/scripts/manage-test-data.ts`로 사람마다 소속을 직접 넣는다.

완료 기준:
- 초대 링크를 받은 사람이 로그인하고 부서를 고르면, 바로 그 학생회의 행사 화면으로 간다.
- 부원은 사이드바에서 초대 링크를 복사할 수 있다.
- 학생회와 부서는 지금처럼 스크립트로 미리 만든다.

## 정책 (확정)

- 학생회마다 초대 링크가 하나 있다. 링크를 받은 사람은 로그인한 뒤 자기 부서를 골라 바로 가입한다.
- 링크는 부원 누구나 공유한다. 관리자 역할은 두지 않는다.
- 판단 기준은 사용자에게 가장 직관적이거나 구현이 가장 간단한 쪽이다. 부서를 잘못 고르거나 링크를 악용할 여지는 고려하지 않는다.

## 데이터

`organizations.invite_code` 칸을 추가한다.

| 항목 | 값 |
|---|---|
| 형식 | text, NOT NULL, UNIQUE |
| 기본값 | `replace(gen_random_uuid()::text, '-', '')` — 16진수 32자리, 무작위 122비트 |
| 마이그레이션 | `0009_organization_invite_code.sql` (`npm run db:generate`로 생성) |

- 기본값은 호출할 때마다 새 값을 만든다. 그래서 마이그레이션 때 기존 학생회마다 서로 다른 코드가 들어가고, 이후 만드는 학생회도 코드를 자동으로 받는다.
- 사용자가 입력하는 칸이 아니어서 길이 CHECK는 두지 않는다.

## API

| 경로 | 인증 | 동작 |
|---|---|---|
| `GET /api/me/memberships` (기존) | 로그인 | 소속마다 `organization.inviteCode`를 함께 준다 |
| `GET /api/invites/:code` | 로그인 | `{ organization: { id, name }, departments: [{ id, name }], joined }`를 준다. 부서는 이름순이고, `joined`는 요청한 사람이 이미 그 학생회 소속인지다. 경로의 코드도 본문과 같은 `token(64)` 검사를 거친다. 검사를 통과하지 못한 코드(NUL 등)와 모르는 코드는 모두 404 `NOT_FOUND`다 |
| `POST /api/organizations/join` | 로그인 | 본문은 `JoinOrganizationSchema = z.strictObject({ code: token(64), departmentId: token(200) })`. 그 코드의 학생회에 그 부서가 있으면 소속을 만들고 `{ membership }`을 준다. 없으면 404 `NOT_FOUND`다. 이미 소속이 있으면 새로 만들지 않고 기존 소속을 그대로 준다. 부서도 바꾸지 않는다 |

- 두 라우트는 기존 `createAccessRoutes`에 넣는다. 그래서 `AppOptions`와 경계 테스트의 모듈 목록은 바뀌지 않는다.
- `POST /api/organizations/join`은 `/api/organizations/` 아래에 있어 공통 가드(출처·형식·크기)를 받는다. `json(JoinOrganizationSchema)`가 인증보다 먼저 검사하고, 경계 테스트가 이 라우트를 자동으로 포함한다.
- `GET /api/invites/:code`는 읽기 전용이라 가드 밖에 둔다. 코드 자체가 초대이므로, 소속이 없는 사람에게도 코드가 맞으면 학생회 이름과 부서를 보여 준다.
- 같은 사람이 동시에 두 번 보내도, `(organization_id, user_id)` 유일 제약과 `ON CONFLICT DO NOTHING` 때문에 소속은 하나만 생긴다.
- 코드는 로그에 남기지 않는다. 오류 로그는 지금도 경로 패턴(`/api/invites/:code`)만 남긴다.

## 화면

링크 형식은 `{origin}/invite/{code}`다. 서버(`apps/api/src/web.ts`)는 `/invite/:code` 경로에도 `index.html`을 준다.

1. **로그인 전:** 기존 로그인 화면에 "학생회 초대 링크로 들어왔어요. 로그인하면 참여할 수 있어요." 한 줄을 더한다. Google 로그인의 `callbackURL`과 `errorCallbackURL`을 현재 초대 경로로 두어, 로그인 뒤 같은 링크로 돌아온다.
2. **로그인 후:** 초대 확인 화면(`apps/web/src/access/JoinOrganization.tsx`)을 보여 준다. 학생회 이름, 부서 목록(라디오 버튼), [참여하기] 버튼이 있다. 버튼 활성화는 `JoinOrganizationSchema.safeParse`로 판단한다.
3. **참여 성공 또는 이미 참여:** 주소를 `/`로 바꾸고(`history.replaceState`) 소속을 다시 불러온다. 그다음 그 학생회를 선택한 행사 화면을 연다.
4. **링크 복사:** 사이드바의 학생회 이름 아래에 [초대 링크 복사]를 둔다. `navigator.clipboard.writeText`가 성공하면 "복사했어요"를 보여 주고, 실패하면 링크를 읽기 전용 입력칸에 보여 준다.
5. **소속이 없을 때:** 문구를 "아직 참여한 학생회가 없어요. 학생회에서 받은 초대 링크로 들어와 주세요."로 바꾼다.

## 실패 처리

| 경우 | 결과 |
|---|---|
| 모르는 코드, 형식이 틀린 코드 | "초대 링크가 올바르지 않아요. 링크를 다시 확인해 주세요."와 [VADA로 가기]. 누르면 주소를 `/`로 바꾸고 평소 화면으로 간다 |
| 초대 확인이나 참여 요청 실패(네트워크, 5xx) | 오류 문구와 [다시 시도]. 고른 부서는 그대로 둔다 |
| 이미 참여한 학생회 | 부서를 고르지 않고 바로 그 학생회 화면으로 간다 |
| 다른 학생회의 부서 ID | 404 |
| 부서가 하나도 없는 학생회 | "아직 부서가 없어요. 학생회에 문의해 주세요."를 보여 주고 [참여하기]는 끈다 |
| 로그인 실패(`?error`) | 기존 오류 문구를 보여 주고 초대 경로는 유지한다 |
| 버튼을 두 번 누름 | 요청 중에는 버튼을 끈다. 서버도 소속을 하나만 만든다 |

## 테스트

- **API (`access.test.ts`):** 성공, 이미 참여(부서 유지), 미인증 401, 모르는 코드 404, 경로 코드의 NUL·상한+1은 500이 아닌 404, 다른 학생회의 부서 404. 필수값 누락·빈 문자열·공백만·상한+1(이모지 포함)·NUL·홀로 쓰인 서러게이트·모르는 키는 400. 소속 응답의 `inviteCode`는 자기 학생회 것만 나온다.
- **경계 테스트:** 새 `POST`가 자동으로 포함되는지 확인한다. 테스트 코드는 바꾸지 않는다.
- **마이그레이션 (`migrations.test.ts`):** 0009 적용 전에 학생회 2개를 넣고, 적용 후 서로 다른 32자리 코드가 생기는지 확인한다. 적용 후 만든 학생회도 코드를 받는지, 같은 코드는 거부되는지 확인한다.
- **웹 서버 (`web.test.ts`):** `/invite/abc`가 `index.html`을 주는지 확인한다.
- **화면 (vitest):** 로그인 전 초대 문구와 `callbackURL`, 부서를 고르기 전 버튼 비활성, 참여 후 그 학생회 선택, 잘못된 링크, 이미 참여, 복사 성공과 실패.
- **실제 확인:** 배포 후 학생회 소속이 없는 Google 계정으로 초대 링크를 열어 가입까지 해 본다. Google 로그인이 필요하므로 사용자가 확인한다.

## 배포 순서

새 코드는 `/api/me/memberships`에서 `invite_code`를 읽는다. 마이그레이션 전에 배포하면 모든 사용자가 소속을 불러오지 못한다. 그래서 제약을 추가할 때와 반대로 마이그레이션을 먼저 적용한다.

1. 브랜치에서 구현하고 테스트한다.
2. 승인을 받은 뒤 dev(`.env`의 `DATABASE_URL`)와 m1-preview에 0009를 적용한다. 적용 전에 이미 적용된 기록이 로컬 파일과 순서·해시까지 일치하는지 확인한다.
3. main에 병합하고 푸시한다(자동 배포). 운영에서 잘못된 코드의 초대 링크와 소속 응답을 확인한다.
4. AGENTS.md의 마이그레이션 절에 "새 컬럼을 읽는 코드는 두 DB에 마이그레이션을 먼저 적용한 뒤 배포한다"를 추가하고, ERD.md에 `invite_code`를 반영한다.

## 하지 않는 것

링크 재발급과 만료, 부서 변경, 탈퇴, 관리자 역할, 로그인 전 학생회 이름 미리 보기, 학생회·부서를 만드는 화면.
