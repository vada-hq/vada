# M2-2 행사 예산·정산·결산 엑셀 설계

2026-10-09. M2 "재정 마무리"의 두 번째 단계다. M2-1로 지출과 영수증이 앱에 남는다. M2-2는 다음을 한다.
- 행사마다 예산을 정한다.
- 예산 대비 실제 지출, 지출 예정, 남은 예산을 보여 준다.
- 증빙이 다 모이면 정산을 닫는다.
- 결산에 쓸 엑셀을 내려받게 한다.

## 왜 이것부터

- 학생회칙은 행사가 끝날 때마다 증빙서류를 첨부해 정산하라고 정한다. 예: [건국대 생물공학과 학생회칙](https://ai.konkuk.ac.kr/sites/microbio/files/건국대학교%20공과대학%20생물공학과%20학생회칙(2023.09.01).pdf) 제30조 2항.
- 학생회 결산서는 사업(행사)별로 예산·결산·집행률을 적는다. 예: [KAIST 전산학부 학생회 2022년 4분기 결산](https://student.kaist.ac.kr/w/images/archive/4/46/20221225125309%21%28KAIST_%EC%A0%84%EC%82%B0%ED%95%99%EB%B6%80_%ED%95%99%EC%83%9D%ED%9A%8C%29_22%EB%85%84%EB%8F%84_4%EB%B6%84%EA%B8%B0_%EA%B2%B0%EC%82%B0.pdf).
- 지출(M2-1)과 승인 품목(M1)이 이미 앱에 있다. 예산 숫자 하나만 더하면 행사별 정산이 계산된다.

## 범위

- **넣는다:**
  - 행사 예산(숫자 하나)
  - 행사 재정 숫자 4개
  - 정산 완료·다시 열기와 정산 뒤 잠금
  - 행사 정산 엑셀
  - 행사 화면의 "재정" 탭
  - 처리 기록
- **넣지 않는다(뒤 단계):**
  - M2-3: 회계 기간·수입원·예산 항목, 상시 운영까지 묶은 학기 결산 엑셀, 전체 재정 현황(FIN-00)
  - 증빙 파일 묶음(ZIP) 내려받기
  - 행사 진행 단계(기획 중·진행 중·완료)

## 정책

1. **예산:**
   - 행사마다 0 ~ 2,147,483,647원 정수 하나이거나 "미정"이다.
   - 재정 권한자(재정 부서·회장단)가 정하고 바꾼다. 바꿀 때마다 이전·이후 값을 처리 기록에 남긴다.
2. **숫자:**
   - **실제 지출:** 이 행사에서 취소하지 않은 지출의 금액 합이다.
   - **지출 예정:** 이 행사의 승인 품목 가운데 지출에 연결되지 않은 것의 수량 × 예상 단가 합이다.
     - 수량이나 단가를 모르는 품목은 합에서 빼고 개수를 따로 알린다.
   - **남은 예산:** 예산 − 실제 지출 − 지출 예정이다.
     - 예산이 미정이면 없다.
     - 0보다 작으면 "초과"로 보인다.
   - **집행률(엑셀만):** 실제 지출 ÷ 예산이다. 예산이 미정이거나 0원이면 없다.
3. **정산 완료 조건:** 아래 셋이 모두 0건이어야 한다.
   - 증빙 누락: 취소하지 않은 지출 가운데 확인된 증빙이 없는 것
   - 검토 대기 요청: 이 행사의 대기(`pending`) 품목
   - 지출로 기록하지 않은 승인 품목: 승인됐지만 지출에 연결되지 않은 품목

   조건이 안 되면 정산 버튼이 꺼지고, 남은 항목과 해결 방법이 보인다. 서버도 다시 확인한다(`NOT_READY_TO_SETTLE`).
4. **정산 뒤 잠금:** `EVENT_SETTLED`(409)로 막는다.
   - **막는 것:**
     - 이 행사로 지출을 기록하기
     - 이 행사 지출의 수정(다른 행사로 옮기기 포함)·취소
     - 다른 행사의 지출을 이 행사로 옮기기
     - 증빙 삭제
     - 예산 변경
     - 이 행사의 구매 요청 제출
   - **그대로 두는 것:**
     - 증빙 추가(정산 뒤에 받은 거래명세서 등)
     - 보기와 엑셀 내려받기
     - 대화, 품목 담기(작성 중), 수령 확인
   - **순서 맞추기:** 잠금과 조건 확인이 겹치지 않도록 행사 행을 잠근다.
     - 예산·정산·다시 열기는 `FOR NO KEY UPDATE`로 잠근다.
     - 지출 변경, 증빙 삭제, 구매 제출은 `FOR SHARE`로 잠근다.
     - 행사를 참조하는 행 추가(외래 키 검사)는 `FOR NO KEY UPDATE`와 부딪히지 않는다.
5. **다시 열기:**
   - 재정 권한자가 사유(200자)를 적고 연다. 잠금이 풀린다.
   - 정산과 다시 열기는 처리 기록에 남는다. 정산할 때는 그 시점의 예산, 실제 지출, 지출 건수도 함께 남긴다.
6. **권한:**
   - 재정 탭, 숫자, 지출 목록, 처리 기록, 엑셀은 학생회 구성원 모두가 본다(사용 내역과 같은 공개 범위).
   - 예산 정하기, 정산 완료, 다시 열기는 재정 권한자만 한다.
   - 다른 학생회의 행사는 없는 것으로 본다(404).
7. **엑셀(행사 정산서):**
   - **파일 이름:** `{행사 이름} 정산 {내려받은 날}.xlsx`이다. 윈도 파일 이름에 쓸 수 없는 글자는 `_`로 바꾼다.
   - 정산 전에도 내려받을 수 있다. 요약에 "정산 전"과 내려받은 때를 적는다.
   - **시트 4개:**
     - **요약:** 학생회, 행사, 정산 상태(완료 일시·처리자 / 정산 전), 내려받은 때, 예산, 실제 지출, 지출 예정, 남은 예산, 집행률, 지출 건수, 증빙 누락, 결제 수단별 합계 4줄, 취소해서 뺀 지출 수.
     - **지출 내역:** 번호, 결제일, 사용처, 내용, 금액, 결제 수단, 결제한 사람, 증빙 수, 메모, 기록한 사람. 맨 아래에 합계 줄을 둔다.
       - 결제일·기록 순으로 1부터 번호를 매긴다. 이 번호가 증빙 번호다.
     - **증빙:** 지출 번호, 종류, 파일 이름, 올린 사람, 올린 날, 열기.
       - "열기"는 앱의 영수증 보기 주소로 가는 링크다. 로그인한 구성원만 열린다.
     - **품목:** 지출 번호, 품목, 수량, 예상 단가, 예상 금액, 요청한 사람.
   - 취소한 지출은 넣지 않는다.
   - 칸 형식:
     - 금액은 숫자 칸(`#,##0`), 결제일은 날짜 칸(`yyyy-mm-dd`)이다.
     - 합계는 서버가 계산한 값을 적는다. 수식을 계산하지 않는 미리 보기에서도 보이게 하려는 것이다.
     - 사용자가 쓴 글은 모두 문자 칸으로 쓴다. 수식으로 읽히지 않게 하려는 것이다.
     - 링크 수식에는 서버가 만든 주소만 넣는다. 주소가 255자를 넘으면 링크를 빼고 "—"를 쓴다(엑셀 수식 문자열 한도).
   - 지출이 1,000건을 넘는 행사는 `EXPORT_TOO_LARGE`(409)로 막는다.
8. **휴대폰 기준:** 재정 탭은 한 열이다. 숫자 4개는 2×2로 놓고, 화면이 넓으면 한 줄 4칸으로 놓는다.

## 와이어프레임과 다른 점

기준 화면은 EVT-FIN-01 `28:685`(행사 재정 — 개요)다.

- **처리 단계 칸반:** "처리 단계" 4열 칸반 대신 정산 체크리스트 3줄과 이 행사의 지출 목록을 둔다.
  - 칸반은 옛 요청서 단위이고, 구매 탭·구매 검토와 겹친다.
  - 휴대폰 화면에는 4열이 들어가지 않는다.
- **정산 완료:** 요청서의 단계가 아니라 행사의 상태다.
- **위쪽 버튼:** [내 구매 요청]·[새 구매 요청]은 두지 않는다. 구매 탭이 따로 있다.
- **예산 출처:** 예산 편성(FIN-PLAN-01)이 아직 없다. 그래서 재정 탭에서 숫자 하나로 정한다.
- **결산 엑셀:** 와이어프레임에 없다. 결산서 사례를 따른다.
- **숫자 이름:** 배정 예산 → 예산, 승인·집행 예정액 → 지출 예정, 실제 지출액 → 실제 지출, 사용 가능액 → 남은 예산.

## API

경로 앞부분은 `/api/organizations/:organizationId`다. 변경 본문은 모두 contracts의 `z.strictObject`이고, `json(Schema)`를 인증보다 앞에 둔다.

| 경로 | 권한 | 본문 → 응답 |
|---|---|---|
| `GET /events/:eventId/finance` | 구성원 | → `{ finance, expenses, truncated }` |
| `POST /events/:eventId/finance/budget` | 재정 | `{ version, budget }` → 같은 응답 |
| `POST /events/:eventId/finance/settle` | 재정 | `{ version }` → 같은 응답 |
| `POST /events/:eventId/finance/reopen` | 재정 | `{ version, reason }` → 같은 응답 |
| `GET /events/:eventId/finance/export` | 구성원 | → xlsx 파일 |

- **`finance` 응답:** `budget`, `spent`, `planned`, `plannedUnknown`(금액을 모르는 승인 품목 수), `remaining`, `expenseCount`, `missingEvidence`, `pendingRequests`, `unrecordedItems`, `settled`(처리자·일시 또는 null), `version`, `history`(최근 100개, 오래된 순)를 담는다.
- **`expenses`:** 이 행사의 지출을 결제일 최근 순으로 300개까지 담는다. 넘으면 `truncated`다.
- **기존 경로 변경:**
  - 지출 기록·수정·취소와 증빙 삭제는 정산된 행사에서 `EVENT_SETTLED`다.
  - 구매 요청 제출도 정산된 행사에서 `EVENT_SETTLED`다.
  - `ExpenseSummary`에 `settled`(행사 정산이 끝났는지)를 더한다.
- **결제 수단·증빙 종류 이름:** 엑셀과 화면이 같이 쓴다. 그래서 contracts로 옮긴다.

**오류**

| 코드 | 상태 | 경우 |
|---|---|---|
| `NOT_FOUND` | 404 | 없는 행사, 다른 학생회 |
| `FORBIDDEN` | 403 | 재정 권한 없음 |
| `VERSION_CONFLICT` | 409 | |
| `INVALID_STATE` | 409 | 이미 정산했는데 정산, 정산하지 않았는데 다시 열기 |
| `NOT_READY_TO_SETTLE` | 409 | 정산 조건이 안 됨 |
| `EVENT_SETTLED` | 409 | 정책 4의 잠금 |
| `EXPORT_TOO_LARGE` | 409 | 지출 1,000건 초과 |

## 화면

- **행사 화면 탭:** 대화 · 구매 · 재정 순이다. 재정 탭은 처음 열 때 불러오고, 다시 고를 때마다 새로 불러온다. 다른 화면에서 승인·지출이 바뀌었을 수 있기 때문이다.
- **재정 탭** (위에서 아래 순서):
  1. 정산이 끝났으면 "정산 완료 · {날짜} · {이름}"을 보여 준다. 재정 권한자에게는 [정산 다시 열기]가 있다.
  2. 숫자 4개: 예산, 실제 지출, 지출 예정, 남은 예산.
     - 예산이 없으면 "미정"이고, 남은 예산이 0보다 작으면 "{금액} 초과"다.
     - 금액을 모르는 품목이 있으면 지출 예정 아래에 "금액을 모르는 품목 N개 제외"를 적는다.
     - 재정 권한자에게는 정산 전 [예산 정하기]가 있다.
  3. "정산하려면": 세 줄과 개수를 보여 준다.
     - 재정 권한자에게는 해결 방법과 [정산 완료]가 있다.
     - [정산 완료]는 세 줄이 모두 0일 때만 켜진다. 누르면 한 번 더 묻는다.
  4. [엑셀 내려받기]: 구성원 누구나 쓴다.
  5. 이 행사의 지출 카드 목록. 누르면 지출 상세를 연다.
     - 재정 권한자에게는 정산 전 [지출 기록]이 있다. 이 행사가 미리 골라져 있다.
  6. 처리 기록.
- **예산 정하기(대화상자):** 금액 칸 하나다. 비우면 미정이다. 저장 버튼은 같은 스키마의 `safeParse`로 켠다.
- **다시 열기:** 사유를 받는다. 지출 취소와 같은 칸 모양이다.
- **지출 상세:** 정산된 행사의 지출이면 아래처럼 바뀐다.
  - [수정]·[지출 취소]·증빙 [삭제]를 숨긴다.
  - "정산이 끝난 행사의 지출이라 수정·취소·증빙 삭제를 할 수 없어요."를 보여 준다.
  - [증빙 추가]는 그대로 둔다.
- **구매 제출이 막히면:** "정산이 끝난 행사예요. 재정부에 정산을 다시 열어 달라고 해 주세요."를 보여 준다.
- **공용 부품:** 사용 내역 요약과 재정 숫자는 공용 표시 부품 `StatGrid`(`src/components`)로 그린다. 부품 확인 화면에도 더한다.
- 긴 행사 이름·사유에는 `wrap-anywhere`를 준다.

**화면 문구** (그대로 쓴다)

| 자리 | 문구 |
|---|---|
| 탭 | 재정 |
| 숫자 | 예산, 실제 지출, 지출 예정, 남은 예산, 미정, {금액} 초과, 금액을 모르는 품목 N개 제외 |
| 체크리스트 | 정산하려면, 증빙 누락 N건, 검토 대기 요청 N건, 지출로 기록하지 않은 승인 품목 N개 |
| 해결 방법 | 지출 상세에서 증빙을 올려 주세요. / 구매 검토에서 승인하거나 반려해 주세요. / 산 품목은 지출에 연결하고, 사지 않을 품목은 승인을 취소해 주세요. |
| 버튼 | 예산 정하기, 정산 완료, 정산 다시 열기, 엑셀 내려받기, 지출 기록 |
| 정산 확인 | 정산을 마치면 이 행사의 지출·예산·증빙 삭제가 잠겨요. |
| 다시 열기 | 다시 열면 지출과 예산을 바꿀 수 있어요. |
| 빈 상태 | 이 행사에 기록된 지출이 없어요 |

## 오류·로그·보안

- **엑셀 응답 머리글:**
  - `Content-Type: application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`
  - `Content-Disposition: attachment; filename="settlement.xlsx"; filename*=UTF-8''…`
  - `Cache-Control: no-store`
- 로그와 오류 응답에 행사 이름, 금액, 파일 이름을 남기지 않는다.
- 엑셀의 사용자 글은 문자 칸으로만 쓴다. 링크 수식에는 서버가 만든 주소만 넣는다.

## 테스트

- **계약:** 예산·정산·다시 열기 스키마의 경계를 확인한다.
  - 버전 0 허용, 음수·소수·상한+1, 예산 null 허용, 사유의 빈 값·상한+1(이모지 포함)·NUL·홀로 쓰인 서러게이트, 모르는 키
- **API(PGlite·가짜 저장소):**
  - 숫자: 취소 제외, 지출 예정의 미연결 승인 품목, 금액 모르는 품목, 남은 예산의 음수
  - 예산: 미정으로 되돌리기, 버전 충돌, 처리 기록
  - 정산: 조건 셋 각각의 `NOT_READY_TO_SETTLE`, 성공, 이미 정산
  - 잠금: 지출 기록·수정·옮기기·취소, 증빙 삭제, 예산, 구매 제출은 막히고, 증빙 추가는 된다. 다른 행사는 영향받지 않는다.
  - 다시 열기: 사유, 잠금 해제
  - 엑셀: 시트·값·번호 순서·취소 제외·날짜 칸·링크 수식·파일 이름, 1,000건 초과
  - 다른 학생회, 미인증, 재정 권한 없음
- **화면:**
  - 재정 탭을 처음 열 때 불러오기, 숫자(미정·초과·금액 모르는 품목)
  - 체크리스트와 정산 버튼 조건, 정산 확인, 정산 완료 표시와 다시 열기
  - 예산 대화상자, 엑셀 내려받기(성공·실패)
  - 재정 권한이 없을 때 버튼 숨김, 지출 상세의 잠금, 세 탭 키보드 이동
- **경계 테스트:** 새 변경 라우트 3개가 공통 가드 검사를 받는다.
