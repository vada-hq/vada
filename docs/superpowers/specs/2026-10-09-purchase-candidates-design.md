## 목표

행사 대화에 올라온 쿠팡 링크를 후보로 모으고, 후보를 골라 담게 한다. 지금은 링크를 복사해 끼룩이 창에 붙여 넣어야 한다. 상품 정보는 링크가 올라올 때 뒤에서 조회해 상품 단위로 저장하고 다시 쓴다.

완료 기준:
- 행사 대화에 쿠팡 상품 링크를 보내면 메시지는 조회를 기다리지 않고 바로 보인다. 링크는 후보가 되고, 상품 정보(이름·가격·이미지)는 보통 10초 안에 채워진다.
- 같은 상품·같은 옵션은 후보에 한 번만 보인다. 누가 언제 공유했는지 보이고, 누르면 대화의 그 메시지로 이동해 강조한다.
- 학생회 누구나 후보를 숨기고 되돌린다. 숨긴 후보 목록에서 누가 언제 숨겼는지 보인다.
- 제출된 품목이 있는 후보에는 "요청됨 · 요청자 · 수량"이 모두에게 보인다.
- 후보를 골라 담으면 작성 중 품목이 생기고 끼룩이가 수량·용도·받을 날짜를 채운다. 그다음은 1차 흐름과 같다.
- 대화의 쿠팡 링크를 누르면 상품 정보가 오른쪽 패널에 열린다.
- 같은 상품은 다시 조회하지 않는다. 제출할 때 24시간이 지난 가격만 다시 조회해 반영하고 요청자에게 알린다.
- 휴대폰 폭(390px)에서 모든 화면을 쓸 수 있다.

## 정책

### 이미 정한 것 (2026-10-04, 10-07)

1. **후보 단위:** 쿠팡 `vendorItemId`(판매자 + 옵션)가 같으면 같은 후보다. 옵션이 다르면 다른 후보다. `vendorItemId`가 없는 링크는 상품마다 "옵션 미정" 후보 하나로 모은다.
2. **공유 표시:** 후보마다 "기획 · 10월 9일 오후 2:12에 공유"를 보여 주고, 여러 번이면 "외 N번"을 붙인다. 누르면 대화 탭의 그 메시지로 이동해 강조한다. 여러 번 공유됐으면 공유 목록을 펼쳐 고른다.
3. **숨기기:** 학생회 누구나 숨긴다. 누가·언제 숨겼는지 남기고, 바로 되돌리기와 "숨긴 후보"에서 다시 보이기를 둔다. 완전 삭제는 없다.
   - 숨긴 후보가 대화에 다시 공유되면 숨김을 푼다(2026-10-09). 다시 올린 사람은 후보에 보이기를 기대한다.
4. **요청됨 표시:** 후보에서 담은 품목이 제출(대기·승인)되면 "요청됨 · 요청자 · 수량"을 모두에게 보여 준다. 반려·요청 취소되면 표시가 빠진다. 다른 사람이 요청한 후보도 담을 수 있다(부서마다 따로 필요할 수 있다). 대신 경고한다(정책 19).
5. **고르기와 수량:** 사람마다 따로다. 공유되는 것은 후보가 있다는 것, 숨김, 요청됨 표시뿐이다.
6. **상품 단위 저장:** 상품 ID로 한 번 조회해 옵션 전체를 저장하고 다시 쓴다. 같은 상품의 다른 옵션 링크는 다시 조회하지 않는다.
7. **뒤에서 조회:** 메시지 전송은 조회를 기다리지 않는다. 조회가 끝나기 전에는 "상품 정보를 불러오는 중…"을 보여 준다.
8. **가격 다시 확인:** 제출할 때만 한다. 최근에 조회한 품목은 건너뛰고, 여러 품목은 동시에 조회한다.
9. **링크 패널:** 대화의 링크를 누르면 대화를 유지한 채 상품 정보를 보여 준다.

### 추천대로 정한 것 (2026-10-09)

10. **후보 위치:** 구매 탭 위쪽에서 **후보 | 내 품목 | 행사 전체**를 고른다. 기본은 후보다. 담기의 시작점이기 때문이다.
11. **붙여 넣기 창과 끼룩이 버튼을 없앤다.** 담는 입구를 "대화 → 후보" 하나로 합친다. 대화에 올리지 않은 링크는 담을 수 없다. 입구가 둘이면 어디서 담는지 헷갈린다.
12. **담기:** 후보를 1~10개 골라 [선택한 N개 담기]를 누른다. 끼룩이가 대화에서 수량·용도·받을 날짜·근거를 채운다(1차와 같은 생성). 상품명·가격은 저장된 조회값을 쓴다. 조회가 아직 안 끝났거나 실패한 후보는 담을 때 그 자리에서 다시 조회한다.
    - 한 번에 10개: 1차의 5개는 붙여 넣기 창 기준이었다. 고르는 방식에서는 더 많이 고르게 된다. 끼룩이 출력 상한(5,000토큰) 안에 들어간다.
13. **옵션 이름:** ReefAPI는 옵션 속성(색상·크기 라벨)을 주지 않는다. 옵션마다 이름에 옵션이 들어 있으므로 옵션별 상품명을 그대로 보여 준다. 담을 때는 1차처럼 끼룩이가 상품명에서 옵션을 나눈다.
14. **조회 결과와 링크 맞추기:**
    - `vendorItemId`가 같은 옵션이 있으면 그 옵션이다.
    - 없고 `itemId`가 같은 옵션이 있으면 그 옵션을 쓰고 "링크의 판매자가 바뀌었을 수 있어요. 쿠팡에서 가격과 판매자를 확인해 주세요."를 붙인다. 판매자가 바뀌면 `vendorItemId`가 달라질 수 있다.
    - 둘 다 없으면 옵션을 모르는 것으로 본다. 상품 이름만 보여 준다.
15. **조회 실행:**
    - 웹 서버 안에서 뒤에서 하고, 동시에 2개까지만 한다(ReefAPI 키당 초당 약 5회).
    - 대기 상태는 DB에 둔다. 서버가 잠들었다 깨면 이어서 한다.
    - 시간 초과·`RATE_LIMITED`·`UPSTREAM_HTTP`·`TARGET_BLOCKED`는 1분·5분·30분 뒤 다시 시도하고, 네 번째 실패에서 멈춘다. `NOT_FOUND`는 바로 멈춘다. 실패는 과금되지 않는다.
    - 실패한 상품이 다시 공유되면 다시 조회한다(`NOT_FOUND` 제외).
16. **제출 때 가격:**
    - 조회한 지 24시간이 지난 품목만 다시 조회한다. 요청자가 직접 고친 가격(조회값과 다른 가격)은 다시 조회하지 않는다.
    - 바뀌었으면 새 가격으로 제출하고, 제출 기록에 이전·이후 가격을 남긴다. 화면은 "가격이 바뀐 품목이 있어 새 가격으로 제출했어요"와 바뀐 품목을 알린다.
    - 조회가 실패하면 원래 가격으로 제출한다. 제출을 막지 않는다.
    - 24시간: 학생회 구매는 제출 후 며칠 안에 결제한다. 화면에 "조회 가격은 참고값" 안내가 있다. ReefAPI 과금(조회 1회 2크레딧)도 줄인다.
17. **링크 패널:**
    - 오른쪽에서 여는 패널(Sheet)로 연다. 대화는 뒤에 그대로 남는다. 좁은 화면에서는 화면 폭의 5/6까지 쓴다. 지금 Sheet 부품에 오른쪽 변형을 더해서 화면 폭 감지 없이 한 가지로 만든다.
    - 내용: 이미지, 옵션 상품명, 예상 가격(정가·할인율이 있으면 함께), 품절 여부, 도착 예정, 조회 날짜, [쿠팡에서 보기].
18. **지원하는 링크:** 쿠팡 상품 주소(`www.coupang.com/vp/products/숫자`, 모바일 `m.coupang.com/vm/products/숫자`)만 후보가 된다.
    - 쿠팡 앱의 공유 짧은 링크(`link.coupang.com/…`)는 후보가 되지 않는다. 짧은 링크를 풀려면 서버가 쿠팡에 요청해야 하는데, 막히는지 확인하지 않았다(후속 실험).
    - 한 메시지에서 앞의 10개 링크까지만 후보로 만든다.
19. **다른 사람이 요청한 후보:** 담은 품목에 "다른 구성원이 이미 요청한 상품이에요. 같은 물건을 두 번 사지 않는지 확인해 주세요."를 붙인다. 내가 이미 담은 상품 경고(1차)는 그대로 둔다.
20. **후보 정렬과 상한:** 마지막 공유가 최근인 순서로 300개까지 보여 준다. 넘으면 "최근 300개만 보여요."를 표시한다.
21. **기존 대화의 링크는 후보로 옮기지 않는다.** 두 DB의 대화는 파일럿 전 시험 데이터다.
22. **가격 표시:** 후보와 패널의 가격은 "예상 9,800원 · 10/9 기준"처럼 조회 날짜를 붙인다. 품절이면 "품절" 칩을 붙인다.
23. **이미지:** ReefAPI가 주는 썸네일 주소가 `https`이고 쿠팡 이미지 서버(`*.coupangcdn.com`)일 때만 저장하고 보여 준다.

## 와이어프레임과의 관계

와이어프레임에는 행사 대화 탭이 없고(메시지는 MSG-01~03에 따로 있다), 후보 목록과 링크 패널 화면도 없다. 그래서 1차의 품목 카드·칩·버튼 모양을 따른다. 비교할 노드가 없다는 것을 적어 둔다.

## 링크 해석 (contracts 공용)

`packages/contracts/src/coupang.ts`에 둔다. 서버(후보 기록)와 화면(대화 링크 버튼)이 같은 함수를 쓴다.

- `parseCoupangLinks(text)`
  - 결과는 `{ url, productId, itemId, vendorItemId, start, end }[]`이고, 메시지 안 순서이며 최대 10개다.
  - `https://`로 시작하는 `www.coupang.com`·`coupang.com`의 `/vp/products/숫자`와 `m.coupang.com`의 `/vm/products/숫자`만 찾는다.
  - 링크 끝에 붙은 문장 부호(`.,!?)]}'"`와 닫는 괄호류)는 링크에서 뺀다.
  - `itemId`·`vendorItemId`는 숫자 1~20자리이고 한 번만 있을 때만 쓴다. 그 밖의 쿼리는 버린다.
- `normalizeCoupangUrl` → `https://www.coupang.com/vp/products/{productId}`에 `itemId`, `vendorItemId` 순으로 쿼리를 붙인다. 1차 `productUrl()`이 만드는 주소와 같다.
- 상품 ID는 숫자 1~20자리다.

## 상품 조회

- 요청: `POST https://api.reefapi.com/coupang/v1/product` `{ product_id }`, 15초 제한. 키는 서버 환경변수 `REEF_API_KEY`만 쓴다.
- 응답 `data.items[]`를 옵션 목록으로 저장한다. 값 검사는 이렇다.
  - 이름: 500자 이내로 자른다. 가격·정가: 0 이상 정수만 받는다. 할인율: 0~100만 받는다.
  - 도착 예정: 100자 이내만 받는다. 이미지: 정책 23. 그 밖의 값은 버린다.
- 오류 원문, 키, 주소, 대화 내용은 로그·응답에 남기지 않는다. 로그에는 오류 코드만 남긴다.
- 실행기(`purchases/lookup-runner.ts`)
  - `kick()`: 대기 중인 상품이 없을 때까지 비운다. 메시지 저장이 끝나면 부른다.
  - 1분마다 재시도할 상품을 확인한다.
  - `REEF_API_KEY`가 없으면 실행기를 켜지 않는다.
- 대기열 가져오기: `status = 'pending' AND next_attempt_at <= now() AND (locked_until IS NULL OR locked_until < now())`를 `FOR UPDATE SKIP LOCKED`로 잠그고 `locked_until`을 60초 뒤로 둔다.

## API

모든 변경 본문은 contracts의 `z.strictObject`이고, `json(Schema)`를 인증보다 앞에 둔다. 경로 앞부분은 `/api/organizations/:organizationId/events/:eventId`다.

| 경로 | 본문 | 동작 |
|---|---|---|
| `GET /purchase-candidates` | 없음 | 행사의 후보. 마지막 공유 최근 순 300개와 `truncated`. 숨긴 후보 포함(`hidden` 칸) |
| `POST /purchase-candidates/:candidateId/hidden` | `{ hidden }` | 숨기기·다시 보이기. 학생회 누구나. 이미 그 상태면 그대로 둔다 |
| `POST /purchase-items/drafts` | `{ idempotencyKey, candidateIds }` | 후보 1~10개로 작성 중 품목을 만든다. `links`를 대신한다 |
| `POST /purchase-items/submit` | 그대로 | 제출 전에 가격을 다시 확인한다(정책 16) |
| `POST /messages` (대화) | 그대로 | 저장하는 트랜잭션에서 링크를 후보·공유로 기록하고, 저장 뒤 실행기를 부른다 |

`PurchaseCandidate` 응답:
- `id`, `url`, `productId`, `itemId`, `vendorItemId`.
- `lookup`: `pending` · `ready` · `failed`, `fetchedAt`.
- `product`: 맞춘 옵션의 `name`, `price`, `listPrice`, `discountPercent`, `inStock`, `deliveryEta`, `imageUrl`. 없으면 `null`.
- `warning`: 정책 14의 판매자 경고. 없으면 `null`.
- `shares`: 최근 20개의 `messageId`, `author`(id·이름), `sharedAt`. `shareCount`도 둔다.
- `hidden`: `{ by, at }` 또는 `null`.
- `requests`: 대기·승인 품목의 요청자·수량·상태. `draftedByMe`: 내 작성 중 품목이 있는지.

오류:

| 코드 | 상태 | 경우 |
|---|---|---|
| `NOT_FOUND` | 404 | 행사·후보가 없거나 다른 학생회 것 |
| `FORBIDDEN` | 403 | 학생회 구성원이 아님 |
| `INVALID_INPUT` | 400 | 형식·상한 위반, 같은 후보 두 번 |
| `GENERATION_IN_PROGRESS`, `IDEMPOTENCY_CONFLICT` 409, `GENERATION_FAILED` 502, `AI_NOT_CONFIGURED` 503 | | 1차와 같다 |

- `INVALID_PRODUCT_LINK`, `DUPLICATE_LINK`는 쓰지 않게 되므로 지운다.

### 끼룩이 생성

- 입력이 링크에서 후보로 바뀐다. 생성기는 더 이상 상품을 조회하지 않는다. 서비스가 저장된 상품 정보(필요하면 그 자리 조회)를 넘긴다.
- 대화 맥락: 최근 100개(2만 자)에 후보를 공유한 메시지를 더한다. 오래전에 공유한 후보도 근거를 찾게 하려는 것이다.
- 생성 기록의 `links`에는 후보 주소를 순서대로 넣는다. 같은 키로 같은 후보를 다시 보내면 만든 품목을 그대로 돌려준다.

## 화면

### 구매 탭: 후보

```
[후보] [내 품목] [행사 전체]
조회 가격은 참고값이에요. 옵션·포장 단위와 배송비·최종 결제 금액을 확인해 주세요.
 ┌──────────────────────────────────────────────┐
 │ □ [img] 모닝글로리 유성매직 12색 ↗              │
 │         예상 9,800원 · 10/9 기준   [품절]       │
 │         기획 · 10월 9일 오후 2:12에 공유 · 외 2번 │
 │         [요청됨 · 박해랑 · 2개]                  │
 │                                       [숨기기]  │
 └──────────────────────────────────────────────┘
 [선택한 2개 담기]
 숨긴 후보 1 ▾
```

- 카드는 1차 품목 카드 모양을 따른다. 상품명·주소·이름에 `wrap-anywhere`를 준다.
- 조회 중이면 이름 자리에 "상품 정보를 불러오는 중…", 실패하면 "상품 정보를 가져오지 못했어요. 쿠팡에서 확인해 주세요."와 주소를 보여 준다. 옵션을 모르면 "옵션 미정" 칩을 붙인다.
- 공유 표시를 누르면 대화 탭으로 가서 그 메시지를 강조한다. 여러 번이면 펼쳐서 고른다.
- [숨기기]를 누르면 "후보를 숨겼어요."와 [되돌리기]를 보여 준다. "숨긴 후보 N"을 펼치면 "기획이 10월 9일에 숨김"과 [다시 보이기]가 있다.
- 내 작성 중 품목이 있는 후보에는 "내가 담음" 칩을 붙인다(나에게만).
- [선택한 N개 담기]는 같은 스키마의 `safeParse`로 켠다. 담는 중에는 "담는 중… 최대 약 75초 걸릴 수 있어요."를 보여 주고, 끝나면 내 품목으로 가서 "N개를 담았어요. 확인하고 제출해 주세요."를 보여 준다.
- 보는 동안 5초마다 새로 불러온다(새 링크, 숨김, 요청됨, 조회 완료).
- 비어 있으면 "아직 올라온 쿠팡 링크가 없어요" / "대화에 쿠팡 상품 링크를 올리면 여기에 모여요."를 보여 준다.

### 대화

- 메시지 안의 쿠팡 상품 링크를 버튼 모양 링크로 그린다(글자는 주소 그대로). 다른 글은 지금과 같다.
- 누르면 오른쪽 링크 패널(정책 17)을 연다. 후보 목록에서 같은 상품·옵션을 찾아 보여 주고, 조회 중이면 5초마다 다시 불러온다.
- 후보에서 메시지로 이동하면, 메시지가 아직 안 불러온 페이지에 있을 때 이전 페이지를 10번까지 더 불러온다. 찾으면 화면 가운데로 옮기고 2초 동안 배경을 강조한다. 못 찾으면 "메시지를 찾지 못했어요."를 보여 준다.
- 대화 탭의 [끼룩이] 버튼과 링크 붙여 넣기 창(`LinkDialog`)을 지운다.

### 내 품목

- 제출 응답에서 가격이 바뀐 품목이 있으면 "가격이 바뀐 품목이 있어 새 가격으로 제출했어요." 아래에 "상품명 4,900원 → 5,200원"을 3개까지 보여 주고, 나머지는 "외 N개"로 줄인다.
- 구매 탭의 [끼룩이로 담기] 버튼을 지운다. 비어 있을 때 안내를 "후보에서 골라 담아 보세요."로 바꾼다.

## 테스트

- **계약**
  - 링크 해석: www·m·`coupang.com`, 쿼리 순서, 끝 문장 부호, 여러 링크·10개 상한, 다른 사이트, 짧은 링크, 잘못된 ID·중복 쿼리.
  - 새 스키마: 필수값 누락, 빈 문자열·공백만, 상한+1, NUL·홀로 쓰인 서러게이트, 모르는 키, 같은 후보 두 번.
- **마이그레이션 0014:** 0013까지 적용한 DB에 적용한다. 새 제약(상품 ID 형식, 숨김 쌍, `NULLS NOT DISTINCT` 고유, 복합 FK, 공유 위치)과 기존 행 보존을 확인한다.
- **API**
  - 대화 저장이 후보·공유를 같은 트랜잭션에서 기록하고 실행기를 부르는지. 같은 상품은 상품 행 하나, 다른 옵션은 후보 둘이 되는지.
  - 실행기: 성공 저장, 맞추기 규칙 세 가지, 재시도 일정·멈춤, `NOT_FOUND`, 동시 실행 상한, 이미지 주소 검사, 키 없음.
  - 후보 목록: 공유·숨김·요청됨·내가 담음이 맞는지. 남의 작성 중 품목은 요청됨에 나오지 않는지. 다른 학생회는 404, 미인증은 401인지.
  - 숨기기: 누구나, 멱등, 다른 학생회 404.
  - 담기: 저장된 정보 사용(조회 없음), 조회 안 된 후보는 그 자리 조회, 경고 둘, 멱등키, 후보 없음 404.
  - 제출 가격: 24시간 지난 품목만 조회, 직접 고친 가격은 건너뜀, 바뀌면 새 가격과 기록, 실패하면 원래 가격.
  - 경계 테스트가 새 변경 라우트를 예외 없이 검사하는지.
- **화면**
  - 후보: 목록·고르기·담기 이동, 숨기기·되돌리기·다시 보이기, 요청됨·내가 담음, 조회 중 표시, 메시지로 이동.
  - 대화: 링크 버튼, 오른쪽 패널, 메시지 강조, 이전 페이지 찾기.
  - 제출 후 가격 바뀜 안내. 붙여 넣기 창이 없어진 것.
- **수동:** dev에서 데스크톱과 390px로 링크 보내기 → 후보 → 담기 → 제출까지 해 본다. 실제 ReefAPI 조회 응답과 이미지 표시를 확인한다.

## 적용 순서

1. 브랜치에서 구현하고 전체 테스트·타입 검사·빌드를 통과시킨다.
2. dev DB에 0014를 적용하고(승인) 로컬 서버로 확인한다.
3. 배포 DB에 0014를 적용하고(승인) 곧바로 main에 병합·푸시한다. 새 표만 더하므로 지금 배포된 코드는 영향을 받지 않는다.
4. CI와 배포를 확인하고, 운영에서 후보·대화 화면이 열리는지 본다.

## 하지 않는 것

- 쿠팡 앱 공유 짧은 링크 해석(후속 실험), 쿠팡 밖 링크.
- 기존 대화 링크를 후보로 옮기기.
- 후보 댓글·투표·수량 합치기, 후보 완전 삭제.
- 상품 검색, 평점·리뷰 표시, 조회 다시 하기 버튼.
- 재정부 화면의 중복 요청 표시.
- 채팅 알림 카드(3차), 알림.
- 여러 서버용 공유 조회 제한(지금은 Render 서버 하나).
