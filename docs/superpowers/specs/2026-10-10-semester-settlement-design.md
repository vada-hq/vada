# M2-3b 실제 수입 기록과 결산서 설계

2026-10-10. M2-3(학생회 예산 편성·학기 결산)의 둘째 단계다. M2-3a로 회계 기간마다 수입·행사·운영 예산을 편성하고 편성 대비 지출을 보게 됐다. 하지만 수입은 계획 금액뿐이다. 실제로 얼마가 들어왔는지, 지금 남은 돈이 얼마인지 알 수 없고, 기간을 마치며 내야 하는 결산서도 만들 수 없다.

M2-3b는 실제 수입을 기록하고, 기간 하나의 결산서를 엑셀로 내려받게 한다. 기간 마감과 남은 돈 이월은 M2-3c에서 한다.

## 왜 이렇게

와이어프레임에는 수입 기록·결산서·마감·이월·엑셀 화면이 없다. 편성 화면(FIN-PLAN-01 `600:2`)의 수입원은 계획 금액만 받는다. 그래서 [부산대 재정운용세칙](https://union.pusan.ac.kr/bbs/union/3153/859765/download.do)을 기준으로 짠다.

- 모든 수입을 세입으로 적는다(제7조). 세입은 학생회비·이월금·사업수익·기타수익으로 나눈다(제12조).
- 회계장부를 두어 모든 경비를 기록한다. 결산안은 분기가 끝나고 14일 안에 감사위원회에 내고 회원에게 공개한다(제9조·제22조).
- 결산안 서식(별지 제2호)은 세 부분이다.
  - 세입내역 요약: 수입원별 금액
  - 세출내역 요약: 항목별 금액과 예산 대비 비율
  - 세부 결산내역: 번호·일시·코드·구분(세입·세출)·세부내역·거래명·수입·지출·잔액
- 결산서의 수입·지출 묶음은 M2-3a 편성 줄을 그대로 쓴다(3a spec "왜 이것부터").

## 범위

- **넣는다:**
  - 실제 수입 기록: 기록·수정·취소와 처리 기록
  - 예산 화면: 수입 줄마다 실제 수입, 수입 내역, 실제 수입과 남은 돈
  - 편성 수정: 수입이 고른 수입 줄 지우기와 수입을 기간 밖으로 내보내는 날짜 변경을 막는다
  - 결산서 엑셀
- **넣지 않는다:**
  - M2-3c: 기간 마감·다시 열기, 남은 돈 이월
  - 수입 증빙 파일(통장 사본 등), 받은 방법(계좌·현금) 구분
  - 행사에 수입(참가비) 붙이기, 학생별 학생회비 납부 명단(ORG-07C)
  - 사용 내역 화면에 수입을 섞는 것

## 정책

1. **수입 한 건:**
   - 통장에 들어온 돈 한 건이다. 학생별로 적지 않는다.
   - 칸: 받은 날, 내용(100자), 금액(1원 이상 정수), 수입 항목(고르지 않아도 됨), 메모(200자, 비워도 됨).
   - 수입은 기간 하나에 속한다. 받은 날은 그 기간 안이어야 한다(`DATE_OUTSIDE_PERIOD`). 다른 기간으로 옮기지 않는다. 옮기려면 취소하고 그 기간에서 다시 기록한다.
   - 지우지 않고 취소로 남긴다(사유 200자). 취소한 수입은 합계에서 빠지고 목록에 "취소됨"으로 남는다. 취소한 수입은 고칠 수 없다(`INVALID_STATE`).
   - 수정은 모든 칸을 다시 보낸다. 버전이 맞아야 한다(`VERSION_CONFLICT`). 바뀐 칸만 처리 기록에 남기고, 바뀐 것이 없으면 버전과 기록을 그대로 둔다.
2. **수입 항목:** 그 기간의 수입 예산 줄만 고른다. 서버가 다시 확인한다(`BUDGET_LINE_INVALID`).
3. **숫자(기간마다):**
   - 수입 줄의 실제 수입: 그 줄을 고른 수입 가운데 취소하지 않은 것의 합
   - 수입 항목을 고르지 않은 수입: 그 기간의 취소하지 않은 수입 가운데 항목이 없는 것의 합과 건수
   - 실제 수입: 그 기간의 취소하지 않은 수입 전부의 합
   - 남은 돈: 실제 수입 − 실제 지출
     - 실제 지출은 3a의 정의(행사 줄 + 운영 줄 + 항목 없는 상시 운영 지출)다.
     - 지출 예정은 빼지 않는다. 아직 나가지 않은 돈이기 때문이다.
     - 0보다 작으면 화면이 알린다. 수입 기록이 빠졌을 가능성이 크다.
   - 3a의 숫자(예산·실제 지출·지출 예정·남은 예산·집행률)는 그대로다.
4. **편성 수정의 제약** (3a 정책 5에 더한다):
   - **수입 줄 지우기:** 그 줄을 고른 수입 가운데 취소하지 않은 것이 있으면 막는다(`LINE_IN_USE`). 취소한 수입에 남은 항목 표시는 함께 지운다.
   - **날짜 바꾸기:** 이 기간의 취소하지 않은 수입이 새 기간 밖으로 나가면 막는다(`INCOMES_OUTSIDE_PERIOD`). 그래서 수입은 늘 자기 기간 안에 있고, 어느 기간에도 들지 않는 수입은 생기지 않는다.
5. **권한:**
   - 수입 기록·수정·취소는 재정 권한자(재정 부서·회장단)만 한다.
   - 수입 보기와 결산서 내려받기는 구성원 누구나 한다. 사용 내역과 같은 공개 범위다.
   - 다른 학생회나 다른 기간의 수입은 없는 것으로 본다(404).
6. **결산서(기간 하나, .xlsx):**
   - 숫자는 예산 화면과 같은 정의다. 지출은 3a 기준으로 센다. 행사 지출은 결제일과 상관없이 행사가 든 기간에, 상시 운영 지출은 결제일이 든 기간에 넣는다.
   - 한 시점의 값이 되도록 자료를 읽기 전용 거래 하나(REPEATABLE READ)에서 읽는다.
   - 수입 1,000건이나 지출 1,000건을 넘으면 만들지 않는다(`EXPORT_TOO_LARGE`). 행사 정산서와 같은 상한이다.
   - 시트 다섯 개(아래 "결산서").
7. **휴대폰 기준:** 3a와 같다. 한 열이고 줄마다 카드로 보여 준다. 수입 내역도 카드 목록이다.

## 와이어프레임과 다른 점

기준 화면은 3a와 같다: FIN-PLAN-01 `600:2`, FIN-00 `30:2475`, FIN-00B `30:2762`.

- **수입 기록:** 와이어프레임에 없는 기능이다. 새 메뉴를 만들지 않고 예산 화면의 수입 묶음 안에 둔다. 한 기간의 수입은 학생회비·지원금·이월금·사업수익처럼 몇 건뿐이기 때문이다.
- **결산서:** 와이어프레임에 없다. 부산대 결산안 서식(별지 제2호)의 세 부분을 시트로 옮긴다.
- **학생회비 납부 명단(ORG-07C):** 뺀다. 학생별 납부 정보는 보관·파기 규칙부터 정해야 한다(M3 참가자 모집 후보).

## API

경로 앞부분은 `/api/organizations/:organizationId/budget/periods/:periodId`이다. 변경 본문은 모두 contracts의 `z.strictObject`이고, `json(Schema)`를 인증보다 앞에 둔다. 수입 라우트는 새 모듈(`apps/api/src/incomes`)이고 `AppOptions.incomes`로 연결한다.

| 경로 | 권한 | 본문 → 응답 |
|---|---|---|
| `POST /incomes` | 재정 | `CreateIncomeSchema` → `{ income }` 201 |
| `GET /incomes/:incomeId` | 구성원 | → `{ income }` |
| `PATCH /incomes/:incomeId` | 재정 | `UpdateIncomeSchema` → `{ income }` |
| `POST /incomes/:incomeId/void` | 재정 | `VoidIncomeSchema` → `{ income }` |
| `GET /export` | 구성원 | → 결산서 .xlsx |

**본문**

- `CreateIncomeSchema`: `{ description, amount, receivedOn, budgetLineId: string | null, note: string | null }`. `budgetLineId`와 `note`는 꼭 보낸다.
- `UpdateIncomeSchema`: `{ version, ...Create }`
- `VoidIncomeSchema`: `{ version, reason }`

**응답**

- `IncomeSummary`: `{ id, budgetLine: { id, name } | null, description, amount, receivedOn, note, recordedBy, voided: { by, at, reason } | null, version, createdAt, updatedAt }`
- `IncomeDetail`: `IncomeSummary` + `history: [{ id, action, actor, changes, createdAt }]`(오래된 순)
- `IncomeResponse`: `{ income: IncomeDetail }`

**편성 응답(`BudgetPlanResponse`)에 더하는 것**

- `incomes`의 줄마다 `received`(실제 수입), `incomeCount`(그 줄을 고른 수입 가운데 취소하지 않은 것의 수. 0이 아니면 지울 수 없다)
- `unassignedIncome`: `{ received, count }`
- `incomeRecords`: 이 기간의 수입. 취소한 것도 준다. 받은 날 최근 순으로 300건까지이고, 넘으면 `incomeRecordsTruncated`가 true다.
- `totals.received`(실제 수입), `totals.balance`(남은 돈)

**오류**

| 코드 | 상태 | 경우 |
|---|---|---|
| `NOT_FOUND` | 404 | 없는 기간·수입, 다른 학생회, 다른 기간의 수입 |
| `FORBIDDEN` | 403 | 재정 권한 없음 |
| `VERSION_CONFLICT` | 409 | 수입 버전 |
| `INVALID_STATE` | 409 | 취소한 수입을 고치거나 다시 취소 |
| `DATE_OUTSIDE_PERIOD` | 409 | 받은 날이 그 기간 밖 |
| `BUDGET_LINE_INVALID` | 409 | 수입 항목이 없거나, 수입 줄이 아니거나, 다른 기간의 줄 |
| `LINE_IN_USE` | 409 | 취소하지 않은 지출이나 수입이 고른 줄 지우기(3a 코드를 수입 줄에도 쓴다) |
| `INCOMES_OUTSIDE_PERIOD` | 409 | 날짜를 바꾸면 이 기간의 수입이 기간 밖으로 나감 |
| `EXPORT_TOO_LARGE` | 409 | 결산서 상한 초과 |

## 동시성

- 수입 기록·수정·취소:
  - 재정 권한을 확인한다.
  - 기간 행을 `FOR SHARE`로 잠근 뒤 날짜와 수입 항목을 확인한다.
  - 수정·취소는 이어서 수입 행을 `FOR UPDATE`로 잠그고 버전을 본다.
- 편성 수정은 같은 기간 행을 `FOR UPDATE`로 잠근다(3a). 그래서 줄 지우기·날짜 바꾸기 확인과 수입 변경이 겹치지 않는다.
- 잠금 순서는 3a와 같다(학생회 잠금 → 기간 → 행사). 수입은 기간만 잠근다.

## 결산서

파일 이름은 `{기간 이름} 결산 {한국 날짜}.xlsx`다. 윈도에서 쓸 수 없는 글자는 `_`로 바꾼다. 사람이 쓴 글은 모두 문자 칸이다(수식으로 읽히지 않는다). 셀 도움 함수와 내려받기 머리글은 행사 정산서와 같이 쓰도록 한 파일로 옮긴다.

1. **요약**
   - 머리: 결산서, 학생회, 회계 기간, 기간(시작일 ~ 끝일), 내려받은 때
   - 수입: 수입 예산, 실제 수입
   - 지출:
     - 예산(예산 미정 행사가 있으면 "예산 미정 행사 N개는 0원으로 셈")
     - 실제 지출, 집행률
     - 지출 예정(금액을 모르는 품목이 있으면 "N개 제외")
     - 남은 예산(음수는 "N 초과")
   - 남은 돈(실제 수입 − 실제 지출)
   - 건수: 수입 N건, 지출 N건, 증빙 누락 N건
   - 알림 줄:
     - 취소한 수입 N건·지출 N건은 넣지 않았어요.
     - 행사 지출은 결제일과 상관없이 행사가 든 기간으로, 상시 운영 지출은 결제일로 셌어요.
     - 잔액은 0원에서 시작해 이 기간의 수입·지출만 더하고 뺀 값이에요.
2. **수입 결산**
   - 열: 수입 항목, 예산, 실제 수입, 비율(실제 ÷ 예산, 예산이 0원이면 —)
   - 줄: 수입 줄(편성 순서), "수입 항목을 고르지 않은 수입", 합계
3. **지출 결산**
   - 열: 구분(행사·운영), 항목, 예산, 실제 지출, 집행률, 지출 예정, 남은 예산, 비고
   - 줄:
     - 행사 줄(편성 순서): 예산이 미정이면 예산 "미정", 집행률·남은 예산 "—". 비고는 "정산 완료"와 "금액을 모르는 품목 N개 제외".
     - 운영 줄(편성 순서): 지출 예정은 비운다.
     - "운영 항목을 고르지 않은 지출": 비고는 "N건".
     - 합계
4. **수입·지출 내역** (세부 결산내역)
   - 열: 번호, 날짜, 구분(수입·지출), 항목, 내용, 사용처, 수입, 지출, 잔액, 결제 수단, 결제한 사람, 증빙 수, 메모, 기록한 사람
   - 항목:
     - 수입: 수입 항목 이름, 없으면 —
     - 지출: 행사 이름, "상시 운영 · 운영 항목", "상시 운영"
   - 순서: 날짜 순이다. 같은 날이면 수입을 먼저 두고, 그다음 기록한 순이다.
   - 잔액: 위에서부터 수입을 더하고 지출을 뺀다.
   - 마지막 줄은 합계(수입 합, 지출 합, 남은 돈)다.
5. **증빙**
   - 열: 내역 번호, 종류, 파일 이름, 올린 사람, 올린 날, 열기
   - 확인된 증빙만 넣는다. 링크는 행사 정산서와 같은 앱 주소다.

## 화면

- **예산 화면** (3a 순서에 더한다):
  - **기간 머리:** 이름·날짜 옆에 [결산서 내려받기]가 있다. 구성원 모두에게 보인다. 내려받기는 행사 정산서와 같은 방식(파일 주소를 40초 뒤에 해제)이고, 이 함수를 같이 쓰도록 옮긴다.
  - **숫자 4개 아래:**
    - 첫 줄(3a 그대로): "수입 예산 N원 · 배정 안 한 돈 N원"
    - 둘째 줄(새로): "실제 수입 N원 · 남은 돈 N원"
    - 남은 돈이 0보다 작으면 둘째 줄 대신 경고를 보인다: "실제 지출이 실제 수입보다 N원 많아요". 재정 권한자에게는 "빠진 수입 기록이 없는지 확인해 주세요."를 덧붙인다.
  - **"수입" 묶음:** 3a의 "수입 예산" 목록을 바꾼다.
    - 줄마다 카드: 이름, 예산, 실제 수입, "예산의 N%"(예산이 0원이면 없음)
    - 이어서 "수입 항목을 고르지 않은 수입 N건 · N원"(있을 때만)
  - **"수입 내역" 묶음:**
    - 재정 권한자에게 [수입 기록]이 있다.
    - 카드: 받은 날, 내용, 수입 항목, 금액. 취소한 수입에는 "취소됨"을 붙이고 흐리게 한다.
    - 카드를 누르면 수입 상세가 열린다. 300건을 넘으면 "최근 300건만 보여요"를 적는다.
- **수입 기록·수정(대화상자):**
  - 칸: 수입 항목(이 기간에 수입 줄이 있을 때만, "고르지 않음" 포함), 내용, 받은 날, 금액(원), 메모
  - 받은 날의 기본값은 오늘이다. 오늘이 기간 밖이면 가까운 쪽 끝날(시작일이나 끝일)이다.
  - 받은 날이 기간 밖이면 "이 기간({시작} ~ {끝}) 안의 날짜를 골라 주세요."를 보이고 저장을 끈다.
  - 저장 버튼은 같은 스키마(`CreateIncomeSchema`·`UpdateIncomeSchema`)의 `safeParse`와 위 날짜 조건으로 켠다.
- **수입 상세(대화상자):**
  - 보이는 것: 내용·금액, 받은 날, 수입 항목, 메모, 기록한 사람, 처리 기록
  - 재정 권한자는 [수정]과 [수입 취소](사유를 받는다)를 쓴다. 취소한 수입은 둘 다 감춘다.
- **편성 수정:** 취소하지 않은 수입이 고른 수입 줄은 [지우기]가 꺼지고 "이 항목을 고른 수입이 있어요"를 적는다.
- 긴 내용·이름에는 `wrap-anywhere`를 준다.

## 오류·로그·보안

- 로그와 오류 응답에 내용·메모·금액·사유를 남기지 않는다.
- 처리 기록의 `changes`에는 바뀐 값을 담는다. 구성원에게만 보이는 화면 자료다.
- 결산서의 영수증 링크는 서버가 만든 앱 주소만 쓴다(행사 정산서와 같다).

## 테스트

- **계약:** 수입 세 본문을 검사한다.
  - 필수값 누락, `budgetLineId`·`note` 빠짐
  - 내용·메모·사유: 빈 값·공백만, 상한+1(이모지 포함), NUL·홀로 쓰인 서러게이트
  - 금액 0·음수·소수·상한+1, 없는 날짜·범위 밖 날짜, 버전 0, 모르는 키
- **API(PGlite):**
  - 기록: 성공(항목 있음·없음), 기간 밖 날짜, 다른 기간의 줄·운영 줄·다른 학생회 줄
  - 수정: 바뀐 칸만 처리 기록, 바뀐 것 없음, 버전 충돌, 취소한 수입
  - 취소, 다시 취소(409)
  - 다른 기간 경로의 수입(404), 다른 학생회, 미인증, 재정 권한 없음(403)
  - 편성 응답: 줄의 실제 수입·건수, 항목 없는 수입, 합계의 실제 수입·남은 돈, 수입 내역 순서와 취소한 것
  - 편성 수정: 수입이 고른 줄 지우기(409), 취소한 수입만 고른 줄 지우기(통과, 표시 지움), 수입을 밖으로 내보내는 날짜 변경(409)
  - 결산서: 머리글·파일 이름, 시트 내용(합계·잔액·순서·지출 기준), 구성원 누구나, 다른 학생회·미인증, 상한 초과
- **결산서 시트(단위):** 요약 숫자와 알림 줄, 수입·지출 결산의 미정·0원 예산, 내역의 순서와 잔액, 증빙 링크, 음수 남은 예산 서식
- **화면:**
  - 예산 화면: 수입 줄의 실제 수입, 항목 없는 수입, 돈 줄과 음수 경고, 수입 내역(취소됨), 재정 권한이 없을 때 버튼 숨김, 결산서 내려받기
  - 수입 대화상자: 저장 버튼 조건, 기간 밖 날짜 안내, 수입 줄이 있을 때만 항목 고르기, 실패 문구
  - 수입 상세: 처리 기록, 취소 흐름, 취소한 수입의 버튼 숨김
  - 편성 수정: 수입이 고른 줄의 지우기 꺼짐
- **경계 테스트:** 새 변경 라우트 3개가 공통 가드 검사를 받는다.
