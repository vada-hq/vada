# 프론트엔드 디자인 기반 설계 (Tailwind v4 + shadcn/ui)

2026-10-07 작성.

## 목표

화면이 임시처럼 보이는 문제를 없앤다. 와이어프레임의 디자인 언어를 코드의 토큰과 부품으로 옮기고, 화면은 그 부품을 조립해서만 만든다. 화면마다 CSS를 새로 짜던 방식이 프론트 작업을 불안정하게 만들었으므로, 그 구조를 바꾸는 것이 목적이다.

완료 기준:
- 남을 화면(로그인, 가입, 사이드바, 행사 목록, 채팅)이 데스크톱에서 와이어프레임과 같은 모양이다.
- 휴대폰 폭에서는 글자가 커지고, 사이드바가 메뉴 버튼으로 접힌다.
- 구매·배송 화면은 배치는 그대로이고, 버튼·입력칸·칩만 새 부품이다.
- 옛 CSS 파일(`styles/*.css`, 화면별 `.css`)이 없다. CSS는 Tailwind 진입 파일(`src/index.css`, 토큰과 기준 글자 크기 포함) 하나만 남는다.
- AGENTS.md에 화면 규칙이 있고, 개발 서버에서 부품 확인 화면(`/ui.html`)을 볼 수 있다.

## 결정 (사용자)

- Tailwind v4와 shadcn/ui를 도입한다.
- 범위는 "남을 화면만 깊게"다. 구매·배송 화면은 구매 재설계 때 다시 만들므로, 지금은 공통 부품만 바꿔 끼운다.
- 데스크톱은 와이어프레임과 똑같이 만들고, 휴대폰에도 대응한다.
- 진행 방식은 접근 A다. 한 브랜치에서 기반 → 부품 → 앱 틀 → 화면 순으로 바꾸고, 마지막에 옛 CSS를 지운다.

## 와이어프레임에서 확인한 사실

Figma `B5OHqrl9bbvXCUkhME4Sfo`를 2026-10-07에 분석했다.

- **화면:** 89개다. 데스크톱 1288×740이 84개이고, 휴대폰 화면은 외부 참가자용 EXT 5개뿐이다.
- **색:** 모든 값이 Tailwind v4 기본 팔레트와 정확히 같다.
- **크기:** Tailwind 기본 스케일에 0.875를 곱한 값이다. 기준 글자를 14px로 두면 표준 클래스로 1:1 재현된다. 예를 들어 사이드바 210px = `w-60`, 헤더 56px = `h-16`, 본문 12.25px = `text-sm`이다.
- **아이콘:** Lucide 외곽선 아이콘이다.
- **글꼴:** 영문은 Inter이고, 한글 글꼴은 지정돼 있지 않다.
- **부품 정의:** Figma 변수, 컴포넌트, variant가 없다. HTML을 캡처한 결과물로 보인다. 그래서 앞으로는 코드의 부품이 디자인 기준이 된다. Code Connect도 쓸 수 없다(조직 플랜의 유료 좌석이 필요하다).
- **상태 화면:** 마우스를 올렸을 때, 눌렀을 때, 포커스를 받았을 때의 모양이 그려져 있지 않다.
- **불일치:** 화면마다 부품 모양이 다른 곳이 14군데 있다. 아래 "통일 규칙"으로 하나씩 정한다.

## 기반

- **패키지:**
  - `tailwindcss`, `@tailwindcss/vite`
  - shadcn이 쓰는 `class-variance-authority`, `clsx`, `tailwind-merge`, `radix-ui`, `tw-animate-css`
  - `lucide-react`, `pretendard`
  - 모두 정확한 버전으로 고정한다.
- **shadcn 설정:**
  - `apps/web/components.json`을 두고, `@/` 별칭이 `src/`를 가리키게 한다(tsconfig와 Vite 둘 다).
  - 부품은 `src/components/ui/`에 둔다. 클래스를 합치는 함수 `cn()`은 `src/lib/utils.ts`에 둔다.
- **기준 글자 크기:** 루트를 `87.5%`(14px)로 둔다. 휴대폰 폭(640px 미만)에서는 `100%`(16px)로 둔다. 모든 크기가 rem이라 함께 커진다.
- **글꼴:**
  - 본문은 `Pretendard Variable`(동적 서브셋, 우리 서버에서 제공)이다. Pretendard의 영문 글자는 Inter 기반이라 와이어프레임과 맞는다.
  - 고정폭은 시스템 고정폭 글꼴을 쓴다. 초대 코드 표시에 쓴다.

## 디렉토리 구조

`apps/web`의 바뀐 뒤 구조다. 기능 폴더(access, auth, chat, deliveries, events, purchases, workspace)는 그대로 둔다. 공통 코드만 shadcn 관례대로 `components/`와 `lib/`로 모은다.

```
apps/web/
  components.json        shadcn 설정 (별칭 @/ = src/)
  index.html             앱 진입
  ui.html                부품 확인 화면 진입 (개발 서버 전용, 운영 빌드 제외)
  vite.config.ts         Tailwind 플러그인, @/ 별칭
  src/
    main.tsx             앱 시작: index.css 불러오기, 카카오톡 전환
    index.css            유일한 CSS: Tailwind, 토큰, 기준 글자 크기, 글꼴
    App.tsx              로그인 · 초대 · 소속 분기
    components/
      ui/                기본 부품 (shadcn에서 가져와 통일 규칙대로 고친 것과
                         같은 규칙으로 만든 것: button, input, textarea, label,
                         native-select, badge, card, alert, dialog, sheet,
                         nav-item, tab-button)
      AuthCard.tsx       로그인·가입 가운데 카드
      EmptyState.tsx     빈 화면
      Avatar.tsx         아바타
      BrandMark.tsx      로고 (사이드바·인증 카드)
      StateMessage.tsx   상태 문구 역할 (shared/ui에서 옮김)
    lib/
      utils.ts           cn()
      in-app-browser.ts  카카오톡 감지 (shared에서 옮김)
    access/              가입 · 초대 화면과 로직
    auth/                인증 클라이언트
    chat/                채팅 화면과 useChat
    deliveries/          배송 화면과 로직
    events/              행사 목록 · 행사 만들기 대화상자와 useEvents
    purchases/           구매 화면과 로직
    workspace/
      Workspace.tsx      로그인 후 앱 틀: 선택 상태 관리 + 사이드바 + 헤더 + 본문
      WorkspaceSidebar.tsx   사이드바 내용 (지금 Sidebar.tsx)
      WorkspaceHeader.tsx    경로 · 제목 · 휴대폰 메뉴 버튼
      EventWorkspace.tsx     행사 탭 (대화 · 구매요청)
    ui-gallery/          부품 확인 화면 (components만 가져오고 API를 부르지 않음)
    test-support/        테스트 도우미 (지금과 같음)
```

- **없어지는 것:** `styles/`(tokens.css, base.css), `shared/`(옮김), `App.css`, 그리고 화면별 `.css` 5개(Chat, Workspace, Purchases, Deliveries, App)가 없어진다.

폴더 규칙:
- **`components/ui/`:** shadcn에서 온 기본 부품이다. API 호출이나 기능 로직을 넣지 않는다. 고칠 때는 통일 규칙을 바꿀 때뿐이다.
- **`components/`:** 여러 기능이 같이 쓰는 표시용 부품이다. API를 부르지 않는다.
- **기능 폴더:** 자기 화면, 데이터 훅(`useX`), 상태 계산을 가진다. 다른 기능의 화면은 조립할 수 있다. 예를 들어 workspace가 chat과 purchases를 넣는다. 다른 기능의 내부 도우미는 가져오지 않는다.
- **새 CSS 파일을 만들지 않는다:** 모양은 클래스로만 준다. `index.css`에는 토큰과 전역 기본값만 둔다.
- **테스트 위치:** 테스트는 대상 파일 옆(`*.test.tsx`)에 두고, 여러 테스트가 쓰는 도우미는 `test-support/`에 둔다.

## 토큰

shadcn 색 변수를 와이어프레임 값으로 정한다.

| 변수 | 값 | 쓰임 |
|---|---|---|
| `--background` | `#f9fafb` (gray-50) | 페이지 배경 |
| `--foreground` | `#101828` (gray-900) | 제목, 본문 기본 |
| `--card`, `--popover` | `#ffffff` | 카드, 대화상자, 사이드바 |
| `--primary` / `-foreground` | `#155dfc` (blue-600) / `#ffffff` | 주 버튼, 활성 탭 밑줄 |
| `--secondary` / `-foreground` | `#f3f4f6` (gray-100) / `#364153` (gray-700) | 보조 버튼, 중립 칩 |
| `--muted` / `-foreground` | `#f3f4f6` / `#6a7282` (gray-500) | 설명, 비활성 탭 |
| `--accent` / `-foreground` | `#eff6ff` (blue-50) / `#1447e6` (blue-700) | 활성 메뉴 항목 |
| `--destructive` | `#e7000b` (red-600) | 위험 버튼, 오류 글자 |
| `--border` | `#e5e7eb` (gray-200) | 카드·구분선 |
| `--input` | `#d1d5dc` (gray-300) | 입력칸·테두리 버튼 |
| `--ring` | `#155dfc` | 포커스 테두리 |

- **의미색:** 칩과 배너의 변형 안에서만 Tailwind 팔레트 클래스로 쓴다. 각각 배경 50, 테두리 200, 글자 700 단계다.
  - info: blue
  - success: green
  - warning: yellow (amber가 아니다)
  - danger: red
  - neutral: gray-100 배경에 gray-500 글자
- **모서리 반경:** 세 단계로 정한다.
  - 작은 값 3.5px: 버튼, 입력칸, 칩, 메뉴 항목
  - 중간 값 5.25px: 배너, 통계 타일
  - 큰 값 약 9px: 카드, 대화상자, 인증 카드
- **그림자:** 두 단계다. 카드는 `shadow-sm`, 대화상자는 `shadow-2xl`이다.

## 통일 규칙 (와이어프레임 불일치 정리)

- **주 버튼:** 한 종류만 쓴다. 반경은 작은 값, 굵기는 500이다. 모든 버튼 변형에 1px 테두리를 둔다(주 버튼은 투명). 그래서 주 버튼과 테두리 버튼의 높이가 같다.
- **버튼 종류:** 주, 테두리, 보조, 텍스트, 위험, 링크의 6가지다. 크기는 보통(md)과 작게(sm) 두 가지다. 비활성은 투명도 0.45다.
- **입력칸:** 한 종류만 쓴다(반경 작은 값, 높이 33.5px). 대화상자 안에서도 같은 입력칸을 쓴다.
- **카드:** 반경 큰 값에 `shadow-sm`이다. 행사 개요 화면(EVT-02)의 그림자 없는 카드는 쓰지 않는다.
- **탭:** 페이지 탭 모양 하나만 쓴다. 높이 40px, 글자 굵기 500이다. 비활성은 gray-500, 활성은 blue-700 글자에 blue-600 2px 밑줄이다.
- **배너:** 모든 종류가 반경 중간 값이다.
- **대화상자:** 오버레이는 검정 45%, 제목 굵기는 600, 안쪽 여백은 21px이다. 버튼 줄은 오른쪽 정렬하고 취소는 테두리 버튼이다. 회색 footer 띠는 쓰지 않는다(와이어프레임의 두 대화상자 모양 중 단순한 쪽).
- **제목 크기:** 헤더 제목은 14px/600(`text-base`)이다. 본문 영역 제목은 17.5px/700(`text-xl`)이다.

## 부품

- **shadcn에서 가져와 위 규칙대로 고친다:** button, input, textarea, label, badge, card, alert, dialog, sheet
- **같은 규칙으로 직접 만드는 기본 부품:** native-select(브라우저 선택칸에 입력칸 모양), nav-item(사이드바 메뉴 항목), tab-button(페이지 탭)
- **shadcn sidebar는 쓰지 않는다:** 접기, 단축키, 쿠키 저장처럼 쓰지 않는 기능이 많다. 데스크톱은 `aside`, 768px 미만은 sheet로 직접 만든다. 화면 폭 판단은 CSS 중단점으로만 한다.
- **직접 만든다:**
  - `EmptyState`: blue-50 원 안에 아이콘, 제목, 설명
  - `Avatar`: gray-200 원 안에 사람 아이콘. 와이어프레임에 사진이나 이니셜이 없다.
  - `AuthCard`: 로그인·가입 가운데 카드
  - `BrandMark`: 파란 정사각형 안의 "V". 사이드바와 인증 카드 머리에 같이 쓴다.
- **체크박스는 브라우저 기본 모양을 쓴다:** 와이어프레임에도 체크박스 디자인이 없다. 크기와 강조색(blue-600)만 준다.
- **`StateMessage`는 남긴다:** 기존 `StateMessage`는 역할(`status`, `alert`)만 담당하므로 그대로 쓴다. 모양은 Tailwind 클래스로 준다.
- **탭은 지금 구현을 유지한다:** 행사 탭(대화·구매요청)은 지금의 ARIA 탭 구현을 그대로 쓰고 모양만 바꾼다. 숨기기만 해서 입력 내용과 스크롤을 보존하는 동작을 지키기 위해서다.

## 앱 틀

- **사이드바:** 데스크톱 폭 210px(`w-60`)이고, 768px 미만에서는 옆에서 열리는 메뉴가 된다. 위에서부터 이렇게 놓는다.
  - **위:** 파란 정사각형 "V", "VADA", 학생회 이름. 소속이 여럿이면 학생회를 고르는 칸을 둔다. 그 아래 [구성원 초대] 버튼을 둔다.
  - **가운데 "행사" 묶음:** 행사마다 메뉴 항목을 둔다. 활성 항목은 accent 배경이다. 묶음 제목 옆에 새로고침 아이콘 버튼과 [+ 새 행사] 버튼을 둔다.
  - **아래:** 아바타, 이름, 부서(없으면 "미배정"), 로그아웃 아이콘 버튼.
  - **없는 기능은 넣지 않는다:** 와이어프레임 메뉴 중 홈, 내 업무, 재정, 기록, 조직 관리, 메시지는 아직 없는 기능이라 넣지 않는다.
- **헤더:** 높이 56px이다.
  - 768px 미만이면 메뉴 버튼을 둔다.
  - 경로("학생회 이름 › 행사")와 제목(행사 이름, 고른 행사가 없으면 "행사")을 둔다.
- **행사 탭:** 헤더 아래 40px이다.
- **본문:** gray-50 배경에 패딩 21px(`p-6`)이다.

## 화면

- **로그인과 가입:**
  - 가운데 카드로 만든다. 와이어프레임 SIGN-IN·INV-00·INV-01처럼 반경 큰 값, `shadow-sm`, 넓은 안쪽 여백을 쓴다.
  - 로그인 화면의 초대 안내, 카카오톡 안내, 오류 문구도 카드 안에 둔다.
  - 로그인한 뒤의 카드(소속 확인 중, 코드 입력, 학생회 확인)도 같은 카드를 쓴다.
- **행사 만들기:** 사이드바의 입력칸 대신 대화상자를 쓴다. 제목 "새 행사", 행사 이름 입력칸과 글자 수, [취소]와 [행사 만들기](와이어프레임 버튼 문구)를 둔다.
- **구성원 초대:** 사이드바 복사 버튼 두 개 대신 대화상자를 쓴다(ORG-03C 모양).
  - 읽기 전용 입력칸 "초대 링크"와 [초대 링크 복사], 고정폭 읽기 전용 입력칸 "초대 코드"와 [코드 복사]를 둔다.
  - 링크와 코드가 늘 보이므로, 복사에 실패하면 안내 문구만 보여 주고 사용자가 직접 선택해 복사한다.
- **빈 화면:** 고른 행사가 없으면 `EmptyState`를 보여 준다. 문구는 지금과 같다.
- **채팅:**
  - 와이어프레임에 말풍선 디자인이 없다. 그래서 같은 디자인 언어로 목록형 메시지를 만든다(아바타, 이름 600, 시간 muted xs, 본문).
  - 입력창은 아래에 둔다. 여러 줄 입력, 글자 수, [전송]을 둔다.
  - 끼룩이 버튼은 보조 버튼 모양으로 둔다.
- **구매·배송:** 버튼, 입력칸, 여러 줄 입력, 칩만 새 부품으로 바꾼다. 배치는 지금 CSS와 같은 모양을 Tailwind 클래스로 옮긴다(`Purchases.css`, `Deliveries.css` 삭제). 구매 링크 대화상자는 지금의 `<dialog>`를 그대로 쓴다.

## 규칙과 확인

- **AGENTS.md "화면" 절:**
  - 화면은 `src/components/ui`와 `src/components`의 부품과 테마 토큰만 쓴다.
  - 색은 테마 토큰이나 Tailwind 기본 팔레트 클래스만 쓴다. `bg-[#...]`, `text-[13px]` 같은 임의 값은 쓰지 않는다.
  - 새 부품이나 변형은 `/ui.html`에 추가한다.
  - 화면을 바꾸면 와이어프레임의 해당 노드 스크린샷과 비교한다.
- **부품 확인 화면:** `apps/web/ui.html`과 `src/ui-gallery/`로 만든다. 개발 서버에서만 열리고 운영 빌드에는 들어가지 않는다. 모든 부품의 변형과 상태(비활성, 오류)를 한 화면에 모은다.
- **테스트:**
  - 기존 테스트는 역할과 문구 기준이라 그대로 통과해야 한다. 행사 만들기와 구성원 초대처럼 구조가 바뀌는 곳만 고친다.
  - 새 동작에는 테스트를 더한다: 대화상자 열기·닫기, 휴대폰 메뉴 버튼.
  - shadcn 부품 자체의 모양은 테스트하지 않는다. 클래스 문자열을 확인하는 테스트는 의미가 없기 때문이다.
  - Radix가 jsdom에서 필요로 하는 기능(ResizeObserver 등)은 테스트 설정에서 채운다.
- **눈으로 확인:**
  - 로컬 `/ui.html`과 와이어프레임 노드 스크린샷을 나란히 비교한다.
  - 실제 화면은 배포 뒤 운영에서 확인한다(가림 여부는 elementFromPoint, 캐시는 새로고침으로 확인).

## 배포

DB 변경은 없다. 브랜치에서 모든 화면을 확인한 뒤 main에 병합하고 푸시한다.

## 위험

- **기존 화면이 한꺼번에 바뀐다:** Tailwind의 기본 초기화(preflight)가 기존 화면을 일제히 바꾼다. 브랜치 안에서 모든 화면을 옮기고 확인한 뒤에 병합한다.
- **글꼴 첫 로딩:** Pretendard 동적 서브셋은 화면에 쓰인 글자 범위의 파일만 받지만, 첫 접속에는 파일 몇 개를 더 받는다.
- **새 와이어프레임:** 시각 스타일이 바뀌면 토큰과 부품을 고친다. 화면 코드는 부품만 쓰므로 영향이 작다.

## 하지 않는 것

다크 모드, 자동 스크린샷 비교, 없는 기능의 화면, 구매·배송 화면 재배치, Storybook, 끼룩이 마스코트 그림, 부서 색 칩, 표·페이지네이션·캘린더 같은 아직 쓰지 않는 부품.
