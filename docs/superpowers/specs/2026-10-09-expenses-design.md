# M2-1 결제·증빙과 사용 내역 설계

2026-10-09. M2 "재정 마무리"의 첫 단계다. M1은 구매 요청 → 재정부 승인 → 구매함·송장 → 수령에서 끝난다. 결제한 금액과 영수증은 앱 밖(엑셀·단톡방)에 남는다. M2-1은 재정부가 결제 한 번마다 "지출"을 기록하고 영수증을 붙이게 한다. 학생회 구성원은 누구나 사용 내역과 증빙 여부를 본다.

## 왜 이것부터

- 학생회칙은 행사가 끝날 때마다 증빙서류를 첨부해 정산하라고 정한다. 예: [건국대 생물공학과 학생회칙](https://ai.konkuk.ac.kr/sites/microbio/files/건국대학교%20공과대학%20생물공학과%20학생회칙(2023.09.01).pdf) 제30조 2항.
- 결산 때마다 학생회비 투명성 논란이 반복된다([동해뉴스](https://dhnews.co.kr/news/view/179515033663138)). 회원은 재정에 대한 알 권리를 가진다(예: [가톨릭관동대 학생회칙](https://www.cku.ac.kr/bbs/math/613/75764/artclView.do)).
- 승인된 품목이 이미 앱에 있으니, 실제 결제액과 영수증만 붙이면 요청부터 증빙까지 한곳에 남는다.

## 범위

- 넣는다: 지출 기록·수정·취소, 승인 품목 연결, 영수증 올리기·보기·지우기, 처리 기록, 사용 내역(합계·증빙 누락), 구매 검토 화면의 진입점.
- 넣지 않는다(뒤 단계):
  - M2-2: 행사 예산·정산 완료·결산 내보내기
  - M2-3: 학생회 예산 편성·예산 항목
  - 구성원의 환급 요청 흐름, 영수증 글자 읽기(OCR)

## 정책

1. **지출 하나 = 결제 한 번(영수증 한 장 단위).** 결제일, 사용처, 내용, 실제 결제액, 결제 수단, 결제한 사람, 행사(없으면 상시 운영), 메모를 둔다.
2. **결제 수단:** 학생회 카드, 계좌이체, 현금, 개인 결제(환급 필요). 개인 결제의 "결제한 사람"은 돌려받을 사람이다.
3. **연결 품목:**
   - 승인된 구매 품목만 연결한다. 품목 하나는 지출 하나에만 연결된다.
   - 연결 품목은 그 지출의 행사에 속해야 한다. 상시 운영 지출에는 품목을 연결하지 않는다.
   - 아직 "샀어요" 전인 품목을 연결하면 그 자리에서 구매함으로 표시하고, 품목 처리 기록에 남긴다.
4. **연결된 품목은 "구매 표시 취소"를 막는다**(`LINKED_TO_EXPENSE`). 지출을 고치거나 취소해 연결을 풀면 다시 할 수 있다.
5. **쿠팡 밖 지출**(현장 구매, 인쇄소, 다과 등)은 품목 없이 내용과 금액만 적는다.
6. **권한:**
   - 기록·수정·취소·영수증 올리기·지우기는 구매 승인 권한이 있는 사람(재정 부서·회장단)만 한다.
   - 사용 내역, 지출 상세, 영수증 파일은 학생회 구성원 모두가 본다.
   - 행사 운영 조직이 없으므로 행사별 권한은 두지 않는다.
7. **취소:**
   - 지출을 지우지 않는다. 사유(200자)를 받아 "취소됨"으로 남긴다.
   - 취소한 지출은 합계에서 빠지고, 연결 품목은 풀린다. 취소한 지출은 고칠 수 없다.
8. **증빙:**
   - 파일마다 종류(영수증·거래명세서·세금계산서·기타)를 고른다.
   - 다 올라간 파일이 1개 이상이면 "증빙 완료", 없으면 "증빙 누락"이다.
   - 지출 하나에 10개까지, 파일 하나 10MB까지다. JPG·PNG·WEBP·HEIC·PDF만 받는다.
9. **승인액 비교:** 연결 품목의 수량 × 예상 단가 합과 실제 결제액이 다르면 차이를 보여 준다. 막지는 않는다. 수량이나 단가가 비어 있는 품목이 있으면 비교하지 않는다.
10. **처리 기록:** 기록, 수정(바뀐 칸의 이전·이후 값), 취소, 영수증 추가·삭제를 남기고 상세에서 보여 준다. 기록은 고치거나 지우지 않는다.
11. **사용 내역:**
    - 결제일 최근 순으로 300개까지 보여 주고, 넘으면 알린다. 취소된 지출도 "취소됨"으로 보인다.
    - 위에 이번 달(한국 시간) 지출 합계, 전체 지출 합계, 증빙 누락 건수를 둔다. 셋 다 취소를 뺀다.
12. **영수증 저장소가 없을 때:** 지출 기록은 된다. 영수증 올리기만 "영수증 저장소가 아직 준비되지 않았어요."로 막는다(`STORAGE_NOT_CONFIGURED`, 503).
13. **휴대폰 기준:** 목록은 한 줄 카드다. 영수증은 파일 선택으로 카메라·사진첩을 둘 다 고를 수 있게 한다(`capture`를 강제하지 않는다).

## 와이어프레임과 다른 점

- **묶음 단위:** 와이어프레임 FIN-EVID-01은 옛 "요청서"(REQ-001) 안에서 업체별로 묶는다. M1에는 요청서가 없고, 쿠팡 주문 하나에 여러 사람의 품목이 들어간다. 그래서 지출(결제 한 번)을 단위로 하고 품목을 연결한다.
- **증빙 종류:** 와이어프레임은 종류마다 "등록 완료/누락"을 따로 둔다. 결제마다 필요한 서류가 달라 판단할 수 없으므로, 파일이 1개 이상이면 완료로 본다.
- **결제 수단:** "법인카드"는 학생회에 맞지 않아 "학생회 카드"로 바꾸고, 현금·개인 결제를 더한다.
- **화면 배치:** 사용 내역(FIN-LEDGER-01)의 6~7열 표 대신, 휴대폰에서 읽히는 카드 목록으로 만든다.
- **예산 항목:** 예산 항목·부서 필터·예산 대비 집행은 M2-2·M2-3에서 다룬다.

## 영수증 저장소 (Cloudflare R2)

- **파일은 우리 서버를 거치지 않는다.** 공통 가드가 `/api/organizations/` 아래 변경 요청을 JSON 32KB로 제한하기 때문이다.
- **올리는 순서:**
  1. 서버가 영수증 행을 `pending`으로 만들고, 10분짜리 서명 주소(PUT)를 준다.
  2. 브라우저가 R2에 바로 올린다.
  3. 서버가 HEAD로 크기·형식을 확인한 뒤 `ready`로 바꾼다. 신고한 크기·형식과 다르면 객체를 지우고 `UPLOAD_MISMATCH`(400)를 돌려준다.
- **보기:** 서버가 5분짜리 서명 주소(GET)로 302 이동시킨다. 사진은 `<img>`로 바로 보이고 PDF는 새 탭으로 연다.
- **저장 경로:** `receipts/{조직}/{지출}/{영수증}`. 서버가 정하고 사용자 입력을 쓰지 않는다. 버킷은 비공개다.
- **서명:** `aws4fetch`로 S3 호환 서명을 한다. 주소는 `https://{계정}.r2.cloudflarestorage.com/{버킷}/{경로}`다.
- **환경변수:** `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET`. 넷 중 하나라도 없으면 저장소를 끈다(정책 12).
- **버킷 CORS:** 운영 원점(`https://vada-m1.onrender.com`)과 개발 원점(`http://127.0.0.1:5180`)에서 PUT·GET, `Content-Type` 헤더를 허용한다.
- **끝나지 않은 업로드:** `pending` 행은 목록·개수에 넣지 않는다. 정리는 뒤 단계에서 한다.

## API

경로 앞부분은 `/api/organizations/:organizationId`다. 변경 본문은 모두 contracts의 `z.strictObject`이고 `json(Schema)`를 인증보다 앞에 둔다.

| 경로 | 권한 | 본문 → 응답 |
|---|---|---|
| `GET /expenses` | 구성원 | → `{ expenses, truncated, totals: { thisMonth, total, missingEvidence } }` |
| `GET /expenses/:expenseId` | 구성원 | → `{ expense }` (상세: 영수증·처리 기록 포함) |
| `POST /expenses` | 재정 | `CreateExpense` → 201 `{ expense }` |
| `PATCH /expenses/:expenseId` | 재정 | `UpdateExpense`(version + 전체 칸) → `{ expense }` |
| `POST /expenses/:expenseId/void` | 재정 | `{ version, reason }` → `{ expense }` |
| `POST /expenses/:expenseId/receipts` | 재정 | `{ fileName, contentType, size, kind }` → 201 `{ receiptId, upload: { url, headers }, expiresAt }` |
| `POST /expenses/:expenseId/receipts/:receiptId/confirm` | 재정 | `{}` → `{ expense }` |

## 화면

- **옆 메뉴 "사용 내역":** 구성원 모두에게 보인다.
  - 위: 이번 달 지출, 전체 지출, 증빙 누락 N건.
  - 재정 권한이 있으면 [지출 기록]이 보인다.
  - 목록:
    - 월별 제목 아래 카드. 카드에는 사용처·내용, 행사(또는 "상시 운영"), 금액, 결제일·결제 수단·결제한 사람, 증빙 칩(완료/누락), 취소됨 칩이 있다.
    - 카드를 누르면 상세를 연다.
  - 빈 상태: "아직 기록된 지출이 없어요". 재정 권한자에게는 "결제한 뒤 지출을 기록해 주세요."도 보인다.
- **지출 상세(대화상자):**
  - 칸, 연결 품목, 승인액 비교("승인 135,000원 → 실제 137,500원 · 2,500원 많음"), 영수증, 처리 기록을 보여 준다.
  - 영수증: 사진은 작은 미리보기, PDF·HEIC는 파일 이름 링크다.
  - 재정 권한이 있으면 [영수증 추가]·[수정]·[취소], 영수증마다 [삭제]가 있다.
- **지출 기록·수정(대화상자):**
  - 칸: 행사(상시 운영 + 행사 목록), 사용처, 내용, 결제일(기본 오늘), 결제 수단, 결제한 사람(기본 나), 금액, 메모, 연결 품목.
  - 연결 품목은 고른 행사의 연결 가능한 승인 품목 체크 목록이다.
  - 저장 버튼은 같은 스키마의 `safeParse`로 켠다. 기록하면 상세로 가서 영수증을 올리게 한다.
- **영수증 올리기:**
  - 파일 선택 한 번에 여러 개를 고른다. 파일마다 "올리는 중…"·완료·실패를 보여 준다.
  - 종류는 기본 "영수증"이고, 올린 뒤 바꾸지 않는다.
  - 형식·크기는 같은 스키마로 먼저 검사한다. 파일 이름이 200자를 넘으면 확장자를 남기고 줄인다.
- **취소(대화상자):** 사유를 받아 취소하고, "합계에서 빠지고 연결 품목은 풀려요."라고 알린다.
- **구매 검토 → 구매·배송:** "산 품목" 제목 옆에 [지출 기록]을 둔다(같은 대화상자). 지출에 연결된 품목의 [구매 표시 취소]는 서버가 막고 안내한다.
- 긴 사용처·내용·파일 이름에는 `wrap-anywhere`를 준다.

## 오류·로그·보안

- 로그와 응답에 파일 이름, 금액, 서명 주소, 키를 남기지 않는다. 서명 주소는 응답 본문(올리기)과 `Location`(보기)에만 담는다.
- 다른 학생회의 지출·영수증은 없는 것으로 본다(404).
- 서명 주소는 짧게 산다(PUT 10분, GET 5분). `Cache-Control: no-store`를 붙인다.

## 테스트

- 계약: 각 스키마의 필수값 누락, 빈 값·공백, 상한+1(이모지 포함), NUL·홀로 쓰인 서러게이트, 모르는 키.
- API(PGlite·가짜 저장소):
  - 기록·수정·취소·버전 충돌
  - 품목 연결 규칙(승인 아님, 이미 연결, 다른 행사, 상시)과 구매함 자동 표시, 구매 표시 취소 막기
  - 영수증 올리기·확인(크기 불일치 삭제)·삭제·개수 제한·저장소 없음
  - 목록 합계(이번 달은 한국 시간, 취소 제외, 증빙 누락), 300개 제한
  - 다른 학생회, 미인증, 재정 권한 없음
- 저장소: 서명 주소의 호스트·경로·만료·서명 헤더, HEAD·DELETE 결과 해석
- 화면: 목록·합계·빈 상태, 기록 대화상자(행사 바꾸면 품목 목록 바뀜, 저장 버튼 조건), 영수증 올리기 순서(만들기 → PUT → 확인)와 실패 표시, 취소, 구매 검토 진입점, 긴 글 `wrap-anywhere`

## 배포 순서

1. 0015를 dev와 배포 DB에 적용한다(새 표만).
2. R2 버킷·CORS·키를 준비해 로컬 `.env`와 Render에 넣는다(사용자 작업).
3. dev에서 실제 R2로 확인한 뒤 main에 병합·푸시한다.
4. 키가 늦어져도 배포는 할 수 있다. 영수증 올리기만 정책 12대로 막힌다.
