# M3b-2 행사 참가비를 정산에서 수입으로 넣기 설계

2026-10-11. M3(참가자 모집·참가비·참석 확인)의 둘째 단계 가운데 뒷부분이다. M3b-1로 운영진이 신청자 명단에서 참가비 입금을 확인하게 됐다. 하지만 받은 참가비는 학생회 장부에 들어가지 않는다. 예산 화면의 실제 수입·남은 돈과 결산서에 빠져 있어, 재정 담당자가 수입 기록으로 다시 적어야 한다. 행사 재정 탭과 정산서에도 참가비가 없다.

M3b-2는 행사를 정산할 때 입금을 확인한 참가비를 그 행사가 든 회계 기간의 수입 한 건으로 넣는다(M2-3c 이월금과 같은 방식). 행사 재정 탭과 정산서에 참가비를 보인다.

## 왜 이렇게

- **참가비는 수입으로 따로 적는다.** [부산대 재정운용세칙](https://union.pusan.ac.kr/bbs/union/3153/859765/download.do)은 모든 수입을 세입으로 적고(제7조), 세입을 학생회비·이월금·사업수익·기타수익으로 나눈다(제12조). 행사 참가비는 사업수익이다. 그래서 행사 지출에서 빼지(상계하지) 않고 기간의 수입으로 적는다. 행사 예산 숫자 4개는 그대로다.
- **정산이 숫자를 닫는 때다.**
  - 정산 뒤에는 입금 확인·확인 취소·금액 변경이 막힌다(M3b-1). 그래서 정산할 때의 받은 참가비가 정산을 다시 열 때까지 그대로다.
  - 입금을 확인할 때마다 수입을 만들면 행사 하나에 수입이 수십 건 생기고, 확인 취소마다 수입도 취소해야 한다.
- **이월금(M2-3c)과 같은 방식이다.** 앱이 만드는 수입 한 건이고 손으로 고치지 않는다. 바꾸려면 원래 기록(행사 정산)을 다시 연다.
- **와이어프레임 행사 재정(EVT-FIN-01 `28:685`)에는 수입이 없다.** 지출과 구매 요청만 다룬다. 참가비 묶음을 새로 둔다.

## 범위

- **넣는다:**
  - 정산할 때 받은 참가비를 행사가 든 기간의 수입 한 건으로 넣기, 정산을 다시 열면 취소
  - 정산 조건: 받은 참가비가 있으면 행사가 회계 기간에 들어 있어야 한다
  - 행사 재정 탭: 참가비 묶음, 정산 확인의 참가비 수입 항목, 처리 기록
  - 정산서 엑셀 요약의 참가비
  - 수입 상세: 참가비 수입 안내와 버튼 감춤
  - 편성 수정: 참가비 수입이 있는 행사는 빼지 않는다
  - 예산 화면 알림: 받은 참가비가 있는데 기간에 넣지 않은 행사도 센다
  - M3b-1에서 미룬 것: 정산한 행사의 참가자 탭에서 입금·참가비 버튼을 감춘다
  - M2-3c에서 미룬 것 가운데 같은 코드: 취소된 이월금 상세에 "다시 열어 주세요"가 붙는 것
- **넣지 않는다:**
  - 환불 처리(운영진 취소 때 "돌려줬어요" 고르기). 위험 절에 둔다.
  - 참가비를 뺀 행사 순지출, 예산 화면 행사 카드의 참가비
  - 참가비 밖의 행사 수입(후원·판매 등)을 행사에 붙이기
  - 학생 화면(공개 신청·내 신청) 변경

## 정책

1. **받은 참가비와 입금 전**
   - 받은 참가비: 이 행사 참가 신청에서 입금을 확인한 신청의 확인 금액 합이다. 취소했거나 정보를 지운 신청도 센다(M3b-1 `payments`와 같다).
   - 입금 확인 수: 그 신청의 수다.
   - 입금 전: 정보를 지우지 않은 신청 가운데 낼 돈이 있고 확인 전인 것의 수다. 참가자 탭의 "입금 전"과 같다.
2. **참가비 수입** (정산할 때)
   - 받은 참가비가 0원보다 크면 행사가 든 기간에 수입 한 건을 만든다.
     - 받은 날: 마지막으로 입금을 확인한 날(한국 날짜). 기간 밖이면 가까운 쪽 끝날(시작일이나 끝일)이다. 수입 기록 대화상자의 기본값과 같은 규칙이다.
     - 내용: "{행사 이름} 참가비". 100자를 넘으면 행사 이름 뒤를 줄이고 "…"를 붙인다.
     - 금액: 받은 참가비
     - 수입 항목: 정산할 때 고른 그 기간의 수입 줄이다. 고르지 않아도 된다. 그 기간의 수입 줄이 아니면 `BUDGET_LINE_INVALID`다.
     - 메모: "입금 확인 N명"
     - 기록한 사람: 정산한 사람
   - 받은 참가비가 0원이면 만들지 않고, 보낸 수입 항목은 보지 않는다.
   - 정산 처리 기록(`settled`)에 `fee: { amount, count, period, line } | null`을 더한다. `period`·`line`은 이름이다.
3. **정산 조건** (M2-2 정책 3에 더한다)
   - 받은 참가비가 있으면 행사가 회계 기간에 들어 있어야 한다. 아니면 `NOT_READY_TO_SETTLE`이다.
   - 입금 전 신청은 정산을 막지 않는다.
     - 오지 않은 신청자는 끝내 입금하지 않는다. 보관 기간(행사 끝 + 30일)이 지나면 운영진이 그 신청을 고칠 수도 없다.
     - 대신 재정 탭이 입금 전 수를 보이고, 정산 확인이 정산 뒤에는 입금을 확인할 수 없다고 알린다.
4. **참가비 수입의 잠금**
   - 수정·취소할 수 없다(`FEE_INCOME`). 바꾸려면 행사 정산을 다시 연다.
   - 정산을 다시 열면 참가비 수입을 취소한다. 사유는 "{행사 이름} 정산을 다시 열었어요"이고 수입 처리 기록에 남는다. 다시 정산하면 그때의 받은 참가비로 새로 만든다.
   - 참가비 수입이 있는 행사는 편성 수정에서 뺄 수 없다(`FEE_INCOME`).
     - 행사 지출은 행사를 따라 기간을 옮기지만 수입은 기간에 붙어 있어, 빼면 둘이 다른 기간에 남는다.
     - 옮기려면 정산을 다시 열고(참가비 수입 취소), 옮긴 뒤 다시 정산한다.
   - 그 밖에는 보통 수입과 같다. 3b·3c 규칙도 그대로다.
     - 기간의 실제 수입·남은 돈·결산서·마감에 들어간다.
     - 고른 수입 줄은 지울 수 없다(`LINE_IN_USE`).
     - 기간 날짜를 바꿔 기간 밖으로 내보낼 수 없다(`INCOMES_OUTSIDE_PERIOD`).
   - 행사 하나에 취소하지 않은 참가비 수입은 한 건뿐이다(DB 부분 unique 색인).
5. **예산 화면 알림** (M2-3a 정책 6을 넓힌다)
   - "지출이 있는데 기간에 넣지 않은 행사"를 "지출이나 받은 참가비가 있는데 기간에 넣지 않은 행사"로 넓힌다.
   - 정산하지 않고 기간에도 넣지 않은 행사의 참가비는 마감 조건에 걸리지 않아 장부에서 빠질 수 있기 때문이다.
6. **정산한 행사의 참가자 탭**
   - 서버는 이미 입금 확인·확인 취소·참가비 바꾸기·금액 변경을 막는다(`EVENT_SETTLED`, M3b-1).
   - 화면이 [입금 확인]·[입금 확인 취소]·참가비 바꾸기를 감추고, 설정 대화상자의 금액 칸을 끄고, 이유를 적는다.
   - 신청 취소는 그대로 된다. 받은 돈은 바뀌지 않는다(M3b-1 정책 7).
7. **권한**
   - 정산·다시 열기는 재정 권한자다(그대로).
   - 재정 탭의 참가비 숫자(합과 수)는 구성원 누구나 본다. 신청자별 이름·금액·납부 구분은 나가지 않는다.

- **행사 재정(EVT-FIN-01):** 숫자 4개와 처리 단계뿐이고 수입이 없다. 숫자 아래에 "참가비" 묶음을 둔다. 숫자 4개(예산 기준)는 바꾸지 않는다. 참가비는 행사 예산을 늘리지 않고 기간의 수입이 된다.
- **참가자 명단(EVT-04):** 정산 상태가 없다. 정산한 행사에서는 입금 버튼을 감추고 이유를 적는다.

**배포 순서**
- 새 코드가 새 칸을 읽는다. 그래서 두 DB에 먼저 적용한 뒤 배포한다.
- 새 칸에만 제약을 건다. 기존 행은 새 칸이 모두 NULL이라 어길 수 없다. 기존 칸에 거는 제약은 없다.
- 적용 전에 두 DB에서 "정산했는데 입금 확인이 있는 행사"가 0건인지 본다. 있으면 그 행사는 참가비 수입 없이 정산된 것이다(위험 절).

## API

본문은 contracts의 `z.strictObject`이고, `json(Schema)`를 인증보다 앞에 둔다. 새 라우트는 없다.

**정산** (`POST /api/organizations/:organizationId/events/:eventId/finance/settle`)
- `SettleEventSchema`: `{ version, feeIncomeLineId: string | null }`. `feeIncomeLineId`는 꼭 보낸다.

**응답에 더하는 것**
- `EventFinance`
  - `fees`: `{ received, count, unpaid } | null`
    - 정책 1의 세 숫자다.
    - 참가 신청이 없거나, 참가비를 받지 않고(참가비 0원, 납부자 참가비 없음) 입금 확인도 없으면 null이다.
  - `period`: `{ id, name, incomes: [{ id, name }] } | null`. 행사가 든 회계 기간과 그 기간의 수입 줄(편성 순서)이다.
  - `feeIncome`: `{ id, amount, period: { id, name }, line: { id, name } | null } | null`. 이 행사의 취소하지 않은 참가비 수입이다.
- `EventFinanceHistoryEntry.changes`(`settled`)에 `fee`(정책 2)
- `IncomeSummary.event`: `{ id, name } | null`. 참가비 수입이면 그 행사다.
- `BudgetEventLine.feeIncome`: boolean. 취소하지 않은 참가비 수입이 있으면 true다. 화면이 [빼기]를 끈다.
- `BudgetPlanResponse.notices.eventsWithSpending` → `eventsWithMoney`: 지출이나 받은 참가비가 있는데 기간에 넣지 않은 행사 수
- `RegistrationResponse.settled`: boolean. 행사 정산이 끝났으면 true다.

**오류**

| 코드 | 상태 | 경우 |
|---|---|---|
| `NOT_READY_TO_SETTLE` | 409 | 받은 참가비가 있는데 행사가 기간에 없음(더함) |
| `BUDGET_LINE_INVALID` | 409 | 참가비 수입 항목이 행사가 든 기간의 수입 줄이 아님 |
| `FEE_INCOME` | 409 | 참가비 수입 수정·취소, 참가비 수입이 있는 행사를 기간에서 빼기 |

## 동시성

- **정산:**
  - 재정 권한 확인 → 학생회 예산 잠금(같이) → 행사가 든 기간 행 `FOR SHARE` → 행사 행 `FOR NO KEY UPDATE` → 버전·상태 → 조건과 받은 참가비 → 참가비 수입 → 정산
  - 예산 잠금을 같이 잡아, 편성 수정(혼자 잡음)이 행사를 빼거나 옮기는 사이에 참가비 수입이 옛 기간에 들어가지 않게 한다. 마감(혼자 잡음)과도 겹치지 않는다.
  - 순서는 정산 다시 열기와 같다(학생회 예산 → 기간 행 → 행사 행).
  - 받은 참가비는 행사 행을 잠근 뒤 센다. 입금 확인·확인 취소(`FOR SHARE`)와 금액 변경(`FOR NO KEY UPDATE`)이 행사 행에서 겹치지 않으므로, 센 값이 정산이 끝날 때까지 그대로다.
- **다시 열기:** 지금 순서 그대로이고, 행사 행을 잠근 뒤 참가비 수입을 취소한다.
- **편성 수정:** 예산 잠금을 혼자 잡은 뒤 뺄 행사의 참가비 수입을 본다.
- **수입 수정·취소:** 수입 행을 잠근 뒤 참가비 수입이면 막는다(이월금과 같은 자리).

## 화면

**행사 재정 탭** (M2-2 순서에 더한다)
1. **정산 상태:** 다시 열기 안내를 바꾼다. 참가비 수입이 있으면 "다시 열면 참가비 수입 N원이 취소되고, 지출과 예산을 바꿀 수 있어요."
2. **숫자 4개:** 그대로
3. **"참가비" 묶음** (새로, `fees`가 있을 때만):
   - "받은 참가비 N원 · 입금 확인 N명"
   - 입금 전이 있으면 "입금 전 N명"
     - 정산 전이면 재정 권한자에게 "정산 뒤에는 입금을 확인할 수 없어요. 들어온 돈이면 참가자 탭에서 먼저 확인해 주세요."
   - 참가비 수입이 있으면 "N원을 {기간} 수입으로 넣었어요."와, 수입 항목을 골랐으면 "수입 항목: {이름}"
4. **"정산하려면":**
   - 받은 참가비가 있으면 줄을 더한다.
     - 기간이 있으면 "참가비를 넣을 회계 기간: {기간}"(체크)
     - 없으면 "참가비를 넣을 회계 기간이 없어요"와 해결 방법 "예산 화면의 편성 수정에서 이 행사를 회계 기간에 넣어 주세요."
   - 정산 확인에 더한다.
     - 받은 참가비가 있으면 "받은 참가비 N원은 {기간} 수입으로 들어가요."
     - `fees`가 있으면 "정산 뒤에는 입금 확인과 참가비를 바꿀 수 없어요."
     - 받은 참가비가 있고 그 기간에 수입 줄이 있으면 "참가비 수입 항목"을 고른다. 기본값은 이름에 "참가비"가 든 첫 줄이고, 없으면 "고르지 않음"이다.
     - 보낼 때 고른 줄이 새로 받은 목록에 없으면 고르지 않은 것으로 보낸다(마감과 같다).
5. **처리 기록:** 참가비 수입을 넣은 정산은 "정산 완료 · 실제 지출 N원 · 참가비 N원 → {기간} 수입"

**예산 화면**
- **수입 상세:**
  - 참가비 수입이면 [수정]·[수입 취소]를 감춘다.
  - 모두에게 "{행사} 정산에서 넣은 참가비예요."를 적는다. 재정 권한자에게는 취소되지 않았고 기간이 열려 있을 때 "바꾸려면 그 행사 정산을 다시 열어 주세요."를 덧붙인다.
  - 이월금의 "바꾸려면 그 기간 마감을 다시 열어 주세요."도 취소된 이월금에는 붙이지 않는다(M2-3c에서 미룬 것).
- **편성 수정:** 참가비 수입이 있는 행사 줄은 [빼기]가 꺼지고 "참가비 수입이 들어간 행사예요. 빼려면 행사 정산을 다시 열어 주세요."를 적는다.
- **알림:** "지출이나 받은 참가비가 있는데 기간에 넣지 않은 행사 N개 — 편성 수정에서 행사를 넣어 주세요."

**참가자 탭** (정산한 행사, `settled`)
- 신청자 카드: [입금 확인]을 감추고, 참가비가 있는 신청이면 "정산이 끝난 행사라 입금과 참가비를 바꿀 수 없어요."를 적는다.
- 관리 대화상자: 참가비 바꾸기·[입금 확인]·[입금 확인 취소]를 감추고 같은 문장을 적는다. [신청 취소]는 그대로다.
- 설정 대화상자: 금액 칸과 납부자 체크를 끄고 "정산이 끝난 행사라 참가비를 바꿀 수 없어요."를 적는다.

긴 행사·기간·수입 항목 이름에는 `wrap-anywhere`를 준다.

## 정산서

- 요약 시트의 "증빙 누락" 아래에 "참가비" 묶음을 둔다. `fees`가 있을 때만이다.
  - "받은 참가비": 금액과 "입금 확인 N명"
  - "참가비 수입": "{기간} 수입", 수입 항목을 골랐으면 " · {이름}"을 붙인다. 참가비 수입이 있을 때만이다.
- 신청자별 입금은 넣지 않는다. 정산서는 구성원 누구나 내려받고, 금액으로 학생회비 납부 여부를 알 수 있기 때문이다.
- 결산서(기간)는 바꾸지 않는다. 참가비 수입은 보통 수입 한 줄로 들어간다.

## 오류·로그·보안

- 로그와 오류 응답에 행사 이름·금액·인원을 남기지 않는다.
- 재정 탭과 정산서에는 참가비 합과 수만 나간다.
- 참가비 수입의 내용·메모는 앱이 만든다. 사람이 쓴 글이 아니지만 결산서에는 다른 수입과 같이 문자 칸으로 쓴다.

## 테스트

- **계약:** `SettleEventSchema`: `feeIncomeLineId` 빠짐(거절), null, 경로 ID 규칙에 맞지 않는 값(거절), 모르는 키
- **API(PGlite):**
  - 정산
    - 받은 참가비가 있는데 기간 없음 → `NOT_READY_TO_SETTLE`
    - 참가비 수입: 받은 날(기간 안·기간 앞·기간 뒤), 내용, 금액, 수입 항목, 메모, 기록한 사람, `event`
    - 취소했거나 정보를 지운 신청의 확인 금액도 센다
    - 받은 참가비가 0원이면 수입을 만들지 않고 기간 없이도 정산한다
    - 수입 항목: 다른 기간의 줄·운영 줄·없는 줄 → `BUDGET_LINE_INVALID`, null이면 고르지 않음
    - 처리 기록의 `fee`, 기간의 실제 수입·남은 돈
    - 긴 행사 이름의 내용 줄이기
  - 재정 탭 응답: `fees`(받은 참가비·입금 확인 수·입금 전), `period`(수입 줄), `feeIncome`, 참가 신청이 없거나 무료일 때 null
  - 다시 열기: 참가비 수입 취소(사유, 처리 기록), `feeIncome` null, 다시 정산하면 새 금액으로 새 수입
  - 수입 수정·취소 → `FEE_INCOME`
  - 편성 수정: 참가비 수입이 있는 행사 빼기 → `FEE_INCOME`, 다시 열면 뺄 수 있음, `events[].feeIncome`, 날짜를 바꿔 참가비 수입이 기간 밖 → `INCOMES_OUTSIDE_PERIOD`
  - 알림: 받은 참가비만 있는 행사도 센다
  - 참가 신청 응답의 `settled`
  - 정산서 자료: `fees`, `feeIncome`
  - 권한: 정산은 재정 권한 없음 403, 다른 학생회 404, 미인증 401(기존 테스트가 새 본문으로 돈다)
- **정산서 시트(단위):** 참가비 묶음(있을 때만), 참가비 수입 줄과 수입 항목
- **마이그레이션:** 0022의 CHECK(이월금이면서 참가비 수입), 부분 unique(행사 하나에 취소하지 않은 것 하나), 같은 학생회 FK
- **화면:**
  - 재정 탭: 참가비 묶음(받은·입금 전·재정 권한자 안내·넣은 기간), "정산하려면"의 기간 줄(있음·없음과 정산 버튼), 정산 확인 문구·수입 항목 기본값·보내는 본문, 다시 열기 안내, 처리 기록
  - 수입 상세: 참가비 수입 안내와 버튼 감춤, 취소된 이월금 안내
  - 편성 수정: 참가비 수입이 있는 행사의 [빼기] 꺼짐과 이유
  - 예산 알림 문구
  - 참가자 탭: 정산한 행사의 입금 버튼 감춤·안내, 관리 대화상자, 설정 대화상자의 금액 칸

## 위험

- **환불:** 운영진이 입금 확인을 취소하지 않고 신청을 취소하면 그 금액은 받은 돈으로 남고, 되돌릴 화면이 없다(M3b-1). 정산하면 수입에 들어간다.
  - 운영진 취소 대화상자가 "돌려줬다면 먼저 입금 확인을 취소해 주세요."라고 알린다.
  - 이미 정산했다면 돌려준 돈을 행사 지출(환불)로 기록한다. 장부의 합계는 맞고, 수입과 지출이 같은 금액만큼 커진다.
- **받은 날은 실제 입금일이 아니다.** 마지막 입금 확인일이다. 결산서 내역의 잔액 흐름이 통장과 며칠 어긋날 수 있다.
- **정산 뒤에 입금한 학생:** 확인할 수 없다. 정산을 다시 열고 확인한 뒤 다시 정산한다. 재정 탭이 입금 전 수를 보여 미리 알 수 있다.
- **M3b-2 배포 전에 정산한 행사:** 입금 확인이 있어도 참가비 수입이 없다. 배포 전에 두 DB에서 0건인지 본다. 있으면 정산을 다시 열고 다시 정산하면 들어간다.

## 배포 순서

1. 0022를 dev와 배포 DB에 적용한다. 새 코드가 새 칸을 읽으므로 먼저 적용한다.
2. dev에서 정산(참가비 수입)·다시 열기·수입 상세·참가자 탭을 확인한 뒤 main에 병합·푸시한다.
