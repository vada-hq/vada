# M5a 행사 완료 설계

2026-10-12. M4까지 행사마다 대화, 업무, 구매, 참가 신청, 재정이 생겼다. 하지만 행사는 끝나지 않는다. 정산까지 해도 옆 메뉴의 행사 목록에 남고, 끝난 행사의 업무는 내 업무에 계속 "지연"으로 남는다. 끝난 행사의 기록도 누구나 계속 바꿀 수 있다.

M5a는 행사를 끝내는 일을 만든다. 행사 단계(기획 중·진행 중·정리 중)는 날짜로 계산한다. 회장단은 정산이 끝난 행사를 "완료"한다. 완료한 행사는 바꿀 수 없고, 옆 메뉴의 "기록"으로 옮겨진다. M5b는 그 기록에 결과보고서를 붙인다.

## 왜 이렇게

2026-10-12에 사용자가 아래 비판과 범위를 승인했다(M5 전체 중 M5a 부분).

- **상태는 날짜로 계산하고, 손으로 하는 것은 "완료" 하나다.**
  - 와이어프레임은 기획 중 → (행사 종료) → 후속 정리 중 → (완료 처리) → 완료를 손으로 넘긴다.
  - 손으로 넘기는 상태는 실제와 어긋난다. 와이어프레임 EVT-02D부터 머리 칩은 "기획 중", 본문은 "후속 정리 중"이다. EVT-02C도 칩은 "기획 중", 본문은 "현재 상태: 진행 중"이다.
  - 행사에는 이미 일시가 있다(M3a). 그래서 기획 중·진행 중·정리 중은 날짜로 계산한다.
- **완료는 회장단만, 정산이 끝나야 한다. 남은 업무는 경고만 한다.**
  - 와이어프레임은 남은 항목이 있어도 경고만 하고 완료한다(EVT-02E).
  - 돈은 막는다. 정산하지 않은 행사가 기록으로 가면 기간 마감(M2-3c) 때 다시 꺼내야 한다.
  - 업무는 돈이 아니다. 끝나지 않은 업무가 있으면 수를 알리고 완료는 막지 않는다.
- **완료한 행사는 서버 한곳에서 막고, 모든 행사 변경 경로를 테스트로 검사한다.**
  - 와이어프레임에는 "완료 처리 후에도 행사 기록은 열람할 수 있습니다"만 있다.
  - 기록은 바뀌지 않아야 한다. M5b 결과보고서의 수치(신청→참석, 예산→집행, 업무)도 이 기록에서 나온다.
  - 화면에서 버튼만 감추면 빠뜨린 버튼이나 오래 열어 둔 화면으로 바뀐다. 그래서 서버가 막는다.
  - 회장단은 완료를 취소할 수 있다. 실수로 완료했을 때 되돌릴 길이다.
- **개요 탭(EVT-02)을 만들지 않는다.**
  - 개요는 다른 탭의 숫자(신청자 수, 납부, 담당자 없는 업무, 다음 일정)를 다시 모은 화면이다.
  - 넣으면 행사 탭이 여섯이 된다. 지금 다섯 탭이 375px 폭에 맞춰져 있다.
  - 단계 칩과 [완료하기]는 화면 머리에 둔다.

## 범위

- **넣는다:**
  - 행사 단계 칩: 기획 중·진행 중·정리 중·완료
  - 완료하기(확인 대화상자)와 완료 취소. 회장단만 한다.
  - 완료한 행사의 쓰기 잠금(서버)과 볼 수만 있는 행사 화면
  - 옆 메뉴 "기록": 완료한 행사 목록
  - 옆 메뉴 행사 목록·내 업무·구매 검토에서 완료한 행사를 뺀다.
  - 저장소 규칙과 테스트: 행사를 바꾸는 경로는 완료를 확인한다.
  - 시연 데이터의 완료한 행사
- **넣지 않는다:**
  - 결과보고서, 기록 목록의 수치(참석·집행률·업무 수), 행사 담당 부서·책임자: M5b
  - 개요 탭, 행사 종료 확인(EVT-02C), 최근 변경 사항, 행사 운영 조직
  - 행사 지우기, 행사 이름 바꾸기, 완료 기록(누가 언제 취소했는지)

## 정책

1. **행사 단계** (저장하지 않고 계산한다)
   - 완료: 완료한 행사. 아래보다 먼저 본다.
   - 기획 중: 시작 일시가 없거나, 지금이 시작 전이다.
   - 진행 중: 시작했고 아직 끝나지 않았다.
     - 끝 일시가 있으면 끝 일시 전까지다.
     - 끝 일시가 없으면 시작한 날(한국 날짜)이 끝날 때까지다.
   - 정리 중: 끝났지만 완료하지 않았다.
   - 화면이 기기 시각으로 계산한다. 서버는 단계를 쓰지 않는다.
2. **완료**
   - 회장단만 한다(`manageOrganization`). 다른 사람은 `FORBIDDEN`이다.
   - 행사 재정이 정산돼 있어야 한다. 아니면 `EVENT_NOT_SETTLED`(409)다.
     - 돈을 쓰지 않은 행사도 재정 탭에서 정산할 수 있다(M2-2).
   - 막지 않고 알리기만 하는 것:
     - 끝나지 않은 업무(예정·진행 중) 수
     - 행사가 아직 끝나지 않음(기획 중·진행 중)
   - 완료 시각과 완료한 사람을 남기고 행사 버전을 올린다.
   - 화면이 본 행사 버전을 보낸다. 다르면 `VERSION_CONFLICT`다. 이미 완료한 행사면 `INVALID_STATE`다.
3. **완료 취소**
   - 회장단만 한다. 완료한 행사만 된다(아니면 `INVALID_STATE`).
   - 완료 시각과 완료한 사람을 지우고 버전을 올린다. 정산은 그대로다.
   - 취소 기록은 남기지 않는다. 돈이 바뀌지 않는다.
4. **완료한 행사에서 막는 것** (`EVENT_COMPLETED`, 409)
   - 행사 일시·장소 고치기
   - 대화 보내기
   - 업무 추가·수정·상태 바꾸기·지우기
   - 구매
     - 후보 숨기기, 끼룩이로 담기, 작성 중 품목 고치기·지우기, 제출, 받을 날짜 바꾸기, 취소, 다시 담기, 받음 표시
     - 구매 검토의 승인·반려, 승인 되돌리기, 구매함 표시
     - 배송 연결·연결 끊기
   - 참가 신청
     - 신청서 만들기·고치기, 운영진 취소, 입금 확인·확인 취소, 참가비 바꾸기, 참석 확인(QR·이름)·확인 취소
     - 공개 신청: 신청서 상태를 "마감"으로 본다(`REGISTRATION_NOT_OPEN`).
     - 내 신청 취소: `CANCEL_CLOSED`로 막는다. 학생에게는 "완료"보다 "취소 기간이 끝났어요"가 맞다.
   - 재정: 행사 예산, 정산, 정산 다시 열기
     - 정산을 다시 열려면 먼저 완료를 취소한다.
   - 그 행사의 지출: 기록, 고치기, 취소, 영수증 올리기·확인·지우기
     - 정산 잠금(`requireOpenEvents`)이 완료를 정산보다 먼저 본다. 그래서 `EVENT_SETTLED`가 아니라 `EVENT_COMPLETED`다.
5. **완료한 행사에서도 그대로 되는 것**
   - 보기: 구성원 모두. 지금과 같은 권한이다.
   - 예산 편성에 행사를 넣고 빼기: 기간의 일이다. 행사 예산 금액은 정산이 막는다.
   - 부서 지우기: 그 부서가 담당인 업무(완료한 행사 포함)의 담당 부서를 비운다(M4). 조직의 일이라 막지 않는다.
   - 신청자 정보 자동 파기: 보관 기간이 지나면 지금처럼 지운다.
   - 배송 조회기가 받아 오는 배송 상태
6. **완료한 행사가 보이는 곳**
   - 옆 메뉴 행사 목록에서 빠지고, 옆 메뉴 "기록"에 나온다(최근 완료 순).
   - 내 업무와 옆 메뉴 수에서 빠진다(할 일·완료 모두).
   - 구매 검토의 대기·살 품목과 배송 연결할 품목에서 빠진다.
   - 지출 기록의 행사 고르기에서 빠진다. 이미 그 행사에 기록한 지출은 사용 내역에 그대로 있다.
   - 예산 화면은 그대로다. 행사 이름을 누르면 볼 수만 있는 행사 화면이 열린다.
   - 공개 신청 화면은 "마감"이다. 내 신청 화면에는 취소 버튼이 없다.
7. **저장소 규칙**(AGENTS.md "새 API를 만들 때"에 더한다)
   - 행사 기록을 바꾸는 라우트는 `/events/:eventId/` 아래에 둔다.
   - 거래 맨 앞에서 행사 잠금 함수(`events/lock.ts`)로 완료를 확인한다.
   - `completion-lock.test.ts`가 그 아래 모든 변경 라우트를 확인한다.

## 데이터 (마이그레이션 0025)

**events** (칸 더하기)

| 칸 | 내용 |
|---|---|
| `completed_at` | timestamptz. 완료하지 않았으면 null |
| `completed_by` | text. users FK, `ON DELETE RESTRICT`. 완료하지 않았으면 null |

- CHECK `events_completed_pair`: `(completed_at IS NULL) = (completed_by IS NULL)`
- 색인은 두지 않는다. 학생회마다 행사가 수십 개다.
- 행사 만들기의 `INSERT … SELECT`는 모든 칸을 골라야 하므로 두 칸을 null로 채운다.

**배포 순서**
- 새 칸만 더하고 기존 칸에 제약을 걸지 않는다. 새 칸은 모두 null이라 위반 행이 생길 수 없다.
- 새 코드가 새 칸을 읽으므로 두 DB에 먼저 적용하고 배포한다.
- 적용한 뒤 배포 전까지 옛 코드는 새 칸을 모른다. 행사를 만들 때 칸 목록을 적어 보내므로 새 칸은 null이 된다.

## API

본문은 contracts의 `z.strictObject`이고, `json(Schema)`를 인증보다 앞에 둔다. 완료 라우트는 이미 있는 `createEventRoutes`에 더한다.

**행사 완료** (앞부분 `/api/organizations/:organizationId/events/:eventId/completion`)

| 경로 | 권한 | 본문 → 응답 |
|---|---|---|
| `GET` | 구성원 | → `EventCompletionResponse` |
| `POST` | 회장단 | `CompleteEventSchema` → `EventResponse` |
| `POST /cancel` | 회장단 | `CancelEventCompletionSchema` → `EventResponse` |

- `CompleteEventSchema`, `CancelEventCompletionSchema`: `{ version }`(행사 버전, 1 이상 정수)
- `EventCompletionResponse`: `{ settled: boolean, openTasks: number }`
  - 완료 확인 대화상자가 연다. `openTasks`는 예정·진행 중 업무 수다.
- `EventSummary`에 `completedAt: string | null`을 더한다(ISO 시각). 행사 목록은 지금처럼 모든 행사를 주고, 화면이 나눈다.
- 회장단 검사는 `access/membership.ts`에 `requireOrganizationManager()`로 더한다. `requireEventManager()`와 같은 꼴이다.

**오류**

| 코드 | 상태 | 뜻 |
|---|---|---|
| `EVENT_COMPLETED` | 409 | 완료한 행사를 바꾸려 함 |
| `EVENT_NOT_SETTLED` | 409 | 정산하지 않은 행사를 완료하려 함 |
| `INVALID_STATE` | 409 | 이미 완료한 행사를 완료, 완료하지 않은 행사를 완료 취소 |
| `VERSION_CONFLICT` | 409 | 다른 사람이 먼저 행사를 바꿈 |
| `FORBIDDEN` | 403 | 회장단이 아님 |
| `NOT_FOUND` | 404 | 다른 학생회 행사, 없는 행사 |

## 거래와 잠금

- **완료·완료 취소:** 행사 행을 `FOR NO KEY UPDATE`로 잠그고, 버전·완료 여부·정산을 본 뒤 바꾼다.
- **행사 기록을 바꾸는 쓰기:** 거래 안에서 행사 행을 `FOR SHARE` 이상으로 잠그고 `completed_at`을 본다. 그 전에는 아무것도 바꾸지 않는다.
  - 완료(`FOR NO KEY UPDATE`)와 겹치지 않는다. 먼저 잠근 쪽이 끝난 뒤 다른 쪽이 진행되고, 나중 쓰기는 완료를 보고 멈춘다.
  - 새 함수(`events/lock.ts`)
    - `requireActiveEvents(tx, organizationId, eventIds)`: `FOR SHARE`, 여러 행사는 ID 순서로 잠근다.
    - `lockActiveEvent(tx, organizationId, eventId)`: `FOR NO KEY UPDATE`, 행을 돌려준다.
  - 이미 행사 행을 `FOR NO KEY UPDATE`로 잠그는 곳은 그 잠금을 `lockActiveEvent`로 바꾼다. 같은 거래에서 `FOR SHARE`를 먼저 잡고 올리면 교착이 날 수 있기 때문이다.
    - 행사 일시·장소, 업무 추가, 신청서 만들기·고치기, 정산·다시 열기·행사 예산
  - `requireOpenEvents`(정산 잠금, `FOR SHARE`)는 정산보다 완료를 먼저 본다. 이미 부르는 곳(지출·영수증·구매 제출·입금)은 고치지 않는다.
  - 나머지는 거래 맨 앞에서 `requireActiveEvents`를 부른다.
- **잠금 순서:** 학생회 예산 → 기간 → 행사 → 신청서·품목·업무·배송 행
  - 정산은 예산·기간을 먼저 잠근다. 그래서 그 뒤에 오는 행사 잠금은 지금 자리에서 본다.
  - 소속·부서 잠금은 지금 자리 그대로 둔다(구매는 소속을 먼저 잠근다). 조직 변경은 행사 행을 잠그지 않아 엇갈리지 않는다.
  - 공개 신청·내 신청 취소는 신청서를 잠그지 않고 먼저 찾아 행사를 안다. 그다음 행사, 신청서 순으로 잠근다.
  - 구매 검토·배송 연결은 품목의 행사를 잠그지 않고 먼저 읽는다. 그다음 행사들을 ID 순으로 잠그고 품목을 잠근다. 품목의 행사는 바뀌지 않는다.
- **끼룩이로 담기:** 상품을 조회하고 끼룩이를 부르기 전에 완료를 한 번 본다(잠그지 않음). 완료한 행사에 생성 비용을 쓰지 않으려는 것이다. 저장 거래에서 다시 잠그고 본다.

## 화면

- **화면 머리** (행사 화면)
  - 제목 옆에 단계 칩: 기획 중(info), 진행 중(success), 정리 중(warning), 완료(neutral)
  - 오른쪽에 회장단만 [완료하기] 또는 [완료 취소]
  - 경로는 완료하지 않은 행사가 "행사", 완료한 행사가 "기록"이다.
- **완료 확인 대화상자**
  - 열면 `GET …/completion`을 부른다.
  - 안내: 완료하면 대화·업무·구매·참가자·재정을 바꿀 수 없고, 행사가 "기록"으로 옮겨진다. 회장단은 완료를 취소할 수 있다.
  - 정산 전: "재정 탭에서 먼저 정산해 주세요" 문구와 꺼진 [완료하기]
  - 알림(켜진 [완료하기]): "끝나지 않은 업무 N개는 그대로 남아요", "아직 행사가 끝나지 않았어요"
- **완료 취소 확인 대화상자:** 다시 바꿀 수 있게 되고 옆 메뉴 행사 목록으로 돌아간다는 안내
- **볼 수만 있는 행사 화면**
  - 탭 위에 한 줄 안내: "완료한 행사라 볼 수만 있어요."
  - 탭마다 바꾸는 버튼과 입력을 감춘다.
    - 대화 입력, 업무 추가·카드 버튼·상세의 상태·수정·지우기
    - 구매: 후보 담기·숨기기, 링크 패널의 담기, 품목 버튼
    - 참가자: 신청서 만들기·설정, 행사 정보 고치기, 신청자 버튼, 참석 확인
    - 재정: 예산, 정산, 다시 열기, 지출 기록
  - 보기용 단추(보드/일정 고르기, 거르기, 상세 열기, 내려받기)는 그대로다.
  - 빠뜨린 버튼이나 오래 열어 둔 화면에는 서버가 `EVENT_COMPLETED`를 준다. 모듈마다 오류 문구에 "완료한 행사라 바꿀 수 없어요"를 더한다.
- **옆 메뉴**
  - 행사 목록은 완료하지 않은 행사만 보인다.
  - 메뉴 끝(참가비 설정 다음)에 "기록". 기록 화면이나 완료한 행사를 볼 때 켜진다.
- **기록 화면**
  - 완료한 행사 목록. 최근 완료 순이다.
  - 줄: 이름(`wrap-anywhere`), 행사 날짜 또는 "날짜 미정", "완료 YYYY. MM. DD."
  - 누르면 볼 수만 있는 행사 화면을 연다(대화 탭).
  - 없으면 빈 상태: "완료한 행사가 아직 없어요"
- 완료·완료 취소가 끝나면 행사 목록의 그 행사를 바꾼다. 화면은 그 행사에 머문다.

## 테스트

- **단계 계산**(화면): 날짜 없음, 시작 전, 진행 중(끝 있음·없음), 끝 일시 정각, 시작한 날 자정 넘김, 완료
- **완료 API**
  - 성공(완료·취소), 회장단 아님, 미인증, 다른 학생회, 없는 행사
  - 정산 전 `EVENT_NOT_SETTLED`, 버전 다름, 이미 완료·완료 아님 `INVALID_STATE`
  - 본문 경계: 버전 누락, 0, 소수, 문자열, 모르는 키
- **잠금** `apps/api/src/events/completion-lock.test.ts`
  - 모든 모듈로 앱을 만든다. 정산·완료한 행사에 신청서·신청·품목·지출을 둔다. 회장단으로 요청한다.
  - `/events/:eventId/` 아래 모든 변경 라우트(완료 라우트 둘은 빼고)가 표의 본문으로 409 `EVENT_COMPLETED`를 받는다.
    - 표에 없는 라우트가 생기거나 없는 라우트가 표에 남으면 실패한다.
  - 그 밖의 경로도 표로 확인한다.
    - 지출 기록·고치기·취소, 구매 검토 승인·되돌리기·구매함, 배송 연결·끊기: `EVENT_COMPLETED`
    - 공개 신청 `REGISTRATION_NOT_OPEN`, 내 신청 취소 `CANCEL_CLOSED`
  - 완료 취소 뒤에는 같은 쓰기가 다시 된다(대화 하나로 확인).
- **빠지는 곳:** 내 업무, 구매 검토 목록, 배송 연결할 품목, 공개 신청 상태(마감), 내 신청(취소 불가)
- **화면:** 칩, 버튼(회장단만), 대화상자의 정산 전·알림, 볼 수만 있는 탭(감춘 버튼), 옆 메뉴 목록과 기록 화면
