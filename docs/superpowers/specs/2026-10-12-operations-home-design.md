# M6 운영 홈: 멈춘 일을 한 화면에

2026-10-12. 회장단은 회의 때마다 부서를 돌며 "그거 어떻게 됐어요?"를 묻는다. 지원서(Q2)의 첫 문제이고, 지원서(Q3-1)는 "회장단은 부서별 진행 상황과 어디서 일이 멈춰 있는지를 한 화면에서 본다"고 약속했다. 인터뷰 I04도 "행사별 진행 상황·역할·사전 준비 업무가 보이지 않음"을 꼽았다.

M6는 이미 쌓인 업무·구매·지출·신청·정산 기록을 모아, 끝나지 않은 행사마다 무엇이 멈췄고 누가 할 차례인지 보여 주는 "운영 현황" 화면을 만든다. 새 입력도, DB 변경도 없다.

## 원칙 대조

기준은 `vada-product/PRODUCT.md`(작동 원칙·제품 경계·성립 조건)와 `vada-product/sources/application-v3.md`다. 여기에 사용자 원칙이 더해진다. 일은 평소대로, 가치는 자연스럽게. 업무를 늘리지 않고, 지금 하는 행위가 그 사람에게 바로 이득인지로 판단한다.

| 사람이 하는 일 | 새로 생긴 일인가 | 바로 이득 | 판단 |
|---|---|---|---|
| 운영 현황 보기(회장단, 첫 화면) | 아니다. 묻고 다니던 일이 준다 | 묻지 않고 바로 안다 | 그대로 |
| 줄을 눌러 그 기록으로 가기 | 아니다 | 찾아 들어가는 수고가 준다 | 그대로 |
| 그 밖의 입력 | 없다 | | |

- **근거 연결(작동 원칙 1):** 줄마다 원래 기록(업무 상세, 지출 상세, 구매 검토, 행사의 업무·구매·참가자·재정 탭)으로 간다. 홈은 숫자를 따로 저장하지 않고 열 때마다 센다.
- **반복 작성 금지(작동 원칙 2):** 상태를 보고하는 칸이 없다. 구매·지출·신청·정산은 실제 일을 하면 상태가 바뀐다.
- **결정 이유와 변경 이력(작동 원칙 3):** 홈은 아무것도 바꾸지 않는다. 이력은 원래 기록에 있다.
- **제품 경계:** AI를 쓰지 않는다.
- **약점:** 업무 상태만은 사람이 바꾸는 값이다(M4). 끝낸 업무를 완료로 바꾸지 않으면 홈이 "지연"으로 보인다. 담당자 이름과 며칠 지났는지를 같이 보여, 회장단이 묻는 대상이 분명하게 한다.

## 왜 이렇게

- **같은 숫자를 한 번만, 같은 정의로 센다.** 와이어프레임 HOME-01은 "확인 필요 3건" 카드, 알림 목록(합 7건), 재정 요약에 같은 문제를 다르게 셌다(증빙 누락이 알림에서 3건, 재정 요약에서 5건). 홈의 수는 줄을 눌러 가는 화면과 같은 정의로 센다.
  - 업무 지연: M4 `isOverdue`(완료가 아니고 마감일이 오늘보다 앞)
  - 증빙 없는 지출: 재정 탭·사용 내역(취소하지 않았고 확인된 증빙이 없음)
  - 입금 확인 전: 참가자 탭의 "입금 전"(`eventFeesOf`의 unpaid)
  - 정산을 막는 것: 정산 조건(`financeNumbersByEvent`의 증빙 누락·승인 대기·지출 기록 전 품목)
  - 행사 단계: M5a `eventPhaseOf`. 서버도 같은 함수를 써야 해서 contracts로 옮긴다.
- **줄마다 누가 할 차례인지 붙인다.** 종류별 숫자만으로는 "누구에게 물어야 하는지"를 알 수 없다. 업무는 그 업무의 담당 부서와 담당자, 돈 관련 일(구매 승인·구매·증빙·입금 확인·정산)은 재정 부서, 행사 완료는 회장단이다.
- **[행사별 | 부서별] 두 보기.** 학생회 회의는 행사별 준비 공유와 부서별 보고로 돌아간다. 두 보기는 같은 목록을 묶는 방식만 다르다.
- **회장단만 첫 화면을 바꾼다.** 부원이 앱을 열 때 바로 필요한 것은 자기 업무다(M4에서 내 업무를 첫 화면으로 정한 이유). 회장단에게는 멈춘 일이 먼저다. 다른 구성원도 옆 메뉴 "홈"으로 같은 화면을 본다. 보이는 것은 모두 지금도 구성원에게 보이는 기록이고, 신청자는 수만 보인다.
- **바로 가기는 그 기록까지 간다.** 업무와 지출은 홈에서 상세를 바로 연다(내 업무·사용 내역과 같은 대화상자). 나머지는 행사의 해당 탭이나 구매 검토로 간다.

## 범위

- **넣는다**
  - 운영 현황 화면(옆 메뉴 "홈"), 회장단의 첫 화면
  - 행사 카드: 단계·일시·담당, 상태 한 줄(업무 완료 수, 신청 수·정원·마감, 정산함)
  - 멈춘 일 여덟 가지(아래 정책 2)와 위쪽 종류별 수
  - [행사별 | 부서별] 보기, 부서별 업무 수(진행 중·지연·완료)
  - 줄을 누르면 그 기록으로 가기
  - 서버: 조회 경로 하나 `GET /home`
  - `eventPhaseOf`를 contracts로 옮기기
- **넣지 않는다**(와이어프레임 비판에서 승인)
  - 숫자 카드(진행 중 행사·예정 행사·이번 주 일정·확인 필요): 행동으로 이어지지 않는다.
  - 최근 활동: 일어난 일이지 해야 할 일이 아니다. 현재 상태 공유가 먼저다(작동 원칙 3).
  - 전체 재정 요약: 예산 화면과 겹친다.
  - 다가오는 주요 일정·캘린더: 회의가 없어 업무 마감뿐이고 행사 일정 탭(M4)과 겹친다.
  - 끼룩이 브리핑(HOME-01K): 아래 목록의 숫자를 문장으로 다시 말할 뿐이다. AI가 쓸모 있을 곳은 "왜 멈췄는지"를 대화에서 찾아 주는 일인데, 정확도를 먼저 검증해야 한다.
  - 운영 홈 OPS-00: 상시 업무·회의·캘린더로 가는 메뉴판이다. 셋 다 없고 옆 메뉴와 겹친다.
  - 알림·배지: 옆 메뉴 "홈"에 수를 달지 않는다.

## 정책

1. **대상 행사:** 완료하지 않은 행사(`completedAt` 없음)만 본다. 완료한 행사는 기록이다(M5a).
2. **멈춘 일 여덟 가지**

| 종류 | 무엇 | 줄 하나 | 할 차례 |
|---|---|---|---|
| `task_overdue` | 완료가 아니고 마감일이 오늘(한국 날짜)보다 앞인 업무 | 업무마다 | 업무의 담당 부서(없으면 "담당 부서 없음") |
| `tasks_unassigned` | 완료가 아니고 담당자가 없는 업무 | 행사 × 담당 부서마다 수 | 업무의 담당 부서 |
| `purchases_pending` | 승인 대기 품목 | 행사마다 수와 가장 오래된 제출 시각 | 재정 |
| `purchases_late` | 승인했고 받지 않았고 필요한 날이 오늘보다 앞인 품목(정산 전 행사) | 행사마다 수와 가장 이른 필요한 날 | 재정 |
| `expense_no_evidence` | 취소하지 않았고 확인된 증빙이 없는 지출(상시 운영 지출 포함) | 지출마다 | 재정 |
| `fees_unconfirmed` | 정보를 지우지 않았고 입금 확인이 없고 낼 돈이 있는 신청(정산 전 행사) | 행사마다 수 | 재정 |
| `settlement_pending` | 정리 중(끝남)이고 정산하지 않은 행사 | 행사마다, 정산을 막는 수와 함께 | 재정 |
| `completion_pending` | 정리 중이고 정산했고 완료하지 않은 행사 | 행사마다 | 회장단 |

   - 지연 업무와 담당자 없는 업무는 겹칠 수 있다. 업무 보드의 "지연"·"담당자 없음" 거르기와 같은 수다.
   - 정산한 행사에는 승인 대기·증빙 누락이 생길 수 없다(정산 조건). 필요한 날 지난 구매와 입금 확인 전은 정산하면 뺀다. 정산하면 돈이 정해져, 남은 미입금·받음 표시는 멈춘 일이 아니다.
3. **할 차례 묶기(부서별 보기)**
   - 재정은 돈을 맡은 부서(`handlesFinance`)다. 여럿이면 모두에 보이고, 없으면 회장단이다(회장단은 늘 구매를 승인한다).
   - 회장단 부서가 없으면 "담당 부서 없음"에 둔다.
   - 묶기는 화면이 한다(`home-view.ts`). 서버는 부서 목록과 줄을 준다.
4. **수:** 위쪽 종류별 수는 서버가 센 전체 수다. 줄 목록이 잘려도 수는 맞다.
5. **상한:** 지연 업무와 증빙 없는 지출은 각각 100줄까지 오래된 것부터 준다. 넘으면 `truncated`이고 화면이 알린다. 행사 수는 자르지 않는다(옆 메뉴 행사 목록과 같다).
6. **권한:** 구성원 누구나 본다. 미배정도 본다(업무·지출·구매·재정 탭이 모두 구성원에게 보인다). 신청자 이름은 주지 않는다.
7. **시각:** 오늘과 행사 단계는 서버의 한국 시각으로 센다. 응답에 `today`를 주고, 화면은 며칠 지났는지를 그 날로 센다.
8. **정렬**
   - 행사: 시작일 이른 순, 날짜 미정은 뒤, 같으면 만든 순 역순(옆 메뉴와 같다). 지난 행사(정리 중)가 위로 온다.
   - 부서: 회장단, 그다음 이름 순, "담당 부서 없음"은 맨 뒤
   - 줄: 종류 순서(완료 전 → 정산 전 → 지연 업무 → 담당자 없음 → 승인 대기 → 필요한 날 지남 → 증빙 없음 → 입금 확인 전), 같은 종류는 오래된 것부터

## API

| 경로 | 권한 | 응답 |
|---|---|---|
| `GET /api/organizations/:organizationId/home` | 구성원 | `HomeResponse` |

```ts
// packages/contracts/src/home.ts
export const HOME_TASKS_MAX = 100
export const HOME_EXPENSES_MAX = 100
export interface HomeTaskCounts { open: number; overdue: number; done: number }
export interface HomeEvent {
  event: EventSummary
  phase: 'planning' | 'ongoing' | 'wrapping'
  tasks: { total: number; done: number; overdue: number; unassigned: number }
  // 참가 신청이 없으면 null. registered는 취소하지 않은 신청 수다(결과보고서와 같다). closesAt은 한국 시각 YYYY-MM-DDTHH:mm이다.
  registration: { registered: number; capacity: number | null; closesAt: string; accepting: boolean } | null
  settled: boolean
}
export type HomeItem =
  | { kind: 'task_overdue'; eventId: string; task: TaskSummary }
  | { kind: 'tasks_unassigned'; eventId: string; department: { id: string; name: string } | null; count: number }
  | { kind: 'purchases_pending'; eventId: string; count: number; since: string }      // 가장 오래된 제출 시각(ISO)
  | { kind: 'purchases_late'; eventId: string; count: number; neededBy: string }      // 가장 이른 필요한 날
  | { kind: 'expense_no_evidence'; eventId: string | null; expense: ExpenseSummary }
  | { kind: 'fees_unconfirmed'; eventId: string; count: number }
  | { kind: 'settlement_pending'; eventId: string; endedOn: string;
      blockers: { missingEvidence: number; pendingRequests: number; unrecordedItems: number } }
  | { kind: 'completion_pending'; eventId: string; endedOn: string }
export type HomeItemKind = HomeItem['kind']
export interface HomeDepartment { id: string; name: string; isLeadership: boolean; handlesFinance: boolean; tasks: HomeTaskCounts }
export interface HomeResponse {
  today: string                       // 한국 날짜 YYYY-MM-DD
  events: HomeEvent[]
  departments: HomeDepartment[]
  unownedTasks: HomeTaskCounts        // 담당 부서가 없는 업무
  items: HomeItem[]
  counts: Record<HomeItemKind, number>
  truncated: boolean
}
```

- `endedOn`은 행사가 끝난 한국 날짜다. 끝 일시가 있으면 그 날, 없으면 시작한 날이다.
- 업무 수(`tasks`, `departments`, `unownedTasks`)는 완료하지 않은 행사의 업무만 센다.
- 오류: 미인증 401, 다른 학생회·없는 학생회 403 `FORBIDDEN`(구성원 검사 미들웨어 그대로). 본문이 없어 본문 경계 검사는 없다.

## 서버

- 새 모듈 `apps/api/src/home/`(`routes.ts`, `service.ts`). `createHomeRoutes(db, session, { now })`를 `AppOptions.home`으로 잇는다. `serve.ts`, `boundary.test.ts`, `completion-lock.test.ts`의 모듈 목록에 더한다.
- 다시 쓰는 것
  - 행사: `eventSummaries`
  - 지연 업무 줄: `tasks/service.ts`의 `summaries`를 `taskSummaries`로 내보낸다.
  - 증빙 없는 지출 줄: `expenseSummaries`. 오래된 것부터 자르도록 순서 인자(`'newest' | 'oldest'`, 기본 newest)를 더한다.
  - 정산을 막는 수: `financeNumbersByEvent`
  - 입금 확인 전: `eventFeesOf`와 같은 식을 행사 여럿에 한 번에 센다(낼 돈 식은 함께 쓰도록 꺼낸다).
- 질의는 열 개 남짓이고 잠그지 않는다. 읽는 사이에 다른 사람이 바꾸면 숫자가 잠깐 어긋날 수 있다. 다시 불러오면 맞는다.

## 화면

- **옆 메뉴:** 맨 위에 "홈"(집 아이콘). 수는 달지 않는다.
- **첫 화면:** 회장단(`manageOrganization`)은 운영 현황, 다른 구성원은 지금처럼 내 업무다. 학생회를 만들면 구성원 화면, 초대로 들어오면 내 업무인 것은 그대로다.
- **머리:** 구역 "홈", 제목 "운영 현황"
- **운영 현황** (`home/Home.tsx`, 한 단, `max-w-3xl`)
  - 설명 한 줄: "끝나지 않은 행사에서 멈춘 일과 할 차례를 모았어요."
  - 종류별 수 칩(0은 감춤): "지연 업무 3", "담당자 없는 업무 2", "구매 승인 대기 1", "필요한 날 지난 구매 1", "증빙 없는 지출 1", "입금 확인 전 5명", "정산 전 행사 1", "완료 전 행사 1". 모두 0이면 "멈춘 일이 없어요."
  - 보기 고르기: [행사별] [부서별] (내 업무의 할 일·완료와 같은 눌림 단추)
  - 잘렸으면: "멈춘 일이 많아 오래된 것부터 일부만 보여요."
  - **행사별:** 행사 카드
    - 첫 줄: 단계 칩(기획 중·진행 중·정리 중), 행사 이름(누르면 행사 대화 탭)
    - 둘째 줄(회색): "10.20 (D-8)" 또는 "날짜 미정", 담당 부서 · 책임자
    - 상태 칩: "업무 6/10"(완료/전체, 업무가 있을 때), "신청 47명"(정원이 있으면 "47/60명"), 신청을 받는 중이고 마감 전이면 "신청 마감 10.20", 정산했으면 "정산함"
    - 날수는 응답의 `today`와 한국 날짜의 차이다. 어제 마감이면 "1일 지남"이다.
    - 멈춘 일 줄: 줄 전체가 단추다. 큰 글과 작은 회색 글, 오른쪽 화살표.
    - 멈춘 일이 없으면 줄이 없다.
    - 상시 운영 지출의 증빙 없음은 맨 아래 "상시 운영 지출" 카드에 둔다.
  - **부서별:** 부서 카드
    - 첫 줄: 부서 이름, 업무 수 "진행 중 5 · 지연 1 · 완료 12"
    - 멈춘 일 줄: 행사별과 같지만 작은 글에 행사 이름을 붙인다.
    - 멈춘 일이 없으면 "멈춘 일이 없어요."
  - **줄 글**

| 종류 | 큰 글 | 작은 글(행사별) | 누르면 |
|---|---|---|---|
| 지연 업무 | 업무 제목 | 부서 · 담당자(없으면 "담당자 없음") · "3일 지남" | 업무 상세(홈에서 연다) |
| 담당자 없음 | "담당자 없는 업무 2건" | 담당 부서(없으면 "담당 부서 없음") | 행사 업무 탭 |
| 승인 대기 | "구매 승인 대기 3건" | 재정 부서 · "2일 전 제출"(오늘이면 "오늘 제출", 가장 오래된 것) | 구매 승인 권한이 있으면 구매 검토, 없으면 행사 구매 탭(행사 전체) |
| 필요한 날 지남 | "필요한 날 지난 구매 2건" | 재정 부서 · "필요한 날 10.10"(가장 이른 것) | 위와 같다 |
| 증빙 없음 | "증빙 없음 · 현수막 인쇄" | 재정 부서 · "45,000원 · 박재정 결제 · 10.3" | 지출 상세(홈에서 연다) |
| 입금 확인 전 | "입금 확인 전 5명" | 재정 부서 | 부서가 있으면 행사 참가자 탭, 없으면 재정 탭 |
| 정산 전 | "정산 전 · 끝난 지 15일"(오늘 끝났으면 "오늘 끝남") | 재정 부서 · 막는 것 "증빙 없는 지출 1 · 승인 대기 1 · 지출 기록 전 품목 2", 없으면 "정산할 수 있어요" | 행사 재정 탭 |
| 완료 전 | "정산 끝, 완료 전" | 회장단 · "끝난 지 15일" | 행사 재정 탭(머리에 [완료하기]) |

  - 부서별에서는 작은 글의 부서 자리에 행사 이름이 온다.
  - 업무 상세에서 바꾸거나 지우면, 지출 상세에서 증빙을 올리면 홈을 새로 불러온다. 업무가 바뀌면 옆 메뉴 내 업무 수도 새로 불러온다.
  - 행사가 하나도 없으면 빈 화면: "진행 중인 행사가 없어요", "행사를 만들면 여기에 진행 상황이 모여요.", [새 행사]
  - 불러오는 중 "운영 현황을 불러오는 중…", 실패 "운영 현황을 불러오지 못했어요." + [다시 불러오기]
- 홈 화면을 열 때마다 새로 불러온다.
- 휴대폰도 같은 한 단이다. 긴 이름에는 `wrap-anywhere`를 준다.

## 와이어프레임과 다른 점

HOME-01 `4:2`, HOME-01K `16:2`, OPS-00 `16:511`과 비교한다.

- 살린 것: 진행 중·예정 행사 목록과 행사별 지연 업무, 조직 주요 알림의 종류
- 바꾼 것
  - 알림 목록은 종류별 수 칩과 행사·부서 카드 안의 줄로 바꿨다. 줄마다 할 차례와 지난 날수가 있다.
  - "준비 62%"는 "업무 6/10"으로 바꿨다.
  - 두 단은 한 단으로 바꿨다.
- 뺀 것: 숫자 카드, 최근 활동, 다가오는 주요 일정, 전체 재정 요약, 내 담당 업무 카드(옆 메뉴 내 업무 수가 있다), 끼룩이 브리핑, 운영 메뉴판, 머리의 학기 칩

## 시연 데이터

새로 넣지 않는다. 배포 DB의 시연 데이터로 아래가 보인다.

- 체육대회: 정산했고 완료 전
- 학술제: 지연 업무, 담당자 없는 업무
- 간식 나눔: 구매 승인 대기, 지연 업무, 담당자 없는 업무
- 현수막 지출: 증빙 없음

## 테스트

- **서버** (`home/home.test.ts`, 시각 고정)
  - 권한: 구성원(미배정 포함) 200, 다른 학생회 403, 미인증 401
  - 대상: 완료한 행사의 업무·구매·신청은 세지 않는다
  - 행사: 단계(기획 중·진행 중·정리 중, 끝 일시 경계), 정렬, 업무 수, 신청 수·정원·마감·받는 중, 정산함
  - 지연 업무: 마감 당일은 아님, 완료는 아님, 담당자 없는 지연도 들어감, 오래된 순
  - 담당자 없음: 부서마다 묶음, 부서 없음
  - 승인 대기: 작성 중은 아님, 가장 오래된 제출 시각
  - 필요한 날 지남: 받은 품목·필요한 날 없음·오늘이 필요한 날·정산한 행사는 아님
  - 증빙 없음: 확인 전(pending) 증빙만 있으면 없음으로 셈, 확인된 증빙·취소한 지출은 아님, 상시 운영 지출 포함, 오래된 순
  - 입금 확인 전: 납부자 참가비 0원인 납부자·입금 확인·취소한 신청·정산한 행사는 아님
  - 정산 전·완료 전: 정리 중만, 정산을 막는 수, `endedOn`
  - 부서 수·담당 부서 없음, 부서 정렬
  - 상한: 지연 업무 101개면 100줄과 `truncated`, 수는 101
  - 같은 수를 쓰는지: 증빙 없음 수가 재정 탭(`missingEvidence`)과 같다
