# 덩어리 만드는 순서

다시 만들기(`docs/superpowers/specs/2026-10-19-rebuild-design.md`)의 덩어리는 모두 이 순서로 만든다. 에이전트와 사람이 같은 순서를 따른다.

## 한 덩어리의 순서

| 단계 | 하는 일 | 남는 것 | 사람 |
|---|---|---|---|
| 1. 사전 조사 | 앞 덩어리를 만드는 동안 시작한다. 설계 문서(vada-docs), 옛 코드(git 기록), 앞 덩어리가 주는 인터페이스, 업계 근거를 모아 정할 것을 뽑는다 | `.superpowers/research/`(git 밖) | |
| 2. 결정 | 정할 것을 하나씩, 근거와 추천을 붙여 정한다. 설계가 바뀌면 vada-docs에 먼저 적는다(결정은 `decisions/`, 표는 `physical-model.md`) | vada-docs 커밋 | 정한다 |
| 3. 설계서 | 범위, 결정, 화면, API, 테스트, 원칙 대조를 적는다 | `docs/superpowers/specs/` | 승인한다 |
| 4. 계획 | 작업마다 파일, 인터페이스, 테스트, 커밋 제목을 적는다. 계획의 코드를 연습용 사본에서 돌려 보고, 설계서의 요구와 작업·테스트의 대응을 따로 점검한다 | `docs/superpowers/plans/` | 승인한다 |
| 5. 실행 | 작업마다 새 작업자가 만들고 다른 검토자가 본다(아래 '실행 규칙') | 덩어리 가지의 커밋, `.superpowers/sdd/<계획>/progress.md` | |
| 6. 마무리 검토 | 가지 전체를 한 번 더 본다. 지적은 한 번에 고치고 고친 곳만 다시 본다. 가지에서 CI를 돌린다 | 수정 커밋, CI 기록 | |
| 7. 반영 | 가지를 main에 fast-forward로 합쳐 올린다. Render가 배포한다 | main | "반영해" |
| 8. 확인 | 공개 주소 → 데스크톱 Chrome → 아이폰·갤럭시 순서로 확인한다(아래 '배포 뒤 확인') | `docs/device-checks.md` | 기기로 해 본다 |
| 9. 넘기기 | 미룬 작은 항목과 확인 안내를 다음 덩어리의 기록으로 옮긴다 | 다음 덩어리의 `progress.md` | |

## 실행 규칙

- 가지는 덩어리마다 하나다. 작업마다 로컬에 커밋하고, 가지는 GitHub에 백업으로 올린다. main은 사람이 반영하라고 할 때만 올린다. 올리면 바로 배포된다.
- 작업자는 저장소 옆의 작업 폴더(git worktree)에서 일한다. 저장소 폴더는 마지막으로 합친 커밋에 두고, 검토자와 품질 검사는 그 폴더를 본다.
- 작업 N이 커밋되면 N의 검토와 N+1의 작업을 함께 시작한다. N의 수정은 N+1이 커밋된 뒤에 한다. 코드를 쓰는 작업자는 늘 하나다.
- 데이터, 권한, 보안, 운영 DB를 다루는 작업은 가장 큰 모델이 검토하고, 나머지는 중간 모델이 검토한다.
- 작업 중에는 바뀐 곳의 테스트만 돌린다. 전체 테스트는 계획이 정한 곳과 마무리의 가지 CI에서 돌린다.
- 작업자는 브라우저를 열지 않는다. 화면은 컨트롤러가 `/ui.html`을 데스크톱 폭과 휴대폰 폭(390px)으로 찍어 본다. 휴대폰 폭은 HTTP로 띄운 틀 안의 iframe으로 찍는다. 파일로 연 틀은 빈 화면이 될 수 있다.
- 계획과 다르게 정한 것은 기록(`progress.md`)에 `Ruling:`으로 남기고, 덩어리가 끝나면 사람이 읽을 목록으로 옮긴다.
- 작업자와 검토자는 `.env`를 읽지 않고, 실제 DB에 닿는 명령을 실행하지 않는다.

## 함께 진행하는 것

- 다음 덩어리의 사전 조사, 결정, 설계서, 계획은 지금 덩어리를 실행하는 동안 진행한다.
- 같은 파일을 건드리지 않는 일만 동시에 한다. 같은 파일을 건드리면 차례로 한다.

## 사람이 정하는 것

- 정할 것(하나씩), 설계서 승인, 계획 승인, 반영, 운영 DB 적용(바꾸는 날).
- 실행 방식은 '작업마다 검토'를 기본으로 하고 따로 묻지 않는다.

## 배포 뒤 확인

1. 공개 주소에서 바뀐 정적 파일과 경로가 기대한 상태 코드를 주는지 본다.
2. 데스크톱 Chrome으로 운영 주소에서 그 덩어리의 흐름을 한 번 해 본다. 휴대폰보다 먼저 한다.
3. 아이폰과 갤럭시로 `docs/device-checks.md`의 단계를 해 보고 결과를 적는다.
4. 막히면 Render에서 이전 배포로 되돌린다.
