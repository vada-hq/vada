# 플러그인의 역할 — 편집기가 아니라 확인기 (2026-08-19 확정)

## 결정

**Figma 플러그인은 명세를 쓰지 않는다.** 로컬 `screen.json`이 유일한 원본이고, 플러그인은 그것을 읽어 **읽기 전용으로 보여준다**. Figma 문서 안에 명세 사본을 두지 않는다.

플러그인에 남는 일은 **Figma 안에서만 가능한 두 가지**뿐이다.

| 하는 일 | 왜 플러그인이어야 하나 |
| --- | --- |
| 원본·자산·reference.png 추출 | Figma API는 플러그인 샌드박스에서만 닿는다 |
| 화면 신원 등록(wireframeKey·screenId ↔ 노드) | Figma 문서 `pluginData`에 쓰는 일이라 밖에서 못 한다 |

## 왜 바꿨나

처음 설계 의도는 *"요소를 정의할 때 무엇을 결정해야 하는지 빼먹지 않도록 스키마로 틀을 세팅한다"* 였다. 그 목적은 지금도 유효하다. 바뀐 것은 **그 틀을 사람이 폼으로 채워야 하는가**다.

세 가지 근거로 아니라고 판단했다.

**1. 목적은 이미 다른 곳에서 달성됐다.** "빠짐없이 결정하게 한다"를 실제로 수행하는 것은 폼이 아니라 스키마·검증기·추출기의 질문 목록이다. 폼은 스키마의 여러 표현 중 하나였을 뿐이고, 목적이 아니라 표현이 잉여가 됐다.

**2. 편집 경로는 이미 쓰이지 않았다.** ORG-01·ORG-02는 사람이 요소를 하나도 등록하지 않고 완결됐다. 값을 정하는 판단 자체를 AI가 할 수 있고, 사람은 확인하고 고칠 곳을 말하면 된다.

**3. 결함이 전부 그 경로에서 나왔다.** 2026-08-19 하루에 처분한 결함 4건 — 정수 편집 위젯 누락, 선택+nullable 조합, `code.mjs` 레지스트리 누락, 속성 순서 노이즈 — 은 **모두** "명세를 폼으로 펼쳤다가 다시 직렬화한다"는 왕복 때문에 존재했다. 왕복이 없으면 이 결함 계급은 성립하지 않는다.

## 잃는 것과 대신 얻는 것

편집을 없앤다고 "확인"의 필요가 사라지지는 않는다. 오히려 확인을 어디서 하느냐가 새 숙제가 됐다. ORG-01은 요소 9개 × 속성 15개 ≈ 135개 값이고, 그걸 JSON으로 훑는 일은 현실적으로 일어나지 않는다. 화면에 드러나는 값은 e2e 스크린샷이 대신 확인해 주지만 `fieldKey`·`valueType`·`mutationKey`·`scopeEvent`처럼 **화면에 안 보이는 값은 틀려도 화면이 멀쩡히 돈다**.

그래서 읽기 전용 화면은 단순 나열이 아니라 **확인을 돕는 표시**를 한다.

- 값이 없는 속성도 이름은 보여준다(무엇을 결정해야 하는지가 스키마의 원래 가치다).
- 선택지 출처는 카탈로그에서 찾아 `static · 선택지 5개`처럼 요약하고, 참조가 닿지 않으면 그렇게 말한다.
- 버튼 실행 조건은 규칙 이름 대신 **이 화면에서 실제 판정 후보가 되는 fieldKey 목록**으로 풀어 보여준다.
- 선택한 노드가 명세에 없으면 "등록되어 있지 않습니다"라고 알린다.

**다음 단계는 근거(provenance) 표시다.** 값마다 "디자인에서 유도됨 / 사람이 답함 / AI가 추정함"을 구분해 보여주면 확인 대상이 135개에서 추정값 몇 개로 줄어든다. 추출기(`screen-draft.mjs`)를 `figma.design.json`에 다시 돌려 대조하면 계산할 수 있으므로 스키마에 새 필드를 넣을 필요는 없다. 브리지에 `figma.design.json` GET 라우트만 있으면 된다.

## 딸려 사라진 계약

편집 왕복을 전제로 만든 규칙들은 근거가 사라졌다. `element-types.md`의 스키마 작성 계약에서 **편집 위젯 필수** 규칙을 삭제했다. 나머지 두 규칙(선택+nullable 금지, 속성 순서)은 근거가 약해졌을 뿐 여전히 값이 있어 유지하되 이유를 다시 적었다.

이제 스키마는 **폼 표현이 아니라 JSON 표현에 맞춰** 설계할 수 있다. 백로그의 `input.validation` 왕복 소실(스키마가 `readOnly`라 플러그인이 항상 `[]`로 덮어쓰던 문제)은 이 결정으로 그냥 사라졌다.
