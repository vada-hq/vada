# 플러그인은 지웠다 (2026-08-25 확정 · 2026-08-19 결정의 종착)

## 결정

**Figma 플러그인과 로컬 브리지를 저장소에서 지웠다.** 이제 원본·자산·
reference.png는 Figma REST API로 직접 받는다
(`apps/spec-service/src/fetch-figma-screen.mjs`).

```bash
node apps/spec-service/src/fetch-figma-screen.mjs vada-wireframe EVT-02
```

사람이 Figma에서 할 일은 **없다**. 토큰은 저장소 루트의 `.env`에
`FIGMA_TOKEN=...`으로 두고, 파일 key는
`specs/figma/<wireframeKey>/figma-file.json`에 있다(비밀이 아니다).

## 왜 근거가 무너졌나

2026-08-19에 "플러그인은 명세를 쓰지 않는다"를 정하면서, 남는 일을
**Figma 안에서만 가능한 두 가지**로 적었다. 둘 다 사실이 아니게 됐다.

| 그때 적은 것 | 지금 |
| --- | --- |
| 원본·자산·reference.png 추출 — Figma API는 플러그인 샌드박스에서만 닿는다 | **틀렸다.** REST API가 같은 것을 준다. `exportAsync({format:"JSON_REST_V1"})`의 결과와 REST 응답이 **바이트까지 같음**을 실측했다(노드 212개, 길이 187187, 차이 0건) |
| 화면 신원 등록 — Figma 문서 `pluginData`에 쓰는 일이라 밖에서 못 한다 | **필요 없어졌다.** 프레임 이름이 이미 screenId를 말한다(`운영 — 행사 · EVT-02 · …`). `screen-naming.mjs`가 그 이름을 읽고, 이름이 여럿 맞으면 조용히 고르지 않고 오류를 낸다 |

그래서 남은 것은 **사람이 Figma를 열어 버튼을 누르는 절차**뿐이었다.
그것은 능력이 아니라 비용이다.

## 무엇이 좋아졌나

- **사이클이 짧아졌다.** 화면 하나를 받는 데 사람 개입이 0이다. 수렴 기준
  (2)("화면당 사람 개입이 고정 목록을 벗어나지 않는다")에서 가장 큰 항목이
  사라졌다.
- **규칙을 여기서 고칠 수 있다.** 자산 단위 규칙이 세 번 틀렸는데, 예전에는
  고칠 때마다 사람이 Figma에서 다시 저장해야 했다. 지금은 다시 받으면 된다.
- **게이트가 절반이 됐다.** 검사 360개 → 263개, 앱 셋 → 둘, 코드 약 7,600줄이
  줄었다. 지운 검사는 전부 사라진 코드의 것이다.

## 함께 지운 것

로컬 브리지(`apps/spec-service/src/server.mjs`, `cli.mjs`)도 지웠다.
`127.0.0.1:3846`의 HTTP 서버였고 **손님은 플러그인뿐이었다.** REST 경로는
파일을 직접 쓰므로 HTTP가 필요 없다.

브리지에서 뽑아 둔 판정은 남는다 —
`packages/contracts/src/screen-folder-identity.mjs`(다른 노드의 산출물을
덮어쓰지 않는다)를 REST 경로가 그대로 쓴다. 이 파일을 미리 뽑아 둔 덕에
브리지를 지우면서 그 규칙이 함께 사라지지 않았다.

## 남아 있는 것

편집을 없애며 남긴 숙제 — **화면에 안 보이는 값을 어떻게 확인하나**(`fieldKey`·
`valueType`·`mutationKey`) — 는 그대로다. 답은 플러그인의 읽기 전용 화면이
아니라 검사 쪽에서 나오고 있다:

- 근거 표시(`spec-provenance`) — 값마다 디자인에서 유도됐는지 사람이 답했는지
  AI가 추정했는지를 가른다. 확인할 것은 추정값뿐이다.
- design 대조(`design-check`) — 그려지는 값은 기계가 견준다.
- 역방향 검사 — design에 있는데 명세에 없는 상호작용을 잡는다.
