# 올리는 일 — 무엇을 어디에, 왜 (2026-08-31)

명세는 사실상 끝났고 서버는 216자리 중 32자리가 답한다. 이 상태에서 자리를 더
쌓는 대신 **한 사이클을 먼저 닫기로 했다** — 그림 → 명세 → 계약 → 서버 →
저장소가 이미 한 줄로 이어지는 것은 검사가 증명했지만, 그것은 전부 한 프로세스
안에서였다. 브라우저와 진짜 주소가 끼면 다른 것들이 깨진다.

## 마일스톤

| | 무엇 | 끝났다고 말할 수 있는 조건 |
| --- | --- | --- |
| **M1** | 배관을 깐다 | 로그인 화면 · 서버 스위치 · CORS · 교차 사이트 쿠키 · 옮김 파일 |
| **M2** | 올리고 도메인을 문다 | 주소를 열어 로그인하고 서버가 낸 값이 그려진다 |
| **M3** | 인자를 넘기는 길을 연다 | **열었다** — 출처 114개가 서버로 불린다(남은 26개는 화면 안의 칸이 필요) |
| **M4** | 살을 붙인다 | event 57 → finance 35 → meeting 34 |

**M3을 M4 앞에 둔다.** 지금 앱은 인자 없는 출처 34개만 서버로 부를 수 있다
(`loadSources`가 나머지에 `NeedsParams`를 던진다). 그 문을 열지 않고 자리부터
만들면 **만들어 놓고 화면이 못 쓰는 자리**가 쌓인다.

## 고른 것

| | 무엇 | 까닭 |
| --- | --- | --- |
| 웹 | **Cloudflare Workers**(정적 자산) | 대역이 무제한이고 무료다. Pages가 아닌 까닭은 아래 |
| api | **Render(무료)** | 카드를 요구하지 않는다. 15분 놀면 잠들고 첫 요청이 30~60초 느리다 — 지금은 상관없다 |
| 저장소 | Neon | Postgres 실물이고 무료 등급이 있다. 잠들었다 깨는 데 몇 백 ms |

동시 규모를 아직 모르므로 **가장 작은 것으로 잡았다.** 셋 다 재장전이 쉽다.

### 웹을 Pages가 아니라 Workers에 올린다 (2026-09-02)

Pages로 잡아 두었는데, 만들려고 보니 Cloudflare가 **새 프로젝트에 Workers를 권한다**.
Pages도 여전히 돌지만 UI에서 뒤로 물러났고, 정적 파일 제공이 Workers에서 무료가
되면서 Pages에 남을 값의 이유가 사라졌다.

바꾼 대가는 작다 — Pages Functions의 `functions/api/[[path]].ts`가 `worker/index.ts`
하나가 되고, `wrangler.jsonc`가 `assets.run_worker_first`로 `/api/*`만 Worker에
보낸다. SPA 되돌림도 `not_found_handling`이 맡아 `_redirects`가 필요 없다.

### api를 Fly에서 Render로 바꿨다 (2026-08-31)

처음에 Fly를 골랐는데 **카드를 등록해야 시작된다.** 옛 무료 등급을 근거로 골랐던
것이고, 확인하지 않은 값으로 고른 것이 틀렸다.

값을 먼저 보되 **유지보수성을 잃지 않는 쪽**으로 옮겼다 — Render는 같은 Dockerfile을
그대로 쓴다. `apps/api/fly.toml`은 지우지 않았다. 나중에 Fly로 옮길 때 **코드는 한
줄도 바뀌지 않는다.**

Cloudflare Workers가 더 싸지만 고르지 않았다. 서버리스라 서버를 다시 짜야 하고,
그것은 이 저장소가 연결 풀을 상시로 두려고 **일부러 피한** 모양이다.

**무료 등급에는 배포 전 명령이 없다.** Fly는 `release_command`가 표를 맞춰 주지만
Render 무료에는 그 자리가 없다. 그래서 표는 **사람이 한 번 맞춘다** — 스키마를
고칠 때마다 `DATABASE_URL`을 걸고 `npm run db:migrate`를 돌린다. 서버가 켜질 때
스스로 맞추게 하지 않는 까닭은 앞과 같다: 여러 대가 켜지면 서로를 밟는다.

## 브라우저가 막는 자리 — 가장 위험한 것

**세션은 쿠키에 있고, 쿠키는 사이트를 건너지 못한다.**

기본값(`SameSite=Lax`)은 다른 사이트에서 온 요청에 쿠키를 붙이지 않는다. 웹이
`*.pages.dev`이고 api가 `*.fly.dev`면 둘은 다른 사이트다 — 로그인은 되는데 그다음
요청마다 로그인하지 않은 사람으로 보이는, **가장 헷갈리는 고장**이 난다.

`SameSite=None`으로 풀 수는 있지만 그것은 서드파티 쿠키이고 브라우저가 막는
중이다(Safari는 이미, Chrome도 줄이는 중). 그래서 길을 둘 두었다.

1. **한 주소로 만든다(권장).** `apps/vada-web/worker/index.ts`가 `/api/*`를 api로
   넘긴다. 브라우저가 보기에 api는 웹과 같은 주소이므로 CORS도 서드파티 쿠키도
   없다. `VITE_API_BASE_URL`을 비워 두면 이 길이다.

   그 Worker는 **보낸 사람의 주소도 함께 넘긴다**(`cf-connecting-ip` → `x-forwarded-for`).
   안 넘기면 서버가 보는 주소가 전부 Cloudflare의 것이 되고, 밖에서 열리는 자리의
   속도 세기가 **행사장 전체를 한 사람으로 센다** — 캠퍼스 NAT을 걱정해 축을 둘로
   나눠 둔 것이 통째로 무의미해진다.
2. **나눠 둔다.** `VITE_API_BASE_URL`을 api 주소로 두면 화면이 그리로 직접 부른다.
   서버가 CORS를 열고(`APP_URL`만), 쿠키를 `None`으로 푼다. **Safari에서 안 될 수 있다.**

**도메인을 사면 둘 다 필요 없어진다.** `vada.app`과 `api.vada.app`은 같은 사이트라
쿠키가 그냥 따라간다 — `sameSiteHosts`가 그것을 보고 스스로 `Lax`로 돌아온다.

## 표를 맞추는 길

검사는 표를 통째로 지우고 다시 만들지만 실서비스는 그럴 수 없다. 그래서
`migrations/`를 두고 **아직 적용하지 않은 것만** 차례로 적용한다(`npm run db:migrate`).

**검사도 같은 파일에서 표를 만든다.** `schema-sql.ts`가 `migrations/`를 읽으므로
두 길이 갈릴 자리가 없다 — 예전에는 검사가 스키마에서 한 번에 만들고 실서비스는
옮김을 쌓아 만들어서, 갈리면 검사가 실제와 다른 표에 대고 도는 모양이었다.

배포가 이것을 **한 번** 부르고 그다음 서버가 선다(`fly.toml`의 `release_command`).
켤 때마다 부르면 여러 대가 서로를 밟는다.

## 로그인 화면은 그림이 없다

와이어프레임은 이미 들어온 사람만 그린다. 그래서 이 화면은 명세에서 나오지
않았고 `App.tsx`가 `SIGN-IN`이라는 id로만 안다 — 준수 검사도 design 대조도 이
자리를 보지 않으므로 `SignInScreen.test.tsx`가 유일한 눈금이다.

예외를 두되 **지어내지는 않는다.**

- 어느 길이 열렸는지는 서버가 말한다(`/api/auth-ways`). 화면이 '구글'을 들고 있으면
  자격증명이 없는 날에도 단추가 그려지고, 누른 사람은 알 수 없는 오류를 본다.
- **단추의 글도 서버가 준다.** 길이 하나 늘 때 화면을 고치지 않기 위해서다.
- 갈 곳도 서버가 준다(Better Auth가 주소를 만든다). 화면이 지어내면 제공자가 바뀔 때
  조용히 틀린 곳으로 보낸다.
- 길이 하나도 없으면 **그 사실을 말한다.** 빈 화면은 고장과 구분되지 않는다.

그림이 생기면 명세로 옮기고 `App.tsx`의 그 줄을 지운다.

## 사람이 해야 하는 것

내가 못 하는 것들이다.

1. **Neon**에서 Postgres를 만들고 연결 문자열을 받는다.
2. **구글·카카오**에서 OAuth 자격증명을 받는다. 돌아올 주소(redirect URI)는
   `<api 주소>/api/auth/callback/<제공자>`다.
3. **Render**와 **Cloudflare** 계정을 만든다(둘 다 카드가 필요 없다).
4. 비밀을 넣는다 — Render 대시보드에 `DATABASE_URL` · `AUTH_SECRET`(32자 이상) · `BASE_URL` ·
   `APP_URL` · `INVITE_LINK_BASE` · 제공자 열쇠. **서버는 이것들 없이 서지 않는다**
   (`config.ts`) — 없는 채로 도는 것이 가장 나쁘기 때문이다.

## 인자를 넘기는 길 (M3, 2026-08-31)

**막고 있던 것은 코드가 아니라 믿음이었다.** `server.ts`에 "그릇은 화면이 무엇을
읽는지는 알지만 어떤 인자로 부르는지는 모른다"고 적혀 있었는데, **그것도 명세가
이미 안다** — 요소마다 `params`가 붙어 있고 그 인자가 어디서 오는지까지 적혀 있다.
화면 코드를 읽지 않고 명세를 걸으면 부를 것이 나온다(`dataSourceCallsOf`).

담아 두는 칸을 **key에서 (key, 인자)로** 바꿨다. 같은 출처를 다른 인자로 두 번
부르면 다른 답이 오는데, key로만 담으면 뒤엣것이 앞엣것을 덮고 **화면이 남의 행사를
그린다.**

셸이 읽는 것도 함께 미리 받는다. 화면만 걸으면 학생회 이름과 보는 사람이 빠지는데,
그 둘은 화면의 요소가 아니라 셸의 것이기 때문이다.

### 조용한 대체를 끊었다

받아 두지 않은 부름은 **터뜨린다.** 전에는 개발용 응답으로 슬쩍 돌아갔고, 그래서
서버를 켜고 도는 검사에서도 **셸은 내내 개발용 응답을 그리고 있었다** — 이 변경이
그 사실을 드러냈다(검사에 진짜 사람을 넣어 고쳤다).

### 남은 26개

화면 컴포넌트 안의 `useState`에 든 값(검색어·거르개)에서 오는 인자다. 그릇이 그것을
보지 못하므로 사람이 거르개를 바꾸면 받아 두지 않은 부름이 되고 터진다. 그 상태를
**숨기지 않는다** — 고치려면 그 상태를 그릇이 볼 수 있는 자리로 올려야 하고, 그것은
화면 일흔여덟을 손대는 일이라 따로 잡는다.

## 아직 안 한 것

- **연기 검사가 없다.** M2의 검증을 눈으로 하면 다음에 또 눈으로 해야 한다 —
  주소를 열어 로그인하고 서버 값이 그려지는지 자동으로 보는 검사가 M2의 마지막 일이다.
- **화면 안의 칸에서 오는 인자**(출처 26개). 위의 '남은 26개'.
