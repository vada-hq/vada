# INV-01 파일럿 — 초대받은 학생회 확인

## 사이클 기록 (2026-08-19)

- 사용자: Figma에서 화면 지정 + `Figma 원본 JSON 저장`. 그것뿐이다.
- AI: 정규화 → 추출기 초안(요소 8개, 질문 17건) → 명세 작성 → 구현.
- 사용자 답변 3건: 버튼 이동 대상(참여→HOME-01K, 거절→ONB-02), 스코프(`onboardingDraft` 재사용), 초대 정보 출처(미정 — 자리만).

추출기 질문 17건 중 **8건은 묻지 않고 ONB-01에서 가져왔다** — `school`·`college`·`department`·`currentGrade`·`studentNumber`의 fieldKey·카탈로그·연쇄 조건·초기화 대상. 라벨이 같으면 선례를 재사용할 수 있다는 뜻이고, 이건 추출기가 자동으로 할 수 있는 일이다.

### 집계

| 분류 | 건수 |
| --- | --- |
| (A) 스키마에 자리가 없다 | **0** |
| (B) 자리는 있는데 안 채웠다 | 1 |
| (C) 원래 명세의 관심사가 아니다 | 12 |

**(A)가 0건이다.** 구현하는 데 명세에 자리가 없어 막힌 것이 하나도 없었다. `summary`는 명세를 *쓰는* 단계에서 신설했고 구현 단계에서는 스키마 부족을 만나지 않았다.

추측은 8건이었고 **8건 모두 기계가 잡았다** — 검증기 2, tsc 2, e2e 2, 커밋 훅 1, 스크린샷 판독 1. 사람 눈에만 의존한 것은 없었다. 다만 전부 *구현 중* 잡혔고, 명세만 읽어서는 알 수 없었다.

### (C)인데 (C)로 끝나지 않는 것

마찰 5번(연쇄 select·필수값 판정 기계 120줄)은 분류상 (C)다 — 명세는 `enabledWhen`·`resetOnChangeOf`·`optionsSource.params`·`executeWhen`으로 동작을 **완전히** 서술하고 해석 규칙도 하나뿐이다. 그런데 ONB-01·ORG-01·ORG-02가 그 코드를 각자 들고 있었다.

**명세의 문제가 아니라 구현에 공용 런타임이 없는 문제**다. 네 번째 사본을 만드는 대신 `useFieldDraft` 훅으로 뽑았다. ORG-01·ORG-02 이관은 남아 있다.

마찰 13번(묶음 상자 형태)도 같은 계급이다. 계약이 "묶음의 시각은 화면마다 다르니 design을 따르라"고 명시하는데 공용 컴포넌트가 ORG-01의 상자를 박아두고 있었다.

## 새 계급

**`summary` 요소 유형.** 이 화면이 다루는 대상의 요약 카드다. `note`가 값들을 한 줄로 잇는 것과 달리 제목과 라벨-값 쌍의 구조를 가진다. 값의 출처(원격 조회·앞 화면 스코프)는 미정이라 디자인의 예시 문자열을 그대로 담는다.

**버튼 강조도(`emphasis`).** 백로그 항목이 트리거를 충족해 신설했다. 색이 아니라 형태에서 유도한다(테두리=보조, 채움=주, 없음=최소).

신규 마찰 계급 **2건** — 수렴 기준(연속 2화면 0건)은 못 맞춘다. 다만 **AI 읽기 쪽은 (A) 0건**이라 두 축의 상태가 다르다: 명세를 만드는 어휘는 아직 자라는 중이고, 명세를 읽고 구현하는 데는 부족함이 없다.
