# VADA 권한 매트릭스 (확정)

2026-07-19 작성·사용자 검토 완료. 2026-07-29 갱신(구매 요청 작성·보완 재제출·재검토 흐름 추가). 구현된 87개 화면에 실제로 존재하는 기능(버튼·액션) 기준이며, **이 표가 역할별 버튼 노출과 ORG-04 화면의 단일 기준이다.**

- 검토에서 수정된 항목 2건: 회의 생성(전 구성원 → 회장단·부서장), 학생 명단 열람(회장단·부서장 → 전 구성원)
- 표의 모든 항목은 현재 범위에서 확정된 권한 규칙이다.

## 구현 규칙

권한 판정은 `src/app/App.tsx`의 헬퍼를 재사용한다. 화면에서 역할 조건을 직접 쓰지 않는다.

| 헬퍼 | 대상 | 적용 |
|---|---|---|
| `isEventManager` | 회장단(기본 역할) 또는 행사 운영 조직 관리자(맥락 역할) | 행사 정보 수정·행사 시작, 운영 조직 구성·수정, 아카이브 작성. `user.role === "회장단" \|\| user.eventRole === "행사 운영 조직 관리자"`로 판정하며 기본 역할 문자열에 행사 역할을 섞지 않는다 |
| `canEndEvent` | 회장단(기본 역할) 또는 행사 운영 조직 관리자(맥락 역할) | 행사 종료(진행 중 → 후속 정리 중). 기본 역할이 부원·부서장이라도 그 행사의 운영 조직 관리자면 가능하고, 관리자가 아니면 불가. `canCompleteEvent`와 다른 기준이다 |
| `canCompleteEvent` | 회장단(기본 역할) | 행사 최종 완료 처리(후속 정리 중 → 완료). 기본 역할 회장단만 판정 근거로 쓰고 행사 맥락 역할(eventRole)은 보지 않는다 |
| `canManageFinance` | 재정부 | 총예산 편성, 구매 검토·승인·주문·주문 취소 확정·증빙 처리 |
| `canSubmitPurchaseRequest` | 재정부 · 부서장 | 구매 요청 작성·보완 재제출 |
| `canCancelPurchaseItemRequest` | 재정부 · 부서장 중 원래 요청자 본인 | 주문 완료 실행분이 없는 본인 요청 품목을 사유 입력 후 요청 취소 |
| `canRequestOrderCancellation` | 재정부 · 부서장 중 원래 요청자 본인 | 본인 요청의 주문 완료 실행분에 주문 취소 요청 제출·결과 조회 |
| `canEditOrganization` | 회장단 | 조직 구조 수정 |
| `canInviteOrganizationMember` | 회장단 · 부서장 | 구성원 초대 |
| `canManageStudentRoster` | 회장단 | 학생 명단 업로드·갱신·내보내기 |
| `canManageStudentFeeRoster` | 재정부 · 회장단 | 학생회비 납부 명단 업로드 |

권한이 없으면 버튼을 비활성화하지 않고 노출하지 않는다. 권한자 전용 단독 화면은 검토 시 해당 역할 사용자를 주입한다(`AsPresident`, `AsFinanceManager`, `AsEventManager`).

기본 역할과 행사 맥락 역할은 서로 다른 필드로 판단한다. `currentUser.role`은 기본 역할(회장단·부서장·부원), `currentUser.eventRole`은 선택한 행사에서의 맥락 역할(행사 운영 조직 관리자·구성원)이다. `EVT-02C → EVT-02D → EVT-02E` 흐름은 화면별 역할 주입 없이 같은 사용자를 유지하며, 검토 시 상단 툴바의 `행사 역할` 선택으로 현재 사용자(박해랑)의 `eventRole`만 바꾼다.

## 역할 축

- 기본 직급: 회장단 / 부서장 / 부원 — "전 구성원" = 셋 전부
- 부서 조건: 재정부 (직급 무관, 재정부 소속)
- 맥락 역할(사안별 부여): 회의 생성자, 회의 진행 권한자, 회의 참가자(초대됨), 행사 운영 조직(행사별, 기본 조직과 별개)
- 외부: 일반 학생 (가입·로그인 없이 모바일 웹)

> **행사 선택 컨텍스트 (2026-07-23 갱신).** 위 권한 규칙은 그대로이며, 판정 대상이 **현재 선택된 행사(`selectedEventId`)의 데이터**로 명확해졌다. 행사 목록·홈에서 특정 행사 카드로 진입하면 먼저 그 행사의 id를 선택한 뒤 워크스페이스로 이동한다. 각 행사는 변하지 않는 `id`를 가지며 기본정보·상태·업무·설문·완료 기록이 id 단위로 분리된다. 행사명은 수정될 수 있으므로 식별자·중복 판정 기준으로 쓰지 않는다. 행사 시작·종료·완료, 기본정보·업무·설문 변경은 모두 선택된 행사에만 적용되고 다른 행사 카드·워크스페이스에는 영향을 주지 않는다. 와이어프레임 화면 목록에서 `EVT-02`·`EVT-02C/D/E`를 직접 열면 대표 행사(체육대회)가 기본 선택된다. `EVT-02C → EVT-02D → EVT-02E` 흐름의 사용자 신원·행사 맥락 역할 유지 규칙은 변경 없다.
>
> **행사 하위 화면 분리 (2026-07-23 추가).** 인원 관리(EVT-03A/B/C·EVT-04·EVT-04C), 관련 회의(EVT-MEET-01), 일정(EVT-SCHED-01), 문서(EVT-DOC-01), 후속 정리(EVT-02D/E), 재정(EVT-FIN-01·MY-REQ-01·구매 요청 상세)도 모두 선택 행사 기준으로 조회한다. 회의는 `CreatedMeeting.eventId`, 구매 요청은 `PurchaseRequest.eventId`로 연결하며 행사명 문자열로 묶지 않는다. 체육대회 샘플(참가자·회의·문서·예산·구매 요청)은 `SPORTS_EVENT_ID`에만 연결하고, 연결 데이터가 없는 행사는 체육대회 값을 복사하지 않고 빈 상태(신청자 없음·연결 회의 없음·연결 문서 없음·연결 데이터 없음/집계 전)를 표시한다. 권한 규칙 자체는 변경하지 않는다.
>
> **행사별 운영 조직 저장 (2026-07-23 추가).** 운영 조직은 `EventRecord.organization`으로 행사마다 저장한다. `EVT-01` 저장은 화면 이동만 하지 않고 현재 선택 행사(`selectedEventId`)에 책임자·모드·팀 구성을 실제로 기록한 뒤 `EVT-03A`로 이동한다. `EVT-03A`는 저장된 조직 유무로 표시하며(정적 배열을 직접 렌더링하지 않음), 없으면 미구성 빈 상태를 보여준다. `EVT-03B`는 같은 행사 조직을 불러와 책임자를 변경·저장(완료)하면 `EVT-03A`에 반영된다. 체육대회 표본 조직은 `SPORTS_EVENT_ID`에만 시드하며 새 행사·다른 행사에 자동 복사하지 않는다. 조직 구성·수정 진입점은 기존대로 행사 운영 조직 관리자·회장단에게만 노출한다(권한 규칙 불변).
