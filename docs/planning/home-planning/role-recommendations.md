# 역할별 홈 정보 추천안

작성: 2026-09-29 · 갱신: 2026-09-30 · 상태 줄 갱신: 2026-10-14  
상태: 회장단(D-06)·부서장(D-07)·부원(D-08)·재정부(D-09) 홈 정보와 겸직 규칙(D-10) 모두 채택. 채택 내용과 다른 `추천안`은 과거 논의 자료이며 구현 근거가 아니다  
연결: [기획·결정 기록](design.md) · [전체 정보 목록](information-inventory.md)

## 1. 목적과 적용 범위

이미 채택한 ‘조직 상황 우선’, ‘전 구성원이 이해할 눈높이’, ‘역할별 홈 구성’을 유지한다. 역할마다 학생회 운영을 이해하는 범위와 필요한 상세도를 달리한다. 부원 홈을 개인 할 일 목록으로 대체하지 않으며 개인 업무 처리는 `내 업무`에서 한다.

사용자가 말한 ‘부서원’은 기존 모델의 `부원`, ‘재무부’는 기존 모델의 `재정부`로 해석했다. 명칭 변경을 채택한 것은 아니다.

회장단·부서장·부원은 직책이고 재정부는 부서다. 아래 네 표는 서로 배타적인 네 권한을 신설하는 안이 아니라 정보 요구를 비교하는 안이다. 겸직·행사 역할·회의 역할의 조합은 후속 결정이 필요하다.

- **기본 요약**: 해당 역할 홈에서 우선 제공할 후보. 독립 카드 개수나 고정 위치를 뜻하지 않는다.
- **조건부**: 해당 사안이 있고 역할·참여·권한 조건이 맞을 때 제공한다.
- **상세로 이동**: 홈에 펼치지 않고 원래 화면에서 확인한다. 접근 권한 제거와는 다르다.
- **준비 상태**: 원본이 있어도 홈 연결·집계 구현은 필요하다. 예시/추가/보류 여부는 전체 정보 목록을 따른다.

## 2. 모든 역할에서 유지할 조직 맥락 — 제안

학생회·기간·현재 역할을 식별할 수 있게 하고, 열람 가능한 주요 행사·가까운 조직 일정을 짧게 제공한다. 역할별 홈의 중심은 아래처럼 다르게 구성한다.

| 대상 | 홈이 답할 질문 | 중심 범위 |
|---|---|---|
| 회장단 | 전체 운영에서 어디를 확인·조정하고 마무리해야 하나? | 학생회 전체 |
| 부서장 | 우리 부서가 맡은 역할은 잘 진행되고 있고, 어디를 조정해야 하나? | 소속 부서의 담당 업무와 참여 행사 |
| 부원 | 학생회와 참여 행사가 어떻게 진행되고 있고, 내가 알아야 할 것은 무엇인가? | 전체의 간단한 맥락 + 참여 행사·소속 부서 |
| 재정부 | 행사 일정에 맞춰 구매·예산·금액 확인이 어디까지 진행됐나? | 여러 행사에 걸친 재정 운영 |

정보가 없는 경우 0·미입력·집계 전을 구분한다. 주요 행사·임박·장기 대기의 기준은 아직 정하지 않았다.

## 3. 회장단 홈 정보 — 채택 (2026-09-30, D-06)

사용자 발언: “회장단 홈 정보는 이걸로 채택할게”. 권한 재검토 후 대화에서 제시한 아래 구성을 채택했다. 이전 회장단 추천안을 대체한다. 시안: `HOME-01C`(2026-09-30, 예시 데이터).

목적: **학생회 전체 운영이 어디까지 진행됐고, 어디에 확인이나 판단이 필요한가**를 파악한다. 조직 관리·행사 관리·최종 완료 권한을 중심으로 하며 재정은 현황을 열람한다.

### 우선 제공할 다섯 정보

| 정보 | 표시 내용 | 채택 근거 |
|---|---|---|
| 전체 행사 진행 현황 | 기획 중·진행 중·후속 정리 중인 행사 수와 목록 | 회장단이 전체 행사 운영 단계와 일이 몰린 구간을 파악 |
| 확인이 필요한 운영 상황 | 마감 지난 미완료 업무, 담당자 미지정 업무, 검토 필요 업무 | 진행 요약에 드러나지 않는 문제 확인. 모두 회장단의 직접 처리 업무로 단정하지 않음 |
| 후속 정리 중인 행사 | 종료된 행사, 남은 정리 항목, 최종 완료 여부 확인 바로가기 | 행사 최종 완료는 회장단만 가능하며 행사일 이후 정리 누락 방지 |
| 가까운 주요 일정 | 행사일·신청 마감·업무 마감·본인에게 공개된 회의 | 일정 중첩과 가까운 마감 파악. 비공개 회의는 생성자·초대 여부에 따른 접근 범위 적용 |
| 전체 재정 요약 | 총예산·실제 지출액·지출 예정/예약액·사용 가능 예산 | 향후 운영 여력 파악. 재정부 소속이 아니면 승인·발주·예산 조정 버튼 미제공 |

### 행사 카드 정보

- 책임부서·책임자는 제외한다. 담당자 미지정 여부의 집계는 유지한다.
- 행사명, 진행 단계, 행사까지 남은 기간, 완료 업무 수/전체 업무 수, 마감 지난 업무·미지정 업무·검토 필요 수, 다음 마감의 이름과 날짜를 제공한다.
- 완료 업무 비율을 곧바로 ‘행사 준비율’이라고 표현하지 않는다. 업무마다 중요도가 다르기 때문이다.
- ‘확인 필요 8건’만 표시하지 않고 ‘마감 지남 3건 · 미지정 2건 · 검토 필요 3건’처럼 이유를 함께 표시한다. 이 수치는 설명용이며 제품 데이터가 아니다.

### 조건부 추가 정보

| 정보 | 조건·이유 |
|---|---|
| 미배정 구성원 | 대상이 있을 때만 표시. 회장단의 구성원 배정·관리 행동으로 연결 |
| 본인의 회의·아카이브 처리 항목 | 본인이 회의 진행 권한자이거나 해당 검토 대상으로 지정된 경우에 표시. 회장단이라는 이유로 모든 정리·검토를 본인 업무로 가져오지 않음 |

### 첫 화면에서 우선 제외할 정보

- 구매 승인 대기·발주 대기: 회장단의 기본 처리 업무로 제공하지 않는다. 재정부 겸직 조합은 별도 논의한다.
- 학생·행사 참가자 전체 명단: 필요한 상세 화면에서 권한에 따라 조회한다.
- 모든 구성원의 개별 업무 목록: 행사별 현황과 예외를 먼저 보여주고 상세로 연결한다.
- 근거가 불명확한 종합 점수: 설명 가능한 지연 건수·남은 마감 등을 우선한다.

정보의 제시 순서는 **전체 행사 현황 → 확인 필요한 상황·후속 정리 → 주요 일정·재정 요약**이다. 구체적인 화면 배치·카드 수·글자 크기·기간 필터·집계 세칙은 후속 설계 대상이다.

기존 권한과 MVP 범위를 변경하지 않는다. 집계에도 열람 권한을 적용하고, 원본이 없는 값은 완료나 0으로 단정하지 않는다. 예산 지표의 정확한 명칭과 계산은 현행 재정 명세를 따른다.

근거: [권한 매트릭스](../../VADA_PERMISSION_MATRIX.md), [재정 명세](../../VADA_FINANCE_SPEC.md), [노션 권한 매트릭스](https://app.notion.com/p/8-11-3b968a85148e80adac1add47e692bc82), [노션 재정 역할·권한](https://app.notion.com/p/02-1-3ae68a85148e80dab65bf332b5f5a947).

## 4. 부서장 홈 정보 — 채택 (2026-09-30, D-07)

### 채택한 구성

1. **학생회 주요 행사** 한 줄: 부서 참여 여부와 관계없이 열람 가능한 행사의 이름·날짜·단계. 조직 상황 우선(D-02)을 지키기 위해 맨 위에 둔다.
2. **우리 부서 참여 행사**: 단계·날짜·부서 업무 완료/전체·다음 마감.
3. **가까운 일정·마감**: 7일 이내 부서 업무 마감과 초대된 회의. 상단 행사 줄과 중복하지 않는다.
4. **부서 구매 진행**: 범위는 **소속 부서 구성원이 요청한 구매와 본인 요청**. 다른 구성원의 요청은 진행 결과만 열람한다.
5. **확인이 필요한 일**: 기본은 부서 업무의 마감 지남·담당자 미지정(회의 후속 업무 포함)과 본인 구매 요청의 보완 필요. 검토 필요 업무는 해당 업무의 검토 권한이 있을 때만 표시한다.
6. **조건부**: 같은 기간 한 구성원에게 마감이 몰렸을 때 한 줄로 표시(순위·성과 판단 금지). 회의 후속 업무는 5번 항목으로 표시한다.

행사 모집·참가·현장 운영 현황은 행사 역할이 있을 때의 조건부 후보로 남기며, 이번 시안에는 넣지 않았다. 시안: `HOME-01D`(예시 데이터).

**상세로 이동**: 관련 없는 부서의 상세 업무, 조직 전체 구성원 관리, 전체 재정 분석, 개인별 참가자 명단. 주요 조직 행사는 공통 요약으로 유지한다.

**제외**: 데이터에 없는 ‘부서 독립 예산 잔액’을 만들어 표시하지 않는다. 현재 예산은 행사·예산 항목 중심이다. 부서장이라는 이유로 행사 최종 완료나 모든 회의 진행·구매 승인 행동을 제공하지 않는다.

## 5. 부원 홈 정보 — 채택 (2026-09-30, D-08)

1. **학생회 주요 행사** 한 줄(모든 역할 공통).
2. **참여 행사 진행**: 단계·날짜·소속 부서 업무 완료/전체·다음 공동 마감.
3. **가까운 일정**: 초대된 회의·행사일·공동 마감. 참석 대상과 열람만 가능한 공개 일정을 구분.
4. **확정된 결정·안내**(조건부): 참여 행사·부서 회의 정리에서 확정된 결정만.
5. **내 업무·메시지 바로가기**: 내 미완료 업무 수·가장 가까운 마감, 안 읽은 메시지가 있는 참여 방 수.

제외: 구매 진행(부원은 요청 작성자가 아니고 업무-구매 연결이 없음, 행사 공간에서 확인), 타 부서 지연·미배정, 예산, 중요한 변경 알림(변경 기록 데이터 없음). 시안: `HOME-01M`.

## 7. 역할이 겹치는 경우 — 채택 (2026-09-30, D-10)

- 직급(회장단·부서장·부원)으로 기본 홈을 정하고, 재정부 소속이면 재정 정보를 **더한다**. 두 홈을 그대로 붙이지 않는다.
- **재정부 부원**: 재정부 홈 + 부원 홈의 내 업무·메시지 바로가기.
- **재정부 부서장**: 재정부 홈 + 재정부 내부 업무의 마감 지남·담당자 미지정.
- **회장단 + 재정부**: 헤더에서 운영 보기 / 재정 보기를 전환한다.
- **행사 관리자·회의 진행 권한자**: 직급과 무관하게 해당 행사·회의의 확인 항목(정리 안 된 회의, 행사 종료 처리 등)만 확인 영역에 추가한다. 새 카드를 만들지 않는다.

### 채택 전 제안 — 참고 자료


- **재정부 부서장**: 재정 운영 현황을 중심으로 두고 재정부 내부 업무 조정 정보를 더한다. 두 홈을 그대로 붙여 중복하지 않는다.
- **재정부 부원**: 일반 부원의 조직 맥락에 재정 운영 정보를 더한다. 현행 처리 권한은 재정부 소속 기준이므로 부원이라는 이유만으로 재정 처리를 숨기지 않는다.
- **회장단과 재정 역할을 함께 맡는 경우**: 전체 운영 관점과 재정 관점의 전환 또는 추가 영역을 검토한다. 역할 우선순위를 임의 확정하지 않는다.
- **행사 운영 관리자·회의 진행 권한자**: 기본 직책과 무관하게 해당 행사·회의에 필요한 확인 항목을 더한다. 다른 행사·회의로 권한을 확장하지 않는다.

## 8. 실제 정보 준비와 과밀 방지

- **원본·계산 중심으로 먼저 검토**: 행사 상태/일정/책임자, 업무 상태·마감·담당자, 생성 회의·후속 업무, 구매 상태·필요일·금액. 홈 통합은 별도 구현이다.
- **데이터 연결 뒤 검토**: 실제 신청·참석 현황, 통합 문서 검토, 중요한 변경 알림, 전체 예산 집계 정합.
- **범위 확인 뒤 검토**: 아카이브 상세 검토·발행, 다른 보류 기능. 화면 자산의 존재와 MVP 포함은 다르다.
- 목록은 필요한 정보의 우선순위다. 제안된 모든 행을 상시 카드로 펼치지 않는다. 조건부 항목은 해당 사안이 있을 때만 노출하는 방향을 검토한다.
- ‘읽기 힘들게 글씨를 줄여 정보를 모두 넣기’보다 요약·개수 제한·전체 보기로 조절한다. 구체적인 글자 크기·카드 수는 미정이다.
- 관련성은 같은 부서라는 추측만으로 확정하지 않는다. 업무 담당 부서, 행사 운영 조직, 회의 초대, 요청자 등의 실제 연결을 사용한다. 없는 연결은 별도 정의가 필요하다.
- 홈에서 안 보이는 정보와 접근 불가 정보는 구분한다. 권한이 없는 내용은 상세뿐 아니라 집계·알림에도 노출하지 않는다.
