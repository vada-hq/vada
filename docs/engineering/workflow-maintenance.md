# 워크플로 유지보수 기준

이 기준은 엄격한 검증을 유지하면서 같은 사실을 여러 JSON과 문서에 다시 입력하는 비용을 줄인다. 기존 승인 R1–R4는 변경하지 않으며, 새 형식은 기존 검증보다 약한 규칙을 선택할 수 없다.

## 정본과 파생값

- 사람과 기본 책임 분담, 변경 위험별 보증 등급은 `.vada/workflow-policy.json` 한 곳에서 관리한다. 다른 문서는 이름이나 규칙을 복사하지 않고 이 파일을 참조한다.
- 작업의 의미와 선행관계는 승인 `delivery-work/R<n>.json`, 실제 전이와 증거는 `execution-runtime/R<n>.json`이 각각 소유한다. `ready`·`blocked`·현재 상태는 두 정본에서 자동 계산하며 별도 문서에 수동 복사하지 않는다.
- 후속 계약 묶음이 기존 승인 묶음 대부분을 재사용하면 `schema_version: 0.2.0`과 `base_bundle_ref`로 기준 묶음을 한 번 고정하고 `contracts`에는 변경분만 둔다. 기준 ID·리비전·해시와 순환 참조는 검증기가 확인한다.
- 후속 작업 그래프는 이전 승인 작업을 ID·리비전·해시로 `imports`하고, 실제로 달라진 작업만 다음 리비전으로 기록한다. 검증기는 상속 계약과 가져온 작업의 커버리지를 함께 계산하고 후속 작업이 바로 이전 리비전을 정확히 대체하는지 확인한다.

## 보증 등급

- `mechanical`: 제품 의미·보안·데이터 경계를 바꾸지 않는 결정적 생성물이나 단순 운영 변경이다. 분리 검증자를 생략할 수 있지만 범위 검사와 총괄 검토는 필수다.
- `standard`: 일반 코드·계약·문서 동작 변경이다. 작성자와 분리된 검증 및 범위 검사를 요구한다.
- `high_assurance`: `.vada/workflow-policy.json`의 `risk_routes`에 해당한다. 사람 승인, 분리 검증, 범위 검사, 전체 통합 검사를 모두 요구한다.

기존 승인 실행 계획이나 하위 규칙이 더 강한 검증을 요구하면 더 강한 쪽이 우선한다. 프로필을 낮춰 기존 승인 게이트를 우회할 수 없다.

## 사용 명령

- `just validate-workflow-policy`: 책임 기본값과 위험 경로가 유효한지 확인한다.
- `pnpm derive:delivery-status -- --du DU-001`: 한 전달 단위의 모든 승인 증분 작업 그래프에서 명시적으로 대체되지 않은 exact work ref를 합성하고, 각 작업의 소유 그래프와 완료·진행·착수 가능·차단 상태를 JSON으로 보여준다.
- `pnpm derive:delivery-status -- --du DU-001 --work-plan R2`: 특정 승인 작업 그래프의 로컬 작업과 그 그래프를 고정한 실행 계보만 역사·디버깅 용도로 보여준다.
- `just validate-delivery-status`: 저장소의 모든 전달 단위를 자동 발견해 파생 결과의 모순을 검사한다.

증분 작업 그래프의 실행 계획은 로컬 후속 작업만 배정한다. 가져온 작업이 현재 커밋 작업의 실제 선행조건일 때만 검증된 충족 증거를 요구하고, 미래 파동의 미완료 선행조건은 해당 작업을 `blocked`로 유지하되 현재 병렬 시작점을 막지 않는다. 과거 완료 상태를 새 런타임에 복사하지 않는다. 런타임이 고정한 실행 계획과 그 계획이 고정한 작업 그래프를 따라 검증된 완료 증거 원장을 만들고, `satisfied_prerequisites`의 locator와 가져온 작업의 착수 가능성을 이 원장으로 확인한다.

기본 상태 조회는 파일명이나 최신 리비전 하나를 현재 전체 범위로 간주하지 않는다. 모든 승인 그래프의 로컬 작업을 exact ref로 합치고 명시적 `supersedes`만 적용한다. 미완료 활성 작업이 이미 대체된 선행 작업을 참조하면 후속 리비전으로 자동 치환하지 않고 `definition_review_required` 오류로 보고한다.
