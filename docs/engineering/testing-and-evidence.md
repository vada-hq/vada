# 테스트와 완료 증거

## 기본 순서

사용자 행동이나 실행 동작이 달라지는 작업은 다음 순서를 지킨다.

1. **RED** — 승인된 완료 증거를 가장 작은 테스트로 표현하고 실행한다. 테스트가 없어서가 아니라 목표 동작이 아직 없기 때문에 실패하는지 확인한다.
2. **GREEN** — 테스트를 통과시키는 최소 변경만 구현한다. 범위를 넓히는 리팩터링이나 미래 기능을 함께 넣지 않는다.
3. **REFACTOR** — 모든 관련 테스트가 녹색인 상태에서 이름·책임·중복을 정리한다.
4. **CHECK** — 작업자는 영향 범위의 검사를 실행하고, 독립 검증자가 이를 재실행한다. 총괄은 승인 변경을 통합한 뒤 저장소 루트에서 `just check`를 한 번 실행한다.

문서만 바꾸는 작업, 순수 설정 변경, 일회성 조사에는 실패 테스트 선행을 강제하지 않는다. 다만 링크·스키마·빌드·구성 검증처럼 자동화 가능한 결과는 해당 검증으로 증명한다.

## 테스트 계층

- **계약·구조 검증**은 제품 명세, 계약 묶음, 구현 아키텍처와 작업 그래프의 참조·리비전·전체 커버리지를 확인한다.
- **API 테스트**는 작은 도메인 동작부터 실제 DB·HTTP 경계까지 확장하며, 권한 거부와 다른 조직 데이터 접근 차단을 정상 경로와 짝으로 검증한다.
- **웹 테스트**는 접근 가능한 사용자 행동과 상태 전이를 검증한다. 승인된 계약 예제와 모의 응답을 사용하고, 실제 API 연결 후 브라우저 E2E로 완주 결과를 증명한다.
- **운영 검증**은 마이그레이션, 관측·알림, 민감정보 비노출, 배포 후 건강 상태와 복구 절차를 대상 작업의 완료 증거에 포함한다.

단위 테스트 비율이나 파일 수를 목표로 삼지 않는다. 실패했을 때 어느 책임이 깨졌는지 가장 빠르게 알려 주는 가장 낮은 계층에 테스트를 두고, 경계 간 위험은 통합·E2E에서 다시 증명한다.

## 증거 기록

최종 CI 성공만으로 테스트 선행 순서를 증명할 수 없으므로 PR 본문을 실행 증거의 기본 기록으로 사용한다. `.github/pull_request_template.md`에 다음을 남긴다.

- 작업 ID·승인 기준선과 실제 변경 범위
- RED 명령과 의도한 실패 요약
- GREEN 명령과 성공 요약
- 작업자 범위 검사와 독립 검증 결과
- 총괄 통합선 또는 CI의 `just check` 결과
- 실제 서비스 통합 검증 위치와 결과. PostgreSQL을 CI에서 검증했다면 해당 작업의 실행 URL
- 보안·계약·마이그레이션·문서 영향과 잔여 위험

비밀값, 전체 운영 데이터, 민감한 요청 본문은 증거에 복사하지 않는다. 긴 로그는 허용된 CI 산출물에 보존하고 PR에는 명령·결과·안전한 위치만 기록한다.

### 실행 런타임 기록

실행 계획 승인 이후의 상태·증거는 JSON을 직접 편집하지 않고 `pnpm record:execution-runtime`으로 원자적으로 추가한다. 갱신 입력에는 근거 내용과 상태 전이 또는 완료 증거만 제공하며, 근거·전이·증거 ID와 모든 기록 시각은 도구가 같은 현재 시각으로 생성한다. 호출자가 과거 시각이나 ID를 주입하는 입력은 거부한다.

새 실행 파동은 승인 계획에서 커밋 작업·실행자·계획 해시를 읽어 런타임을 자동 초기화한다. 먼저 `--dry-run`으로 확인하고 같은 명령에서 옵션만 제거한다.

```powershell
pnpm record:execution-runtime -- --runtime delivery-units/DU-001/execution-runtime/R7.json --plan delivery-units/DU-001/execution-plan/R7.json --initialize --dry-run
```

```powershell
$runtimeUpdate = @'
{
  "source": {
    "type": "user_statement",
    "locator": "conversation:approval",
    "content_ko": "제품 책임자가 착수를 승인했습니다."
  },
  "transition": {
    "work_item_ref": "WORK:example@R1",
    "to": "in_progress",
    "actor_ref": "EXEC:ai-coordinator",
    "note_ko": "승인된 작업을 시작합니다."
  }
}
'@
$runtimeUpdate | pnpm record:execution-runtime -- --runtime delivery-units/DU-001/execution-runtime/R2.json --dry-run
```

`--dry-run` 결과와 검증을 확인한 뒤 같은 입력에서 옵션만 제거해 기록한다. 과거 기록을 정정할 때는 값을 조용히 덮어쓰지 않고 Git·PR·CI의 영구 메타데이터를 사용하며, 정정 이유와 근거를 새 실행 근거로 추가한다. 정확한 시각이 보존되지 않았다면 추정하지 말고 처음 확인 가능한 영구 기록 시각을 사용한다.

## 완료 판정

다음을 모두 충족해야 완료다.

- 작업의 모든 `completion_evidence`가 재현 가능한 결과로 확인됐다.
- 계약과 구현이 같은 의미를 가지며 승인 범위를 벗어난 변경이 없다.
- 경로별 검사와 `just check`가 통과했다.
- 로컬 또는 CI로 지정한 실제 PostgreSQL 통합 검증이 통과했다. CI 검증은 구성 존재가 아니라 해당 커밋의 성공한 실행 결과로 증명한다.
- 필요한 문서·계약·마이그레이션·운영 절차가 코드와 같은 변경 집합에 포함됐다.
- 검증자와 총괄의 검토를 거쳤고, 요구된 사람 승인 게이트를 통과했다.
