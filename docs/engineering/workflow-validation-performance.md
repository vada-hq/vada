# 거버넌스 검증 실행 성능 기록

## 목적

기존 검증 항목과 개별 명령은 유지하면서, `just check`와 CI에서 반복되던 PowerShell·pnpm·Node 프로세스 시작 비용을 줄인다. 검증 의미나 제품·계약 데이터는 변경하지 않는다.

## 측정 조건

- 측정일: 2026-08-05
- 환경: Windows, Node.js 22.13.1, pnpm 11.12.0, just 1.57.0
- 방법: 각 경로를 한 번 예열한 뒤 3회 실행하고 중앙값을 사용
- 출력 비용을 줄이기 위해 측정 중 표준 출력과 표준 오류를 버림
- 로컬 단일 장비 측정이므로 절대 성능 보증이 아니라 변경 전후의 방향성 증거로 사용

## 비교한 작업량

직접 Node 경로는 다음 12개 기존 검증을 순서대로 별도 Node 프로세스에서 실행한 결과와, 같은 검증 함수를 한 Node 프로세스에서 실행하는 `node scripts/run-governance-validations.mjs`를 비교했다.

- 워크플로 정책
- 계약, 계약 묶음, 계약 픽스처, 구매 요청 OpenAPI·생성 클라이언트
- 제품 명세, 구현 아키텍처, 전달 작업, 화면 명세
- 실행 계획, 실행 런타임, 전달 상태 파생

pnpm 경로는 기존의 9개 `validate:*` 스크립트 연속 실행과 `pnpm validate:governance`를 비교했다. just 경로는 기존의 9개 검증 레시피가 수행하던 모든 스크립트 단위 테스트와 검증을 `just validate-governance`가 수행하는 경우와 비교했다.

## 결과

- 직접 Node 검증: 3,490.80ms → 994.57ms, 71.51% 감소
  - 변경 전 3회: 3,538.13ms, 3,490.80ms, 3,390.98ms
  - 변경 후 3회: 994.57ms, 1,049.25ms, 992.51ms
- pnpm 검증: 17,946.54ms → 3,129.94ms, 82.56% 감소
  - 변경 전 3회: 21,247.79ms, 17,946.54ms, 17,516.36ms
  - 변경 후 3회: 2,419.52ms, 3,815.35ms, 3,129.94ms
- just 테스트·검증: 84,199.33ms → 11,983.22ms, 85.77% 감소
  - 변경 전 3회: 71,267.42ms, 111,128.65ms, 84,199.33ms
  - 변경 후 3회: 11,983.22ms, 11,176.17ms, 16,570.76ms

## 보존한 안전장치

- 기존 개별 `test:*`, `validate:*` 스크립트와 just 레시피는 그대로 유지한다.
- 집계 실행기는 일부 검증이 실패하거나 예외를 던져도 나머지를 실행하고, 실패한 검증기 ID와 비정상 종료 코드를 반환한다.
- 집계 목록 테스트가 12개 검증 항목의 누락을 감지한다.
- `node --test "scripts/*.test.mjs"`가 현재 131개 스크립트 단위 테스트를 한 Node 테스트 실행으로 수행한다.

## 남은 변동 요인

- Windows 파일 캐시, 보안 프로그램, 백그라운드 부하로 실행 시간 편차가 있다.
- CI는 Node.js 24와 Linux를 사용하므로 절대 시간은 다를 수 있다.
- OpenAPI 생성 결정성 테스트 자체의 하위 프로세스 비용은 유지한다. 이번 변경은 검증 의미를 바꾸지 않고 불필요한 상위 프로세스 중복만 제거한다.
