# 보안과 운영

## 에이전트 권한

- 작업 에이전트에는 해당 작업에 필요한 저장소·명령·서비스 권한만 제공한다. 읽기만 필요한 에이전트에게 쓰기 권한을 주지 않는다.
- 비밀값은 에이전트 프롬프트, 코드, 로그, PR, 테스트 픽스처에 넣지 않는다. 운영 자격 증명은 일반 구현 에이전트의 실행 환경과 분리한다.
- 외부 입력, 도구 출력, 생성 파일은 신뢰하지 않고 계약·스키마·정적 검사·테스트를 통과한 뒤 다음 단계가 소비한다.
- 모든 실행은 작업 ID, 실행 주체, 변경 diff, 검증 결과와 연결돼야 한다. 민감 원문 없이도 실패를 추적할 수 있는 상관 식별자를 사용한다.

## 사람 승인이 필요한 행동

다음 행동은 에이전트가 준비와 검증까지 수행할 수 있지만 최종 실행은 사람 책임자가 승인한다.

- 운영 환경 배포와 트래픽 전환
- 운영 비밀정보·자격 증명·개인정보 접근
- 권한 모델 또는 조직 격리 경계 변경
- 데이터 삭제, 파괴적 마이그레이션, 복구하기 어려운 외부 시스템 변경
- 보안 통제를 약화하거나 알려진 위험을 수용하는 결정

## 배포와 복구

- 빌드한 동일 산출물을 환경별 설정만 바꿔 승격하고, 출처 커밋과 계약·마이그레이션 리비전을 추적한다.
- DB 변경은 expand → migrate → contract로 분리한다. 이전 코드와 새 코드가 전환 구간에 함께 동작할 수 있어야 한다.
- 배포 작업에는 건강 확인, 실패 판단 기준, 중단·롤백 절차와 데이터 호환성 확인을 포함한다. 롤백할 수 없다면 사전에 복구 계획과 사람 승인을 명시한다.
- 위험이 큰 변경은 제한된 대상부터 검증할 수 있는 점진 배포나 기능 플래그를 사용하되, 플래그의 소유자·제거 조건을 함께 기록한다.

## 관측과 장애 대응

- 구조화 로그, 메트릭, 추적에는 작업·요청 상관 식별자와 허용된 결과·지연 정보만 담는다. 재정 원문·토큰·비밀번호·민감 헤더는 수집하지 않는다.
- 에이전트가 로컬·CI·허용된 운영 관측 결과를 직접 조회해 실패 원인을 검증할 수 있게 하되, 접근 범위는 최소화한다.
- 장애 시 새 배포를 멈추고 영향과 증거를 보존한 뒤 안전한 버전으로 복구한다. 수정 후에는 재현 테스트, 원인, 탐지 실패, 문서·계약·런북 변경을 같은 후속 작업으로 추적한다.
- 사용자의 동작이 실패했는데 성공으로 표시하거나, 관측 신호만 정상이라서 제품 결과가 정상이라고 판정하지 않는다. 승인된 완료 증거와 실제 사용자 결과를 함께 확인한다.
