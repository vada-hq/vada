# 026 업무를 와이어프레임에 맞추기

> 만들 때의 명세다. 지금의 규칙은 vada-docs `decisions/`와 `logical-model.md`, 동작은 코드가 원문이다(DEC-77).

상한: 조각 1~11(묶음 1·2, 리허설 2026-11-03 전)은 10시간(실제로 도는 시간). 조각이 11개라 025처럼 처음 기본값(6시간에 7개)의 비율로 잡았다. 넘으면 늘리지 않고 조각 11(학생회 업무 범위), 조각 9(업무 추가 창), 조각 7(칩 줄), 조각 8(상세 패널) 차례로 리허설 뒤로 넘긴다(지금 화면으로도 리허설 길은 돈다, DEC-94 '시기'). 조각 1·2(위반)와 첫날 휴대폰 길(조각 3·4·5·10)은 넘기지 않는다. 조각 12~16(묶음 3·4)은 시기가 조각마다 달라 따로 5시간이고, 진행 에이전트가 따로 된 기능 번호로 나눠도 된다. 시작은 진행 에이전트가 적는다. 양식은 `docs/work-method.md`를 따른다. 가지는 `work/026-조각번호`, 진행 기록은 `.superpowers/sdd/026/progress.md`.

## 왜

운영진이 업무 화면을 열면 와이어프레임의 칸반 대신 표가 나와 지금 무엇이 어느 상태인지 한눈에 보이지 않는다. 휴대폰에서 첫날 "다음 할 일 하나를 업무로 만들고 담당과 마감을 정한다"(pilot/onboarding.md 15~22분)를 하려면 빠른 추가로 만든 뒤 상세를 열어 담당과 마감을 따로 고른다. '담당자 없음'이 서버(부서 없는 업무 포함)와 화면 묶음(담당자 빈 것만)에서 다르게 세져 수가 어긋난다. 비어 있는 업무를 찾을 '마감 없음'이 없고, 부서 업무와 담당자별 보기가 탭 넷에 갇혀 있다. 내 업무는 급한 순 줄일 뿐 카드에서 바로 끝내지 못하고, 업무 상세가 대화상자라 보드 위에서 열리지 않는다. 행사 업무 탭의 보기와 거르기는 새로고침하면 풀리고(DEC-78 위반), 부원이 자기 업무를 아무 행사에 이어 자기 부서 모두가 그 행사 신청자 정보를 보게 할 수 있다(DEC-28 위반). 이 기능은 와이어프레임(Figma `B5OHqrl9bbvXCUkhME4Sfo`의 OPS-TASK-01과 그 상세 패널·업무 추가 창, EVT-TASK-01과 그 업무 추가 창, MY-01)에 맞추되 DEC-94가 다르게 정한 곳은 그것을 따른다. 기능 018의 표는 지우지 않고 배치 고르기의 '표'로 남긴다.

### 원칙 대조

- 새로 하는 입력
  - 빠른 추가의 담당 칩과 마감 칩: 둘 다 선택이고 기본값이 채워져 있다. 지금은 만든 뒤 상세를 열어 고르던 것을 같은 줄에서 한 번에 하므로 입력이 줄어든다. 그 사람에게 바로 오는 덕은 첫날 15~22분 일이 휴대폰 한 화면에서 끝나는 것이다.
  - 업무 추가 창: 필수는 제목 하나다. 창은 [자세히]나 [업무 추가]를 누를 때만 열려 빠른 추가로 충분한 사람에게는 입력이 늘지 않는다.
  - 반복(조각 16): 기본은 '반복 없음'이라 고르지 않으면 입력이 없다. 고르면 마감이 필수가 되는데, 그 수고로 다음 주기 업무를 다시 만들지 않아도 된다(지금 그 사람에게 오는 덕).
  - 상태를 바꿀 때 처리 내용은 받지 않는다(DEC-94). 와이어프레임보다 입력이 하나 적다.
- 근거 연결: 바뀌지 않는다(업무에 근거 메시지는 아직 없다, 004). '구매 요청' 배지와 다음 행동 줄은 이어진 결과물을 가리킨다.
- 변경 이력: 카드 메뉴와 내 업무 [끝내기]의 상태 바꾸기, 패널의 고치기는 지금처럼 판(`record_version`)에 이전·이후와 바꾼 사람이 남고 같은 값이면 남지 않는다. 반복으로 생긴 다음 업무는 끝낸 사람이 만든 기록이고, 끝난 업무의 반복 비우기도 판에 남는다. 계산되는 값(지남, 담당자 없음, 칩 수, D-DAY, 진행 막대, 부서 색, 다음 행동 줄)은 저장하지 않는다.

## 범위 밖

2026-10-26 사용자 추가 요청으로 넓은 화면 칸반의 상태 열 사이 끌어 놓기를 범위에 넣는다(DEC-97). 카드의 기존 '⋯' 메뉴와 상세 상태 선택은 유지한다([WCAG 2.5.7](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements)). 같은 열·취소·권한 없음·보내는 중에는 저장하지 않고, 빈 열에도 놓을 수 있다. 저장은 기존 상태 변경과 재조회를 쓰며 실패는 원래 열의 카드에 남긴다. 재조회로 권한·상태가 바뀌었으면 오래된 끌기를 무시한다. 드래그 끝이 상세 클릭으로 이어지지 않는다. 열 안 정렬·순서 저장·서버 권한 변경·휴대폰 끌기는 포함하지 않는다. 사용자가 브라우저 시각 대조를 완료 조건에서 뺐으므로 관련 자동 검사와 CI로 검증하며 실제 포인터 실기 미확인은 보고에 구분한다. 아래 원래 범위 밖의 '끌어 놓기'만 이 추가 요청이 바꾼다.

2026-10-29 사용자 추가 요청으로 업무 정렬을 범위에 넣는다. 고르는 값은 부서별(기본), 마감 임박순, 최신순이다. 보드의 열, 표·줄의 묶음, 내 업무의 마감 묶음은 그대로 두고 그 안의 차례만 바꾼다. 부서별은 조직의 부서 차례이고 부서 없는 업무는 맨 뒤, 같은 부서 안은 마감 임박순이다. 마감 임박순은 마감 없는 업무가 뒤다. 서버가 상한 안에 들일 업무를 고른 뒤 화면이 받은 목록 안에서 줄 세운다. 고른 값은 이 기기에 운영진마다 기억하고 서버에 두지 않는다. 학생회 업무, 내 업무, 행사의 업무 탭이 같은 값을 쓴다(`tasks/task-sort.ts`, `useTaskSort.ts`).

- DEC-94 '버린 안': 검토 단계와 '검토 필요', 완료 기준·우선순위·초기 상태·결과물 유형·연결된 항목·제출 후 검토 칸, 상태 바꿀 때 처리 내용과 메모만 남기기, 끝내기 선택 메모, 처리 기록 탭, 업무 번호, 끌어 놓기, 휴대폰 탭 밀기, 부서 가로 줄, 부서 색 고르기, 끝남 50개 넘게 더 읽기, 사람마다 서버에 보기 저장, 칩 수를 서버가 세기.
- 내 회의 칸과 회의 후속 업무(회의 영역), 문서 칸(문서 영역), 대화에서 업무 만들기(DEC-90 시범 운영 첫 주 뒤, 대화 영역), 마감·지남 휴대폰 알림.
- 업무 화면의 자리(옆 메뉴 '업무'의 위쪽 탭 둘 '학생회 업무'(첫 탭, 기본)·'내 업무', 지금 보기 탭 넷 걷기, 옛 보기 주소의 새 도착지)는 메뉴 v7의 업무 두 탭 조각이 잇는다. 와이어프레임 v7(2026-10-27)이 DEC-96의 '업무 메뉴 안에 위쪽 탭 둘을 두지 않음'과 028 조각 8의 최상위 '내 업무'를 뒤집었다. 이 기능은 내 업무 화면과 학생회 업무 보드 부품을 만든다. 업무 두 탭 조각 전까지 옆 메뉴 [업무]와 `/tasks`는 지금 길(지금 보기 탭) 그대로다.
- 홈의 업무 카드와 홈에서 보드 거르기로 들어오는 링크 모양(홈 영역). '담당자 없음'의 같은 조건은 조각 6이 홈에도 건다.
- 업무 화면의 달력 배치는 지금 그대로 둔다(캘린더 영역).
- 사용자 추가 요청(2026-10-26): 행사 업무 달력 최초 월/선택일은 해당 행사 시작일(없으면 종료일, 둘 다 없으면 한국 시각 오늘)이다. 행사 상세 일시를 우선 사용해 목록 상한·비동기 지연의 영향을 피하고, 다른 행사로 가면 초기화한다. 월/날짜를 직접 고른 뒤에는 재조회가 그 선택을 덮지 않는다. 전체 업무 달력과 [오늘]은 한국 시각 오늘을 유지한다. 새 입력·DB 저장·화면 배치는 추가하지 않는다(PRIN-1).
- 행사 공통 머리(025 조각 5)와 개요 '담당자 없음' 경고 자리(025 조각 8). 이 기능은 그 경고가 여는 주소만 맞춘다(조각 2·7).
- 담당자 이름 누르기 부품 자체(022 조각 7). 이 기능은 업무 화면에 그 부품을 쓴다(조각 14).

## 위험

- **권한과 개인정보 열람 범위(깊게).** 조각 1은 신청자 정보를 보는 사람을 정한다. `tasks/policy-table.test.ts`에 줄을 더해 만들기·행사 바꾸기·선택지가 같은 판정인지 직급(회장단, 부장, 부원, 행사 책임자)마다 본다. 판정을 지우면 세 경로가 함께 실패해야 한다(work-method '자주 잡힌 것'). 다른 학생회 행사를 같은 모양으로 두고 거르기를 지우면 실패하는 시험을 둔다. 선택지에 없는 짝은 403이고 기록이 없다.
- **리허설 흐름.** 조각 1 뒤에도 `flows/rehearsal-event.ts` 5단계 `assignTaskStep`(기획부장이 행사 A에 기획부 업무를 만들고 기획부원에게 맡김)이 그대로 통과해야 한다. 기획부장이 1단계에서 행사 A를 만들어 책임자다(025 조각 3, main에 있음). 흐름 시험이 실패하면 배포하지 않는다.
- **브라우저 흐름 시험(Playwright, 휴대폰 폭).** 조각 4가 휴대폰의 업무 화면을 줄 목록에서 상태 탭으로 바꾸고, 조각 10이 내 업무를 바꾼다. 업무 화면을 지나는 브라우저 흐름의 선택자를 함께 고친다. CI에서만 돈다.
- **나란히 만드는 같은 파일.** `web/tasks/TasksPage.tsx`·`useTaskControls.ts`·contracts `paths.ts`는 조각 2·3·4·7·10·11이 함께 고친다. `events/EventDetailView.tsx`는 조각 2·12와 025 조각 5, 022 조각 9가 함께 고친다. `api/tasks/results.ts`는 조각 15와 022 조각 1이 고친다. 오른쪽 패널 부품은 조각 8과 025 조각 6이 겹칠 수 있다. 나중에 합치는 쪽이 main 위로 다시 올리고 그 부품 시험을 세 번 연속 돌린다(work-method '동시에 하는 일', 018 회고).
- **018 표를 지우지 않는다.** `TaskTable.tsx`·`TaskTableCell.tsx`·`TaskTextCells.tsx`·`task-table-cells.ts`·`useGridNav.ts`와 그 시험은 그대로 통과해야 한다. 배치 값만 바뀌므로 표 시험이 `layout=list`를 주소에 넣고 열도록 고치는 것은 된다. knip이 표 부품을 안 쓰는 것으로 잡지 않게 '표' 배치에서 계속 부른다.
- **옛 주소.** 알림(배정 알림의 업무 주소)과 홈 링크가 `view` 값을 쓴다. 조각 7과 10이 보기 탭 넷을 걷을 때 정한 것 9의 옮기기 시험(값마다)을 둔다.
- **실제 폭.** 보드(열 셋), 카드, 칩 줄, 상세 패널, 내 업무 카드, 배너는 1024px, 1280px, 390px에서 넘침을 재고 올린다(work-method 차례 2의 실제 폭 규칙). 부품 확인 화면(`src/ui-gallery/TaskSections.tsx`)의 보드는 고정 폭 틀로 묶지 않는다.
- **목록 상한과 그리기 비용.** 칩 수와 거르기는 받은 목록 상한(끝나지 않은 것 300, 끝남 50) 안에서 맞다. 넓은 화면에서 카드 300장을 한 번에 그려 느리면 작업자가 열마다 처음 N장과 [더 보기]를 재고 보고한다(휴대폰은 탭 하나만 그린다).
- **표 바꾸기(깊게).** 조각 16에서 값 CHECK를 더할 때만 마이그레이션 하나(T1)다. 새 칸이 아니라 기존 칸 `task.recurrence`에 거는 제약이라 vada AGENTS.md '마이그레이션'의 '제약을 추가하는' 순서(코드 배포 → 두 DB에서 위반 행 0건 조회 → 적용, 그 파일은 코드 배포 뒤 따로)를 따른다. `db/schema.ts`를 같이 고쳐 `schema-match.test.ts`가 통과해야 한다. 번호는 순번이라 만들기 직전에 main 위로 올린다.
- **동시 처리.** 반복 업무를 두 사람이 같이 끝내거나 결과물 자동 전환과 손으로 끝내기가 겹치면 다음 업무가 둘 생길 수 있다. 업무 행을 잠그고(끝내기의 지금 잠금 꼴) 반복을 비운 쪽만 다음 업무를 만든다. 실제 PostgreSQL 점검(`pg-smoke`)에 이 경우를 더한다(진행 에이전트가 돌림).
- **배정 알림.** 빠른 추가 칩과 업무 추가 창으로 담당자를 정해 만들어도 018의 10초 모으기를 거친다. 정상 종료 때 대기 타이머를 바로 내보내고 진행 중인 알림을 최대 5초 기다린다. 이벤트 요약은 `push_fanout`, 예외·기기 실패는 `push_send_failed`다. 강제 종료·상한 뒤의 유실을 막는 outbox는 나중이다(018 위험 그대로).
- **되돌린 배포.** 이 기능은 표를 바꾸지 않아(조각 16 CHECK 제외) Render에서 이전 배포로 되돌리면 옛 화면(표 기본)으로 돌아갈 뿐 깨지지 않는다. 브라우저에 남은 배치 기억 `board`는 옛 코드가 모르는 값이라 fallback(목록)으로 읽힌다.

### 사람이 시작 전에 할 일

## 닫기

기기 확인은 사람이 하고 `docs/device-checks.md`의 새 절 '업무 보드'에 옮긴다. A는 기획부장(데스크톱 Chrome), B는 기획부 부원(아이폰), C는 회장(갤럭시), D는 홍보부 부원(휴대폰).

1. A가 학생회 업무 보드(메뉴 v7 뒤에는 옆 메뉴 '업무' → '학생회 업무' 탭)를 연다 → 1024px 이상에서 열 셋 보드이고, 행사에 이은 업무는 없다. '담당자 없음 N'을 누르면 N장과 필터 띠가 있다.
2. B가 휴대폰에서 '새 업무'를 누르고 아래 시트에서 제목, 담당(나), 마감을 넣어 만든다 → '할 일' 탭에 카드가 있고 '내 업무'의 마감 묶음에 있다. 카드의 [끝내기]를 누르면 '완료된 업무'로 간다.
3. A가 빠른 추가 줄에서 담당을 B로 골라 만든다 → 약 10초 뒤 B의 잠금 화면에 알림이 온다. 알림을 누르면 업무 패널이 열린다.
4. A가 카드를 진행 중 열로 끌어 놓는다 → 카드가 진행 중 열에 있다. 카드 '⋯'에는 [링크 복사]와 [지우기]만 있다. 배치를 '표'로 바꾸고 새로고침하면 표다.
5. D가 홍보부 업무가 없는 행사 A의 업무 탭을 연다 → 빠른 추가 칸이 없다. D가 자기 업무 고치기에서 행사 선택칸을 열면 행사 A가 없다.
6. C가 행사 A 업무 탭에서 '끝남'을 고르고 새로고침한다 → '끝남' 그대로다. 배너에 D-DAY와 진행 막대가 있다.
