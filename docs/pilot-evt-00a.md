# EVT-00A(행사 목록) 파일럿

목록 계열의 세 번째 화면이다. 회의 목록(OPS-MEET-01A)에서 넓힌 자리 셋이 고치지
않고 쓰이는지가 이 사이클의 물음이었다.

## 1. 수렴 판정: 아직 아니다 (1건)

| 사이클 | 신규 계급 | 새 개념 | (A) 마찰 |
| --- | --- | --- | --- |
| INV-01 | 2 | 2 | 0 |
| HOME-01K | 3 | 3 | 1 |
| MY-01 | 4 | 1 | 1 |
| OPS-00 | 3 | 0 | 1 |
| TASK-01 | 1 | 0 | 0 |
| OPS-MEET-01A | 3 | 2 | 3 |
| **EVT-00A** | **1** | **0** | **1** |

**스키마는 한 줄도 넓히지 않았다.** 이 사이클에서 처음이다. 신규 계급 1건은 명세가
아니라 **구현의 셸에 자리가 없던 것**이고(아래 2), (A) 마찰 1건은 추출기다(아래 5).

판정에 앞서 미뤄 두었던 물음 — "계열 안에서 무엇이 같아야 연속으로 셀 수 있는가" —
은 `docs/decisions/implementation-methodology.md`에 정리했다. 답은 **고르지 않는다**이다.
계열에는 예측력이 없다는 것이 실측으로 드러났기 때문이다: OPS-MEET-01A의 요소 구성은
MY-01의 부분집합인데 계급이 셋 났다. 마찰은 요소 유형이 아니라 **그 유형의 속성**에서
난다.

## 2. 머리 오른쪽의 화면 동작 (신규 계급 · 새 개념 0)

'완료된 행사 보기 →'는 헤더에 있지만 셸이 아니라 **이 화면의 요소**다. 명세는
`button` 그대로 적을 수 있었다 — `emphasis: quiet`가 '채움도 테두리도 없는' 자리다.
없던 것은 **그릴 자리**였다. `AppShell`에 `headerAction`을 냈다.

**이 자리가 없던 동안 조용히 빠진 것이 있었다.** TASK-01의 design에는 `18:86`
'업무 추가'가 있는데 명세에도 화면에도 없었다. 대조기는 등록 노드 밖을 보지 않으므로
아무 검사도 이것을 잡지 못했다. 이번에 명세에 넣고 그렸다.

교훈은 자리가 아니라 검사 쪽이다 — **design에 있는데 명세에 없는 것을 아무도 안 본다.**
대조는 한 방향이고, 그 방향이 '명세 → 화면'이라 명세의 구멍은 통과한다.

## 3. 지난번에 넓힌 셋 중 하나만 다시 쓰였다

| 지난 사이클에 넓힌 자리 | 여기서 |
| --- | --- |
| `itemList.group` | **안 씀** — 행사가 곧 항목이라 묶음이 없다 |
| `labelField`·`emphasisField` | **안 씀** — 카드 전체가 눌리고 버튼이 없다 |
| `group.collapsible` | **안 씀** |
| `data-sources`의 조각 중첩(`fields[].fields`) | **씀** — 카드의 딱지(`highlights`)가 행사마다 개수가 다르다 |

정직하게 적자면 이 화면은 그 셋의 시험이 되지 못했다. 중첩만 **다른 쓰임**으로
재사용됐다 — 지난번에는 묶음 → 항목이었고 여기서는 한 항목 안의 딱지들이다.

그대로 쓰인 다른 것들:

| 이미 있던 자리 | 여기서 |
| --- | --- |
| `select.presentation: choiceGroup` + `params`(TASK-01의 범위 토글) | 진행 단계 거르개 |
| `input`(`inputType: search`) + `itemList.params` | 행사명 검색 |
| 톤 이름을 데이터가 준다(`statusTone`) | 상태 딱지 |
| 완성된 문자열로 온다 | `lastModifiedNote`·'일시 미정'·'담당 미정' |
| 없으면 오지 않는 조각(TASK-01의 `alert`) | 카드의 주의 줄 |
| 빈 드롭다운은 명세에서 뺀다(MY-01) | `20:4166` |

## 4. design 대조가 0곳에서 시작했다

| 화면 | 처음 어긋난 곳 |
| --- | --- |
| MY-01(붙일 때) | 30 |
| 아홉 화면 전체 | 234 |
| OPS-MEET-01A | 6 |
| **EVT-00A** | **0** |

믿기 전에 반증했다 — 카드 부제의 글자 색을 `gray-500`에서 `gray-700`으로 한 글자
바꾸니 **9곳**을 정확히 짚어 실패했다. 검사는 살아 있고 화면이 맞은 것이다.

상태 딱지의 규칙(**바탕 -50 / 테두리 -200 / 글씨 -700**)도 견뎠다. '후속 정리 중'이
`orange-50`/`orange-200`/`orange-700`으로 규칙 그대로여서, `design/tones.ts`의
`STATE_CHIP`에 **줄 하나만 늘었다.** 규칙을 고칠 일이 없었다.

## 5. (A) 마찰 — 추출기가 화면을 거의 못 봤다

초안에 나온 것은 **버튼 4개**(진행 단계 거르개)뿐이다. 검색칸도, 카드 목록도,
머리의 이동도 아예 없었다. 원인은 `packages/contracts/src/screen-draft.mjs`의 두 조건이다.

- `isFieldWrapper`: **직계 자식에 `Label`이라는 노드가 있어야** 필드로 본다.
  이 화면의 검색칸은 라벨 없이 placeholder만 있다(`20:4153`).
- `readSection`: **묶음에 제목이 있어야** 목록으로 본다. 이 화면의 카드 목록
  (`20:4167`)에는 제목이 없다.

즉 추출기는 **이름표가 붙은 것만 본다.** 라벨 없는 입력칸과 제목 없는 목록은 통째로
보이지 않는다.

지난 사이클(OPS-MEET-01A)의 오독 — 카드 안 라벨-값 쌍을 목록으로 보고 카드마다
`itemList`를 뽑은 것 — 과 원인은 다르지만 **결과가 같은 계급의 재발**이다: 초안이
화면을 대표하지 못한다. 두 사이클 연속이므로 방법론의 "기존 계급의 재발은 시스템
결함으로 즉시 처리한다"에 걸린다. BACKLOG에 트리거 충족으로 올렸다.

이것이 중요한 이유는 수렴 기준 (2) 때문이다 — 화면당 사람 개입을 고정 목록 안에
두려면 초안이 쓸 만해야 한다. 지금은 화면을 사람(또는 AI)이 처음부터 읽고 있다.

## 6. 이 화면에서 다시 나지 않은 것

**아이콘 셋이 한 덩이로 뽑히는 문제**(OPS-00 `16:615`, OPS-MEET-01A `18:720`)가
여기서는 나지 않았다. 자산 20개가 전부 아이콘 하나씩이다. 이 화면은 카드의
날짜·장소·담당을 각각 제 `Container`로 감쌌고, 회의 목록은 더 납작했다. 규칙이
'사이에 글이 있는가'를 보므로 감싸는 깊이에 따라 갈린다 — 트리거는 그대로 유효하다.
