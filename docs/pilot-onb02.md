# ONB-02 사이클

확장된 스펙 체계(meta·flows·disabledPlaceholder) 위에서 도는 두 번째 화면 사이클이다. 목적: 화면당 비용 실측과 번들 결함 지도 갱신. 방법론은 `docs/decisions/implementation-methodology.md`.

## 사이클 기록 (2026-08-17)

1. 사용자: 플러그인 동기화(meta 보존 왕복 실전 검증됨) → `Figma 원본 JSON 저장` — 1회 재시도(첫 시도는 작업 화면 불일치로 브리지 미도달, 파일 mtime으로 원인 추적).
2. 정규화 CLI → 61노드·자산 11, 검증 CLI 오류 0(동작 명세 nodeId 3개↔design 교차 검증 자동 통과).
3. 시스템 결정 2건(아래 마찰 1·2) → 스키마 수정 → 구현.
4. 구현: ONB02Screen 재구현(카드 2·배지·안내문·뒤로 링크), 테스트 22/22, 빌드 통과.
5. 검증 통과: 사용자 육안(스크린샷 4장 — reference 일치, 미등록 오류 카드 2건=계약 동작, 복귀 시 값 유지) + Playwright e2e 도입(시나리오 2개, 스크린샷 6장 자동 생성·AI 판독 일치). 이후 화면부터 시각 검증은 e2e가 1차 담당한다.

## 완료 기준

1. 레이아웃: 구조·순서·정렬·상대 비율이 `reference.png`와 일치(절대 픽셀 제외).
2. 동작: 버튼 3개 — 카드 2개는 각 targetScreenId로 이동(미등록 화면이면 명시적 오류 카드 = 내비게이션 계약의 정상 동작), 이전으로는 ONB-01 복귀 + 입력값 유지.
3. 검증: 빌드·검증 CLI 오류 0 유지.
