# HOME-01K 파일럿 — 대시보드는 다른 계열이다

`INV-01`까지의 다섯 화면은 전부 **폼 화면**이었다(입력·선택·제출). `HOME-01K`는
처음 만나는 **읽기 전용 대시보드**이고, 처음 만나는 **데스크톱 화면**이다.

사이클을 끝내기 전에 측정부터 기록한다. 규약대로 진행 중에 적는다 — 끝난 뒤
재구성하면 과소 보고된다.

## 1. 자산 추출 실패 (해결됨)

벡터 64개 중 3개가 export를 거부당했다.

```
Failed to export node. This node may not have any visible layers.
```

두 가설이 교차 검증에서 죽었다.

| 가설 | 반례 |
| --- | --- |
| 면적이 0인 벡터(직선) | ONB-02는 면적 0 벡터 5개를 갖고도 11개 전부 성공 |
| 조상이 숨겨져 있다 | 조상 11단계가 모두 보임 |

살아남은 판별자는 `absoluteRenderBounds === null`이다. 등록된 6개 화면의 벡터
120개 중 null은 그 셋뿐이고, 그 셋은 전부 실패했다. `isVectorAssetNode`로
계급을 고쳤다(플러그인과 정규화기가 같은 규칙을 쓴다).

**부수 발견**: 진짜 오류 메시지가 `error instanceof Error`에 걸려 버려지고 있었다.
Figma 샌드박스가 던지는 값은 다른 렐름의 객체라 `instanceof`가 거짓일 수 있다.
이것 때문에 진단이 한 번 왕복했다. 플러그인 9개 지점을 `toErrorMessage`로 교체.

또한 자산 추출이 **전부 아니면 전무**여서 벡터 하나가 실패하자 나머지 63개와
`reference.png`까지 버려졌다. 이제 실패한 것만 보고하고 나머지는 건진다.

## 2. 추출기가 화면의 45%를 못 본다

| | 개수 |
| --- | --- |
| 텍스트 노드 총계 | 69 |
| 추출기가 요소로 잡은 것(전부 `button`) | 38 |
| **아예 못 본 것** | **31 (45%)** |

못 본 31개의 정체:

| 묶음 | 개수 | 예 |
| --- | --- | --- |
| 사이드바 내비게이션 + 사용자 | 12 | 홈 · 내 업무 · 운영 · 재정 · 기록 · 조직 관리 · 메시지 |
| 상단 헤더 | 3 | 제12대 소프트웨어융합대학 학생회 운영 현황 · 2026년 1학기 |
| 끼룩이 브리핑 | 4 | 박해랑님, 확인이 필요해요 · 지연된 업무가 1건 있습니다. |
| 섹션 제목 | 4 | 진행 중·예정 행사 · 다가오는 주요 일정 · 조직 주요 알림 · 전체 재정 요약 |
| 재정 요약 수치 | 8 | 전체 예산 사용률 34% · 사용 가능 예산 66% · 증빙 누락 5건 |

그리고 잡은 38개도 **유형이 틀렸다**. Figma에서 `Btn`으로 이름 붙었다는 이유로
전부 `button`이 됐지만, 실제로는 행사 카드(`기획 중`), 일정 행(`07.20`),
알림 행(`증빙 서류 누락`)이다. 추출기 질문 30건 중 22건이 이 오인에서 나온
`description·badge`와 `targetScreenId` 질문이다.

## 3. 선례 재사용은 이 화면에서 무력하다

이 화면에는 `input`·`select`가 **하나도 없다**. 선례의 확정 단위가 필드이므로
적용할 자리가 없었다. 화면당 사람 개입 절감은 **0건**이다.

선례 재사용은 폼 화면끼리만 효과가 있다 — INV-01에서 11건을 줄인 것은
ONB-01과 같은 폼이었기 때문이다.

## 결론 (진행 중)

수렴이 아니라 **발산**이다. 다만 원인이 어휘의 부실함이 아니라 **화면 계열의
전환**이다 — 폼에서 대시보드로 넘어왔다. 이 구분이 이번 측정의 소득이다.
