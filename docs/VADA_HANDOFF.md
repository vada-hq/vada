## 2. 현재 상태

- 화면 100개. `src/app/App.tsx`의 `SCREENS` · `SPEC_DATA`(화면정의서) · `SCREEN_COMPONENTS`가 같은 수여야 한다.
- Vite + React + Tailwind. 백엔드는 없고 모든 데이터는 화면을 새로 고치면 초기화되는 로컬 상태다(구매 요청 임시 저장만 브라우저 저장소).
- 앱 왼쪽 `Vada 와이어프레임` 패널에서 화면을 고른다. 위쪽 `샘플` 선택의 `첫 사용 · 빈 상태`는 신규 학생회 상태를 보는 검토용 컨트롤이다.
- 배포: Cloudflare Worker `vada-wireframe-2026` (`pnpm run build` 후 `wrangler deploy`).

## 3. 메뉴 구조 (v6.2, 2026-10-12~13 채택)

```text
사이드바
├─ 홈 (역할별 홈으로 이동, 안 읽은 메시지 배지)
├─ 내 업무 (해야 할 업무 + 내 회의)
├─ 캘린더
├─ 재정 (학생회 전체 현황)
├─ 기록
└─ 조직 관리
공간 목록
├─ 우리 학생회 (구 상시 업무, 맨 위 고정)
├─ 활성 행사 (진행 중 → 기획 중 → 후속 정리 중)
├─ 전체 행사 보기
└─ + 새 행사 (회장단·부서장만)
```

- `운영`·`메시지` 사이드바 메뉴는 없어졌다. `OPS-00 운영 홈`은 화면만 남아 있고 메뉴에서 들어오지 않는다.
- **우리 학생회 탭**: 메시지 · 업무(`OPS-TASK-01`) · 회의(`OPS-MEET-01A`) · 일정(`OPS-CAL-01`) · 재정(상시 지출 컨테이너의 `EVT-FIN-01`). 누르면 메시지가 첫 화면이다.
- **행사 탭**: 메시지 · 개요 · 업무 · 회의 · 일정 · 문서 · 재정 · 인원 관리. 누르면 메시지가 첫 화면이다.
- 결정 근거: [planning/messaging/design.md](planning/messaging/design.md) M-01~M-08.

## 4. 공간별 원칙

### 홈

- 사이드바 `홈`은 역할별 홈으로 간다: 회장단 `HOME-01C`, 부서장 `HOME-01D`, 부원 `HOME-01M`, 재정부 `HOME-01F`(재정부 소속이면 직급보다 우선). 네 시안 모두 예시 데이터다.
- 인사 카드 안에 메시지함(안 읽은 방·1:1 상위 3개 + `전체 보기`)이 있다. 1:1 칩은 사이드챗으로 연다.
- 헤더에 끼룩이가 `{기준 시점} 기준으로 정리했어요` 한 줄만 말한다. 상시 브리핑 배너(`HOME-01K`)는 미채택이며 화면만 남아 있다. 기존 `HOME-01`도 비교용으로 남아 있다.
- 홈은 `내 업무`의 상위 공간이 아니다(`홈 > 내 업무` 경로를 쓰지 않는다).
- 결정 근거: [planning/home-planning/design.md](planning/home-planning/design.md) D-01~D-14.

### 내 업무

- 현재 사용자에게 배정된 행사·우리 학생회 업무를 상태별로 모은다. 범위·상태·키워드 필터가 있다.
- `내 회의`: 우리 학생회·행사 회의 중 내가 참여·진행·회의록 정리·요약 확인할 회의를 모은다. 전체 회의 목록의 역할을 대신한다.

### 업무 칸반 (우리 학생회·행사 공통)

```text
예정 → 진행 중 → 검토 필요 → 완료
```

- `내 업무(MY-01)`, `우리 학생회 업무(OPS-TASK-01)`, `행사 업무(EVT-TASK-01)`는 같은 카드 언어를 쓴다. 흰 카드에 부서 색상선과 부서 칩, 지연·검토 필요는 상태 배지, 담당자 없는 카드는 빨간색.
- `전체 업무 / 내 업무` 전환. 우리 학생회 카드는 오른쪽 상세 패널, 행사 카드는 `EVT-TASK-02` 상세로 연다.
- 담당자가 `미지정`일 때만 `담당자 배정`을 보인다. 상태 변경은 처리 내용을 필수로 기록한다.
- 회의록 정리(`OPS-MEET-06B`)에서 만든 후속 업무 카드는 업무·내 업무·캘린더에 바로 반영된다.

### 행사

- 상태: `기획 중 → 진행 중 → 후속 정리 중 → 완료`.
- 메시지 탭을 뺀 모든 탭 위에 행사 요약 줄(상태, 지연·미배정·검토 필요로 계산한 건강도, 담당 부서·책임자, 행사일, 다음 미완료 업무)을 둔다.
- 기본정보 수정과 상태 전환은 행사 운영 조직 관리자·회장단만 본다.
- 일정 탭은 기본정보·회의·업무를 모아 보는 열람 화면이며 여기서 날짜를 중복 수정하지 않는다.

### 메시지

- 대화방은 사용자가 만들지 않고 미리 연결되어 있다(공간 방·부서 방·부서 간·1:1).
- **공간 메시지 탭**: `공지방 · ○○부 방 · 구매 후보 N`. 탭을 열면 부서방부터 보인다. 다른 부서의 부서방은 보이지 않는다. 메시지 탭 배지는 두 방의 안 읽은 수 합이다.
- **링크**: 쇼핑 링크를 누르면 오른쪽에 `상품 정보` 패널이 열린다(사이드챗 위에 덮고, 닫으면 사이드챗으로 돌아간다).
- **사이드챗(1:1·부서 간)**: 모든 화면 오른쪽에 하나만 열린다. 입력창 `/`(사람·부서·직책 자동완성), 사람 이름 누르기, 홈 메시지함 1:1 칩으로 연다. 오발송을 막도록 색·제목·보내기 문구(`○○님에게 보내기`)를 메인 방과 다르게 하고, 열리면 커서를 옮기며, Esc로 닫아도 쓰던 글을 남긴다.
- `MSG-01` 전체 방 목록, `MSG-03` 대화 화면, `MSG-04` 사이드챗 시안이 있다. `MSG-02` 방 만들기는 미리 연결 원칙(M-09) 이전 화면이다.
- 결정 근거: [planning/messaging/design.md](planning/messaging/design.md) M-09~M-15.

### 구매 후보 → 구매 요청 (2026-10-14)

- 부서방에 올라온 쇼핑 링크(쿠팡 외 쇼핑몰 포함)는 모두 그 부서의 구매 후보로 자동으로 담긴다. 쇼핑이 아닌 링크와 링크 없는 말은 담지 않는다. 공지방·사이드챗의 링크는 `부서방으로 옮기기`만 둔다.
- 후보 카드: 체크박스·품목명·옵션(쿠팡 옵션 목록에서 고르면 가격 확정)·가격·수량·올린 사람. 옵션·수량은 모두가 같이 보는 값이다.
- 체크하면 그 자리에서 구매 요청 카드로 펼쳐진다. 제목·구매 목적은 끼룩이 초안(목적은 확인해야 제출), 필요한 날짜·우선순위는 직접 입력. 둘 이상 체크하면 위로 모아 묶음 요청 1건이 된다.
- 요청은 부서장·재정부(부원 포함)·회장단만 할 수 있다. 제출하면 그 공간의 재정 칸반으로 간다.
- 대여·용역의 대화 연결은 보류. 결정 근거: [planning/chat-purchase/design.md](planning/chat-purchase/design.md) P-01~P-19.

### 재정

재정 확정 사항의 단일 기준은 `VADA_FINANCE_SPEC.md`, MVP 범위의 단일 기준은 `VADA_MVP_SPEC.md` §6.1이다.

- **MVP 제품화 대상**(2026-08-19 확정)은 요청·검토의 책임 흐름과 처리 상태 가시성이다: `EVT-FIN-01`(품목 현황 + 재정부 처리 단계 칸반) · `MY-REQ-01` · `FIN-REQ-01B/01C` · `FIN-REQ-02` · `FIN-REV-01` · `FIN-SUP-01B` · `FIN-00` · `FIN-PROC-01`(칸반 카드 상세이자 `구매 불가 처리 필요`를 푸는 유일한 경로).
- **제외·보류**: 증빙 묶음(`FIN-EVID-01`), 사비 선지출(`FIN-ADV-01`·`01B`), 집행 유형 17종 판정. 화면은 지우지 않고 좌측 목록 `재정(MVP 제외·보류)` 그룹에 두며 스위치(`EVIDENCE_STAGE_ENABLED`, `ADVANCE_CLAIM_ENABLED`)로 닫아 둔다. 다시 꺼낼 때는 `VADA_FINANCE_DEFERRED.md`부터 읽는다.
- **새 재정 화면을 만들기 전에 출처를 확인한다.** 사용자가 말한 고통이면 MVP 후보, 세칙·별칙 대조에서 나왔으면 기본은 MVP 밖이다. 와이어프레임에 이미 있다는 사실은 근거가 아니다.
- **예산 항목은 재정부가 검토할 때 고른다**(2026-10-14). 요청자는 고르지 않으며, 고르지 않은 품목은 승인할 수 없다. 구매 유형은 요청자가 고른다.
- **쿠팡 링크 자동 채우기**: 구매 요청 카드에 쿠팡 링크를 붙이면 품목명·판매처·배송비·배송 정보·옵션 전체 목록을 불러오고, 옵션을 고르는 즉시 가격이 확정된다. 쿠팡 외 쇼핑몰은 판매처만 채운다.
- **구매 종결은 실지출 금액 확정이다**(2026-09-01). `수령 완료`·`이행 완료` 다음에 실제 결제액과 결제 수단을 확정한 실행분만 `정산 완료`가 된다.
- **상시 지출**은 행사 레코드의 `kind: "상시"`로 처리하고 우리 학생회의 재정 탭으로 연다.
- 중앙감사위원회가 작성하는 감사 결과 보고서·판정 문서는 만들지 않는다. 피감기구 제출물(결산안·소정 양식 보고서·증빙 묶음) 작성·내보내기는 허용한다(2026-08-14).
- 검토용 예시 사용자: 재정부 `김민준 · 재정부 · 부서장`, 요청자 `박해랑 · 운영부 · 부서장`, `김민석 · 홍보부 · 부서장`(보완 재제출 `REQ-002`).
- `EVT-FIN-DEMO`: 빈 행사(`EVT-WELCOME`)에서 재정 흐름을 직접 조작해 시연하는 화면. `시연 초기화`는 빈 행사의 요청만 지운다.

### 기록 · 행사 아카이브

```text
아카이브: 미발행 → 초안 → 검토 중 → 발행
```

- 행사 완료와 아카이브 발행은 별개다. `REC-01`은 완료 행사와 발행 상태를 함께 보여 준다.
- `REC-02`는 발행·검토 중 아카이브를 읽는 문서형 화면, `REC-02A`는 행사 운영 조직 관리자·회장단만 작성·검토·발행한다. 자세한 정의는 `VADA_EVENT_ARCHIVE_SPEC.md`.

### 조직 관리

- 학생 명단(`ORG-07B`)과 학생회비 납부 명단(`ORG-07C`)은 따로 업로드한다. 납부 명단은 학생 명단과 일치한 학생만 갱신하고 새 학생을 만들지 않는다.
- 학생 명단 업로드·내보내기는 회장단, 납부 명단 업로드는 재정부·회장단.
- 조직 구조 설정(`ORG-02`)은 구조만 만들며 아직 초대되지 않은 구성원을 배치하지 않는다.

### 끼룩이

- 끼룩이는 별도 AI 비서가 아니다. 실제로 자동화한 일에만 `끼룩이가 ○○했어요`로 표시하고, 판단·선별한 것처럼 말하지 않는다. 경고·차단·재정 판정에는 쓰지 않는다.
- AI 초안은 `끼룩이 초안 · 검토 필요`로 표시하고, 사람이 확정한 결과물에는 끼룩이를 작성자로 남기지 않는다.
- 표정 3종은 `public/kkiruk-hello·check·think.png`(크롭본, 배경 불투명).
- 결정 근거: [planning/kkiruk-presence/design.md](planning/kkiruk-presence/design.md) K-01~K-07.

## 5. 회의

회의 화면 ID는 `OPS-MEET-*`를 그대로 쓴다. 우리 학생회 회의 탭과 행사 회의 탭(`EVT-MEET-01`)에서 열고, 전체 회의는 `내 업무 > 내 회의`에서 모아 본다.

| 단계 | 화면 |
|---|---|
| 목록·생성 | `01A` 일반 참가자 · `01B` 진행 권한자 · `01C` 회의 생성 가능(회장단·부서장) · `01D` 미참가자 · `02` 생성·수정 |
| 예정 | `03A` 일반 참가자 · `03B` 생성자 관리 · `03C` 진행 권한자(권한 현황 인라인) · `04B` 진행 권한 관리(생성자) |
| 진행 중 | `05A` 일반 참가자 · `05B` 진행 권한자 |
| 정리 | `06A` 일반 참가자 · `06B` 회의록 정리(진행 권한자) |
| 완료·취소 | `07` 완료 회의록 · `08` 불참자 요약 확인 · `09` 취소된 회의 |
| 확인 모달 | `D01` 시작 · `D02` 종료 · `D03` 진행 권한 부여 · `D04` 취소 |

```text
예정 → 진행 중 → 정리 중 → 완료   (예정 회의는 취소 가능)
```

- **회의 진행 권한과 회의 생성 권한은 분리한다.** 진행 권한만으로 새 회의를 만들거나 다른 사람의 권한을 바꿀 수 없다. 생성자는 기본 진행 권한자이며 진행 권한 부여·해제는 생성자만 한다.
- 일반 참가자에게 회의 시작·종료·권한 관리 버튼을 보이지 않는다.
- 안건 하나에 `논의 내용 → 결정사항 → 후속 업무`가 붙는다. 안건을 바꾸면 세 영역이 함께 바뀐다. 결정사항·후속 업무를 회의 전체 목록으로 따로 빼지 않는다.
- `06B` 정리 완료는 모든 안건에 `결정사항 또는 없음`, `후속 업무 또는 없음`이 있어야 켜진다.
- 참석: 진행 중에 `회의 참가`를 누르면 참석(첫 시각만 기록). 예정 상세·완료 회의록 열람, 불참자의 요약 확인은 참석이 아니다. 시작한 사람은 자동 참석.
- 비공개 회의는 참가자·생성자에게만 목록에 보인다. 공개 회의의 미참가자가 참가하면 확인을 거친다.
- 생성 회의의 일시는 캘린더·홈 일정·행사 일정에 자동 표시되고, 취소된 회의는 제외된다.

### AI 회의 전체 요약 (2026-07-19 승인, `OPS-MEET-06B`)

- 안건별 정리본으로 끼룩이가 전체 요약 초안을 만든다. 기록에 없는 결정·담당자·기한·후속 업무를 만들지 않는다.
- 생성 전 → 초안·검토 필요 → 원본 변경 경고 → 최종 확인(검토자·시각). 실패하면 직접 작성할 수 있다.
- 선택 사항이며 정리 완료를 막지 않는다.

## 6. 권한 원칙

- 권한 판정은 헬퍼를 재사용하고 화면에서 역할 조건을 직접 쓰지 않는다. 목록은 `VADA_PERMISSION_MATRIX.md` `구현 규칙` 절.
- 권한이 없으면 버튼을 비활성화하지 않고 아예 보이지 않는다.
- 권한자 전용 단독 화면은 검토용으로 해당 역할 사용자를 주입한다(`AsPresident`, `AsFinanceManager`, `AsEventManager` 등).
- 역할 표기는 권한 매트릭스 어휘(회장단·부서장·부원·재정부 등)를 쓴다.

## 7. 작업 방식

1. 로컬 화면(`pnpm run dev` → `http://localhost:5173/`)과 관련 코드를 직접 확인한다.
2. 고칠 화면의 목적·구조·문제점을 먼저 설명하고 동의를 받은 뒤 고친다.
3. 요청하지 않은 화면·기능은 추가하지 않는다. 기존 화면과 디자인 스타일을 재사용한다.
4. 화면을 새로 만들거나 구조를 바꾸면 같은 작업에서 화면정의서(`SPEC_DATA`)도 고친다.
5. `pnpm run build`와 `pnpm run test`를 통과시키고 브라우저에서 확인한다.
6. 기획 결정은 사용자가 채택한 것만 `docs/planning/<주제>/design.md`에 기록한다.

검증 체크리스트:

- 역할에 맞지 않는 버튼이 보이지 않는가?
- 회의 안건을 바꾸면 논의·결정·후속 업무가 함께 바뀌는가?
- 기존 VADA 스타일과 맞는가?
- 화면을 더하거나 지웠다면 `SCREENS`·`SPEC_DATA`·`SCREEN_COMPONENTS` 수가 같고, `nextScreens`·`entryPath`가 없는 화면을 가리키지 않는가? 화면 수는 이 문서 2장, `VADA_MENU_STRUCTURE.md`, `VADA_PERMISSION_MATRIX.md` 머리말에서 함께 고친다.
