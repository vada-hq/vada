## 주요 공간 원칙

### 기록 · 행사 아카이브

`기록 > 완료된 행사(REC-01)`는 완료 행사와 아카이브 발행 상태를 함께 보여 준다. 행사 완료와 아카이브 발행은 별개다.

```text
아카이브: 미발행 → 초안 → 검토 중 → 발행
```

- `REC-02`는 발행 또는 검토 중인 아카이브를 열람하는 문서형 화면이다. 발행본은 발행 시점의 성과·타임라인·근거 자료를 고정하며, 검토 중인 문서는 확정 전임을 표시한다.
- `REC-02A`는 행사 운영 조직 관리자·회장단만 작성·검토 요청·보완 요청·승인·발행할 수 있다. 발행은 필수 기록 작성 및 검토 승인 이후에만 가능하다.
- 완료 행사의 원본 워크스페이스가 행사별로 분리되기 전까지, 미발행 아카이브의 일반 사용자에게는 발행 전 안내만 표시한다. 찾을 수 없는 진행 행사 목록으로 보내지 않는다.

### 홈

학생회 전체 운영 현황을 요약하는 최상위 공간이다. 홈은 `내 업무`의 상위 공간이 아니다.

### 내 업무

현재 사용자가 처리해야 하는 여러 행사와 조직 업무를 모아보는 개인 공간이다.

올바른 경로:

```text
내 업무 > 해야 할 업무
```

잘못된 경로:

```text
홈 > 내 업무 > 해야 할 업무
```

내 구매 요청(MY-REQ-01)은 2026-07-19 결정으로 `운영 > 행사 > 재정 > 내 구매 요청`으로 이동했다. 행사 스코프의 개인 요청 화면이며 화면 ID는 유지한다.

### 운영

사이드바의 `운영`은 `OPS-00 운영 홈`으로 진입한다. 이 허브는 사용자에게 같은 수준의 네 하위 공간을 선택하게 한다.

```text
운영
├─ 상시 업무 → OPS-TASK-01
├─ 회의 → OPS-MEET-01A
├─ 행사 → EVT-00A
└─ 캘린더 → OPS-CAL-01
```

회의 생성·행사 생성처럼 권한이 필요한 행동은 운영 홈에서 노출하지 않고 각 하위 공간에서만 제공한다.

### 행사 > 업무

특정 행사 참가자 모두가 보는 칸반 협업 공간이다.

```text
예정 → 진행 중 → 검토 필요 → 완료
```

`내 업무(MY-01)`, `상시 업무(OPS-TASK-01)`, `행사 업무(EVT-TASK-01)`는 동일한 카드 언어를 쓴다. 기본 카드는 흰 배경에 부서별 좌측 색상선과 부서 칩을 사용하고, 지연·검토 필요는 상태 배지로 분리한다. 담당자가 없는 카드는 빨간색으로 표시한다. 상시·행사 업무는 `전체 업무 / 내 업무` 전환을 제공하며, 행사 업무에는 중복된 하단 개인 업무 목록을 두지 않는다.

상시 업무의 카드를 누르면 오른쪽 읽기 전용 상세 패널이 열린다. 패널에서는 업무 설명, 담당자·부서, 상태·마감일, 반복 주기와 연결 항목을 확인하며, 배경 또는 닫기 버튼으로 원래 칸반으로 돌아간다.

### 2026-07-19 흐름 연결 보강

- 홈의 요약 카드, 행사·일정·주요 알림, 재정·내 업무 바로가기는 대상 화면으로 이동한다. 행사 업무의 지연·담당자 미지정 수와 현재 사용자의 미완료 담당 업무 수는 실제 업무 데이터에서 계산해 홈에 반영한다. 기본 샘플에서는 검토용 행사·일정 예시를 함께 보이되, `첫 사용 · 빈 상태`에서는 이를 숨기고 `다가오는 주요 일정`과 ‘이번 주 주요 일정’을 행사·상시 업무의 미완료 마감과 취소되지 않은 생성 회의만으로 계산한다. 일정 행과 `캘린더 보기`는 통합 캘린더로 이동하며, 행을 통해 들어온 경우 해당 월·날짜와 일정명을 강조한다. 담당자 미지정 알림은 행사 업무의 미지정 필터를 적용한다.
- 운영 홈의 상시 업무 카드에는 실제 상시 업무의 진행 중·검토 필요 수를, 캘린더 카드에는 행사·상시 업무의 이번 주·다가오는 미완료 마감 수를 표시한다.
- `내 업무`는 행사 업무와 상시 업무에서 현재 사용자에게 배정된 카드만 상태별로 합쳐 보여준다. 업무 생성·담당자 배정·상태 변경 결과는 요약 칩과 탭별 목록에 즉시 반영된다. 체육대회·상시 업무 범위, 상태, 키워드 필터로 목록을 좁힐 수 있고 결과가 없으면 초기화한다. 카드는 읽기 전용 상세 패널을 열고, 행사 업무는 선택한 업무의 상세 화면으로, 상시 업무는 선택한 카드의 상세 패널이 열린 상시 업무 보드로 이동한다.
- 행사 업무 카드는 `EVT-TASK-02` 상세 화면으로 이동한다. 해당 화면은 선택한 카드의 담당자·부서·상태·마감일·설명을 표시한다.
- 행사 업무의 `업무 추가`는 업무명·설명·완료 기준을 필수로 받고, 부서·담당자·마감일·초기 상태·우선순위·결과물 유형·연결 항목·제출 후 검토 여부까지 정의한다. 입력한 업무 정의는 상세 화면에도 그대로 표시되며 칸반에 즉시 추가한다.
- 상시 업무의 `업무 추가`는 업무명·설명, 담당 부서·담당자, 반복 주기·첫 마감일·초기 상태와 연결 항목을 입력받는다. 생성 즉시 선택한 상태 열에 추가하고 오른쪽 상세 패널을 연다.
- 행사·상시 업무 상세에서 담당자가 `미지정`인 경우에만 구성원 선택과 `담당자 배정` 버튼을 표시한다. 배정 결과는 해당 카드와 상세에 즉시 반영되며, 배정된 사용자의 내 업무 대상이 된다.
- 행사 업무 상세와 상시 업무 상세 패널에서 `상태 변경`을 제공한다. 예정·진행 중·검토 필요·완료 중 다음 상태를 선택하고 처리 내용을 필수로 기록한다. 완료 처리 시 해당 칸반의 완료 열로 이동하며 지연 표시는 해제된다. 행사 업무는 처리 기록 탭에, 상시 업무는 상세 패널의 처리 기록에 변경 내용과 작성자를 남긴다. 상시 업무의 담당자 배정도 같은 기록에 남긴다.
- 회의록 정리(OPS-MEET-06B)에서 안건별 후속 업무의 업무명·담당자·마감일을 확정하고 `업무 카드 만들기`를 누르면 상시 업무 카드가 생성된다. 카드가 생성되어야 해당 안건의 후속 업무 정리가 완료되며, 생성된 카드는 상시 업무·내 업무·캘린더에 즉시 반영된다. 완료 회의록(OPS-MEET-07)은 안건에 연결된 같은 카드와 원래 업무 상세로 가는 링크를 표시하며, 전체 완료 수와 지연·검토 필요·미배정 업무를 실제 카드 상태에서 요약한다. 불참자 요약(OPS-MEET-08)은 현재 사용자에게 배정된 미완료 카드만 별도로 모아 보여 주고, `회의 요약 확인 완료`를 누르면 확인 시각을 남긴다. 이 기록은 로컬 데모 상태이며 참석·불참 상태를 바꾸지 않는다. `후속 업무 없음`도 명시적으로 선택할 수 있다.
- 회의 생성(OPS-MEET-02)은 회의명·일시·장소가 채워진 경우 예정 회의를 로컬 상태로 생성하고, 권한자용 회의 목록(OPS-MEET-01C)의 해당 회의 그룹에 즉시 카드로 추가한다. 목록은 키워드·상태(취소 포함) 필터와 일시·이름 정렬을 제공한다. 생성 카드에는 생성자 관계와 예정·작성 전 상태를 표시하며, `회의 정보 보기`를 누르면 생성한 회의명·일시·장소·안건·참가자가 표시되는 예정 상세로 열린다. 생성자는 예정 상태에서 참가자 추가·제거, 진행 권한 부여·해제, 안건 추가·수정·삭제, 회의 취소를 할 수 있고 시작 이후에는 이 관리를 잠근다. 생성자는 시작과 함께 참석 처리되며, 초대된 구성원은 진행 중 `회의 참가`로 참석 시각을 남긴다. 진행 중인 생성 회의는 종료 확인을 거쳐 `정리 중`으로 바꾸며 종료 시각과 `정리 필요` 상태를 목록에 반영한다. 정리 중에는 `회의록 정리`에서 안건별 논의, 결정 또는 없음, 후속 업무 카드 생성 또는 없음을 기록한다. 만든 후속 업무 카드는 실제 상시 업무·내 업무·캘린더에 즉시 반영된다. 모든 안건의 정리 조건이 충족된 경우에만 `완료`로 전환하며, 완료 회의록에는 안건별 최종 기록, 생성된 실제 업무 카드, 참가자별 참석·불참 결과를 표시한다. 불참자는 요약 확인 시각을 남길 수 있으며 이 확인은 참석 결과를 바꾸지 않는다.
- 회의는 공개·비공개로 구분한다. 생성 화면(OPS-MEET-02)의 비공개 토글을 켜면 선정한 참가자와 생성자에게만 전체 회의 목록에 노출되고, 그 외 구성원의 목록에서는 제외한다. 목록 카드에는 `비공개` 칩을 표시한다. 공개 회의는 기존처럼 모든 구성원이 목록에서 보되, 진행 중 회의에 미참가 구성원이 `회의 참가`를 누르면 `참가자가 아닙니다. 그래도 참여하시겠습니까?` 확인을 거쳐야 진행 중 회의로 이동한다.
- 생성 회의의 예정 일시는 통합 캘린더(OPS-CAL-01), 홈의 다가오는 주요 일정, 행사 일정(EVT-SCHED-01)에 자동 표시된다. 취소된 회의는 전체 회의 목록의 취소 상태로만 보관하고 이 일정 화면들에서는 제외한다. 캘린더에서 생성 회의를 누르면 해당 회의의 현재 상세 또는 완료 회의록을 연다.
- 행사 관련 회의 탭(EVT-MEET-01)은 현재 행사에 연결해 만든 회의를 기존 관련 회의와 함께 표시하며, 예정·진행 중·정리 중·완료 건수를 실제 목록에서 계산한다. 생성 회의 카드를 누르면 해당 회의의 현재 상세 또는 완료 회의록을 연다.
- 행사 일정 탭(EVT-SCHED-01)도 현재 행사에 연결한 생성 회의의 원본 일시·상태·담당자를 날짜순으로 표시하며, 일정 항목을 누르면 해당 회의의 현재 상세 또는 완료 회의록을 연다. 이 탭에서는 회의 일시를 중복 수정하지 않는다.
- 부서장·재정부가 구매 요청을 제출하면 새 `검토 대기` 요청이 로컬 상태로 생성되어 `내 구매 요청`과 `행사 재정`의 목록·단계 보드에 즉시 반영된다. 행사 재정에서 재정부는 처리 화면으로, 일반 구성원은 상태 확인 화면으로 이동한다.
- 통합 캘린더는 이전·다음 달 이동을 지원하며, 행사·상시 업무의 미완료 마감일을 자동으로 함께 표시한다. 업무 마감 항목을 누르면 행사 업무는 해당 상세 화면으로, 상시 업무는 해당 카드의 상세 패널이 열린 상시 업무 보드로 이동한다. 캘린더 자체의 생성·수정 정책은 여전히 읽기 전용이다.

### 2026-07-20 검토 보강

- 와이어프레임 상단의 `샘플` 선택에서 `첫 사용 · 빈 상태`를 선택하면 회의 목록·상시 업무·구매 요청·완료 행사 기록의 신규 학생회 상태를 직접 확인할 수 있다. 이는 제품 기능이 아니라 검토용 컨트롤이다.
- `REC-02A` 단독 화면은 회장단 예시 사용자를 주입해 권한 가드와 별개로 작성 화면을 검토할 수 있다.
- `EVT-TASK-02`의 공식 참고 문서·작업 결과물·검토 현황은 선택한 업무를 따른다. 결과물이 없는 업무에는 미제출 빈 상태를 표시한다.
- 구매 요청의 필요일은 오늘 이전 날짜를 선택·제출할 수 없다.

### 2026-07-21~23 변경 요약

**학생 명단·학생회비 납부 명단 업로드 분리**

- `ORG-07B`는 양식 다운로드 없이 기존 학생 명단 파일을 업로드하고 `파일 업로드 → 검증 결과 → 명단 반영` 순서로 진행한다. 이름·학번·단과대학·학부·학과·학년만 갱신하며 학생회비 상태는 건드리지 않는다.
- `ORG-07C`는 기준 학기의 전체 학생회비 납부자 명단을 별도로 업로드한다. 학생 기본 명단과 일치한 학생만 납부 상태를 갱신하며 기준 명단에 없는 학번으로 학생을 생성하지 않는다.
- 학생 기본 명단과 학생회비 명단은 갱신 시각·작성자를 따로 표시한다. 다른 학기 납부 상태와 과거 행사·참가 기록은 보존한다.
- 학생 명단 업로드·내보내기는 회장단, 학생회비 납부 명단 업로드는 재정부·회장단이 담당한다.

**메시지 기능 신설 (채택 확정)**

- `MSG-01` 방 목록·빈 상태, `MSG-02` 방 만들기, `MSG-03` 대화. 사이드바 최상위 메뉴로 `조직 관리` 다음에 배치.
- 방 만들기는 학생회 조직도를 그대로 사용한다. 부서 단위 선택과 개별 구성원 선택을 함께 하며, 부서 옆 돋보기로 부서원을 펼친다. 이름 검색은 결과가 있는 부서만 남기고 자동으로 펼친다.
- 방 이름은 선택 입력이다. 비우면 `○○ 외 N명` 규칙으로 자동 생성한다. 선택한 대상을 입력란에 자동으로 채우지 않으며, 선택 결과는 `구성원` 영역에서만 확인한다.
- 분류는 `일반` 또는 행사이며 목록을 묶는 기준으로만 쓴다. 행사 워크스페이스의 7개 탭은 바꾸지 않는다.
- 대화 화면은 파일 첨부와 이미지 썸네일, 인원 추가, 방 나가기를 제공한다. 메시지 첨부는 대화 공유용이며 정산 증빙이 아니다.
- 방 생성은 전 구성원이 할 수 있다. 공식 기록이 남는 절차가 아니므로 제한하지 않는다.

**재정 구조 재정의**

- 재정 도메인, 상태, 권한, 예산, 보완, 주문, 증빙 묶음과 미결정 사항의 단일 기준은 `docs/VADA_FINANCE_SPEC.md`다.
- 최상위 재정은 전체 현황 열람 공간이고, 구매 요청과 처리는 각 `행사 > 재정`에서 시작한다.
- 확정된 핵심 원칙은 `구매 요청으로 묶어서 제출 → 구매 품목별 검토·구매 → 같은 구매처·영수증 품목을 증빙 묶음으로 재구성`이다.
- 현재 재정 화면은 기준 문서와 완전히 일치하지 않으므로, 미결정 사항을 확정하기 전에는 추가 구현하지 않는다.

**끼룩이 (마스코트) — 검토안**

- `HOME-01K`는 홈에 끼룩이 브리핑을 얹은 검토안이며 `HOME-01`과 병존한다. 채택 여부는 미정이다.
- 끼룩이는 정보를 만들지 않는다. 홈이 이미 계산한 값을 문장으로 엮어 최대 2줄만 말한다.
- 우선순위: 지연 업무 → 담당자 미지정 → 읽지 않은 메시지 → 임박 일정 → 이번 주 일정.
- 톤 3단계: 지연·미지정은 사무적, 일반 알림은 담백, 평온·빈 상태만 친근하게. 경고 톤에서는 화자 표시의 느낌표를 뺀다.
- 표정 3종(`안녕`·`확인 중`·`생각 중`)은 캐릭터 시트에서 추출해 `public/kkiruk-*.png`에 두었다. 크롭본이라 배경이 투명하지 않다.
- 홈은 내 업무의 상위 공간이 아니므로 브리핑에서 개인 업무 건수를 말하지 않는다.

**권한 정리**

- 권한 판정은 헬퍼를 재사용한다. 화면에서 역할 조건을 직접 쓰지 않는다. 목록은 `VADA_PERMISSION_MATRIX.md`의 `구현 규칙` 절에 있다.
- 권한이 없으면 버튼을 비활성화하지 않고 노출하지 않는다.
- 권한자 전용 단독 화면은 검토 시 해당 역할 사용자를 주입한다(`AsPresident`, `AsFinanceManager`, `AsEventManager`).
- 조직 구조 설정(`ORG-02`)은 구조만 만드는 단계다. 아직 초대되지 않은 구성원을 배치하지 않으며 구성원 추가 버튼도 노출하지 않는다.
- 화면정의서의 역할 표기를 권한 매트릭스 어휘로 정규화했다. `학생회장`·`관리자`·`운영진`·`재정부원` 같은 미정의 용어는 쓰지 않는다.

### 행사 공통 탭

```text
개요 → 업무 → 문서 → 관련 회의 → 일정 → 인원 관리 → 재정
```

모든 공통 탭은 행사 워크스페이스 안에서 서로 이동한다. `관련 회의(EVT-MEET-01)`, `일정(EVT-SCHED-01)`, `문서(EVT-DOC-01)`는 행사 범위의 열람 화면이며, 회의 생성·일정·문서 편집 권한은 기존 담당 화면과 역할 규칙을 따른다. 행사 상태는 와이어프레임 로컬 상태로 `기획 중 → 진행 중 → 후속 정리 중 → 완료` 전환을 공유한다.

행사 공통 헤더는 모든 탭에 상태, 행사 업무의 지연·미배정·검토 필요 수로 계산한 건강도와 근거, 담당 부서·책임자, 행사일, 다음 미완료 업무를 표시한다. 기본 사용자(행사 참가자)는 열람과 협업 영역만 보고, 행사 운영 조직 관리자·회장단만 기본정보 수정 및 행사 상태 전환 행동을 본다. 개요의 `담당자 없는 업무`와 `확인 필요 참가자`는 각각 필터된 업무·참가자 목록으로 이어진다. 일정 탭은 원본(기본정보·회의·업무)과 담당자를 표시하는 통합 열람 화면이며, 행사 업무의 실제 마감일·상태·담당자가 즉시 반영되고 항목을 누르면 해당 업무 상세로 이동한다. 여기서 날짜를 중복 수정하지 않는다.

### 재정

재정 관련 확정 사항은 `docs/VADA_FINANCE_SPEC.md`를 단일 기준으로 사용한다. 이 절은 화면 검토용 사용자 예시만 유지한다.

- 재정부 예시: `김민준 · 재정부 · 부장`
- 일반 요청자 예시: `박해랑 · 운영부 · 부서장` (구매 요청·주문 취소 요청 권한 보유). 동명이인 학생 참가자는 `박해수 · 컴퓨터학부 2학년`으로 구분한다.
- 구매 요청 권한 보유자 예시: `김민석 · 홍보부 · 부서장`. `FIN-REQ-01B`에서 작성 화면을, 본인이 제출한 보완 요청 `REQ-002`를 기준으로 `FIN-SUP-01B`에서 재제출 화면을 검토한다.
- 기존 `docs/VADA_FINANCE_ITEM_STATUS.md`의 내용은 기준 문서로 통합했으며, 기존 링크 유지를 위한 안내 파일만 남긴다.
- 감사보고서 생성 기능은 추가하지 않는다.

**행사 재정 허브(EVT-FIN-01/01B) 하위 메뉴 (2026-08-01 확정)**

탭을 두 그룹으로 나눈다. `묶음(📦)`과 `개별(▪)`의 경계를 시각적으로 항상 구분한다.

```text
행사 재정
 ├ 일반 구성원·부서장 → 품목 현황만 (본인 요청은 내 구매 요청 MY-REQ-01에서)
 └ 재정부
     ├ 작업 보드 — 진행 중 업무 처리 (칸반)
     │   ├ 품목 현황      (전 구성원 공용)
     │   └ 처리 단계      (7개 업무 영역 하위 탭: 요청 검토·구매 준비·물품 배송·수령·대여 이행·용역 이행·환불·증빙)
     └ 기록 — 요청·묶음 단위 열람 (건수 배지, 재정부 전용)
         ├ 구매 요청      ▪ 요청 단위 (취소 품목도 보존)
         ├ 승인 묶음      📦 선진행 동의된 승인 품목 묶음 (파생·읽기 전용)
         └ 증빙 묶음      📦 구매처·영수증 기준 실행분 재구성 (저장 레코드)
```

- **기록 그룹(구매 요청·승인 묶음·증빙 묶음)과 처리 단계는 재정부 전용**이다. 일반 구성원·부서장에게는 품목 현황만 보이고, 본인 요청은 내 구매 요청(MY-REQ-01)에서 열람한다(기준 문서: 증빙 아카이브 원본은 재정부, 일반은 확정 결과만).
- **품목 현황**에는 `전체 요청 / 내 요청` 필터가 있어 본인이 요청한 품목만 볼 수 있다.
- **승인 묶음**은 저장하지 않고 요청별로 파생해 보여 준다. 요청 취소·미동의 품목은 자동 제외된다.
- **증빙 묶음**은 `EvidenceBundle` 레코드로 저장한다(`AppContext.evidenceBundles`). `FIN-EVID-01`에서 증빙 묶음을 완료하면 구매처·결제·영수증·실제 지출·담긴 실행분이 레코드로 남아 `기록 > 증빙 묶음`에서 다시 열람된다. 서로 다른 요청·승인 묶음의 실행분도 같은 거래면 한 묶음에 담긴다.
- **품목 단위 요청 취소**: 요청자(재정부·부서장 중 본인)는 주문 완료 전 개별 품목을 `FIN-REQ-02`에서 사유와 함께 취소한다. 취소 품목은 `구매 요청`(요청 아카이브)에 보존되고 승인 묶음·활성 칸반·현재 집계에서는 자동 제외된다.

## 회의 화면 목록

### 목록과 생성

- `OPS-MEET-01A` 전체 회의 — 일반 참가자
- `OPS-MEET-01B` 전체 회의 — 진행 권한자
- `OPS-MEET-01C` 전체 회의 — 회의 생성 가능(회장단·부서장)
- `OPS-MEET-01D` 전체 회의 — 미참가자
- `OPS-MEET-02` 회의 생성·수정

`01B`와 `01C`는 권한 축을 분리한 화면이다.

- `01B`: 회의별 진행 권한에 따른 시작·진행·정리만 제공하며 `새 회의 만들기`는 노출하지 않는다.
- `01C`: 회장단·부서장에게 `새 회의 만들기`를 제공한다. 기존 회의의 수정·취소·권한 관리는 해당 회의의 생성자인 경우에만 가능하다.

### 예정 회의

- `OPS-MEET-03A` 예정 회의 상세 — 일반 참가자
- `OPS-MEET-03B` 예정 회의 관리 — 회의 생성자
- `OPS-MEET-03C` 예정 회의 상세 — 진행 권한자

### 진행 권한

- `OPS-MEET-04B` 진행 권한 관리 — 회의 생성자용

진행 권한자용 읽기 전용 현황(구 `OPS-MEET-04A`)은 별도 화면 없이 `OPS-MEET-03C`의 참가자 카드에 인라인 읽기 전용으로 통합되었다.

연결:

- `03C → 진행 권한 확인 (인라인 읽기 전용)`
- `03B → 진행 권한 관리 → 04B`

진행 권한자는 회의를 시작·종료하고 안건을 진행할 수 있지만 다른 사람의 권한을 변경할 수 없다.

### 진행 중

- `OPS-MEET-05A` 진행 중 회의 — 일반 참가자
- `OPS-MEET-05B` 진행 중 회의 — 진행 권한자

2열 구조:

- 왼쪽: 선택한 안건의 넓은 회의록 문서
- 오른쪽: 전체 안건과 참가 현황

각 안건은 하나의 데이터 단위로 다음 네 영역을 가진다.

```text
안건
→ 논의 내용
→ 결정사항
→ 후속 업무
```

결정사항과 후속 업무를 회의 전체 단위의 별도 목록으로 분리하지 않고 원래 안건에 귀속시킨다.

### 종료와 정리

- `OPS-MEET-06A` 정리 중 회의 — 일반 참가자
- `OPS-MEET-06B` 회의록 정리 — 진행 권한자

`06B` 구조:

- 왼쪽: 회의 중 작성한 안건별 전체 회의록
- 오른쪽: 같은 안건의 결정사항과 후속 업무 정리 패널

결정이 없으면 `결정사항 없음`, 후속 업무가 필요 없으면 `후속 업무 없음`을 명시한다.

모든 안건에 `결정사항 또는 없음`, `후속 업무 또는 없음`이 표시되기 전에는 `정리 완료` 버튼을 활성화하지 않는다. AI 회의 전체 요약은 선택 사항이므로 작성하지 않아도 정리 완료를 막지 않는다.

### 완료와 취소

- `OPS-MEET-07` 완료 회의록 — 참석자
- `OPS-MEET-08` 회의 요약 확인 — 불참자
- `OPS-MEET-09` 취소된 회의 상세

- `OPS-MEET-D02` 회의 종료 확인

## 회의 역할과 상태

역할:

- 일반 참가자
- 진행 권한자
- 회의 생성자·관리자

상태:


예정 회의는 취소할 수 있다.

버튼:

- 예정·진행 권한자: `회의 시작`
- 진행 중·미참가: `회의 참가`

- 정리 중·진행 권한자: `회의록 정리`
- 완료·참석자: `회의록 보기`

- `진행 중` 상태에서 초대된 사용자가 `회의 참가`를 누르면 참석 처리
- 예정 상세 열람과 완료 회의록 열람은 참석이 아님
- 불참자가 요약을 확인해도 참석으로 바뀌지 않음
- 회의를 시작한 사용자는 자동 참석 처리
- 첫 참가 시각만 기록
- 지각·중도 퇴장 판정은 아직 구현하지 않음

종료:

```text

```

확정된 구현 원칙:

- 안건별 회의 정리본을 바탕으로 AI가 전체 요약 초안을 생성
- AI가 공식 결정, 담당자, 기한이나 후속 업무를 임의 생성하면 안 됨
- 사용자가 초안을 검토·수정한 뒤 최종 승인
- 원본 회의록 변경 시 요약이 오래된 상태임을 경고
- AI 실패 시 수동 작성 가능
- AI 기능이 없어도 정리 완료를 막지 않음

구현 상태:

1. 생성 전: `AI로 전체 요약 만들기`
2. 생성 후: `AI 생성 초안`과 수정 가능한 요약
3. 생성 실패: 원본 보존 안내와 다시 시도·직접 작성
4. 원본 변경 후: 다시 생성 또는 직접 검토 안내
5. 최종 확인: 검토자와 검토 시각
