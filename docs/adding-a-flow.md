# 흐름 하나를 서버에 붙이는 차례

**이 문서의 목적은 판단을 줄이는 것이다.** 화면이 부르는 자리 백예순이 남았는데 한 줄로만
갈 수는 없다. 여럿이 나란히 붙이려면 (1) 서로의 글을 안 건드리고 (2) 같은 순서로
움직여야 한다. 여기 적힌 것이 그 순서다.

앞선 세 흐름(들어오기 · 밖에서 오는 사람 · 조직 보기)에서 실제로 밟은 차례이고,
그때 **제품 판단이 0번** 필요했다 — 명세가 이미 답을 갖고 있었기 때문이다. 판단이
필요한 자리는 아래 '멈추는 자리'에 모아 두었다.

## 0. 무엇이 남았는지 센다

```
node scripts/left.mjs        # 영역별로 몇이 남았나
node scripts/left.mjs 회의   # 그 영역에 남은 것의 이름
npm --prefix apps/api test -- src/app.test.ts    # 계약 219자리 중 몇 개가 답하는지
```

## 1. 이미 답하는 자리가 있는지 먼저 본다

`apps/api/src/handlers/`를 훑어라. **서버가 이미 답하는데 화면이 개발용 응답을
그리는 자리가 있다.** 조직 보기에서 12개, 행사에서 8개가 그랬다 — 그것부터 하면
서버를 한 줄도 안 짓고 진도가 난다.

그런 자리는 3번으로 바로 간다.

## 2. 서버를 짓는다 — **눈금부터**

1. `apps/api/src/<영역>/<이름>.test.ts`에 검사를 먼저 쓴다. **빨간 것을 확인한다.**
   확인하지 않으면 그 검사가 무엇을 지키는지 아무도 모른다.
2. `apps/api/src/<영역>/<이름>.ts`에 답을 짓는다.
3. `apps/api/src/handlers/<영역>.ts`에 자리를 매단다. 열쇠는 계약의 `operationId`다.
   - 영역 파일이 없으면 만들고 `handlers/index.ts`에 두 줄 더한다.
   - **다른 영역 파일을 가져오지 마라.** 검사가 막는다(`handlers/index.test.ts`).

표에 담을 것과 읽을 때 만들 것을 가르는 규칙은 `db/schema.ts` 머리에 있다.
**완성된 글·색 이름·센 값·판정은 열이 아니다.**

## 3. 화면을 잇는다 — **증거와 함께**

1. `apps/vada-web/src/data-sources/served/<영역>.ts`에 열쇠를 올린다.
   - 파일이 없으면 만들고 `served.ts`에 두 줄 더한다.
2. `apps/vada-web/src/data-sources/<영역>.server.test.tsx`에 통합 검사를 쓴다.
   진짜 서버 + 진짜 저장소(PGlite)에 대고 **화면을 그린다.**

**쓰기는 `runMutation`으로 보낸다.** 서버를 직접 부르면 그 사이의 코드가 통째로
빠지고, 이 저장소에서 두 번 값을 치른 결함이 정확히 그 사이에 있었다. 검사가
막는다(`served-evidence.test.ts`).

**자리 단위로 가릴 수 있게 둘러라.** 한 화면이 여러 자리를 읽는데 그중 하나가 아직
안 지어졌으면 **그 자리만** 가려야 한다 — 하나 때문에 화면이 통째로 닫히면 지어 놓은
나머지를 아무도 못 본다(홈이 그랬다). 화면이 블록마다 따로 읽으므로 그 블록을
`<Built what="...">`로 감싸면 된다. 안 두른 화면은 바깥 그물(`SourceGate`)이 통째로
가린다 — 잊어도 가짜가 새지는 않는다.

**읽기는 `<ScreenRouter>`를 그려서 잰다.** 그릇에 손으로 값을 먹이면 거르개가 달린
화면이 서버에 붙는 순간 터지는 것을 못 본다 — ORG-07A가 그렇게 붙어 있었다.

## 4. 재고 민다

```
npm run check:fast     # 계약 · 앱 · api · 명세
npm run e2e            # 브라우저. 미는 것은 CI가 다시 본다
```

커밋은 **생각 하나에 하나**. 제목 50자 이내, 본문은 **왜**를 적는다.

## 멈추는 자리 — 여기서는 사람에게 묻는다

아래는 명세가 답을 갖고 있지 않은 것들이다. **지어내지 말고 물어라.**

| 무엇 | 왜 못 정하나 |
| --- | --- |
| 아카이브를 어떻게 발행하나 | `record.archive.requestReview`가 '발행이 아니다'라고 못 박았고 발행 단추는 안 그려졌다 |
| 회의 진행 방식·업무 우선순위·안건 소요 시간의 목록 | 디자인이 펼친 목록을 안 그렸다. 표는 글로 담아 두었다 |
| 품목 카테고리·구매 유형 | 명세가 '조직이 정한다'는데 정하는 화면이 없다 |
| 문서의 갈래·반영 여부·쓸 예정인 때 | 문서를 만들거나 고치는 화면이 명세에 없다. 지금은 아는 사실에서 읽는다(`documents/labels.ts`) |

### 이미 정한 것 (2026-09-05) — 다시 묻지 마라

| 무엇 | 정한 것 |
| --- | --- |
| 예산을 누가 언제 넣나 | **아직 안 정한다. 재정은 뒤로 미룬다.** 34자리가 전부 0원 위에 서므로 붙여도 사람이 볼 것이 없다. 표는 자리를 비워 두고 기다린다 |
| 장부에 줄이 어떻게 드나 | 같은 사정. 재정과 함께 미룬다 |
| 메시지 방에 무엇이 있나 | **뺀다.** 와이어프레임이 빈 화면만 그려 `message.rooms`의 조각이 `id` 하나뿐이다. 그림을 그려 명세를 만드는 길은 열려 있다(SIGN-IN이 그랬다) — 다만 지금은 아니다 |
| 회의를 시작하면 첫 안건이 열리나 | **열린다.** 명세가 거기까지 말하지 않았고 사람이 정했다. 시작을 누르고 다시 '다음 안건 시작'을 누르는 것은 같은 몸짓을 두 번 시키는 일이다 |

명세가 **`pending`**이라 적어 둔 동작도 같다. 그것은 '아직 안 정했다'는 뜻이고,
지금 지으면 그 모양을 짓는 것이 아니라 **정하는 일**이 된다.

## 재는 법

- **진도**: `apps/api/src/app.test.ts`가 계약 219자리 중 몇이 답하는지 찍는다.
- **가짜와 진짜**: `apps/vada-web/src/data-sources/served.test.ts`가 읽기·쓰기를 센다.
- **울타리**: `apps/api/src/db/fences.test.ts`가 조직을 든 두 표의 이음매를 본다.
- **값**: `apps/api/src/db/schema.test.ts`가 명세의 고정 목록과 표의 갈래를 견준다.
- **겹침**: `apps/api/src/handlers/index.test.ts`가 두 영역이 같은 자리를 답하는지 본다.

## 나란히 갈 때 부딪히는 자리

가른 뒤에 남은 것은 셋뿐이다. 하나같이 **두 줄**이라 병합이 쉽다.

| 파일 | 무엇 |
| --- | --- |
| `apps/api/src/handlers/index.ts` | 영역을 하나 더할 때 가져오는 줄과 펼치는 줄 |
| `apps/vada-web/src/data-sources/served.ts` | 같은 자리 |
| `specs/figma/vada-wireframe/openapi.json` | 명세를 고쳤을 때만. 부딪히면 `npm run openapi`로 다시 내면 된다 |

`app.test.ts`의 자리 수는 **래칫**이라 부딪히지 않는다 — 줄지 않는 것만 지킨다.
