# MY-01(내 업무) 파일럿

두 번째 데스크톱 화면이다. HOME-01K에서 처음 연 대시보드 어휘
(`itemList`·`data-sources.json`·`action.pending`)가 사례 하나로만 검증돼 있었고,
이 화면이 그것을 두 번째로 시험한다. 수렴 판단의 재료가 여기서 나온다.

## 1. 추출기가 절반을 틀렸다

초안 7개 중 쓸 수 있었던 것은 검색 입력 하나뿐이다.

| 디자인 | 초안이 읽은 것 | 실제 |
| --- | --- | --- |
| 사이드바 로고 'V' | `itemList` (title: "V") | **셸이다. 화면의 요소가 아니다** |
| 상태 칩 3개(지연·해야 할·검토 필요) | 못 봄 | `summary` |
| 탭 3개 | `button` 3개 | `select` 하나 |
| 필터 드롭다운 2개 | 못 봄 | 자식 없는 빈 프레임(기존 한계) |
| 검색 입력 | `input` | 맞음 |
| "확인 필요" + 업무 카드 2개 | `button` 2개 | `itemList` |

가장 나쁜 것은 첫 줄이다. **셸이 화면 명세로 새어 들어왔다.** HOME-01K에서는
셸을 손으로 뺐기 때문에 드러나지 않았고, 화면이 늘어날수록 화면마다 되풀이된다.

## 2. 화면 셸 — 사례가 둘이 되어 일반화했다

HOME-01K와 MY-01의 사이드바는 텍스트까지 동일하다.

```
V | Vada | 소프트웨어융합대학 | 홈 | 내 업무 | 운영 | 재정 | 기록 | 조직 관리 | 메시지 | 박해랑 | 운영부 · 부원
```

처분: wireframe 단위 `shell.json` 신설. 화면마다 복사하면 원본이 화면 수만큼
생긴다. 헤더의 문구는 각 화면의 `meta`가 갖는다 — 셸은 자리만 정한다.
추출기는 `shell.json`의 `design.excludeNodeNames`를 받아 그 노드를 건너뛴다.
어느 노드가 셸인지는 wireframe이 아는 것이므로 파이프라인이 이름을 갖지 않는다.

헤더는 셸이 아니었다. HOME-01K의 헤더에는 MY-01에 없는 것이 둘 더 있다
(`제12대 … 운영 현황`, `2026년 1학기`). 지금은 두 화면 모두 `meta`가 가진 것만
그리고, 그 둘은 어디에도 담기지 않았다. 사례가 하나뿐이라 미룬다.

## 3. 탭은 새 유형이 아니다

세 갈래를 놓고 판단했다.

| 탭에 필요한 것 | `select`에 있나 |
| --- | --- |
| 고정 선택지 3개 | `optionsSource` static |
| 라벨 없음 | `label` 선택 사항(ORG-02 선례) |
| 하나만 선택 | select의 본질 |
| 기본값 | `initialValue` |
| 펼쳐 보임 | `presentation: choiceGroup` |
| 선택지별 개수 | **없음** ← 유일한 구멍 |

`tabs`를 만들지 않은 이유는 셋이다.

1. **탭만 다르다고 볼 근거가 없다.** "탭은 보기를 바꾼다"가 이유라면 바로 옆
   필터 드롭다운도 같다. 제출되느냐 거르느냐는 값이 어디로 가느냐의 문제이지
   컨트롤의 성질이 아니다.
2. **시각은 design이 갖는다.** 탭 모양이냐 카드 모양이냐는 INV-01의 묶음 상자,
   HOME-01K의 진행률 막대와 같은 판정이다.
3. **유지보수.** `tabs`는 선택지 참조·`initialValue`·라벨·비활성·검증기 교차
   검사·렌더러·준수 테스트를 전부 복제해야 하고, 새로 만든 개수 자리도 두 곳에
   넣어야 한다. 앞으로 select에 무엇을 더할 때마다 "탭에도?"를 물어야 한다.

대가는 하나 있다. **같은 `presentation`이 두 화면에서 다르게 그려진다** —
ORG-02는 라디오 카드, MY-01은 탭 줄이다. 근거는 design에 있는데 구현이 그것을
자동으로 읽지 않으므로 화면마다 사람이 정한다. (A)가 아니라 (C)로 본다:
시각을 명세에 넣지 않기로 이미 정했기 때문이다.

## 4. 요구되는 신규 계급

| # | 계급 | 근거 | 처분 |
| --- | --- | --- | --- |
| 1 | 화면 셸 | HOME-01K + MY-01, 텍스트까지 동일 | **`shell.json` 신설** |
| 2 | 선택지별 개수 | 탭 배지 2/2/0이 서버 값 | **`select.optionCounts` 신설** |
| 3 | 목록의 조회 인자 | 탭·검색어가 목록을 거른다 | **`itemList.params` 신설** |
| 4 | 목록 항목의 이동 | 업무 카드를 누르면 상세로 간다 | **`itemList.itemAction` 신설** |

| 사이클 | 신규 계급 |
| --- | --- |
| ORG-02 | 1 |
| ORG-01 | 2 |
| INV-01 | 2 |
| HOME-01K | 3 |
| **MY-01** | **4** |

**수렴하지 않았다.** 다만 성격이 다르다 — HOME-01K의 셋은 새 어휘였고(무엇을
표현할 수 없었다), MY-01의 넷 중 셋은 **이미 있는 것을 잇는 자리**다.
`params`는 `select.optionsSource.params`와 같은 모양이고, `itemAction`은
`button.action`과 같은 규칙이며, `optionCounts`는 `dataSourceKey`를 하나 더
가리킬 뿐이다. 새 개념은 `shell.json` 하나다.

되풀이해 나타난 것은 **"화면의 값이 서버에서 온다"**의 갈래다. HOME-01K에서
`data-sources.json`으로 열었고, MY-01은 그것을 세 방향으로 넓혔다(인자·항목별
동작·선택지 곁의 값). 다음 화면에서 이 셋이 그대로 쓰이고 새 자리가 필요 없으면
그것이 첫 수렴 신호다.

## 5. 새 자리는 전부 조용히 통과했다

셋을 열고 나서 일부러 틀린 값을 넣어 봤다.

| 넣은 값 | 검증기 |
| --- | --- |
| `optionCounts.dataSourceKey: "nope.missing"` | 통과 |
| `params: { bogusParam: "bogusField" }` | 통과 |
| `itemAction.targetScreenId: "ZZZ-99"` | 통과 |

전부 **틀려도 화면이 멀쩡히 도는 값**이다(배지가 비고, 목록이 안 걸러지고,
이동이 조용히 죽는다). 교차 검사 5건을 넣어 막았다. 이동 대상 검사는
`spec.type === "button"` 조건을 떼고 '이동을 선언한 요소'로 넓혔다 — 새 유형이
이동을 가질 때마다 조건을 고치지 않게 하려는 것이다.

## 6. AI 읽기 마찰

| 무엇을 | 어디서 | 왜 명세에 없었나 | 추측했나 |
| --- | --- | --- | --- |
| 상태 칩·검색·카드의 아이콘 | `figma.design.json`의 assetRef | (C) 시각은 design이 갖는다 | 아니오 |
| 탭을 탭 줄로 그릴지 카드로 그릴지 | 디자인 스크린샷 | (C) 위와 같다 | 아니오 |
| 필터 2개의 선택지 | 사용자에게 질문 | (A) 빈 Dropdown은 원리적으로 유도 불가 | 아니오(이번엔 제외) |
| 업무 카드의 '다음 행동'·'연결 문서' 라벨 | 디자인 텍스트 | (C) 고정 카피는 design에 있다 | 아니오 |
| 다른 탭의 업무 목록 | 없음 — 지어냄 | (C) 개발용 mock의 몫 | **예** |

**(A) 1건**(필터 선택지, 기존에 알던 한계). HOME-01K에서 (A)가 처음 0이 아니게
된 뒤 이번에도 0이 아니지만, 새 종류는 아니다.

마지막 줄이 이번의 유일한 추측이다. 디자인은 '해야 할 업무' 탭만 그리는데
배지는 '진행 중인 업무 2건'이라고 말한다. 그 2건이 무엇인지는 어디에도 없다.
처분: mock의 탭 건수를 **업무 목록에서 세도록** 해서 목록과 배지가 어긋날 수
없게 했다. 지어낸 것은 행의 내용뿐이고 개수는 데이터에서 나온다.

## 7. 셸의 자산은 공유되지 않는다

셸은 `shell.json` 하나로 모았지만 사이드바 아이콘 7개는 화면마다 따로 저장된다
(HOME-01K와 MY-01이 같은 아이콘을 다른 nodeId로 갖는다). 자산은
`screens/<screenId>/assets/`에만 있고 wireframe 단위 자산 저장소가 없다.

지금은 셸을 글자만으로 그린다. 화면이 늘어날수록 같은 아이콘이 화면 수만큼
쌓이므로 wireframe 단위 자산 자리가 필요하다. 사례가 둘뿐이라 미룬다.

## 8. 스크린샷 판독이 잡은 것

- 첫 판독에서 아이콘이 하나도 없었다. HOME-01K가 `FigmaAsset`으로 그리는
  선례를 만들어 두었는데 이 화면이 따르지 않았다 — 준수 테스트가 자산을 보지
  않기 때문이다(자산은 시각이라 스펙 준수의 대상이 아니다). 판독이 없었으면
  그대로 넘어갔다.
- `내 담당 업무` 버튼(HOME-01K)이 `navigate`로 바뀌었는데 구현이 `pending`만
  그리고 있었다. e2e가 이동 실패로 잡았고, `PendingLink`를 `ActionLink`로 넓혀
  두 종류를 모두 소비하게 고쳤다. **이름이 한 가지 경우만 가리키면 그 이름이
  다른 경우를 막는다.**

## 9. 흐름이 닫혔다

`HOME-01K → 내 담당 업무 → MY-01 → 셸 메뉴 홈 → HOME-01K`.
대시보드끼리 오가는 첫 왕복이다. HOME-01K의 `pending` 버튼 4개 중 하나가
진짜 이동이 됐다.
