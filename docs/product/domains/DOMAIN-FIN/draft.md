# 재정

## 목적과 경계

- **목적**: 행사에 필요한 구매 요청부터 품목별 검토, 구매 실행, 증빙과 실제 지출 반영까지의 재정 기록을 일관된 처리 단위와 이력으로 관리한다.
- **포함**: 구매 요청·품목 검토·승인 묶음·구매 실행분·증빙 묶음·예산 예약과 실제 지출·재정 기록 조회
- **인접 도메인**: 모든 구매 요청은 하나의 행사에 연결된다. 행사 자체의 생성·운영 규칙은 행사 도메인이 소유한다.
- **현재 제외**: 감사보고서 생성 기능과 학교 공식 감사 지침이 있어야 확정할 수 있는 필수 증빙 규칙

## 핵심 용어와 처리 단위

| 용어 또는 단위 | 의미 | 생성되는 시점 | 원본으로 소유하는 사실 |
| --- | --- | --- | --- |
| 구매 요청 | 한 행사의 하나 이상 구매 품목을 함께 제출하는 행정적 묶음 | 요청 제출 | 행사·요청자·요청 부서·제출 내용과 이력 |
| 구매 품목 | 요청 안에서 독립적으로 검토·승인·보완·반려되는 단위 | 요청 작성 중 품목 추가 | 검토 상태·승인 범위·예산 예약 |
| 구매 승인 묶음 | 같은 시점에 구매 진행이 허용된 승인 품목의 구성 불변 기록 | 승인 품목의 진행이 확정될 때 | 포함 품목·생성자·생성 시각·생성 사유 |
| 구매 실행분 | 주문부터 수령·이행·취소·재주문·증빙까지 일관된 상태로 처리하는 최소 단위 | 승인 묶음에서 실제 구매 진행을 시작할 때 | 주문·수령·이행·취소·환불·재주문·증빙 상태 |
| 증빙 묶음 | 실제 거래·영수증·결제 관계에 따라 실행분을 다시 묶은 단위 | 재정부가 증빙 정리를 시작할 때 | 연결 대상·자료·직접 금액·조정 내역·완료본과 정정본 |
| 실제 지출 | 실행분 직접 금액에 증빙 조정액을 더해 증빙 완료로 확정한 금액 | 증빙 완료 | 확정 금액과 예산 반영 이력 |
| 아카이브 | 기존 처리 단위와 이력을 조회하는 읽기 관점 | 해당 기록 존재 시 | 별도 상태를 소유하지 않음 |

## 불변 관계

- 구매 요청은 정확히 하나의 행사에 속하고 하나 이상의 구매 품목을 포함한다.
- 같은 구매 요청의 품목은 서로 다른 검토 결과와 진행 속도를 가질 수 있다.
- 구매 요청과 구매 승인 묶음에는 전체 진행을 대표하는 원본 상태를 두지 않는다.
- 구매 품목의 구매 진행 결과는 연결된 구매 실행분의 원본 상태에서 계산하며 직접 수정하지 않는다.
- 증빙 아카이브를 비롯한 아카이브는 새 처리 단위가 아니라 기존 기록의 조회 관점이다.

## 역할과 능력 경계

| 행위자 또는 능력 | 가능한 행동 | 열람 범위 | 제한 |
| --- | --- | --- | --- |
| 일반 부원 | 재정 현황·사용 내역·행사 재정·구매 요청 조회 | 대표 상태와 확정 실제 지출 중심 | 구매 요청 작성과 재정 처리 불가; 구매 요청 상세 범위는 승인 전 재확인 필요 |
| 부서장 | 구매 요청 작성, 본인이 제출한 요청의 보완·재제출 | 일반 부원 범위와 본인 요청의 과거 보완·검토 이력 | 승인·보완 요청·반려 등 재정 처리 불가 |
| 재정부 | 구매 요청 작성과 본인 요청 보완, 예산·검토·주문·수령·환불·증빙 처리 | 모든 구매 요청 이력과 증빙 아카이브 전체 원본 | 자기 요청 검토도 허용하지만 동일한 처리 기록 필수 |

권한이 없는 사용자에게 처리 버튼을 비활성 상태로 보여주지 않고 노출하지 않는다. 실제 서버 권한 경계는 아직 재정 권한 계약으로 생성되지 않았으므로 구현 전에 계약 리비전이 필요하다.

## 상태 소유와 파생 표시

| 대상 | 원본으로 소유하는 상태 | 파생되는 표시 또는 집계 | 직접 수정 금지 항목 |
| --- | --- | --- | --- |
| 구매 요청 | 제출 관계와 요청 이력 | 소속 품목별 현재 결과 목록 | 요청 전체 통합 진행 상태 |
| 구매 품목 | 검토 상태·승인 범위·예산 예약 | 일반 사용자 대표 상태, 재정부 처리 단계 | 구매 진행 집계와 보드 위치 |
| 구매 승인 묶음 | 구성과 생성 기록 | 소속 품목·실행분 결과 | 묶음 전체 진행 상태 |
| 구매 실행분 | 주문·배송·수령/이행·취소·환불·증빙 상태 | 품목 진행 결과와 역할별 표시 | 계산된 대표 상태와 칸반 위치 |
| 증빙 묶음 | 작성·완료·정정 상태와 금액 | 증빙 업무 위치와 실제 지출 결과 | 완료본 덮어쓰기 |

- 일반 사용자에게는 필요한 조치·예외를 우선하고, 그 외에는 마지막으로 달성한 결과를 표시한다.
- 재정부에는 현재 남은 최우선 미완료 업무를 표시한다.
- 같은 처리 단위의 활성 카드는 하나의 보드에서 한 영역·한 열에만 둔다.
- 역할별 표시와 칸반 위치는 공통 원본 상태와 관계에서 계산하며 별도 상태로 저장하지 않는다.

## 도메인 공통 불변 규칙

- 요청은 여러 품목을 함께 제출하지만 검토 이후에는 품목과 실행분별로 독립 처리한다.
- 금액만을 이유로 구매 요청 입력 항목을 숨기거나 생략하지 않는다.
- 사용 가능 예산을 초과한 요청도 제출할 수 있지만 승인할 수 없다.
- 요청 전체·승인 묶음 전체에 `부분 승인`, `구매 중`, `정산 중` 같은 임의의 통합 상태를 만들지 않는다.
- 감사보고서 생성 기능은 현재 메뉴·버튼·문서·내보내기 어떤 형태로도 추가하지 않는다.
- 보류 사항은 확정 기능·상태·화면으로 구현하지 않는다.

## 기록과 이력 원칙

- 모든 원본 상태 전환에 처리자·처리 시각·이전 상태·변경 상태·처리 사유를 남긴다.
- 계산된 품목 집계와 칸반 위치에는 별도 처리자를 만들지 않고 계산 원인이 된 원본 기록을 추적한다.
- 보완 제출본은 수정 전후 값·첨부자료·처리자·시각을 회차별 불변 기록으로 보존한다.
- 완료·정정·취소 기록을 직접 덮어쓰거나 삭제하지 않는다.
- 완료 후 수정이 필요하면 이전 완료본을 남기고 정정본과 변경 이유를 추가한다.
