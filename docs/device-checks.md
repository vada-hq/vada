# 실제 기기 확인

휴대폰에서만 드러나는 동작을 실제 기기로 확인한 기록이다. 다시 만들기(`docs/superpowers/specs/2026-10-19-rebuild-design.md`)의 덩어리마다, 그리고 리허설 때 이어 쓴다.

결과는 됨 / 안 됨 / 해당 없음으로 적는다. 안 됐으면 무엇이 보였는지 적는다. 화면은 찍어 두되 커밋하지 않는다.

## 휴대폰 길 (덩어리 1)

절차는 `docs/superpowers/specs/2026-10-19-mobile-path-design.md`의 '흐름'을 따른다. 확인 전에 vada-m1에 휴대폰 길이 배포되어 있고, Render에 알림 열쇠 세 값이 있어야 한다. 안 됐을 때 무엇을 바꾸는지는 spec의 '실제 기기 확인' 표를 따른다.

### 기기

| 날짜 | 기기 | OS | 카톡 | 넘어간 브라우저 | 확인한 사람 |
|---|---|---|---|---|---|
| 2026-10-19 | Windows 데스크톱 | Windows 11 | 해당 없음 | Chrome | 성욱 |
| 2026-10-19 | 아이폰 | | | 사파리 → 홈 화면 앱 | 성욱 |

### 아이폰

| 단계 | 결과 | 보인 것 |
|---|---|---|
| 1. 카톡 링크를 누르면 사파리로 넘어간다 | | |
| 2. 사파리에서 Google로 로그인한다 | | |
| 3. '휴대폰 알림'의 안내대로 홈 화면에 추가한다 | 됨 | 홈 화면 앱으로 열었다(알림에 'from VADA'로 보인다) |
| 4. 홈 화면의 VADA로 열면 로그인된 채 열린다 | 됨 | 로그인된 작업 공간이 열렸다 |
| 5. '알림 켜기'를 누르고 허락한다 | 됨 | "이 기기에서 알림을 받아요." |
| 6. 시험 알림이 잠금 화면에 뜨고, 누르면 VADA가 열린다 | 됨 | 앱을 연 채 배너로 받았다: "시험 알림이에요. 누르면 VADA가 열려요." 잠금 화면과 누르기는 따로 적지 않았다 |
| 7. 로그아웃 뒤 홈 화면 앱 안에서 'Google로 로그인'(앱 안 창) | | |
| 7-1. 안 되면 '다른 방법으로 로그인' | | |

### 데스크톱 Chrome

배포 직후 휴대폰보다 먼저, 알림 열쇠와 알림 서버 길이 맞는지 본다.

| 단계 | 결과 | 보인 것 |
|---|---|---|
| 1. 로그인 뒤 종 버튼에서 '알림 켜기'를 누르고 허락한다 | 됨 | "이 기기에서 알림을 받아요." |
| 2. '시험 알림 보내기'를 누르면 5초 뒤 Windows 알림이 뜬다 | 됨 | "VADA 시험 알림이에요. 누르면 VADA가 열려요." |
| 3. 알림을 누르면 VADA 창이 앞으로 온다 | | |

### 배포 전에 먼저 해 본 것

휴대폰 길을 배포하기 전에, 가장 막히기 쉬운 단계(카톡 → 바깥 브라우저 → Google 로그인)를 그때 배포돼 있던 vada-m1로 먼저 해 봤다.

| 날짜 | 기기 | 단계 | 결과 | 보인 것 | 확인한 사람 |
|---|---|---|---|---|---|
| 2026-10-19 | 아이폰 | 카톡 '나와의 채팅'에 보낸 vada-m1 링크를 누른다 | 됨 | 바깥 브라우저로 넘어갔다 | 성욱 |
| 2026-10-19 | 아이폰 | 넘어간 브라우저에서 Google로 로그인한다 | 됨 | 로그인됐다 | 성욱 |
