# 대화 → 구매 후보 → 구매 요청 기획

작성: 2026-10-10
상태: 방향·핵심 결정 채택(P-01~P-06) · 발전 주제 4건 채택(P-07~P-10) · 메시지 방·구매 후보·요청 흐름 채택(P-11~P-19, 2026-10-14) / 발전 주제 보류 2건 / 결정 사항 5건 미결정(§6) / 대여·용역의 대화 연결 보류

## 1. 문서의 역할

행사 대화에서 오간 상품 링크를 구매 후보로 모으고, 그중 살 것을 골라 구매 요청으로 만드는 흐름을 정한다. 다른 기획 문서와 같은 규칙을 따른다: **사용자가 확정한 것만 `채택`**, 나머지는 `제안`·`보류`·`미결정`으로 둔다.

## 2. 배경

- 개발 쪽 M1 프로토타입(`127.0.0.1:8765`, 사용자 첨부 화면 2장)이 행사 대화방에 올라온 쿠팡 링크를 읽어 `구매 후보` 탭에 모으는 모습을 보여 주었다. **이해를 돕는 참고 화면이며, 그대로 만들 필요는 없다**(사용자 발언).
- 와이어프레임에는 이미 쿠팡 링크로 구매 요청 품목 카드를 채우는 기능이 있다(`FIN-REQ-01B`, 커밋 `c3f85c0`): 품목명·판매처·배송비·배송 정보·옵션 전체 목록 불러오기, 옵션을 고르는 즉시 가격 확정.
- 메시지 화면(`MSG-01~03`)은 와이어프레임에 있으나 MVP 기준서 §5에서 제외되어 있다.
- 끼룩이는 별도 AI 비서로 쓰지 않고 자동화를 보여 주는 표시로만 쓴다(끼룩이 기획 K-01·K-02).

### 3.1 메시지 방·구매 후보·요청 흐름 — 채택(2026-10-14)

사용자가 M1 프로토타입 화면 2장(대화·구매 후보 탭)을 방향으로 제시하고 질문에 답해 정했다. 처음 만든 `재정 탭 맨 위 구매 후보` 안은 사용자 요청으로 되돌렸다("내가 생각한 방향성이 아니야").

| ID | 결정 | 근거(사용자 발언) |
|---|---|---|
| P-11 | **공간 메시지 = 공지방 + 부서방.** 행사·우리 학생회의 메시지 탭에 `공지방`(그 공간의 모든 구성원)과 `부서방`(그 공간 안의 내 부서 방)을 둔다. 메시지 탭을 열면 부서방부터 보인다. 방마다 안 읽은 수, 메시지 탭 배지는 두 방의 합. 메시지 탭에서는 행사 요약 줄(상태·주요 지연·담당·날짜)을 빼고 그 자리에 방 전환을 둔다(다른 탭은 유지) | "메세지 방을 늘릴게 … '공지방', '부서방'을 추가할게" · "메세지 방에서만 빼자" · "부서방부터 보이게 하자" · "우리 학생회도 같은 구조야" |
| P-12 | **방 전환과 구매 후보는 한 줄**: `공지방 · ○○부 방 · 구매 후보 N`. 구매 후보는 부서방의 후보 | "추천대로 할게" |
| P-13 | **부서방의 쇼핑 링크는 전부 자동으로 담는다.** 쿠팡 외 쇼핑몰도 담는다(쿠팡 외는 판매처만 채우고 가격은 직접). 쇼핑이 아닌 링크는 담지 않는다. 한 메시지에 링크가 여럿이면 후보도 여럿, 같은 링크가 다시 오면 `○○ · 시각 외 N번`으로 합친다 | "전부 자동으로 받는거야" · "부서방에서만 올린 링크를 담자" · "쿠팡이 아닌 쇼핑몰 링크도 자동으로 담을 수 있어. 쇼핑이 아닌 링크는 담지 않아" |
| P-14 | **공지방·사이드챗 링크는 담지 않고 `부서방으로 옮기기`만 둔다.** 옮긴 사람 이름으로 부서방에 다시 올리며 `옮겨 옴` 표시는 붙이지 않는다. 부서방에 올라가는 순간 후보로 담긴다 | "사이드챗에서는 링크를 담지 않아. 대신 … 부서방으로 옮겨 올 수 있는 기능" · "옮겨 왔다는 것은 붙일 필요는 없을 것 같아" |
| P-15 | **대화의 링크를 누르면 오른쪽에 `상품 정보` 패널**(사진·이름·옵션·가격·쿠팡에서 보기). 사이드챗이 열려 있으면 그 위에 덮어 열고, 닫으면 사이드챗으로 돌아온다 | "너의 추천대로 할게" |
| P-16 | **구매 후보 카드 = 구매 요청 카드.** 카드 좌상단 체크박스 하나. 체크하면 그 자리에서 펼쳐져 구매 요청 카드가 된다(별도 작성 화면으로 넘어가지 않음). 옵션은 기존 구매 요청 작성의 쿠팡 불러오기 기능으로 고르고(옵션 목록·가격 즉시 확정), 수량은 −/+. 펼친 카드에는 제목·구매 목적(대화와 상품명으로 끼룩이가 채운 초안, `끼룩이 초안 · 검토 필요`)과 필요한 날짜·우선순위(사용자 입력)가 있다. 예산 항목·구매 유형은 보이지 않는다(구매 유형은 일반 구매) | "체크박스를 클릭하면 자동으로 제목, 목적은 기존의 대화와 쿠팡 링크의 상품명을 토대로 자동으로 채워주고, 우선순위와 날짜는 사용자에게 입력을 받아" |
| P-17 | **여러 개를 체크하면 위로 모아 묶음 = 요청 1건.** 묶음 맨 위에 제목·구매 목적·필요한 날짜·우선순위를 한 번만 두고(제목·목적은 묶인 상품명과 대화로 끼룩이가 다시 씀), 묶음 안 카드는 같은 방식으로 펼쳐지되 상품 정보(옵션·수량·가격)만 보인다. 아래 `구매 요청하기` 옆에 선택한 품목의 합계 | "흩어져 있는 박스를 상단으로 모아서 그룹화" · "구매 요청 하기 옆에 선택한 물품들의 총 합한 가격" · 묶음 제목·목적은 "추천대로 할게" |
| P-18 | **제출하면 그 공간의 재정 칸반으로 간다.** 제출한 카드는 후보 목록에서 빠지고 `요청 완료 · REQ-xxx`와 `재정 칸반에서 보기`가 남는다. 대화 속 링크에도 `요청 완료 · REQ-xxx` | "제출 후에는 기존의 행사의 재정처럼 칸반에 담기는 거지 … 칸반으로 이동할 수 있는 버튼" · "맞아" |
| P-19 | **예산 항목은 요청자가 고르지 않고 재정부가 검토할 때 고른다.** 구매 후보 카드와 기존 구매 요청 작성(`FIN-REQ-01B`) 모두에서 뺀다. 재정부 검토(`FIN-REV-01`)에서 품목별로 고르며, 고르지 않으면 승인할 수 없다. 항목별 예약·초과 판정은 재정부가 고른 항목 기준. 구매 유형은 기존 작성 화면에 그대로 둔다 | "재정을 관리하는 것은 재정부다 보니까 요청자가 잘못 선택할 경우도 있다" · "전부 수정해줘" · "구매 유형은 빼지 않아" |

**권한(P-16·P-17)**

| 할 수 있는 일 | 누가 |
|---|---|
| 구매 후보 보기 | 그 부서방의 모든 구성원 |
| 옵션·수량 바꾸기(모두가 같이 보는 값) | 모든 구성원 |
| 체크해서 펼치기·묶기 | 모든 구성원 |
| 구매 요청 제출 | 부서장, 재정부(부원 포함), 회장단 |
| 펼친 카드의 제목·목적·날짜·우선순위 | 보이지만 제출 권한이 없으면 저장하지 않는다. 제출 버튼 자리에 `구매 요청은 부서장·재정부·회장단이 해요` |
| 예산 항목 지정 | 재정부(검토 시) |

구매 요청 작성 권한은 기존 `부서장·재정부`에서 회장단을 더한 것으로 바뀐다(기존 작성 화면에도 적용).

## 4. 세부 흐름 — 제안 (선별 전, 2026-10-14 일부는 3.1로 대체)

3.1과 다르면 3.1을 따른다. 특히 `옵션·수량은 구매 요청 카드에서만 정한다`와 `요청 만들기 → 작성 화면` 항목은 P-16(후보 카드 = 요청 카드)으로 대체됐다.

| 항목 | 제안 |
|---|---|
| 링크를 읽는 시점 | 대화에 링크가 올라오는 즉시 읽고 옵션 목록까지 저장한다. 후보 목록에서 이름·가격·옵션 상태가 바로 보인다 |
| 옵션이 정해진 링크 | 링크에 옵션 식별자(`vendorItemId`)가 있으면 그 옵션을 미리 선택하고 바꿀 수 있게 한다. 없으면 `옵션 미정`. 쿠팡에서 옵션을 고른 뒤 복사한 링크에는 이 값이 실제로 붙는다(M1 화면에서 확인). **와이어프레임에서 뺐던 이 경로를 되살린다** |
| 옵션·수량을 정하는 곳 | 구매 요청 카드 한곳에서만 정한다. 후보 목록은 `옵션 미정` 등 상태만 보여 준다(같은 값을 두 곳에서 관리하지 않음) |
| 요청 만들기 | 후보를 골라 `구매 요청 만들기` → 작성 화면이 고른 후보들이 카드로 채워진 상태로 열린다. 가격은 이때 다시 읽고 바뀌었으면 표시한다. 구매 목적에는 끼룩이 초안(P-06)이 들어간다 |
| 권한 | 후보 추가: 대화방 참여자 누구나(부원 포함). 요청 만들기: 부서장·재정부(현행 작성 권한). 부원의 구매 제안이 권한 변경 없이 가능해진다 |
| 후보 상태 | 후보 → `요청에 담김(REQ-xxx)` → 승인·반려·구매 완료. 요청에 담긴 후보는 다시 고를 수 없다(중복 요청 방지) |
| 같은 상품 | 같은 링크는 하나로 합친다(M1의 `외 1번`처럼 올린 사람 표시). 같은 상품이라도 옵션이 다르게 정해진 링크는 별도 후보 |
| 쿠팡 외 링크 | 판매처만 채운 후보로 두고 카드에서 가격을 직접 입력한다 |

## 7. 위험

- **채팅 품질이 서비스 핵심 요구사항이 된다.** 이동을 강제하면 불편이 곧바로 이탈 사유가 된다(§6 미결정 4와 연결).
- **끼룩이 초안만으로 쓰는 구매 목적의 형식화.** 초안이 뻔한 문장이 되면 확인 없이 제출되어 구매 이유 기록이 형식만 남을 수 있다. P-06의 조건(근거 없는 이유 금지, 못 찾으면 비움, 확인 후 제출)을 지킨다. 대화 근거 첨부는 이번에 채택하지 않았다(필요해지면 재론).
- **가격 변동.** 링크를 올린 날과 요청하는 날의 가격이 다를 수 있다(§4 요청 만들기에서 다시 읽음).

## 9. 논의 이력

- **2026-10-10**: 사용자가 M1 프로토타입 화면 2장(대화·구매 후보)을 첨부해 대화 링크 → 구매 후보 → 구매 요청 구상을 제시했다. 채팅 이동 위험·MVP 범위·주문 표현·구매 목적 작성·옵션 지정 링크를 검토했다. 사용자가 채팅 이동 강제, MVP 확대, `주문`이 아닌 `구매 요청`, 후보 = 구매 요청 카드, 구매 목적은 끼룩이 초안만을 정했다(P-01~P-06). 이어 발전 가능 주제 중 보완 요청을 대화로·대화에서 업무 만들기·대화 속 결정 기록·후보 단계 예산 보기를 채택하고(P-07~P-10), 작년 구매 기록으로 다시 사기·같은 판매자 묶기는 보류했다. `아직 정해야 할 것` 8건은 미결정이다(§6).
- **2026-10-14**: 처음 만든 `재정 탭 맨 위 구매 후보` 시안을 사용자 요청으로 되돌렸다. 사용자가 M1 화면 2장을 방향으로 제시하고, 질문에 답해 공지방·부서방, 부서방 자동 수집, 후보 카드 = 요청 카드(체크해서 펼침·묶음), 권한, 제출 후 칸반, 예산 항목은 재정부가 검토 시 지정을 정했다(P-11~P-19). 대여·용역의 대화 연결은 보류.
