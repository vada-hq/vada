# 끼룩이 표현 기획 — 자동화를 끼룩이가 한 듯 보여주기

작성: 2026-10-05
상태: 방향·원칙·적용 위치·과의존 방지 모두 채택(K-01~K-07) / 1단계(기존 화면) 적용 완료, 2단계(신규 요소) 대기
관련: [홈 기획 D-13](../home-planning/design.md), [인계 문서](../../VADA_HANDOFF.md), [MVP 기준서](../../VADA_MVP_SPEC.md) §4-F·§5, [행사 아카이브 정의](../../VADA_EVENT_ARCHIVE_SPEC.md)

## 1. 문서의 역할

끼룩이(마스코트)를 서비스 어디에, 어떤 말로 등장시킬지 정한다. 홈 기획과 같은 규칙을 따른다: **사용자가 확정·채택한 것만 `채택`으로 기록**하고, 나머지는 `제안`으로 두어 구현 근거로 쓰지 않는다.

- **채택**: 사용자가 명시적으로 정한 사항
- **제안**: 검토할 방향. 구현 근거 아님
- **보류·기각**: 지금 하지 않는 방향과 이유

## 2. 배경

- 홈 기획에서 상시 브리핑 배너(`HOME-01K`)는 미채택하고, 홈 헤더에 `끼룩이가 {기준 시점} 기준으로 정리했어요` 한 줄만 두기로 했다(D-13).
- 이후 끼룩이를 구성원·부서 사이를 잇는 **대화형 AI 비서**(우하단 상시 채팅, 링크로 구매 요청서 초안 작성)로 쓰는 구상을 검토했다.
- 그사이 쿠팡 링크 자동 채우기는 구매 요청 작성 화면(`FIN-REQ-01B`) 자체 기능으로 구현되었다(커밋 `c3f85c0`). 비서가 맡을 몫이었던 '대신 써 주기'의 상당 부분이 화면 기능으로 해결되었다.

## 4. 표현 원칙 — 채택(K-04)

1. **실제로 자동화된 곳에만 붙인다.** 사람이 입력한 값, 정해진 규칙으로 막는 동작에는 붙이지 않는다.
2. **'해 줬다'만 말하고 '판단했다'고 말하지 않는다.** 쓸 수 있는 말: 불러왔어요·정리했어요·모았어요·찾았어요·올렸어요. 쓰지 않는 말: 승인해도 돼요·중요한 걸 골랐어요·괜찮아요. 결정과 책임은 사람에게 남긴다(과의존 방지, K-01 취지).
3. **경고·차단·재정 판정에는 쓰지 않는다.** 예산 초과·구매 불가·필요일 이후 도착·중복 구매·지연·미지정 경고는 중립 문장으로 둔다. 기존 규칙 "재정·지연 항목에 마스코트 말투를 쓰지 않는다"와 같다. 끼룩이가 막는 주체로 보이면 불만이 캐릭터로 향한다.
4. **한 화면에 한 번, 행동이 일어난 자리에만.** 작은 끼룩이 그림 + 한 줄. 칸마다 붙는 `링크에서 가져옴` 같은 표시는 글자로만 둔다.
5. **실패도 부드럽게, 할 일은 분명하게.** 예: `끼룩이가 이 링크는 읽지 못했어요. 직접 입력해 주세요.`
6. **AI가 만든 초안은 `끼룩이 초안 · 검토 필요`로 표시하고, 사람이 확정한 결과물에는 끼룩이를 작성자로 남기지 않는다.** 발행·확정된 문서의 책임자는 작성자·검토자다.
7. **표정 사용은 기존 규칙을 따른다.** 처리 중 `생각 중`, 완료·안내 `인사`. `확인 중`은 쓰지 않는다(경고에 쓰지 않으므로).

공통 부품 후보(제안): ① `끼룩이가 ○○했어요` 한 줄 표시, ② `끼룩이 초안 · 검토 필요` 표시. 화면마다 따로 만들지 않고 같은 부품을 쓴다.

| 우선 | 화면 | 자동화 | 끼룩이 표현(예) |

후속 업무 반영과 불참자 요약 전달은 사람·부서 사이에 정보를 잇는 자동화다. 대화형 비서 없이 '구성원 사이 연결다리'라는 처음 취지를 살리는 자리다.

### 5.3 신규 요소 후보 (현재 와이어프레임에 없음)

| 우선 | 요소 | 내용 | 비용·주의 |
|---|---|---|---|
| ⭐⭐ | 지난 행사 기록 찾아 주기 | 새 행사 생성(`EVT-00B`) 또는 행사 개요(`EVT-02`)에서 이름·유형이 비슷한 지난 행사의 아카이브를 `끼룩이가 지난 가을 축제 인수인계를 찾았어요`로 연결 | 인수인계 기록이 실제로 다음 담당자에게 읽히게 하는 연결고리. 이름·유형 일치 규칙이라 과의존 위험 낮음. 작은 신규 기능 |
| ⭐ | 행사 완료 → 기록 정리 이어 주기 | 행사 완료 처리(`EVT-02E`) 직후 `끼룩이가 이 행사 기록을 모아 두었어요. 회고와 인수인계를 남겨 주세요` + 아카이브 작성 연결 | 완료 후 기록으로 가는 흐름 보강. 문구·버튼 추가 수준 |
| ⭐ | 지난 회의의 남은 일 가져오기 | 회의 생성(`OPS-MEET-02`) 때 직전 회의의 미완료 후속 업무를 `끼룩이가 지난 회의에서 남은 일 2개를 안건 후보로 가져왔어요`로 제안 | 후보로만 제시, 선택은 사람. 작은 신규 기능 |
| 선택 | 첫 사용 빈 상태 안내 | 홈·완료된 행사 목록 등 빈 화면에 `행사를 마치면 끼룩이가 기록을 모아 둘게요` 같은 안내 | 기존 `샘플: 첫 사용` 모드에 문구만 추가 |

신규 요소는 화면·화면정의서가 늘어나며, MVP 포함 여부는 별도로 판단한다(§7).

## 6. 과의존 방지 장치 — 채택(K-07)

- **인수인계 AI 초안의 항목별 확인**: 항목마다 근거 기록 링크를 달고 처음에는 `확인 전`으로 둔다. 작성자가 항목을 하나씩 확인해야 발행 조건이 채워진다. 초안을 읽지 않고 통째로 승인하는 것을 막는다.
- **확정본의 책임자 표시**: 발행·확정된 문서에는 작성자·검토자만 남기고 끼룩이를 작성자로 표시하지 않는다(원칙 6).
- **제안은 후보로만**: 지난 회의 남은 일·지난 행사 기록은 선택지로 보여 주고 자동으로 넣지 않는다.

## 7. 범위와 MVP

- MVP §4-F 행사 완료 기록은 `자동 집계 + 최소 회고`다. MVP 화면에서는 자동 집계 쪽 끼룩이 표시만 해당된다.
- 검토·승인·발행이 있는 정식 행사 아카이브와 AI 인수인계 초안, AI 회의 전체 요약은 MVP §5 다음 릴리스 후보다. 해당 끼룩이 표현은 와이어프레임 시안으로 둔다.
- §5.3 신규 요소는 어떤 것도 MVP에 포함된 것이 아니다. 포함하려면 MVP 기준서를 별도로 갱신한다.

## 10. 논의 이력

- **2026-10-01**: 끼룩이 브리핑 검토 후 홈 헤더 한 줄로 정리(D-13). 사용자가 끼룩이를 소통 연결 AI 비서로 쓰는 구상을 제시했고, 구매 링크 초안·담당자 연결·질문 답변·권한·비용·개인정보를 분석했다(대화에서만, 미저장).
- **2026-10-02~03**: 쿠팡 링크 자동 채우기를 구매 요청 작성 화면 기능으로 구현(옵션 전체 불러오기·즉시 가격·배송비·추출 정보). 비서 기획은 보류.
- **2026-10-05**: 사용자가 분리된 AI 비서를 쓰지 않고 자동화 기능에 끼룩이 디자인 요소만 넣기로 정했다(K-01·K-02). 기록(인수인계) 영역에도 넣기로 했다(K-03). 전체 화면정의서에서 자동화 약 30곳을 점검해 적용 위치·제외 위치·신규 후보를 정리했다(§5, 제안).
- **2026-10-05**: 사용자가 §4~§6 제안을 모두 채택했다(K-04~K-07). 기존 화면에 넣는 1단계부터 적용한다.
- **2026-10-05**: 1단계 적용. 공통 부품 `KkirukDone`(한 줄)·`KkirukDraftBadge`(초안 표시)를 만들고 구매 요청 불러오기, 회의 AI 요약·후속 업무 반영, 불참자 요약, 아카이브 자동 채움·인수인계 초안(그대로 둔 줄 하나씩 확인 → 발행 조건), 아카이브 상세 자동 집계, 기본 조직 생성, 행사 정보 저장 안내, 내 업무 헤더에 반영했다. 각 화면정의서에 `끼룩이 표시` 행을 추가했다. 미결정 3(공통 부품 형태)은 이 구현을 시안으로 본다.
