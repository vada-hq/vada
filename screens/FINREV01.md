## 이 화면이 MVP에서 갖는 범위

재정부가 제출된 구매 요청을 **품목별로** 보고 승인·보완 요청·반려 중 하나를 정한다. `VADA_MVP_SPEC.md` §3 성공 기준 5번이 요구하는 결과가 여기서 만들어진다.

> 구매 요청 1건이 제출되어 승인·반려·보완 요청 중 하나의 결과를 가진다.

**이 화면이 재정 슬라이스의 시작점이다.** 지금 서버가 저장할 수 있는 상태는 `review_pending` 하나뿐이라(`apps/api/.../finance/api.py`), 이 화면이 생기기 전에는 `EVT-FIN-01`의 품목 현황이 한 열밖에 채우지 못한다.

| 와이어프레임 요소 | MVP에서 | 이유 |
| --- | --- | --- |
| 품목 검토 표 | **만든다** | 이 화면의 본체 |
| 상태 변경 — 승인·보완 요청·반려 | **만든다** | 성공 기준 5번이 요구하는 결과 |
| 보완 요청 모달 — 사유·재제출 기한 | **만든다** | 보완 요청에 필수 입력이다 |
| 처리 기록 | **만든다** | 요청자와 재정부가 같은 이력을 봐야 한다(성공 기준 흐름 4) |
| 확정 후 진행 — 선진행 동의·구매 승인 묶음 | **만들지 않는다** | 구매 승인 묶음은 `FIN-PROC-01`의 단위이고 MVP 후속 범위다 |

전량 확정 시 "주문 대기로 넘어간다"도 주문 흐름이 없어 다루지 않는다. 확정까지만 하고 그 뒤는 이 화면의 책임이 아니다.

## 검토 규칙 (`VADA_FINANCE_SPEC.md` §6)

**결정은 품목 단위다.** 요청 단위가 아니다.

| 상태 | 뜻 | 다음 |
| --- | --- | --- |
| 검토 대기 | 제출 또는 보완 재제출 후 확인을 기다림 | 승인 / 보완 요청 / 반려 |
| 승인 | 요청 내용과 **요청 금액 그대로** 구매를 허용 | 품목 예산 예약 |
| 보완 요청 | 정보가 부족해 요청자 수정이 필요 | 요청자가 보완 후 재제출 |
| 반려 | 더 이상 구매하지 않기로 확정 | 활성 처리에서 제외, 기록 보존 |

**별도 `검토 중` 단계가 없다.** 재정부가 열어보고 바로 결정한다. 화면에 "검토 시작" 같은 중간 행동을 만들지 않는다.

**승인액을 입력하지 않는다.** 승인은 품목 요청 금액을 그대로 예산 예약한다. 금액을 깎는 행동은 이 화면에 없다. 금액이 문제면 보완 요청이다.

**반려 사유 목록을 시스템이 주지 않는다** — §6.2가 "시스템은 반려 사유 목록·자동 판정·추천을 제공하지 않는다"고 못박는다. 자유 입력으로 받는다.

**한 요청 안에서 품목마다 결과가 달라도 된다**(§6.3). 품목 A 승인, B 보완 요청, C 반려가 정상이다.

**요청 수준의 통합 상태를 만들지 않는다** — §6.3이 "구매 요청 수준의 `부분 승인`, `구매 중`, `정산 중` 등 통합 진행 상태는 만들지 않는다"고 정한다. 요청은 소속 품목의 개별 상태를 보여줄 뿐이다.

## 화면 구조

- **머리말** — 요청 제목, 요청자·부서, 제출 시각, 전체 요청액.
- **품목 검토 표** — 품목마다 한 행. 품목명·수량·요청액·가격 근거·현재 상태, 그리고 결정 행동.
- **결정 팝업** — 보완 요청은 사유와 재제출 기한을, 반려는 사유를 받는다. 승인은 받을 값이 없어 곧바로 보낸다.
- **처리 기록** — 상태 변화를 시간순으로. 누가 언제 무엇을 했는지.

## 상태

**로딩** — 진행 상태만 알린다. 이전 값이나 샘플을 결과처럼 표시하지 않는다.

**검토 대기 품목이 있음** — 결정 행동을 제공한다.

**모든 품목이 확정됨** — 결정 행동을 더 제공하지 않고 결과와 이력만 보여준다. 이미 처리된 요청에 결정을 덮어쓰지 않는다.

**재정부가 아님(403)** — 검토 결정을 변경할 수 없다(화면정의서 예외). 다른 조직 데이터의 존재를 노출하지 않는 안내를 표시하고 재시도를 제공하지 않는다.

**보완 요청 입력 누락** — 사유나 재제출 기한이 없으면 제출하지 않고 항목별 오류를 표시한다.

**결정 실패(409 충돌)** — 다른 사람이 먼저 처리했으면 덮어쓰지 않는다. 현재 상태를 다시 읽어 보여준다.

**일시 장애(503)** — 재시도를 제공한다. 같은 결정의 재시도는 같은 멱등성 키를 재사용한다.

**인증 필요(401)** — 재인증 안내만 표시한다.

## 와이어프레임과 다르게 하는 것

**확정 후 진행을 다루지 않는다** — 와이어프레임 기능 05는 전량 확정 시 구매 준비로, 보완 품목이 남으면 선진행 동의 대기로 보낸다. 둘 다 구매 승인 묶음을 만드는 일이고 그 단위는 `FIN-PROC-01`이 소유한다. 이 화면은 품목 결정까지만 책임진다.

**미검토 품목이 남아도 화면을 막지 않는다** — 화면정의서 예외는 "미검토 품목이 있으면 최종 처리할 수 없다"고 하는데, 그 `최종 처리`가 곧 확정 후 진행이다. 이번 범위에 없으므로 품목별 결정은 언제든 개별로 저장한다.

**사이드바·브레드크럼·행사 탭** — 공통 셸이 제공한다.

## 보완 기한이 지나면

**아무 일도 일어나지 않는다.** `VADA_FINANCE_SPEC.md` §7이 못박는다.

> 보완 기한이 지나도 **자동 반려하지 않는다.**

기한은 요청자에게 알리는 값이고 시스템이 그것으로 상태를 바꾸지 않는다. 화면은 기한을 기록하고 표시만 한다.

이 문서는 처음에 이것을 열린 질문으로 남겼다. §7을 읽지 않고 "명세에서 찾지 못했다"고 적었기 때문이다.
