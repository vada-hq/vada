## 화면 구조

와이어프레임 위계를 따른다.

- **상단 행동** — 셸 머리말 오른쪽에 `내 구매 요청`과 `새 구매 요청`.
- **예산 요약** — 카드를 가로로 나열한다. 각 카드에 작은 레이블과 큰 금액을 둔다. 사용 가능액은 주 색상으로 강조한다.
- **보기 전환** — `처리 단계`와 `전체 목록` 두 탭. 오른쪽에 검토 대기 건수를 뱃지로 표시한다.
- **처리 단계 보드** — 단계별 세로 칸. 각 칸 머리에 단계 이름, 아래에 요청 카드. 카드에는 요청 부서 칩, 제목, 품목 요약, 금액, 상태 칩.
- **전체 목록** — 열 머리글이 있는 표. 열은 `요청일 · 구매 요청명 · 요청 부서 · 전체 요청액 · 현재 상태`.

## 상태

**로딩** — 예산과 목록을 함께 불러온다. 진행 상태만 알리고 이전 값이나 샘플을 결과처럼 표시하지 않는다.

**성공** — 예산 요약은 서버가 준 항목별 배정·집행 예정·사용 가능액을 표시한다. 사용 가능액이 음수면 초과 상태로 구분해 보여준다.

**빈 결과** — 구매 요청이 없으면 단계별 0건과 빈 상태를 표시한다. 예산 요약은 그대로 보여준다.

**권한 없음(403)·찾을 수 없음(404)** — 다른 조직 데이터의 존재를 노출하지 않는 같은 수준의 안내를 표시한다. 재시도를 제공하지 않는다.

**일시 장애(503)** — 재시도를 제공한다.

**인증 필요(401)** — 재인증 안내만 표시하고 과거 값이나 캐시를 대신 보여주지 않는다.

## 와이어프레임과 다르게 하는 것

**예산 요약을 네 개에서 세 개로 줄인다** — 와이어프레임은 배정 예산·승인 집행 예정액·실제 지출액·사용 가능액 넷을 표시한다. 실제 지출액은 구매 실행과 증빙 단계에서 나오는 값인데, 승인 제품 명세가 그 흐름을 후속으로 미뤄뒀고 계약도 없다. 0원으로 두면 "지출이 없다"인지 "집계가 없다"인지 구분되지 않으므로 배정·집행 예정·사용 가능 셋만 표시한다.

**처리 단계 보드의 뒤 두 칸을 비운다** — 와이어프레임은 검토 필요·구매 필요·증빙 필요·정산 완료 넷이다. 계약이 정의한 상태는 검토 단계까지(검토 대기·승인·부분 승인·보완 요청·반려)이므로 증빙 필요와 정산 완료 칸은 "아직 처리 단계가 없습니다"로 정직하게 비운다. 없는 상태를 있는 것처럼 만들지 않는다.

**항목을 누르면 가는 곳** — 와이어프레임 화면정의서대로 재정부와 회장단은 검토 화면으로, 일반 구성원은 자신의 요청 상태 확인 화면으로 간다. 검토 화면(`FIN-REV-01`)은 아직 없으므로 지금은 모두 상세 화면으로 보내고, 검토 화면이 생기면 분기한다.

**예산은 예산 항목별로 배정한다** — 와이어프레임은 총액만 하드코딩해 두었다. 품목 입력에 이미 예산 항목이 있으므로 같은 어휘로 항목별 배정을 정본으로 삼는다.

**사이드바·브레드크럼** — 공통 셸이 제공한다.
