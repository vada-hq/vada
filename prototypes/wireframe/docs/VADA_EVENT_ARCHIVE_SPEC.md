# 행사 아카이브·인수인계 화면정의서

2026-07-20 작성·구현. 완료된 행사를 "운영 도구 재열람"이 아니라 **다음 학생회가 읽는 인수인계 문서**로 분리하기 위한 정의다. `REC-01`, `REC-02`, `REC-02A` 및 `SPEC_DATA`에 반영됐다.

## 배경

현재 `REC-01`은 완료 행사를 정적 배열로 표시하고 `상세 보기` 버튼이 동작하지 않는다. 기존 정의서는 상세 보기가 "행사 워크스페이스를 열람 모드로 연다"고만 규정해, 회고·인수인계를 담을 구조가 없다.

운영 워크스페이스는 진행 중 작업을 위한 도구이고, 완료 행사에 필요한 것은 읽는 문서다. 목적이 다르므로 화면을 분리한다.

## 설계 원칙

### 1. 행사 완료 상태와 아카이브 발행 상태를 분리한다

```text
행사 상태:   기획 중 → 진행 중 → 후속 정리 중 → 완료
아카이브 상태: 미발행 → 초안 → 검토 중 → 발행
```

- 아카이브가 미발행이어도 행사 완료를 막지 않는다. (회의록 정리에서 AI 요약이 완료를 막지 않는 것과 같은 원칙)
- 대신 완료 행사 목록에 `인수인계 문서 미발행`을 명시해 후속 작업이 남았음을 드러낸다.

### 2. 발행된 아카이브는 스냅샷으로 보존한다

- 발행 시점의 성과·타임라인·근거 수치를 고정한다. 이후 원본 업무·문서가 수정되어도 발행본은 변하지 않는다.
- 원본으로 이동하는 링크는 제공하되, 아카이브 본문에는 `발행 시점 기준` 표기와 발행 버전을 함께 남긴다.
- 발행 후 내용을 고치면 새 버전(v1.1)으로 발행하며 이전 버전 기록을 남긴다.

## 아카이브 상태 정의

| 상태 | 의미 | 목록 표시 | 상세 진입 |
|---|---|---|---|
| 미발행 | 아직 작성 시작 안 함 | 회색 `인수인계 문서 미발행` | 권한자는 작성 시작, 열람자는 발행 전 안내에 머묾 |
| 초안 | 작성 중 | 노랑 `초안` | 권한자만 REC-02A |
| 검토 중 | 검토자 확인 대기 | 파랑 `검토 중` | 열람은 REC-02(검토 중 배너), 검토자는 REC-02A에서 보완 요청 또는 승인 |
| 발행 | 확정 공개 | 초록 `발행 v1.0` | 전 구성원 REC-02 |

## REC-01 완료된 행사 목록 (개편)

- **id / stateChip**: `REC-01` / 기본
- **목적**: 완료된 행사의 성과 요약과 인수인계 문서 상태를 확인하고 아카이브로 진입한다.
- **주요 사용자**: 전 구성원 (열람). 작성 진입은 행사 운영 조직 관리자·회장단
- **진입 경로**: 사이드바 기록 → 완료된 행사 / `EVT-02E` 완료 처리 후

| # | UI 요소 | 기능 설명 / 제약 |
|---|---|---|
| 01 | 행사 카드 | 행사명, 행사 일시, 담당 부서·책임자, 완료 처리일을 표시한다. |
| 02 | 성과 요약 | 참석 인원(신청 대비), 예산 집행률, 완료 업무 수를 요약한다. ⚠ 발행본이 있으면 발행 시점 수치를 쓴다. |
| 03 | 아카이브 상태 배지 | 미발행 / 초안 / 검토 중 / 발행 vN을 표시한다. |
| 04 | 상세 보기 | 발행·검토 중이면 `REC-02`로, 미발행·초안이면 권한자에게 `REC-02A` 작성 화면으로 이동한다. ⚠ 일반 열람자는 발행 전 안내에 머무르며 찾을 수 없는 진행 행사 목록으로 보내지 않는다. |
| 05 | 검색·정렬 | 행사명 검색, 완료 처리일순·행사 일시순 정렬. |
| 06 | 미발행 안내 | 인수인계 문서가 없는 행사 수를 상단에 표시한다. ⚠ 완료 처리를 되돌리거나 막지 않는다. |

- **예외**: 완료 행사 자체는 열람만 가능하며 상태 되돌리기는 별도 권한 절차가 필요하다.
- **다음 화면**: `REC-02` 행사 아카이브 상세 / `REC-02A` 아카이브 작성·검토

## REC-02 행사 아카이브 상세

- **id / stateChip**: `REC-02` / 발행
- **목적**: 완료된 행사의 전 과정과 인수인계 내용을 문서 형태로 열람한다.
- **주요 사용자**: 전 구성원 (열람 전용)
- **진입 경로**: `REC-01` → 상세 보기
- **선행 조건**: 아카이브가 검토 중 또는 발행 상태

레이아웃: 상단 요약 헤더 / 좌측 목차 / 본문 기록 / 우측 인수인계 체크리스트

| # | UI 요소 | 기능 설명 / 제약 |
|---|---|---|
| 01 | 문서 헤더 | 행사명, 기간, 담당 부서·책임자, 아카이브 상태 배지, 발행 버전·발행일·작성자·검토자를 표시한다. ⚠ 기록 신뢰성 정보는 항상 함께 노출한다. |
| 02 | 좌측 목차 | 문서 옆에 고정되어 따라다니며, 대목을 누르면 본문의 해당 위치로 이동한다. 현재 읽고 있는 대목을 강조 표시한다. ⚠ 문서가 길어도 지금 어디를 읽는지와 남은 대목을 항상 알 수 있어야 한다. |
| 02-1 | 목차 구성 | 개요 · 성과 · 타임라인 · 현장 운영 · 근거 자료 · 회고 · 인수인계를 나열한다. 회고는 잘된 점 / 미흡했던 점 / 개선안을 하위 항목으로 펼친다. |
| 02-2 | 비어 있는 대목 표시 | 검토 중 상태에서 내용이 없는 대목은 목차에 `작성 전`으로 표시한다. ⚠ 발행본에는 나타나지 않는다. |
| 03 | 행사 개요 | 목표, 참여 대상, 일정·장소, 책임 부서·책임자, 행사 규모를 표시한다. |
| 04 | 성과 | 계획 대비 실제 신청·참석 인원, 만족도, 예산 계획 대비 집행 요약을 표시한다. |
| 05 | 타임라인 | 기획 확정, 주요 의사결정, 업무 완료·지연, 회의 결정, 일정 변경, 행사 종료를 시간순으로 표시한다. |
| 06 | 현장 운영 | 실제 진행 순서, 인력 배치, 돌발 상황과 대응, 운영 변경 사항을 표시한다. |
| 07 | 근거 자료 | 업무·회의·문서·정산 요약을 표시하고 각 항목에서 원본으로 이동한다. ⚠ 수치는 발행 시점 스냅샷이며 `발행 시점 기준`을 표기한다. |
| 08 | 회고 | 잘된 점, 미흡했던 점과 원인, 다음 행사 개선안을 표시한다. |
| 09 | 인수인계 체크리스트 | 우측 고정 패널에 부서별 확인 항목, 재사용 자산, 협력처·담당자, 주의사항, 다음 담당자를 표시한다. AI 초안을 `REC-02A`에서 검토·발행한 결과이며 이 화면에서는 열람만 한다. |
| 10 | 원본 이동 | 원본 업무·회의·문서로 이동하는 링크를 제공한다. ⚠ 원본이 바뀌어도 이 문서는 변경되지 않는다. |
| 11 | 아카이브 수정 | 권한자에게만 `REC-02A`로 가는 버튼을 노출한다. |

- **예외**: 검토 중 상태에서는 상단에 `검토 중 · 확정 전 내용` 배너를 표시한다.
- **다음 화면**: `REC-02A` 아카이브 작성·검토 / 원본 화면(업무·회의·문서·정산)

## REC-02A 아카이브 작성·검토

- **id / stateChip**: `REC-02A` / 초안
- **목적**: 행사 책임자와 회장단이 회고·인수인계 내용을 작성하고 아카이브를 발행한다.
- **주요 사용자**: 행사 운영 조직 관리자 · 회장단
- **진입 경로**: `REC-01` 미발행·초안 행사 → 아카이브 작성 / `REC-02` → 아카이브 수정

| # | UI 요소 | 기능 설명 / 제약 |
|---|---|---|
| 01 | 자동 채움 영역 | 개요·성과·타임라인·근거 자료는 행사 데이터에서 자동으로 채우며 편집하지 않는다. ⚠ 원본 수치를 사람이 고쳐 쓰지 않는다. |
| 02 | 현장 운영 작성 | 실제 진행 순서, 인력 배치, 돌발 상황·대응을 입력한다. |
| 03 | 회고 작성 | 잘된 점, 미흡했던 점과 원인, 다음 행사 개선안을 각각 입력한다. ⚠ 개선안은 다음 담당 부서를 함께 지정한다. |
| 04 | 인수인계 작성 | AI가 행사 기록을 바탕으로 재사용 자산, 협력처·담당자, 부서별 체크리스트, 주의사항, 다음 담당자 초안을 생성하고, 작성자가 검토·수정해 확정한다. ⚠ 기록에 없는 내용을 임의로 만들지 않으며, 사람 검토·확인 없이는 발행하지 않는다. |
| 05 | 발행 조건 | 현장 운영·회고·인수인계 필수 항목 충족 여부를 체크리스트로 표시한다. ⚠ 조건 미충족 시 발행 버튼을 비활성화한다. |
| 06 | 검토 요청 | 검토자를 지정해 `검토 중`으로 전환한다. |
| 07 | 검토 의견 | 검토자가 의견을 남기고 보완 요청하거나 승인한다. |
| 08 | 발행 | 검토 승인 후에만 발행할 수 있다. 발행 시점의 성과·타임라인·근거를 스냅샷으로 고정하고 버전을 부여한다. ⚠ 발행 후 수정은 새 버전으로 발행하며 이전 버전 기록을 남긴다. |
| 09 | 임시 저장 | 작성 중 내용을 초안으로 보관한다. |
| 10 | 좌측 목차 | 열람 화면과 같은 목차를 제공하고, 아직 작성하지 않은 대목을 `작성 전`으로 표시해 남은 작업을 드러낸다. |

- **예외**: 행사가 완료 상태가 아니면 진입할 수 없다. 발행 이력이 있는 문서는 삭제하지 않는다.
- **다음 화면**: `REC-02` 행사 아카이브 상세

## 보류 사항 (별도 안건)

아래는 실제 서비스 구현 시 필요한 데이터 구조이며, 와이어프레임 범위 밖으로 판단해 보류한다. 아카이브 화면은 완료 시점에 고정된 전용 샘플 데이터로 구현하며, 이는 스냅샷 개념과도 일치한다.

- 모든 업무·회의·문서·구매 요청에 `eventId` 연결
- 행사 상태를 전역 단일 상태가 아닌 행사 단위로 관리
- 완료 행사 목록을 실제 완료 행사 데이터에서 생성
- 업무 이력에 실제 시각·완료 결과·지연 사유·검토 의견 기록
- 아카이브 발행 시 원본 정보를 스냅샷으로 저장
