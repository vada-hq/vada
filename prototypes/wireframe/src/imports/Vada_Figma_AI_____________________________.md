# Vada Figma AI 화면정의서 구현 프롬프트

## 먼저 알아둘 점

이 프롬프트는 새로운 와이어프레임을 만드는 용도가 아닙니다. 이미 제작한 Vada 와이어프레임을 유지하면서 각 프레임에 번호 주석과 화면 정의 패널을 추가하기 위한 프롬프트입니다.

### 권장 사용 순서

1. 화면정의서를 붙일 기존 프레임들을 선택합니다.
2. 원본 보존을 위해 프레임을 복제하거나 별도 Figma 페이지 `02_화면정의서`에 복사합니다.
3. Figma AI의 수정 입력창에 아래 통합 프롬프트를 붙여넣습니다.
4. 한 번에 모든 프레임을 처리하지 못하면 화면군별로 나누어 입력합니다.

---

# 통합 프롬프트

```text
선택한 Vada 와이어프레임의 UI 구조와 레이아웃은 변경하지 말고, 각 프레임을 실제 화면정의서처럼 이해할 수 있도록 기능 주석과 정의 패널을 추가해줘.

[가장 중요한 작업 원칙]
- 기존 와이어프레임의 구성요소, 크기, 위치, 문구를 임의로 삭제하거나 재설계하지 마.
- 원본 프레임 내부에는 작은 번호 pin만 추가해줘.
- 상세 설명은 프레임 오른쪽의 화면 정의 패널에 작성해줘.
- 주석은 실제 서비스 UI가 아니라 문서용 표시라는 점이 구분되게 만들어줘.
- 구매 요청, 증빙, 정산, 감사보고서 등 재정 화면이나 재정 기능은 추가하지 마.
- 참가자 명단의 입금 상태와 학생 명단의 학생회비 상태는 기존 범위이므로 유지해줘.
- 모든 설명은 자연스러운 한국어로 작성해줘.

[전체 배치 방식]
- 기존 desktop frame 1440×1024 또는 mobile frame 390×844는 그대로 유지해줘.
- 각 프레임 오른쪽 48px 간격을 두고 폭 520px 정도의 화면 정의 패널을 배치해줘.
- 기존 프레임과 정의 패널을 하나의 Figma Section 안에 묶어줘.
- Section 이름은 `[화면 ID] 화면명` 형식으로 지정해줘.
- 여러 상태가 있는 화면은 기본 화면 아래 또는 오른쪽에 variant frame으로 정렬해줘.
- 화면 사이 간격과 정의 패널의 폭을 모두 동일하게 유지해줘.

[화면 정의 패널 공통 구성]
각 화면 오른쪽 패널에 아래 항목을 같은 순서로 표시해줘.

1. 화면 ID
2. 화면명
3. 화면 목적
4. 주요 사용자
5. 진입 경로
6. 진입 전 조건
7. 기능 정의 표
8. 상태·예외 처리
9. 연결되는 다음 화면 또는 결과

기능 정의 표의 열:
- 번호
- UI 요소
- 기능 설명
- 사용자 행동
- 실행 결과
- 예외·제약

[주석 디자인]
- 번호 pin은 24×24px 원형으로 만들고 `01`, `02`, `03`처럼 두 자리 숫자를 사용해줘.
- 주석 pin은 제품 UI의 파란색 활성 상태와 혼동되지 않도록 주황색 계열을 사용해줘.
- 번호 pin을 해당 UI 요소의 우측 상단 또는 가까운 빈 공간에 배치해줘.
- 정의 패널의 같은 번호 행과 대응되게 해줘.
- 설명을 프레임 안에 긴 문장으로 직접 넣지 마.
- 필요한 경우 얇은 회색 연결선을 사용하되 화면을 가리지 않게 해줘.
- 주석 요소는 `SPEC_Annotation` component로 만들어줘.
- 정의 패널은 `SPEC_DefinitionPanel` component로 만들어줘.
- 상태 chip은 `SPEC_State` component로 만들어줘.
- 모든 문서용 요소는 `SPEC`이라는 별도 layer group으로 묶어줘.

[공통 상태 표기]
각 프레임 상단에 다음 중 해당하는 상태 chip을 표시해줘.
- 기본
- 수정 모드
- 팝업 열림
- 패널 열림
- 모달 열림
- 빈 상태
- 오류 상태
- 완료 상태

[공통 UX 정의]
- 간단한 정보 확인은 작은 popover를 사용한다.
- 긴 검색·선택 작업은 오른쪽 panel을 사용한다.
- 파일 업로드나 단계가 있는 작업은 중앙 modal을 사용한다.
- 조직 수정은 별도 페이지가 아니라 같은 화면의 수정 모드로 처리한다.
- 위험한 삭제·재생성 작업은 확인 dialog를 거친다.
- 작업 완료 후에는 결과 toast 또는 상태 변경을 보여준다.
- 같은 구성원 카드는 기본 조직, 미배정 구성원, 행사 조직, 추가 가능한 구성원 영역에서 동일하게 사용한다.

[최신 조직도 수정사항]
- 회장단은 한 사람만 표시하는 단일 구성원 카드가 아니다.
- 회장단도 일반 부서처럼 여러 구성원을 담는 큰 조직 카드로 표현한다.
- 회장단 카드 내부에 회장, 부학생회장 등 여러 구성원 카드를 세로로 배치한다.
- 회장단 구성원 카드는 일반 구성원 카드와 같은 크기와 형식을 사용하되 역할명 `회장`, `부학생회장`을 함께 표시한다.
- 회장단 카드가 조직도의 최상단에 위치하고 하단 부서 카드들과 연결된다.
- 회장단 카드 안의 특정 한 명만 전체 회장단처럼 보이게 만들지 마.

아래 화면별 정의를 기존 화면 ID와 매칭하여 구현해줘.

────────────────────────────
[ONB-01 본인 소속 입력]

화면 목적:
내부 사용자의 개인 학적 소속을 등록한다.

주요 사용자:
Vada에 처음 가입한 학생회 구성원

진입 경로:
회원가입 완료 → 본인 소속 입력

진입 전 조건:
로그인 또는 회원가입 완료

번호 기능:
01 진행 단계
- 현재 온보딩 단계 `1/2`를 보여준다.

02 학교 선택
- 학교를 검색·선택한다.
- 캠퍼스는 별도 필드가 아니라 `한양대학교 ERICA`처럼 학교명에 포함한다.

03 단과대학 선택
- 선택한 학교에 속한 단과대학만 보여준다.

04 학부·학과 선택
- 선택한 단과대학에 속한 학부·학과만 보여준다.

05 직접 입력
- 목록에 소속이 없을 때 사용자가 직접 입력한다.

06 학년·이름·학번
- 학년과 이름은 필수다.
- 학번은 선택 입력이다.

07 다음
- 필수값을 검증한 뒤 ONB-02로 이동한다.
- 누락된 값이 있으면 해당 입력창에 오류를 표시한다.

중요 제약:
- 개인 소속과 학생회 대표 범위는 별도 데이터다.

────────────────────────────
[ONB-02 시작 방식 선택]

화면 목적:
사용자가 새 학생회를 만들지, 기존 학생회에 참여할지 선택한다.

주요 사용자:
본인 소속 입력을 완료한 사용자

진입 경로:
ONB-01 → 시작 방식 선택

번호 기능:
01 새 학생회 만들기
- ORG-01 새 학생회 생성으로 이동한다.

02 초대받은 학생회 참여하기
- 초대 링크 또는 참여 정보 확인 흐름으로 이동한다.

03 진행 단계
- 온보딩 `2/2`를 표시한다.

예외·제약:
- 초대 링크로 직접 들어온 사용자는 이 화면을 건너뛴다.
- 현재 한 사용자는 하나의 학생회에만 참여한다.

────────────────────────────
[ORG-01 새 학생회 생성]

화면 목적:
새 학생회의 기본 정보와 관리 범위를 설정한다.

주요 사용자:
학생회 생성자, 학생회장

진입 경로:
ONB-02 → 새 학생회 만들기

번호 기능:
01 학생회 유형
- 총학생회, 단과대 학생회, 학부 학생회, 학과 학생회, 기타 중 하나를 선택한다.

02 대표 범위
- 학생회 유형에 맞춰 학교 → 단과대학 → 학부·학과를 단계적으로 선택한다.
- 이후 학생 명단 관리 범위를 결정하는 핵심 데이터다.

03 학생회명
- 공식 학생회 이름을 입력한다.

04 기수·임기
- 기수 또는 임기명과 시작일·종료일을 입력한다.

05 추천값
- 사용자의 개인 소속을 추천값으로만 보여준다.
- 개인 소속을 대표 범위로 강제하지 않는다.

06 다음
- 입력값을 저장하고 ORG-02 조직 구조 설정으로 이동한다.

────────────────────────────
[ORG-02 조직 구조 설정]

화면 목적:
학생회 생성 직후 회장단과 부서의 기본 구조를 만든다.

주요 사용자:
학생회 생성자, 학생회장

진입 경로:
ORG-01 → 조직 구조 설정

번호 기능:
01 시작 방식
- 기본 구조, 템플릿, 빈 조직 중 하나를 선택한다.

02 회장단 조직 카드
- 조직도 최상단에 위치한다.
- 일반 부서처럼 큰 조직 카드이며 여러 구성원 카드를 담을 수 있다.
- 회장과 부학생회장 등 복수의 역할을 표현한다.

03 부서 카드
- 기획부, 홍보부, 디자인부 등 부서 구조를 표시한다.
- 이 단계에서는 구성원 배정보다 구조 설정에 집중한다.

04 부서 추가
- `＋ 부서 추가`로 새 부서를 만든다.

05 부서명 수정
- 부서명을 더블 클릭해 인라인 수정한다.
- Enter 저장, Esc 취소, 바깥 클릭 저장이다.
- 공백·중복 이름은 오류다.

06 조직 만들기
- 설정한 구조를 저장하고 ORG-03 조직 관리 메인으로 이동한다.

후순위:
- 이전 기수 조직 불러오기는 현재 범위에서 제외한다.

────────────────────────────
[ORG-03 조직 관리 메인 — 보기 모드]

화면 목적:
학생회 전체 조직과 구성원의 현재 배치 상태를 확인한다.

주요 사용자:
학생회장, 조직 관리자, 권한이 있는 구성원

진입 경로:
사이드바 조직 관리 → 부서 및 구성원

번호 기능:
01 회장단 카드
- 최상단에 위치한다.
- 회장과 부학생회장 등 여러 구성원 카드를 포함한다.

02 부서 카드
- 부서장, 부원 수, 구성원 카드를 보여준다.
- 부서장이 없으면 `＋ 부서장 지정`을 표시한다.

03 구성원 카드
- 이름, 학부·학과, 학년을 표시한다.
- 클릭하면 ORG-05 구성원 상세 popover가 열린다.

04 미배정 구성원 패널
- 아직 부서가 없는 구성원을 검색·확인한다.
- 미배정 구성원 카드는 부서 내부 카드와 같은 형식이다.

05 수정
- 같은 화면을 ORG-03 수정 모드로 전환한다.

06 구성원 초대
- 오른쪽 패널을 초대 링크 UI로 전환한다.
- 별도 페이지로 이동하지 않는다.

────────────────────────────
[ORG-03 조직 관리 메인 — 수정 모드]

화면 목적:
구성원과 부서 구조를 같은 화면에서 수정한다.

번호 기능:
01 완료
- 수정 내용을 저장하고 보기 모드로 돌아간다.

02 구성원 드래그
- 미배정 구성원과 각 부서 사이에서 구성원을 이동한다.
- 드래그 중에도 카드 크기와 형태를 유지한다.

03 구성원 제거
- 카드의 `－`를 누르면 확인 dialog가 열린다.
- 기본 조직의 부서에서 제거하면 구성원을 삭제하지 않고 미배정으로 이동한다.
- 처리 후 실행 취소 toast를 제공한다.

04 부서 추가·수정·삭제
- 별도 부서 상세 화면 없이 현재 조직도에서 처리한다.

05 부서장 지정
- 구성원을 부서장으로 임명하기 전 확인 dialog를 표시한다.
- 임명하면 역할과 연결된 권한을 자동으로 부여한다.

06 회장단 구성원 관리
- 회장단 카드 내부에서도 여러 구성원을 추가·이동·제거할 수 있다.
- 회장과 부학생회장 역할이 서로 구분되어야 한다.

────────────────────────────
[ORG-03 구성원 초대 패널 상태]

화면 목적:
학생회 공용 초대 링크를 관리한다.

번호 기능:
01 초대 링크
- 현재 학생회의 공용 초대 링크를 보여준다.

02 링크 복사
- 클립보드에 복사하고 완료 toast를 표시한다.

03 링크 재생성
- 기존 링크가 만료된다는 확인 dialog 후 새 링크를 만든다.

04 뒤로가기
- 미배정 구성원 패널로 돌아간다.

제약:
- 개별 초대 대기 목록은 만들지 않는다.
- 초대받아 가입한 구성원은 미배정 구성원으로 자동 추가된다.

────────────────────────────
[ORG-05 구성원 상세 팝업]

화면 목적:
조직도를 벗어나지 않고 구성원 정보를 간단히 확인한다.

번호 기능:
01 기본 정보
- 이름, 학교, 단과대학, 학부·학과, 학년을 보여준다.

02 조직 정보
- 현재 부서와 역할을 보여준다.

03 부서 이동
- 별도 라디오 목록 대신 조직도를 부서 선택 모드로 전환한다.
- 배정 가능한 부서 테두리를 강조한다.
- 부서를 선택하면 이동하고 실행 취소 toast를 제공한다.

제약:
- 별도 구성원 상세 페이지나 긴 오른쪽 패널을 만들지 않는다.
- 팝업 바깥 클릭 시 닫힌다.

[INV-01 초대받은 학생회 확인]

번호 기능:
01 학생회 정보
- 학생회명, 유형, 대표 범위, 임기를 보여준다.

02 개인 소속
- 사용자의 현재 개인 소속을 보여준다.

03 개인 소속 수정
- 잘못된 개인 소속을 수정한다.

04 학생회 참여하기
- 사용자를 해당 학생회의 미배정 구성원으로 추가한다.
- 완료 후 학생회 홈으로 이동한다.

[ORG-07 학생 명단 관리]

화면 목적:
학생회 대표 범위 안의 전체 학생과 학생회비 상태를 하나의 명단에서 관리한다.

주요 사용자:
학생회장, 관리자, 학생회비 반영 권한자

진입 경로:
사이드바 조직 관리 → 학생 명단

번호 기능:
01 관리 범위 안내
- 학생회 생성 시 선택한 대표 범위를 고정 정보로 보여준다.
- 예: `한양대학교 ERICA › 소프트웨어융합대학 › 컴퓨터학부`
- 이 화면에서 대표 범위를 변경할 수 없다.

02 학생 명단 갱신
- 중앙 modal에서 엑셀 양식 다운로드, 파일 업로드, 오류 확인, 최종 반영을 처리한다.

03 학생회비 내역 반영
- 중앙 modal에서 납부 자료를 업로드하고 통합 학생 명단과 대조한다.
- 납부 파일은 학생회비 상태를 갱신하기 위한 입력 자료다.

04 명단 내보내기
- 현재 필터와 관리 범위에 맞는 명단을 내보낸다.

05 검색·필터
- 이름·학번 검색, 학년, 학생회비 상태 필터를 제공한다.
- 대표 범위가 넓으면 단과대학과 학부·학과 필터를 자동 추가한다.

06 통합 학생 명단
- 전체 학생 명단과 학생회비 납부 명단을 별도 화면으로 나누지 않는다.
- 각 학생 행에 학생회비 상태를 함께 표시한다.

07 학생회비 상태
- 미확인, 납부 확인, 미납, 확인 필요를 사용한다.
- 학번을 주 기준, 이름을 보조 기준으로 대조한다.
- 학번은 같지만 이름이 다르면 `확인 필요`다.

08 범위 제한
- 대표 범위 밖 학생은 오류 목록에 표시하고 명단에 추가하지 않는다.
- 납부 파일에만 있는 학생도 자동으로 추가하지 않는다.

09 행사 설문 연결
- 참여 설문의 학번을 이 명단과 연결한다.
- 납부 확인은 납부자 참가비, 미납은 미납자 참가비를 적용한다.
- 확인 필요 또는 명단 없음은 참가비 미확정 후 관리자 확인으로 처리한다.
```

# 화면정의서 최종 형태 예시

각 Section은 아래 구조로 보이면 됩니다.

```text
┌──────────────────────── 기존 와이어프레임 ────────────────────────┐   ┌──────── 화면 정의 패널 ────────┐
│  01 ○ 화면 요소                                                   │   │ ORG-03 조직 관리 메인           │
│                                                                   │   │ 목적 / 사용자 / 경로            │
│            02 ○ 조직도                                            │   │                                │
│                                                                   │   │ 01 수정 버튼                    │
│                                  03 ○ 미배정 패널                  │   │ - 수정 모드 진입                │
│                                                                   │   │ - 버튼이 완료로 변경            │
└───────────────────────────────────────────────────────────────────┘   │                                │
                                                                        │ 02 구성원 카드                  │
                                                                        │ - 클릭: 정보 팝업               │
                                                                        │ - 수정 모드: 드래그 가능         │
                                                                        └────────────────────────────────┘
```

실제 Figma에서는 위 예시의 긴 텍스트를 프레임 안에 넣지 말고, 번호 pin과 오른쪽 정의 패널로 분리합니다.
