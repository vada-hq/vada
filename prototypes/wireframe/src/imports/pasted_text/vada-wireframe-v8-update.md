현재 작성되어 있는 **VADA 와이어프레임 v7**을 기반으로 다음 요구사항을 반영한 **v8 수정본**을 만들어줘.

이 작업은 전체 디자인을 새로 만드는 작업이 아니다. 기존 화면의 시각 스타일, 컴포넌트, 좌측 화면 탐색 목록, 상단 툴바, 화면정의서 패널 구조를 최대한 유지하면서 아래에서 명시한 화면과 흐름만 정확히 수정해줘.

# 1. 서비스와 사용자에 대한 전제

VADA는 학생회가 조직, 업무, 회의, 행사, 참여자, 학생 명단을 함께 관리하는 운영 서비스다.

내부 사용자는 학생회장, 부학생회장, 부서장, 부원 등 학생회 구성원이다. 외부 사용자는 행사에 참여하는 일반 학생이며, 외부 학생은 회원가입·로그인·앱 설치 없이 모바일 웹으로 참여 설문과 QR 참석 확인을 이용한다.

한 사용자는 하나의 학생회에만 속한다.

이번 범위에는 학생회 조직, 행사 운영 조직, 학생 명단, 학생회비 납부 상태, 행사 설문, 참가자, 참석 확인이 포함된다. 구매, 영수증, 결산, 감사 등 별도의 재정 워크스페이스는 만들지 않는다.

# 2. 반드시 유지할 공통 UX 원칙

- 짧은 정보 확인은 작은 popover를 사용한다.
- 긴 검색과 선택은 오른쪽 panel을 사용한다.
- 단계가 있는 업로드나 설정 작업은 중앙 modal을 사용한다.
- 조직 수정은 별도 페이지가 아니라 같은 화면의 수정 모드에서 처리한다.
- 위험한 작업은 확인 dialog를 거친다.
- 작업 완료 후에는 toast 또는 즉각적인 상태 변경을 제공한다.
- 회장단은 한 사람만 표시하는 카드가 아니라, 회장·부학생회장 등 복수의 구성원 카드를 담는 부서형 조직 카드로 유지한다.
- 기본 학생회 조직과 행사 운영 조직은 서로 다른 데이터다. 행사 조직을 수정해도 기본 조직은 변경되지 않는다.
- 이름, 학번, 소속, 학년을 표시하는 구성원 카드 형식을 모든 조직 화면에서 일관되게 사용한다.
- 기존 화면정의서 토글과 오른쪽 520px 화면정의서 패널을 유지한다.
- 화면을 전환하면 해당 화면의 화면정의서도 자동으로 전환한다.
- 각 화면의 상태 chip과 Annotation Pin 체계를 유지한다.

# 4. 초대 링크 및 초대 코드

## ONB-02 시작 방식 선택 수정

현재 `초대받은 학생회 참여하기`를 선택한 뒤의 흐름이 불명확하다.

다음과 같이 수정한다.

- `새 학생회 만들기` 선택 → ORG-01
- `초대받은 학생회 참여하기` 선택 → ONB-03
- 초대 링크로 직접 접속한 사용자는 ONB-03을 건너뛰고 INV-01로 이동
- 한 사용자가 이미 다른 학생회에 참여 중이라면 새 학생회 참여를 제한하고 안내

## ONB-03 초대 코드 입력 신규 화면

온보딩과 동일한 중앙 집중형 레이아웃을 사용한다.

화면 구성:

- 제목: `초대 코드를 입력해 주세요`
- 설명: `학생회 관리자에게 전달받은 초대 코드를 입력하면 학생회 정보를 확인할 수 있습니다.`
- 6~8자리 영문·숫자 초대 코드 입력란
- 예시 placeholder: `AB12CD34`
- 붙여넣기 지원
- `학생회 확인` 버튼
- `이전으로` 버튼

상태 및 오류:

- 존재하지 않는 코드
- 만료되거나 재생성으로 무효화된 코드
- 이미 참여한 학생회
- 다른 학생회에 참여 중인 사용자
- 네트워크 오류
- 정상 코드 확인 시 INV-01로 이동

## ORG-03C 구성원 초대 패널 수정

초대 링크와 초대 코드를 함께 제공한다.

- 공용 초대 링크
- 짧은 초대 코드
- 링크 복사
- 코드 복사
- 초대 정보 재생성
- 링크 또는 코드로 참여한 구성원은 미배정 구성원으로 등록된다는 안내

링크와 코드는 별도 초대 체계가 아니다. 하나의 동일한 초대 권한을 두 가지 형식으로 제공한다.

`초대 정보 재생성`을 실행하면 기존 링크와 기존 코드가 모두 즉시 무효화된다. 실행 전 확인 dialog를 표시한다.

# 5. 학생회 생성 정보 단순화

## ORG-01 새 학생회 생성 수정

기존의 `기수·임기명`과 임기 시작일·종료일 입력을 제거한다.

입력 항목은 다음과 같다.

- 학생회 유형
- 대표 범위
- 학생회명
- 운영 연도

운영 연도는 연도 단위 selector로 제공한다. 기본값은 현재 연도다.

예:

- 학생회명: `제12대 소프트웨어융합대학 학생회`
- 운영 연도: `2026년`

학생회명 안에 `제12대` 등의 표현이 포함될 수 있으므로 별도의 기수 입력란을 만들지 않는다.

운영 연도는 학생회 기록과 구분을 위한 기준값으로 사용한다. 사용자가 별도로 날짜 범위를 입력하게 하지 않는다.

# 6. 부서 카드 메뉴 정리

## ORG-02 조직 구조 설정 수정

현재 부서 카드에 노출된 `수정`, `삭제` 버튼을 제거한다.

각 부서 카드 우측 상단에 `…` 더보기 버튼을 배치하고 다음 메뉴를 제공한다.

- 부서명 수정
- 부서 삭제

부서명 수정은 인라인 편집으로 처리한다.

- Enter: 저장
- Esc: 취소
- 공백 이름 오류
- 중복 부서명 오류

삭제는 확인 dialog를 거친다.

기존의 `부서명을 더블 클릭하면 편집` 방식은 제거한다. 수정 진입 방식을 더보기 메뉴 하나로 통일한다.

가능하면 ORG-03B와 EVT-03B의 부서·팀 카드에도 같은 더보기 메뉴 패턴을 적용해 편집 방식의 일관성을 유지한다.

# 7. 학생 명단과 학생회비 데이터 구조 변경

학생 명단 업로드의 목적을 정확하게 반영해야 한다.

이 파일은 기존 학생 명단과 학생회비 납부 파일을 대조하기 위한 보조 자료가 아니다. 업로드한 전체 학생 명단 자체가 앞으로 행사 신청자를 대조할 기준 데이터가 된다.

데이터 흐름:

`전체 학생 명단 업로드 → 학생별 학생회비 납부 여부 저장 → 행사 참여 설문 제출 → 학번 기준 대조 → 참가비 및 확인 상태 결정`

## ORG-07A 학생 명단 관리 수정

상단 action을 다음과 같이 변경한다.

- 학생 명단 업로드·갱신
- 명단 내보내기

기존의 `학생회비 내역 반영` 버튼은 제거한다.

학생 표의 주요 열:

- 이름
- 학번
- 단과대학
- 학부·학과
- 학년
- 학생회비 상태

학생회비 상태의 기본값은 다음 두 가지다.

- 납부
- 미납

파일 누락이나 데이터 오류처럼 정상적으로 판단할 수 없는 경우에만 `확인 필요`를 사용한다.

검색과 필터:

- 이름·학번 검색
- 단과대학
- 학부·학과
- 학년
- 학생회비 납부 여부

## ORG-07B 학생 명단 업로드·갱신 모달 수정

업로드 파일에 포함되는 정보:

- 이름
- 학번
- 단과대학
- 학부·학과
- 학년
- 학생회비 납부 여부

업로드하는 파일 자체가 전체 학생 관리 명단이므로 기존 명단과의 대조 결과 화면을 만들지 않는다.

제거할 항목:

- 기존 명단과의 일치·미일치 대조
- 학생회비 납부 파일과 기존 명단 비교
- 이름 불일치 대조 표
- 추가·변경·제외 예정 인원 비교 화면
- 별도 학생회비 반영 단계

필요한 흐름:

1. 현재 대표 범위에 맞는 명단 양식 다운로드
2. 전체 학생 명단 파일 업로드
3. 파일 형식 검증
4. 정상 데이터 반영

파일 검증과 명단 대조를 혼동하지 않는다.

파일 검증에서 확인할 항목:

- 필수 열 누락
- 이름 또는 학번 누락
- 학번 형식 오류
- 중복 학번
- 대표 범위 밖 학생
- 학생회비 상태값 오류

정상 파일이라면 복잡한 결과 화면 없이 바로 반영할 수 있게 한다. 오류가 있을 때만 오류 항목과 수정 방법을 보여준다.

명단 재업로드 시 학번을 기준으로 최신 상태를 갱신한다. 행사 참가자와 과거 행사 기록은 삭제하지 않는다.

기존 ORG-07C 화면과 화면정의서는 완전히 제거한다.

# 8. 행사 생성 흐름 변경

행사는 모든 정보가 결정된 다음 만드는 것이 아니다.

실제 업무 흐름은 다음과 같다.

`행사 아이디어 발생 → 행사 공간 생성 → 회의·업무 진행 → 행사 정보 점진적 확정 → 참여 설문 → 행사 운영`

따라서 행사 생성 시 일시, 장소, 참가비, 모집 정원, 운영 조직 등을 강제로 입력하지 않는다.

## EVT-00 새 행사 만들기 모달 신규

행사 목록의 `새 행사 만들기` 버튼을 누르면 중앙 modal을 연다.

입력값:

- 행사명 또는 가칭

버튼:

- 취소
- 행사 만들기

행사명만 입력하면 행사 워크스페이스를 생성하고 EVT-02 행사 개요로 이동한다.

생성자는 임시 행사 담당자로 자동 설정할 수 있다.

별도의 `기획 중` 상태 chip은 만들지 않는다. 행사 전까지 기획이 계속되는 것은 자연스러운 상태이므로 사용자가 상태를 관리하게 하지 않는다.

아직 정해지지 않은 정보는 개별 항목에 `미정`이라고 명확하게 표시한다.

## EVT-01 행사 운영 조직 설정 수정

이 화면을 `행사 만들기 2단계`에서 제거한다.

행사 공간 생성에 필수인 화면이 아니라, 생성된 행사 워크스페이스 안에서 필요할 때 설정하는 선택적 화면으로 변경한다.

진입 경로:

- EVT-02 행사 개요의 운영 조직 카드
- EVT-03A 운영 조직 탭
- `운영 조직 설정` 버튼

유지할 기능:

- 기본 조직 불러오기
- 참여 부서만 선택
- 빈 조직
- 행사 책임자 지정
- 행사 전용 팀·부서 설정
- 기본 학생회 조직과 별도 데이터라는 안내

# 9. 행사 개요 대시보드 개편

## EVT-02 행사 개요 수정

행사 정보를 단순히 나열하는 화면이 아니라, 현재 데이터를 해석하고 운영진에게 다음 행동을 알려주는 대시보드로 만든다.

전체 행사 준비도를 근거 없는 하나의 퍼센트로 표현하지 않는다.

대신 의미가 명확한 숫자와 상태를 사용한다.

예:

- 업무 12개 중 7개 완료
- 모집 정원 200명 중 142명 신청
- 입금 미확인 13명
- 담당자 없는 업무 2개
- 미정 정보 3개

### 상단 요약

행사 데이터를 기반으로 한 문장의 상황 요약을 표시한다.

행사 정보가 미정인 경우 예시:

`행사 일시와 장소가 아직 정해지지 않았습니다. 이번 주 마감 업무 4개 중 1개는 담당자가 없습니다.`

모집 중 예시:

`모집 마감까지 3일 남았습니다. 정원 200명 중 142명이 신청했고, 명단 확인이 필요한 신청자가 6명 있습니다.`

행사 직전 예시:

`행사까지 하루 남았습니다. 참가자 186명 중 173명이 납부 확인되었고, 현장 역할 2개가 미배정 상태입니다.`

### 행사 기본 정보 카드

다음 정보를 표시한다.

- 행사명
- 일시
- 장소
- 참여 대상
- 참가비
- 모집 정원
- 신청 기간
- 행사 설명
- 문의 방법

정해지지 않은 정보는 빈칸 대신 `미정`으로 표시한다.

`정보 입력·수정` 버튼을 누르면 EVT-02B 오른쪽 패널을 연다.

### 상황에 따라 우선순위가 달라지는 대시보드

별도의 수동 상태를 만들지 않고 현재 데이터를 통해 우선순위를 자동으로 바꾼다.

참여 설문 활성화 전:

- 미정인 행사 정보
- 다음 회의에서 결정할 항목
- 담당자 없는 업무
- 가까운 회의와 마감 업무
- 설문 활성화를 막는 미완성 조건

모집 중:

- 정원 대비 신청자 수
- 최근 신청 추이
- 모집 마감일까지 남은 기간
- 학생회비 납부자·미납자
- 명단과 일치하지 않는 신청자
- 승인 또는 확인이 필요한 신청자

행사 직전:

- 최종 참가자 수
- 참가비·입금 미확인 인원
- QR 생성 여부
- 체크인 시간
- 현장 역할 미배정
- 완료되지 않은 필수 업무

행사 종료 후:

- 실제 참석자 수
- 불참 및 미확인 인원
- 최종 업무 완료 상태
- 행사 기록과 관련 문서

### 최근 변경 사항

- 행사 정보 변경
- 신규 신청자
- 완료된 업무
- 최근 회의에서 결정된 내용
- 설문 교체
- QR 상태 변경

단순 카드 나열이 아니라, 사용자가 지금 확인하거나 처리해야 할 항목에 바로 이동할 수 있는 action을 제공한다.

# 10. 행사 정보 편집

## EVT-02B 행사 정보 편집 패널 신규

EVT-02 위에 오른쪽 panel로 표시한다.

정보는 한 번에 모두 입력하지 않아도 저장할 수 있다.

입력 가능한 정보:

- 행사명
- 일시
- 장소 또는 온라인 접속 정보
- 참여 대상
- 행사 설명
- 문의 방법
- 참가비 사용 여부
- 학생회비 납부자별 참가비 구분 여부
- 모집 정원 사용 여부
- 신청 기간 사용 여부
- 승인제 여부
- 참석 확인 사용 여부

운영 옵션에 따라 필요한 추가 입력값을 조건부로 노출한다.

예:

- 오프라인 행사 → 일시, 장소
- 온라인 행사 → 일시, 접속 안내
- 참가비 있음 → 참가비 금액과 학생회비 납부자 구분 규칙
- 정원 있음 → 모집 정원과 초과 신청 처리 방식
- 신청 기간 있음 → 시작일과 마감일
- 특정 대상 행사 → 대상 단과대·학부·학과·학년

저장되지 않은 필수 정보가 있어도 행사 공간과 내부 업무 기능은 계속 사용할 수 있다.

이미 참여 설문이 활성화된 상태에서 일시·장소·준비물·문의처를 변경하는 것은 허용한다. 저장 전에 `기존 신청자에게 별도 공지가 필요한 변경입니다`라고 안내하되 변경을 막지 않는다.

참가비, 참여 자격, 개인정보 동의처럼 신청 조건 자체가 달라지는 변경은 기존 설문을 직접 수정하지 않고 새 설문으로 교체하도록 안내한다.

# 11. 참여 설문 생성 조건

## EVT-05 참여 설문 생성·관리 수정

설문을 다음 두 단계로 구분한다.

- 설문 초안 작성
- 설문 링크 활성화

행사 정보가 완성되지 않아도 설문 초안은 작성할 수 있다. 회의와 기획 과정에서 질문을 미리 구성할 수 있어야 한다.

그러나 외부 학생이 접근할 수 있는 설문 링크는 필요한 정보가 모두 준비된 뒤에만 활성화할 수 있다.

버튼 문구는 `설문 링크 생성`보다 `설문 링크 활성화`를 우선 사용한다.

### 설문 운영 조건

행사별로 필요한 정보가 다르므로 관리자가 복잡한 필수조건을 직접 만드는 방식은 사용하지 않는다.

행사 정보에서 선택한 운영 옵션을 기준으로 시스템이 필수조건을 자동 생성한다.

예:

- 오프라인 행사 → 일시·장소 필요
- 참가비 있는 행사 → 참가비 규칙 필요
- 정원 있는 행사 → 모집 정원 필요
- 신청 기간 사용 → 마감일 필요
- 승인제 → 승인 기준 또는 안내 필요
- 특정 대상 행사 → 참여 대상 필요

### 설문 활성화 조건 영역

화면에 다음과 같은 checklist를 표시한다.

- 행사 일시: 입력 완료
- 장소: 미정
- 참여 대상: 입력 완료
- 참가비 규칙: 입력 완료
- 모집 마감일: 미정
- 필수 질문: 설정 완료
- 개인정보 동의: 설정 완료

조건이 부족하면 `설문 링크 활성화` 버튼을 비활성화하고, 어떤 정보가 부족한지 버튼 근처에 명확하게 표시한다.

### 설문 질문

기본 질문:

- 이름
- 학번
- 단과대학
- 학부·학과
- 학년
- 개인정보 동의

이름과 학번은 삭제할 수 없다.

추가 질문 유형:

- 단답형
- 객관식
- 체크박스
- 개인정보 동의

설문 제출 자체가 참여 신청이므로 별도의 `참여 여부` 질문은 만들지 않는다.

### 설문 상태

- 초안
- 활성
- 종료
- 교체됨

`기획 중`이라는 행사 상태는 만들지 않는다.

# 12. 설문 수정 및 교체 정책

설문은 응답이 들어오기 전과 후의 수정 정책이 다르다.

- 초안: 자유롭게 수정
- 활성 상태이지만 응답 0명: 수정 가능
- 응답이 1명이라도 존재: 질문 구조와 신청 조건 직접 수정 불가
- 변경이 필요하면 기존 설문을 종료하고 새 설문으로 교체

응답이 있는 활성 설문에서는 기존 `수정` 대신 `새 설문으로 교체` action을 제공한다.

다음 변경은 설문 교체 대상이다.

- 질문 추가·삭제
- 선택지 변경
- 필수 여부 변경
- 참여 자격 변경
- 참가비 기준 변경
- 개인정보 동의 내용 변경

다음 변경은 설문 교체 대상이 아니다.

- 장소
- 일시
- 준비물
- 행사 설명
- 문의처

이 정보들은 행사 정보에서 최신화하고 기존 신청자에게 학생회가 별도로 공지한다.

단, 기존 신청자에게 영향을 줄 수 있다는 안내는 관리자 화면에 표시한다.

## EVT-05B 기존 설문 교체 모달 신규

모달 내용:

- 현재 설문 응답자 수
- 기존 설문이 종료된다는 안내
- 기존 응답은 삭제하지 않고 보관된다는 안내
- 기존 응답자는 다시 응답해야 한다는 안내
- 새 설문 활성화 시 기존 링크가 종료된다는 안내

새 설문은 기존 질문을 복사한 새로운 초안으로 만들 수 있다. 질문은 복사하되 응답 데이터는 절대 복사하지 않는다.

새 설문 활성화 후:

- 기존 설문 상태 → `교체됨`
- 기존 응답 → 기록으로 보관
- 기존 응답자 → `재응답 필요`
- 새 응답 → 학번을 기준으로 기존 응답자와 연결
- 기존 링크 → 설문 종료 안내와 새 설문 이동 버튼 표시

대시보드와 참가자 명단에 다음 정보를 표시할 수 있다.

- 이전 설문 응답자 84명
- 새 설문 응답자 52명
- 재응답 필요 32명

기존 응답과 설문은 실제로 삭제하지 않는다.

# 13. 행사 참가자와 학생 명단 연결

## EVT-04 행사 참가자 명단 수정

행사 참여 설문이 제출되면 학번을 기준으로 ORG-07A의 전체 학생 명단과 대조한다.

처리 규칙:

- 학번 일치 + 학생회비 납부 → 납부자 참가비 규칙 적용
- 학번 일치 + 학생회비 미납 → 미납자 참가비 규칙 적용
- 학번 일치 + 이름 불일치 → 확인 필요
- 학번이 전체 명단에 없음 → 명단 외 학생 또는 확인 필요
- 동일 학번으로 중복 신청 → 중복 신청 안내
- 이전 설문에만 응답 → 재응답 필요
- 새 설문에 다시 응답 → 최신 응답으로 활성 참가자 등록

참가자 표에 필요한 상태:

- 신청 완료
- 대기 중
- 확인 필요
- 재응답 필요
- 납부 확인
- 미납
- 참석
- 불참
- 참석 미확인

설문이 교체되어도 기존 응답과 참가자 기록을 삭제하지 않는다. 현재 활성 설문의 응답자를 기본 참가자 목록으로 표시하고, 이전 설문 응답자는 `재응답 필요` 필터에서 확인할 수 있게 한다.

# 15. 화면정의서 작성 규칙

모든 화면의 오른쪽 화면정의서 패널을 최신 흐름에 맞게 갱신한다.

각 화면정의서는 반드시 다음 구조를 사용한다.

1. 화면 ID
2. 화면명
3. 화면 상태
4. 화면 목적
5. 주요 사용자
6. 진입 경로
7. 진입 조건
8. 기능 정의
9. 상태 및 예외 처리
10. 연결되는 다음 화면
11. 공통 UX 원칙

기능 정의는 번호가 있는 표 형식으로 작성한다.

열 구성:

- 번호
- UI 요소
- 기능 설명 및 제약

새로 추가된 화면의 화면정의서 핵심 내용은 다음과 같다.

## ONB-03 화면정의서

- 화면 목적: 초대 코드를 입력해 참여할 학생회를 확인한다.
- 주요 사용자: 초대 코드를 전달받은 신규 구성원
- 진입 경로: ONB-02 → 초대받은 학생회 참여하기
- 진입 조건: 로그인 및 개인 소속 입력 완료
- 주요 기능: 코드 입력, 코드 검증, 학생회 조회, 오류 안내
- 다음 화면: INV-01

## EVT-00 화면정의서

- 화면 목적: 최소한의 정보로 행사 작업 공간을 즉시 생성한다.
- 주요 사용자: 학생회장, 행사 기획자
- 진입 경로: 행사 목록 → 새 행사 만들기
- 진입 조건: 행사 생성 권한
- 주요 기능: 행사명 입력, 행사 공간 생성
- 제약: 일시·장소·참가비·운영 조직 입력을 강제하지 않음
- 다음 화면: EVT-02

## EVT-02B 화면정의서

- 화면 목적: 회의와 업무 과정에서 결정된 최신 행사 정보를 점진적으로 반영한다.
- 주요 사용자: 행사 책임자와 편집 권한이 있는 운영진
- 진입 경로: EVT-02 → 정보 입력·수정
- 주요 기능: 행사 정보 저장, 운영 옵션 설정, 조건부 입력값 표시
- 예외: 설문 활성화 후 주요 정보 변경 시 별도 공지 필요 안내
- 다음 화면: EVT-02

## EVT-05B 화면정의서

- 화면 목적: 응답이 존재하는 기존 설문을 종료하고 새로운 설문으로 교체한다.
- 주요 사용자: 행사 책임자, 설문 관리 권한자
- 진입 경로: EVT-05 → 새 설문으로 교체
- 주요 기능: 영향 인원 안내, 새 설문 초안 생성, 기존 설문 종료, 응답 보관
- 제약: 기존 응답을 삭제하지 않음
- 다음 화면: EVT-05 새 설문 초안

ORG-07A와 ORG-07B의 화면정의서에서는 `기존 명단과 학생회비 파일 대조`라는 설명을 모두 제거한다.

EVT-01의 화면정의서에서는 `행사 생성 2단계`라는 표현을 제거한다.

EVT-02의 화면정의서에서는 `단순 행사 정보 요약`이 아니라 `행사 데이터를 해석하고 현재 필요한 행동을 보여주는 대시보드`라고 목적을 수정한다.

# 16. 반드시 피해야 할 결과

- 행사 생성 시 일시·장소·참가비·조직 설정을 강제하지 않는다.
- `기획 중`이라는 수동 행사 상태를 만들지 않는다.
- 행사 전체 진행도를 근거 없는 하나의 퍼센트로 표시하지 않는다.
- 미정 정보를 빈칸으로 방치하지 않고 `미정`이라고 표시한다.
- 학생 명단 업로드 시 존재하지 않는 비교군과 대조하지 않는다.
- 학생회비 반영 전용 ORG-07C 화면을 남기지 않는다.
- 학생 명단 파일과 학생회비 파일을 별도 업로드 흐름으로 분리하지 않는다.
- 링크와 코드를 서로 다른 초대 권한으로 생성하지 않는다.
- 응답이 존재하는 활성 설문을 직접 수정하지 않는다.
- 기존 설문과 응답을 실제로 삭제하지 않는다.
- 장소·일시 변경만으로 설문 전체를 교체하지 않는다.
- 설문 초안 작성과 외부 링크 활성화를 같은 행동으로 취급하지 않는다.
- 설문 링크가 활성화되기 전에 필요한 정보가 무엇인지 모호하게 두지 않는다.
- 재정·결산 워크스페이스를 새로 만들지 않는다.

# 17. 최종 검수

작업 완료 후 다음을 확인해줘.

- 좌측 화면 탐색 목록이 최종 26개 화면 및 상태와 일치하는가
- 제거된 ORG-07C가 어디에도 남아 있지 않은가
- 모든 이전·다음 화면 연결이 새로운 흐름과 일치하는가
- 신규 화면과 변경 화면의 화면정의서가 작성되어 있는가
- 화면정의서의 다음 화면 ID가 실제 화면 목록과 일치하는가
- 초대 링크와 초대 코드가 동일한 초대 권한으로 표현되었는가
- 행사명만으로 행사 공간을 생성할 수 있는가
- 행사 정보의 미정 상태가 명확하게 보이는가
- 대시보드가 단순 카드 나열이 아니라 현재 상황과 다음 행동을 보여주는가
- 학생 명단이 행사 설문 대조의 기준 데이터로 표현되었는가
- 설문 초안과 설문 링크 활성화가 구분되어 있는가
- 응답이 존재하는 설문은 교체 흐름을 통해서만 변경되는가
- 기존 설문과 기존 응답이 삭제되지 않고 보관되는가
- 외부 모바일 화면에서도 최신 흐름과 예외 상태가 반영되었는가

기존 VADA의 디자인 톤과 컴포넌트를 유지하면서 위 요구사항이 실제 화면, 인터랙션, 화면 상태, 화면정의서에 모두 동일하게 반영되도록 수정해줘.
