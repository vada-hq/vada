현재 VADA 와이어프레임에 추가된 재정 관리 화면을 검토한 결과에 따라 교정한다.

이번 작업은 신규 기능 확장이 아니라 기존 재정 화면의 데이터, 조건부 입력, 상태 연결, 유효성 검사를 바로잡는 작업이다.

## 작업 범위

다음 4개 화면만 수정한다.

- MY-FIN-01 내 업무 — 재정 처리함
- FIN-01 행사 업무 — 재정부 워크스페이스
- FIN-REQ-01 구매 요청 작성·수정
- FIN-REV-01 구매 요청 상세·검토

기존 화면 ID와 화면 이름을 유지하고 신규 화면을 추가하지 않는다.

## 작업 제외 범위

- 신규 화면을 만들지 않는다.
- 화면정의서를 새로 추가하지 않는다.
- 기존 화면정의서 내용을 수정·갱신·재생성하지 않는다.
- SPEC_DATA 등 화면정의서용 데이터를 추가하거나 수정하지 않는다.
- 화면정의서 버튼과 기존 화면정의서 구조는 그대로 둔다.
- 구매·발주·결제·배송·증빙 처리 화면은 아직 만들지 않는다.
- 감사보고서 생성 기능, 버튼, 문구, 화면을 추가하지 않는다.
- 전체 재정 대시보드를 추가하지 않는다.
- `행사 > 재정` 메뉴를 추가하지 않는다.
- 반응형 대응, 모바일 화면, 시각적 고도화, 디자인 폴리싱은 하지 않는다.
- 기존 재정 화면과 직접 관계없는 다른 화면은 수정하지 않는다.
- 기존 화면 전체를 재작성하지 말고 필요한 부분만 최소한으로 수정한다.

## 1. 재정 데이터 일원화 및 금액 오류 수정

4개 화면에서 서로 다른 예시 데이터를 하드코딩하지 말고, 동일한 구매 요청 데이터를 함께 사용하도록 한다.

구매 요청의 전체 요청액은 항상 품목별 요청액 합계로 자동 계산한다.

예시 구매 요청 `REQ-001`의 품목 데이터는 다음과 같이 통일한다.

- 박스테이프 / 5개 / 총 10,000원
- 생수 500ml / 10박스 / 총 50,000원
- 이름표 용지 / 200장 / 총 60,000원
- 유성 마커 / 10개 / 총 15,000원
- 전체 요청액 / 135,000원

모든 화면에서 기존 `325,000원`을 위 데이터에 맞게 `135,000원`으로 변경한다.

`유성 매크` 오타는 `유성 마커`로 수정한다.

품목 추가·삭제·수량·단가 수정 시 품목 금액과 전체 요청액이 자동으로 다시 계산되어야 한다.

FIN-01의 예산 요약은 계산 관계가 이해되도록 다음 항목으로 구성한다.

- 배정 예산: 3,000,000원
- 승인·집행 예정액: 1,100,000원
- 실제 지출액: 950,000원
- 사용 가능액: 950,000원

계산식:

`사용 가능액 = 배정 예산 - 승인·집행 예정액 - 실제 지출액`

검토 대기 건수는 금액 카드와 분리하여 작은 상태 요약으로 표시한다.

## 2. MY-FIN-01 재정 처리함 교정

여러 행사의 재정 요청을 처리하는 통합 목록이라는 현재 목적을 유지한다.

다음 필터가 실제 목록 데이터에 적용되도록 수정한다.

- 전체
- 검토 필요
- 구매 필요
- 증빙 필요
- 긴급

필터를 선택하면 해당 상태의 요청만 표시한다. 해당 요청이 없으면 기존 요청을 그대로 보여주지 말고 빈 상태를 표시한다.

검색창에서는 다음 항목을 검색할 수 있게 한다.

- 행사명
- 요청 제목
- 요청 부서
- 요청자

상단 요약 카드와 실제 목록 데이터가 일치하도록 한다.

`보완 후 재검토 1건`이 표시된다면 목록에도 반드시 재검토 대상 요청 1건을 포함하고, 행동 버튼은 `재검토하기`로 표시한다.

목록의 행동 버튼 연결을 유지한다.

- 검토하기 → FIN-REV-01
- 재검토하기 → FIN-REV-01의 재검토 상태
- 구매 요청 수정이 필요한 사용자 상태 → FIN-REQ-01 수정 상태

기존 `기타 배정 업무` 영역은 유지하되 재정 처리 목록보다 강조되지 않게 한다.

## 3. FIN-01 행사별 재정부 워크스페이스 교정

`행사 > 업무` 안에서 재정부원이 보는 화면이라는 현재 정보 구조를 유지한다.

행사 메뉴는 다음 구조를 그대로 유지한다.

- 개요
- 업무
- 관련 회의
- 일정
- 인원 관리
- 문서

별도의 `재정` 탭을 추가하지 않는다.

다음 기능을 유지하고 실제 데이터와 연결한다.

- 처리 단계 보기
- 전체 목록 보기
- 구매 요청 카드 선택 → FIN-REV-01
- 새 구매 요청 → FIN-REQ-01
- 예산 요약
- 검토 대기 건수

처리 단계 칸반은 다음 상태를 사용한다.

- 검토 필요
- 구매 필요
- 증빙 필요
- 정산 완료

카드가 지나치게 좁아 제목, 부서, 금액, 필요일, 상태가 세로로 깨지지 않도록 한다.

현재 미리보기 폭에서 4열 칸반의 가독성을 확보하기 어렵다면 다음 중 하나로 처리한다.

- 칸반 영역만 가로 스크롤 허용
- 열의 최소 너비 지정
- 기본 보기를 전체 목록으로 설정

카드에는 최소한 다음 정보를 읽을 수 있게 표시한다.

- 요청 제목
- 요청 부서
- 품목 수
- 전체 요청액
- 필요한 날짜
- 현재 상태

## 4. FIN-REQ-01 구매 요청 작성·수정 교정

이 화면의 기본 사용자는 재정부원이 아니라 구매를 요청하는 일반 부서원으로 변경한다.

예시 사용자:

- 이름: 박해랑
- 소속: 운영부
- 역할: 부원
- 요청 부서: 운영부, 자동 입력 및 읽기 전용

재정부원이 다른 부서를 대신해 요청을 작성하는 기능은 이번 작업에서 구현하지 않는다.

한 요청에 여러 품목을 추가할 수 있는 현재 구조는 유지한다.

각 품목에서 다음 정보를 구분한다.

- 품목 카테고리
- 예산 항목
- 구매 유형

`품목 카테고리`와 `예산 항목`은 서로 다른 값으로 관리한다.

### 구매 유형별 조건부 입력

구매 유형을 선택하면 해당 품목 카드 안에 유형별 상세 입력이 실제로 나타나야 한다.

#### 일반 구매

- 판매처 또는 쇼핑몰
- 상품 URL
- 상품 옵션 또는 규격
- 수량
- 단위
- 예상 단가
- 배송 요청사항

#### 제작·인쇄

- 제작물 종류
- 사이즈 또는 규격
- 색상
- 인쇄 위치
- 인쇄 방식
- 옵션별 수량
- 납품 희망일
- 디자인 파일
- 인쇄용 최종 파일
- 참고 이미지
- 제작 요청사항

사이즈·색상에 따라 수량이 달라지는 경우를 입력할 수 있도록 간단한 옵션 조합 목록을 제공한다.

예:

- M / 검정 / 20개
- L / 검정 / 30개
- XL / 흰색 / 10개

#### 대여·용역

- 업체 또는 제공자
- 대여·용역 기간
- 수행 장소
- 수령 또는 시작 일시
- 반납 또는 종료 일시
- 포함 항목
- 담당자 연락처
- 요청사항

### 견적 정보

견적서는 구매 유형으로 취급하지 않는다.

각 품목에 다음과 같은 별도 견적 상태를 둔다.

- 미요청
- 요청 중
- 수령 완료

`수령 완료`를 선택한 경우 다음 입력을 표시한다.

- 견적 업체
- 견적 금액
- 견적서 파일
- 견적 유효기간
- 비고

### 필수값 검증

다음 정보가 없으면 구매 요청을 제출할 수 없게 한다.

요청 단위:

- 요청 제목
- 필요한 날짜
- 구매 목적
- 한 개 이상의 품목

품목 단위:

- 품목명
- 품목 카테고리
- 예산 항목
- 구매 유형
- 수량
- 단위
- 예상 단가
- 구매 유형별 필수 상세 정보

필수값이 누락되면 해당 입력 근처에 오류를 표시하고 누락된 첫 항목으로 이동한다.

빈 요청이 제출되어 FIN-01로 이동하는 현재 동작을 제거한다.

`임시 저장`은 필수값이 완성되지 않아도 가능하게 한다.

보완 요청을 받은 구매 요청을 수정하는 경우 동일한 FIN-REQ-01을 재사용한다.

이때 상단에 다음 정보를 표시한다.

- 보완 요청 상태
- 보완 대상 품목
- 재정부의 보완 사유
- 재제출 기한

수정 완료 버튼은 `수정 내용 재제출`로 변경하고, 재제출 후 요청 상태를 `재검토 대기`로 변경한다.

## 5. FIN-REV-01 구매 요청 상세·검토 교정

FIN-REQ-01에서 입력한 품목 데이터와 조건부 상세 정보를 그대로 표시한다.

제작·인쇄 품목을 검토할 때는 다음 정보를 확인할 수 있어야 한다.

- 규격
- 색상
- 인쇄 위치
- 옵션별 수량
- 디자인 파일
- 인쇄 파일
- 참고 이미지
- 견적 정보

품목별 검토 선택지는 현재처럼 다음 세 가지를 유지한다.

- 승인
- 보완
- 반려

### 품목별 승인

승인을 선택하면 승인액의 기본값을 해당 품목 요청액으로 입력한다.

재정부원은 승인액을 수정할 수 있다.

승인액은 0원보다 커야 하며 요청액을 초과하면 경고를 표시한다.

### 품목별 보완

`보완`을 선택한 품목을 정확하게 기억해야 한다.

하단의 `보완 요청`을 누르면 모달에 실제로 보완을 선택한 품목만 표시한다.

현재처럼 생수를 선택했는데 이름표 용지가 표시되는 고정 데이터 오류를 제거한다.

각 보완 품목에는 다음 정보를 입력한다.

- 보완 사유
- 요청자에게 필요한 수정 내용

보완 사유가 비어 있으면 `보완 요청 발송` 버튼을 비활성화한다.

재제출 기한은 선택 입력으로 유지한다.

보완 요청 발송 후 전체 요청 상태를 `보완 요청`으로 변경한다.

FIN-REQ-01에서 요청자가 수정해 다시 제출하면 `재검토 대기`로 변경한다.

### 품목별 반려

반려를 선택하면 반려 사유 입력을 요구한다.

반려 사유가 없으면 최종 처리를 할 수 없게 한다.

### 전체 요청 상태 자동 계산

품목 검토 결과에 따라 요청 전체 상태를 자동 계산한다.

- 모든 품목 미검토 → 검토 대기
- 한 개 이상 보완 → 보완 요청
- 보완 후 요청자가 재제출 → 재검토 대기
- 모든 품목 승인 → 승인 완료
- 승인과 반려가 함께 존재 → 부분 승인
- 모든 품목 반려 → 반려
- 승인과 보완이 함께 존재 → 일부 승인·보완 요청

모든 품목의 검토 결과가 정해지지 않았다면 최종 처리 버튼을 비활성화하고, 미검토 품목 수를 표시한다.

최종 처리 버튼의 문구는 현재 결과에 맞게 변경한다.

- 모두 승인 → 승인 완료
- 보완 포함 → 보완 요청 발송
- 승인과 반려 혼합 → 부분 승인 처리
- 모두 반려 → 반려 처리

처리가 완료되면 MY-FIN-01과 FIN-01의 동일한 구매 요청 상태가 함께 변경되어야 한다.

## 6. 최종 검증 조건

작업 완료 전 다음 항목을 직접 확인한다.

1. 신규 화면이 추가되지 않았는가
2. 전체 화면 수가 35개로 유지되는가
3. 화면정의서와 SPEC_DATA를 수정하지 않았는가
4. 감사보고서 관련 기능이 추가되지 않았는가
5. `행사 > 재정` 탭이 추가되지 않았는가
6. 제작·인쇄 선택 시 조건부 입력이 나타나는가
7. 대여·용역 선택 시 조건부 입력이 나타나는가
8. 여러 품목의 유형을 서로 다르게 선택할 수 있는가
9. 품목 합계와 전체 요청액이 일치하는가
10. 빈 요청이 제출되지 않는가
11. MY-FIN-01 필터가 실제로 목록을 변경하는가
12. 선택한 보완 품목이 보완 요청 모달에 정확히 표시되는가
13. 보완 사유 없이 보완 요청을 발송할 수 없는가
14. 품목 결과에 따라 전체 요청 상태가 자동 계산되는가
15. 내 업무와 행사 업무에서 동일한 요청 상태가 일치하는가
16
