현재 최신 VADA Figma Make 파일을 기준으로 재정부 관련 핵심 와이어프레임과 화면 연결을 추가해 주세요.

이번 작업은 기존 VADA 디자인 시스템, 사이드바, 행사 워크스페이스, 기존 행사·참여 설문·조직 관리 화면을 유지하면서 재정부 업무 화면만 추가하는 작업입니다.

관련 없는 기존 화면을 재생성하거나 수정하지 마세요. 반응형 보정, 세밀한 간격 수정, 화면정의서 작성은 이번 작업에서 제외합니다.

## 핵심 정보구조 원칙

행사 워크스페이스 아래에 `재정` 메뉴를 새로 추가하지 않습니다.

기존 메뉴 구조를 유지합니다.

```text
행사
├─ 개요
├─ 업무
├─ 관련 회의
├─ 일정
├─ 인원 관리
└─ 문서
```

재정부원이 행사 워크스페이스에서 `업무`를 선택하면 일반 업무 보드 대신 해당 행사의 재정부 업무 워크스페이스를 보여줍니다.

- 일반 부서원: 기존 부서 업무 화면 유지
- 재정부원: FIN-01 재정부 업무
- 회장단·행사 책임자: 기존 전체 업무 현황 유지

전체 메뉴의 `내 업무`에서 재정부원은 여러 행사의 재정 처리 항목을 통합한 MY-FIN-01을 봅니다.

재정부원이 아닌 사용자는 재정부 전체 화면에 접근할 수 없지만, 자신이 작성한 구매 요청의 상태와 보완 요청은 확인할 수 있어야 합니다.

## 감사보고서 기능 제거

다음 기능은 만들지 않습니다.

- 감사보고서 생성
- 감사보고서 초안
- 감사보고서 검토
- 감사보고서 확정
- 감사보고서 만들기 버튼

기존 파일에 관련 화면이나 버튼, 화면 목록, 경로가 있다면 제거합니다. 구매 요청의 처리 기록은 유지하되 별도 감사보고서를 생성하지 않습니다.

## 추가할 화면

### 1. MY-FIN-01 내 업무 — 재정 처리함

재정부원이 여러 행사에서 자신에게 배정된 재정 업무를 한곳에서 처리하는 화면입니다.

기존 VADA 사이드바와 `내 업무` 헤더를 유지합니다. 별도의 `일반 업무 / 재정 업무` 하위 메뉴를 만들지 말고 재정 처리함을 화면의 중심으로 보여주세요.

상단 요약:

- 내 승인 대기
- 보완 후 재검토
- 구매 기한 임박
- 증빙 누락
- 지연된 처리

필터:

- 전체
- 검토 필요
- 구매 필요
- 증빙 필요
- 긴급
- 행사
- 처리 담당자
- 키워드 검색

목록은 칸반보다 행 단위의 처리 목록으로 구성합니다.

각 항목에 표시:

- 행사명
- 구매 요청 제목
- 요청 부서
- 품목 수
- 요청액 또는 승인액
- 현재 처리 상태
- 필요한 날짜
- 사용자가 지금 해야 할 행동
- 긴급 또는 지연 표시

예시 항목:

1. `2026 체육대회 · 체육대회 운영 물품 4종`
   - 운영부
   - 요청액 325,000원
   - 품목 3개 승인, 1개 보완 필요
   - 내가 할 일: 재검토

2. `봄 축제 · 현수막 제작`
   - 홍보부
   - 승인액 180,000원
   - 구매 기한 오늘
   - 내가 할 일: 구매 등록

3. `신입생 행사 · 명찰 인쇄`
   - 실제 결제 75,000원
   - 영수증 미등록
   - 내가 할 일: 증빙 확인

검토 관련 항목을 선택하면 FIN-REV-01로 이동합니다.

구매·배송·증빙 관련 항목은 2차 작업에서 FIN-PROC-01로 연결할 예정이므로, 이번에는 `처리 화면 준비 중` 상태로 연결하거나 버튼만 배치합니다.

재정부원이 맡은 일반 행사 업무가 있다면 화면 하단에 `기타 배정 업무`로 2~3건만 보조 표시합니다. 별도 하위 공간은 만들지 않습니다.

### 2. FIN-01 행사 업무 — 재정부 워크스페이스

진입 경로:

```text
운영 → 행사 → 2026 소프트웨어융합대학 체육대회 → 업무
```

기존 행사 워크스페이스 탭을 그대로 유지하고 `업무`를 활성화합니다.

브레드크럼과 화면명:

```text
운영 > 행사 > 2026 소프트웨어융합대학 체육대회 > 업무
재정부 업무
```

`재정`이라는 별도 행사 탭을 만들지 마세요.

상단 행사 맥락:

- 행사명
- 상태
- 행사일
- D-day
- 최근 일정 변경
- 긴급 공지

재정 요약:

- 배정 예산: 3,000,000원
- 아직 결제되지 않은 승인액: 1,100,000원
- 실제 지출액: 950,000원
- 사용 가능액: 950,000원
- 검토 대기: 4건
- 증빙 누락: 2건

금액의 의미를 구분합니다.

- 요청액: 요청자가 예상한 금액
- 승인액: 재정부가 허용한 금액
- 결제액: 실제로 지출한 금액

사용 가능액은 승인액과 결제액을 중복 차감하지 않도록 표시합니다.

본문에는 다음 보기 전환을 제공합니다.

```text
[처리 단계] [전체 목록]
```

기본 화면은 `처리 단계`입니다.

처리 영역:

- 검토 필요
- 구매 필요
- 증빙 필요
- 정산 완료

이 영역은 별도 하위 메뉴가 아니라 동일 화면 안의 처리 필터입니다.

카드는 품목 하나가 아니라 구매 요청 단위로 표시합니다.

예시 카드:

```text
체육대회 운영 물품 · 4개 품목
운영부 · 요청액 325,000원
테이프 / 생수 / 이름표 / 마커
3개 승인 · 1개 보완 필요
필요일 3월 15일
```

다른 예시:

```text
현수막 A형 제작 · 제작·인쇄
홍보부 · 견적 180,000원
견적서·디자인 파일 첨부
검토 대기
```

```text
음향 장비 대여 · 대여·용역
기획부 · 예상액 280,000원
이용일 3월 20일
구매 담당자 미배정
```

카드를 선택하면 FIN-REV-01로 이동합니다.

헤더에 `새 구매 요청` 버튼을 제공하고 FIN-REQ-01로 이동시킵니다. 실제 권한 정책은 추후 확정하므로 이번 와이어프레임에서는 버튼만 표현합니다.

### 3. FIN-REQ-01 구매 요청 작성·수정

한 요청에 여러 품목을 등록할 수 있는 전체 페이지 형태로 제작합니다. 작은 우측 패널로 만들지 마세요.

공통 요청 정보:

- 행사
- 요청 제목
- 요청 부서
- 요청자
- 구매 목적
- 필요한 날짜
- 우선순위
- 전체 예상 금액

품목 목록:

- 품목명
- 품목 카테고리
- 예산 항목
- 구매 유형
- 수량과 단위
- 예상 단가
- 예상 총액
- 품목별 필요일
- 현재 입력 상태
- 수정
- 삭제
- 품목 추가

`품목 카테고리`와 `예산 항목`은 별도 필드로 구분합니다.

품목 카테고리 예시:

- 운영 물품
- 제작·굿즈
- 인쇄물
- 식음료
- 대여
- 용역
- 기타

예산 항목 예시:

- 행사 운영비
- 홍보비
- 식비
- 시설·장비비
- 예비비

구매 유형:

- 일반 구매
- 제작·인쇄
- 대여·용역

구매 방식:

- 상품 링크로 직접 구매
- 업체 견적 필요
- 견적서 확보 완료
- 구매처 미정

구매 유형은 각 품목별로 선택하며 선택한 유형에 따라 필요한 입력 영역이 달라지게 합니다.

#### 일반 구매 입력

- 구매 링크
- 상품 옵션
- 수량
- 예상 단가
- 예상 배송일
- 대체 상품 허용 여부

#### 제작·인쇄 입력

- 제작 업체
- 규격
- 소재
- 색상
- 인쇄 위치
- 인쇄 방식
- 디자인 파일
- 참고 이미지
- 시안 확인 필요 여부
- 제작 소요 기간
- 납품 희망일
- 견적서

단체복이나 굿즈는 옵션별 수량 표를 제공합니다.

```text
사이즈 | 색상 | 수량
S      | 검정 | 10
M      | 검정 | 20
L      | 흰색 | 15
```

#### 대여·용역 입력

- 업체
- 이용 시작일
- 이용 종료일
- 반납일
- 보증금
- 설치·철거 포함 여부
- 담당자 연락처
- 견적서 또는 계약서

하단 버튼:

- 취소
- 임시 저장
- 구매 요청 제출

제출 시 FIN-01의 검토 필요 영역에 새로운 요청이 추가되는 흐름을 연결합니다.

보완 요청을 받은 건으로 진입한 경우 수정 요청 내용이 상단에 표시되고, 제출 버튼은 `수정 후 다시 제출`로 변경됩니다.

### 4. FIN-REV-01 구매 요청 상세·검토

전체 페이지 형태로 제작합니다. 기존 420px 상세 패널은 복잡한 구매 검토에 사용하지 않습니다.

상단:

- 구매 요청 제목
- 행사명
- 요청 부서와 요청자
- 요청일
- 전체 요청액
- 필요한 날짜
- 승인 상태
- 긴급도
- 예산 사용 가능액

탭:

- 요청 정보
- 품목 검토
- 첨부파일
- 처리 기록

품목 검토 표:

- 품목명
- 카테고리
- 예산 항목
- 구매 유형
- 수량
- 요청액
- 승인액
- 첨부파일
- 품목별 검토 상태

각 품목은 다음 상태를 가질 수 있습니다.

- 검토 대기
- 승인
- 보완 요청
- 반려

한 요청 안에서 품목마다 다른 결과를 선택할 수 있게 합니다.

예시:

- 테이프: 승인
- 생수: 승인
- 이름표: 보완 요청
- 마커: 승인

이 경우 전체 요청 상태는 자동으로 `부분 승인`으로 표시합니다.

하단 주요 액션:

```text
[반려] [보완 요청] [승인]
```

보완 요청은 토글로 만들지 않습니다.

보완 요청을 선택하면 중앙 모달을 열고 다음을 입력합니다.

- 보완이 필요한 품목
- 보완 내용
- 필요한 추가 자료
- 재제출 기한

반려는 사유 입력을 필수로 합니다.

요청자가 보완 후 다시 제출하면 상태를 자동으로 `재검토 대기`로 변경합니다. 재정부가 누르는 별도의 `재검토` 버튼은 만들지 않습니다.

처리 기록에는 다음을 시간순으로 표시합니다.

- 요청 생성
- 제출
- 보완 요청
- 수정
- 재제출
- 품목별 승인
- 부분 승인
- 반려

## 공통 데이터 원칙

구매 요청 데이터는 한 번만 저장하고 다음 화면에서 같은 데이터를 필터링하여 보여줍니다.

```text
같은 구매 요청
├─ MY-FIN-01: 나에게 배정된 처리 건
├─ FIN-01: 현재 행사의 요청
├─ FIN-REQ-01: 작성·수정
└─ FIN-REV-01: 검토
```

같은 구매 요청을 일반 업무와 재정 업무로 중복 생성하지 마세요.

## 실제 화면 연결

다음 이동을 실제 Figma Make 미리보기에서도 연결합니다.

- 재정부원 기준 `내 업무` → MY-FIN-01
- 재정부원 기준 행사 `업무` → FIN-01
- FIN-01 새 구매 요청 → FIN-REQ-01
- FIN-REQ-01 제출 → FIN-01 검토 필요
- MY-FIN-01 검토 항목 → FIN-REV-01
- FIN-01 요청 카드 → FIN-REV-01
- FIN-REV-01 보완 요청 → 보완 요청 모달
- 보완 요청 완료 → 요청 상태 변경 및 처리 기록 추가
- FIN-REV-01 승인 → FIN-01 구매 필요 영역
- 뒤로가기 → 직전 화면 복귀

## 이번 작업에서 제외

- 주문·배송 세부 등록
- 결제 등록
- 영수증·거래명세서 업로드
- 정산 완료 처리
- 감사보고서
- 모바일 화면
- 세밀한 시각 보정
- 화면정의서 작성·수정
- 관련 없는 기존 화면 수정

## 검수 조건

1. 행사 아래에 재정 메뉴가 새로 생기지 않는다.
2. 재정부원은 행사 `업무`에서 FIN-01을 본다.
3. MY-FIN-01은 여러 행사의 재정 처리 건을 보여준다.
4. FIN-01은 현재 행사 데이터만 보여준다.
5. 한 구매 요청에 여러 품목을 추가할 수 있다.
6. 품목별로 카테고리와 예산 항목을 따로 선택할 수 있다.
7. 구매 유형에 따라 입력 항목이 달라진다.
8. 제작·인쇄 유형에서 옵션별 수량과 디자인 파일을 등록할 수 있다.
9. 품목별 승인·보완 요청·반려가 가능하다.
10. 일부 품목만 승인되면 요청이 부분 승인으로 표시된다.
11. 보완 후 재제출하면 재검토 대기 상태가 된다.
