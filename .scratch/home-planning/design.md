# VADA 홈 화면 기획 논의

작성: 2026-09-26 · 갱신: 2026-10-03  
상태: 조직 상황 우선·전 구성원 눈높이·역할별 구성 확정 / 회장단·부서장·부원·재정부 정보와 겸직 규칙 채택 / 홈 디자인 정리 채택(D-14)  
대상: `HOME-01` 기본 홈, `HOME-01K` 끼룩이 브리핑 검토안

## 1. 문서의 역할

홈의 목적, 대상 사용자, 정보 구성, 채택 이유와 미결정 사항을 함께 기록한다. **최우선 원칙: 사용자가 확정·채택하겠다고 명시한 뒤에만 기획 내용을 문서에 저장한다. 미확정 제안은 대화에서 의논하며 문서에 선저장하지 않는다.** 기존에 저장된 미채택 제안은 과거 논의 자료이며 구현 근거가 아니다.

- **기존 기준**: 현재 프로젝트 문서의 원칙. 변경할 때는 변경 이유를 남긴다.
- **채택**: 이번 논의에서 사용자가 명시적으로 선택한 사항.
- **제안**: 검토할 방향. 구현 근거로 쓰지 않는다.
- **미결정**: 추가 논의가 필요한 선택.
- **보류·기각**: 지금 적용하지 않는 방향과 그 이유.

기획 합의와 구현 완료는 별도로 기록한다. 구체적인 화면 변경 요청 전에는 앱 코드를 수정하지 않는다. 채택한 내용을 구현할 때 관련 화면정의서와 기준 문서를 동기화한다.

### 논의를 이어갈 문서

- **이 문서**: 목표·공통 원칙·채택 결정·변경 이유·논의 이력.
- **[정보 목록 및 회장단 검토](information-inventory.md)**: 11개 영역의 86개 정보 후보, 제공 준비 상태, 회장단에게 필요한 이유, 항목별 채택 상태.
- **[역할별 홈 정보 추천안](role-recommendations.md)**: 회장단·부서장·부원·재정부의 우선 정보·조건부 정보·상세로 넘길 정보와 이유. 겸직 시 검토 사항.

논의할 때 정보 ID 또는 이름으로 대상을 지정한다. 채택·보류·제외를 결정하면 이유와 날짜를 기록하고, 이전 결정을 바꾸면 변경 이유를 남긴다. 다음에 이어갈 지점은 현재 **부서장·부원·재정부 정보의 채택·조건부·제외 선별**이다. 전체 정보 목록의 누락도 함께 보완한다.

## 2. 기존 기준과 확인된 요구

### 기존 기준

- 홈은 학생회 전체 운영 현황을 요약하는 최상위 공간이다. `내 업무`의 상위 공간이 아니다.
- 내 업무는 현재 사용자에게 배정된 업무를 모아 처리하는 개인 공간이다.
- 행사 공간은 특정 행사에 연결된 업무·회의·참가자·재정을 운영하는 공간이다.
- `HOME-01K`의 정식 채택은 아직 결정되지 않았다.
- 증빙 묶음 등 재정 보류 기능을 홈 기획만으로 MVP에 다시 포함하지 않는다.

근거: [인계 문서](../../docs/VADA_HANDOFF.md), [MVP 기준서](../../docs/VADA_MVP_SPEC.md), [재정 보류 범위](../../docs/VADA_FINANCE_DEFERRED.md).

### 사용자에게 직접 확인된 요구

| ID | 요구·문제 | 상태 |
|---|---|---|
| U-01 | 홈의 필요성·편의성과 사용자 이해 난도를 검토하고 싶다 | 논의 출발점 |
| U-02 | 현재 글씨가 너무 작다 | 해결해야 할 사용자 문제. 구체적인 크기·적용 범위는 미정 |
| U-03 | 좋은 홈을 위한 목표를 잡고 채택 사항과 기획 전반을 문서화하며 의논한다 | 진행 방식 채택 |

글자 크기 변경은 아직 적용하지 않았다. 정보 배치 개선 제안이나 끼룩이 유지 제안도 아직 채택되지 않았다.

## 3. 채택한 방향과 목표 초안

**채택: A. 조직 상황 우선 (D-02)**

학생회 전체 행사·일정·문제를 먼저 보여주고 개인 업무는 별도 `내 업무` 공간으로 연결한다. 홈이 조직 상황을 파악하는 공간이라는 기존 원칙을 유지한다.

**채택: 전 구성원 기준 (D-03)**

처음 사용하는 부원도 학생회 전체 상황을 이해할 수 있는 눈높이를 설계 기준으로 삼는다. 회장단·부서장만 이해하는 관리 용어나 상세 지표를 전제로 하지 않는다.

**채택: 역할별로 홈을 다르게 구성 (D-04)**

역할별로 필요한 정보와 우선순위를 먼저 논의하고 홈 구성을 정한다. 전 구성원 기준은 각 역할의 사용자 모두가 이해할 수 있는 눈높이를 뜻하며, 동일한 홈을 제공한다는 뜻은 아니다. 역할 구분·겸직 시 조합·권한별 노출·배치·정보량은 미결정이다.

전체 정보 후보와 회장단 선별 제안은 [정보 목록 및 회장단 검토](information-inventory.md)에서 관리한다. 목록에 있다는 사실이나 추천 등급은 홈 채택 또는 접근 권한 승인을 뜻하지 않는다.

목표 문구 초안:

> 구성원이 여러 메뉴를 돌아다니지 않고 학생회의 중요한 운영 상황과 확인할 대상을 이해하고, 관련 화면으로 이동할 수 있게 한다.

홈에서 답할 질문 후보:

1. 우리 학생회가 지금 준비하거나 운영하는 중요한 행사는 무엇인가?
2. 곧 다가오는 중요한 일정과 마감은 무엇인가?
3. 어떤 문제가 있고, 누가 확인해야 하며, 어디에서 확인할 수 있는가?

조직 전체 상황을 사용자 자신의 행동보다 먼저 보여주는 방향은 확정했다. 위 세 질문 사이의 우선순위와 구체적인 배치는 아직 정하지 않았다.

### 목표 달성 확인 방법 — 제안

| 관점 | 사용자에게 확인할 내용 |
|---|---|
| 상황 파악 | 홈을 보고 지금 중요한 행사와 가까운 일정을 설명할 수 있는가? |
| 관련성 | 표시된 항목이 학생회 전체·소속 부서·본인 중 누구의 것인지 구분하는가? |
| 다음 행동 | 확인할 항목과 담당 주체를 이해하고 관련 화면을 찾아가는가? |
| 숫자 이해 | 건수의 단위, 비율의 계산 기준, 집계 범위를 오해하지 않는가? |
| 가독성 | 실제 사용하는 화면 크기에서 확대 없이 내용을 읽고 버튼을 구별하는가? |
| 편의성 | 홈 없이 각 메뉴에서 찾을 때보다 중요한 상황을 적은 이동으로 파악하는가? |

검증 참가자·인원·시간 기준·통과 기준은 미정이다. 수치 목표를 검증된 사실처럼 두지 않는다.

## 4. 현재 화면에서 관찰한 문제

2026-09-26 Chrome 로컬 화면과 `src/app/App.tsx`의 `HOME01`·`KkirukBriefing`을 확인했다. 실제 사용자 테스트 결과가 아닌 화면·구현 검토다. 검토 도구의 화면 목록 패널은 제품 홈의 정보량과 구분한다.

| 관찰 | 사용자에게 생길 수 있는 어려움 |
|---|---|
| 다수의 보조 글자가 10px, 본문·제목 상당수가 12px로 지정되어 있다 | 읽기 위해 화면에 가까이 가거나 확대해야 함. 사용자가 직접 작다고 지적 |
| 개인 이름을 부른 뒤 조직 전체 지연·미지정 건수를 알려준다 | 본인이 처리할 일로 오해할 수 있음 |
| `준비 62%`의 계산 기준이 화면에 없다 | 실제 행사 준비 수준으로 받아들일 수 있음 |
| `증빙 서류 누락 3건`과 `증빙 누락 5건`이 함께 나온다 | 집계 범위가 불명확하고 숫자에 대한 신뢰가 떨어짐 |
| `참가자 명단 확인 필요 1건`이 행사 수를 나타낸다 | 사람 수인지 명단 수인지 구분하기 어려움 |
| 끼룩이가 지연·미지정 두 항목을 말하지만 행동 버튼은 하나다 | 두 번째 항목으로 바로 이동하기 어려움 |
| 큰 브리핑 배너 아래에 요약 숫자 카드가 다시 이어진다 | 실제 행사와 일정이 첫 화면에서 밀려남 |
| 내 담당 업무 바로가기는 오른쪽 하단에 있다 | 개인 업무를 시작하러 온 사용자가 찾기 어려울 수 있음 |
| 날짜와 여러 수치가 고정 예시다 | 현행 시점이나 다른 화면과의 불일치가 기획 검증을 방해할 수 있음 |

샘플 데이터의 정합성 문제와 홈 자체의 정보 구조 문제는 분리해서 검토한다.

## 5. 다른 서비스에서 참고할 원칙

공식 문서를 바탕으로 한 비교다. 다른 서비스의 구성 자체가 VADA에서의 효과를 입증하지는 않는다.

| 서비스 | 확인한 구성 | 적용 후보 |
|---|---|---|
| [ClickUp My Tasks — 구 Home](https://help.clickup.com/hc/en-us/articles/18944788880791-My-Tasks-page-formerly-Home) | 개인 배정 업무·일정·리마인더·최근 항목 등 | 상태 숫자에서 실제 처리 대상으로 연결 |
| [Notion 사이드바 Home](https://www.notion.com/help/navigate-with-the-sidebar) | 예정 일정·최근 항목·즐겨찾기·팀스페이스 등. 과거 전체 페이지 Home에서 변경 | 일부 핵심 정보와 전체 보기를 구분하고 작업 재개 지원 |
| [monday.com Workspace home](https://support.monday.com/hc/en-us/articles/360010785460-Getting-started-with-workspaces) | 워크스페이스 자료·최근 항목·구성원 등 | 조직 공간과 개인 업무의 범위를 명확히 표시 |

위젯 편집, AI 브리핑, 최근 항목 등은 자동으로 채택하지 않는다. VADA 사용자가 해결할 문제와 연결되는 경우에만 검토한다.

## 6. 논의 순서와 미결정 사항

| 순서 | 질문 | 현재 상태 |
|---|---|---|
| 1 | 홈에서 가장 먼저 해결할 문제는 조직 상황 파악인가, 개인 행동 안내인가? | **A. 조직 상황 우선 채택(D-02)** |
| 2 | 회장단·부서장·부원·재정부 중 누구를 우선 설계 대상으로 삼는가? | **전 구성원 기준 채택(D-03)** |
| 3 | 모두 같은 홈을 보되 일부 항목만 다르게 할 것인가? | **역할별 홈 구성 채택(D-04)**. 역할·겸직 규칙은 미정 |
| 4 | 제공 가능한 정보 중 역할별로 무엇을 보여줄 것인가? | **4개 역할 모두 채택(D-06~D-09)**, 겸직 규칙 채택(D-10) |
| 5 | 중요도·긴급도·사용자 관련성을 어떤 순서로 판단할 것인가? | **목록 정렬·개수·빈 상태 규칙 채택(D-11)** |
| 6 | 클릭 시 어느 대상의 어떤 상태로 이동해야 하는가? | **클릭 이동 규칙 채택(D-12)** |
| 7 | 끼룩이는 필요한가? 필요하다면 어떤 역할과 크기인가? | **상시 브리핑 미채택, 헤더 ‘정리했어요’ 한 줄 채택(D-13)**. 끼룩이 비서는 별도 기획 |
| 8 | 본문·보조 정보·제목의 크기와 대비 기준은 무엇인가? | 작은 글씨 문제 확인, 기준 미정 |
| 9 | 첫 사용·정상 운영·문제 다수·권한 제한 상태를 어떻게 보여줄 것인가? | 첫 사용·0건·미입력·항목 과다 채택(D-11). 권한 제한 상태는 미결정 |
| 10 | 로그인 첫 화면을 홈으로 고정할 것인가? | 미결정 |

### 첫 논의의 선택지와 결과

- **A. 조직 상황 우선**: 학생회 전체 행사·일정·문제를 먼저 보여주고 개인 업무는 명확한 바로가기로 연결한다. 기존 홈 목적을 가장 직접적으로 유지한다.
- **B. 개인 행동 우선**: 본인이 확인·처리할 일을 먼저 보여주고 전체 상황을 보조로 둔다. `내 업무`와의 역할을 다시 정해야 한다.
- **C. 역할에 따라 우선순위 변경**: 회장단은 전체 현황, 일반 구성원은 개인 행동 등을 먼저 보여준다. 공통 구조와 역할별 범위를 추가로 정의해야 한다.

사용자가 A를 확정했다. 이후 조직 상황 우선 목적은 유지하면서 역할별로 홈 구성을 다르게 하기로 했다(D-04). 처음 제시한 C의 예시인 ‘부원은 개인 행동 우선’까지 채택한 것은 아니다.

### 역할별 노출 — 논의 결과

공통 구조에 권한별 버튼만 달리하는 이전 제안은 채택하지 않았다. 사용자는 역할별로 정보 구성을 다르게 하길 선택했다. 기존 열람·행동 권한과 홈 노출 우선순위는 구분하여 검토한다.

## 8. 논의 이력

- **2026-09-26**: 기본 홈과 끼룩이 홈을 비판적으로 검토하고 업무 서비스 3종을 비교했다. 사용자가 작은 글씨 문제를 지적했다. 홈의 필요성과 편의성을 논의한 뒤 기획 문서 관리를 시작했다. 다음 논의는 **홈의 최우선 목적**이다.
- **2026-09-26**: 사용자가 **A. 조직 상황 우선**을 확정했다(D-02). 목표·선택지·논의 상태에 반영했다. 다음 논의는 **우선 설계 대상 사용자**다.
