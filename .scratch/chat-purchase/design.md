# 대화 → 구매 후보 → 구매 요청 기획

작성: 2026-10-10
상태: 방향·핵심 결정 채택(P-01~P-06) · 발전 주제 4건 채택(P-07~P-10) / 세부 흐름은 제안 / 발전 주제 보류 2건 / 결정 사항 8건 미결정
관련: [끼룩이 표현 기획](../kkiruk-presence/design.md), [MVP 기준서](../../docs/VADA_MVP_SPEC.md) §5·§6.1, [재정 명세](../../docs/VADA_FINANCE_SPEC.md), 와이어프레임 `MSG-01~03`(메시지), `FIN-REQ-01B`(구매 요청 작성), `EVT-FIN-01`(행사 재정)

## 1. 문서의 역할

행사 대화에서 오간 상품 링크를 구매 후보로 모으고, 그중 살 것을 골라 구매 요청으로 만드는 흐름을 정한다. 다른 기획 문서와 같은 규칙을 따른다: **사용자가 확정한 것만 `채택`**, 나머지는 `제안`·`보류`·`미결정`으로 둔다.

## 2. 배경

- 개발 쪽 M1 프로토타입(`127.0.0.1:8765`, 사용자 첨부 화면 2장)이 행사 대화방에 올라온 쿠팡 링크를 읽어 `구매 후보` 탭에 모으는 모습을 보여 주었다. **이해를 돕는 참고 화면이며, 그대로 만들 필요는 없다**(사용자 발언).
- 와이어프레임에는 이미 쿠팡 링크로 구매 요청 품목 카드를 채우는 기능이 있다(`FIN-REQ-01B`, 커밋 `c3f85c0`): 품목명·판매처·배송비·배송 정보·옵션 전체 목록 불러오기, 옵션을 고르는 즉시 가격 확정.
- 메시지 화면(`MSG-01~03`)은 와이어프레임에 있으나 MVP 기준서 §5에서 제외되어 있다.
- 끼룩이는 별도 AI 비서로 쓰지 않고 자동화를 보여 주는 표시로만 쓴다(끼룩이 기획 K-01·K-02).

## 4. 세부 흐름 — 제안 (선별 전)

| 항목 | 제안 |
|---|---|
| 링크를 읽는 시점 | 대화에 링크가 올라오는 즉시 읽고 옵션 목록까지 저장한다. 후보 목록에서 이름·가격·옵션 상태가 바로 보인다 |
| 옵션이 정해진 링크 | 링크에 옵션 식별자(`vendorItemId`)가 있으면 그 옵션을 미리 선택하고 바꿀 수 있게 한다. 없으면 `옵션 미정`. 쿠팡에서 옵션을 고른 뒤 복사한 링크에는 이 값이 실제로 붙는다(M1 화면에서 확인). **와이어프레임에서 뺐던 이 경로를 되살린다** |
| 옵션·수량을 정하는 곳 | 구매 요청 카드 한곳에서만 정한다. 후보 목록은 `옵션 미정` 등 상태만 보여 준다(같은 값을 두 곳에서 관리하지 않음) |
| 요청 만들기 | 후보를 골라 `구매 요청 만들기` → 작성 화면이 고른 후보들이 카드로 채워진 상태로 열린다. 가격은 이때 다시 읽고 바뀌었으면 표시한다. 구매 목적에는 끼룩이 초안(P-06)이 들어간다 |
| 권한 | 후보 추가: 대화방 참여자 누구나(부원 포함). 요청 만들기: 부서장·재정부(현행 작성 권한). 부원의 구매 제안이 권한 변경 없이 가능해진다 |
| 후보 상태 | 후보 → `요청에 담김(REQ-xxx)` → 승인·반려·구매 완료. 요청에 담긴 후보는 다시 고를 수 없다(중복 요청 방지) |
| 같은 상품 | 같은 링크는 하나로 합친다(M1의 `외 1번`처럼 올린 사람 표시). 같은 상품이라도 옵션이 다르게 정해진 링크는 별도 후보 |
| 쿠팡 외 링크 | 판매처만 채운 후보로 두고 카드에서 가격을 직접 입력한다 |
| 후보 삭제 | 올린 사람과 부서장만 |

## 6. 미결정 — 아직 정해야 할 것

| # | 결정 | 선택지 / 제안 |
|---|---|---|
| 1 | 어떤 대화방에서 후보를 모으나 | 제안: 행사별 방만 자동 수집. 일반 방에 올라온 링크에는 `어느 행사 후보로 담을지` 고르는 버튼만 |
| 2 | 후보 목록을 어디서 보나 | 대화방 `구매 후보` 탭 + 행사 재정 화면에도 같은 목록(재정부도 보게)할지 |
| 3 | 구매 목적의 단위 | 현행: 요청 1건에 목적 1개 → 끼룩이 초안이 품목 전체를 아우르는 한 문단. 품목별 목적이 필요한지 |
| 4 | 채팅 기본 기능 범위(MVP 필수) | 후보: 알림(모바일 포함)·읽음·사진·파일·답장·멘션·검색. 이동을 강제하므로 카톡 수준이 필요 |
| 5 | 끼룩이 진행 알림 시점 | 제안: 승인·보완 요청·수령 세 시점에만 행사 대화방에 알림 |
| 6 | 링크가 아닌 말 | 제안: 링크 없는 말은 후보로 만들지 않음(끼룩이가 대화를 판단하면 K-01과 충돌) |
| 7 | 행사가 끝난 뒤 남은 후보 | 버린다 / 아카이브에 `검토했지만 사지 않은 것`으로 남긴다 |
| 8 | MVP 기준서 수정 | §5의 `메시지방·실시간 채팅 제외`를 빼고 채팅·구매 후보를 MVP로 올리는 문구. 공식 문서라 수정안을 먼저 확인받는다 |
| — | §4 세부 흐름 | 항목별 채택 여부 |

## 7. 위험

- **채팅 품질이 서비스 핵심 요구사항이 된다.** 이동을 강제하면 불편이 곧바로 이탈 사유가 된다(§6 미결정 4와 연결).
- **끼룩이 초안만으로 쓰는 구매 목적의 형식화.** 초안이 뻔한 문장이 되면 확인 없이 제출되어 구매 이유 기록이 형식만 남을 수 있다. P-06의 조건(근거 없는 이유 금지, 못 찾으면 비움, 확인 후 제출)을 지킨다. 대화 근거 첨부는 이번에 채택하지 않았다(필요해지면 재론).
- **가격 변동.** 링크를 올린 날과 요청하는 날의 가격이 다를 수 있다(§4 요청 만들기에서 다시 읽음).

## 9. 논의 이력

- **2026-10-10**: 사용자가 M1 프로토타입 화면 2장(대화·구매 후보)을 첨부해 대화 링크 → 구매 후보 → 구매 요청 구상을 제시했다. 채팅 이동 위험·MVP 범위·주문 표현·구매 목적 작성·옵션 지정 링크를 검토했다. 사용자가 채팅 이동 강제, MVP 확대, `주문`이 아닌 `구매 요청`, 후보 = 구매 요청 카드, 구매 목적은 끼룩이 초안만을 정했다(P-01~P-06). 이어 발전 가능 주제 중 보완 요청을 대화로·대화에서 업무 만들기·대화 속 결정 기록·후보 단계 예산 보기를 채택하고(P-07~P-10), 작년 구매 기록으로 다시 사기·같은 판매자 묶기는 보류했다. `아직 정해야 할 것` 8건은 미결정이다(§6).
