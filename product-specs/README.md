# AI용 제품 명세 정본

> 지원 구조: `schemaVersion: 1 | 2` · 새 문서와 재검토 문서는 v2 사용

현재 재정 기준선은 `DOMAIN-FIN@R1`과 `FLOW-FIN-001@R2`이며, 두 문서 모두 v2 출처 우선순위 검증을 통과한 승인본입니다. 플로우 R2는 임시 저장을 계정 기반 서버 개인 초안으로 정의하고 저장 실패 복구를 추가했습니다.

`SOLUTION-FIN-001@R1`은 이 두 승인본을 시스템 책임·경계·품질·검증 의도로 연결한 승인 목표 설계입니다. 서버 초안을 정본으로 두고 브라우저 영속 저장을 정본으로 사용하지 않는 방향을 포함합니다. `draft.json`은 승인 전 검토 이력이며 구현 기준선으로 사용하지 않습니다.

`product-specs/`는 AI가 제품 의미를 읽는 구조화 정본입니다. Notion·Figma·대화는 입력 근거이며, 그 내용이 이 폴더의 승인 리비전에 반영되기 전에는 제품 규칙이 아닙니다. 사람용 화면이나 문서는 이 JSON에서 파생하는 VIEW로 취급합니다.

## 문서 계층

- `domains/<DOMAIN-ID>/`: 여러 사용자 흐름이 공유하는 행위자·개념·권한 능력·불변 규칙
- `flows/<FLOW-ID>/`: 한 사용자가 시작부터 관찰 가능한 결과까지 완주하는 흐름·분기·완료 시나리오
- `solutions/<SOLUTION-ID>/`: 승인된 도메인·플로우를 중복하지 않고 시스템 책임·데이터 의미·인터페이스 경계·품질·검증 의도로 연결한 목표 동작 설계
- `schemas/v<n>/`: 특정 구조 버전에 고정된 JSON Schema Draft 2020-12 규칙. 키는 도구 호환성을 위해 영어, 제품 내용은 팀의 기본 언어로 작성합니다.

도메인과 플로우는 제품 의미만 소유합니다. 목표 동작 설계는 승인된 제품 항목을 정확히 참조하고 구현 전 시스템 경계를 제안하지만 제품 정책을 새로 만들지 않습니다. API·DB 테이블·런타임 모듈·태스크·담당자·일정은 제품 의미에 역참조로 넣지 않으며, 후속 계약과 작업 계획이 승인된 제품·설계 리비전을 정방향으로 참조합니다.

## 상태와 리비전

1. 작성·검토 중에는 `draft.json`, `revision: 0`, `status: draft|review`, `approval: null`을 사용합니다.
2. 제품 책임자가 전체 내용을 승인하면 `R1.json`처럼 새 파일로 고정하고 `revision >= 1`, `status: approved`, `approval`을 기록합니다.
3. 승인본은 수정하지 않습니다. 의미 변경은 같은 안정 ID의 새 승인 파일을 만들고 `supersedes`로 바로 이전 승인 리비전을 가리킵니다.
4. `schemaVersion`은 JSON 구조의 버전이고 `revision`은 제품 의미의 버전입니다. 승인 문서는 정확한 `schemas/v<n>/` 경로를 계속 사용하며, 새 구조는 기존 스키마를 덮어쓰지 않고 새 버전 폴더와 마이그레이션으로 추가합니다.

## 근거와 미확정 사항

- `sourceEvidence`는 읽은 입력의 제목·위치·관찰 시각·버전을 스냅샷으로 보존합니다. 승인 리비전의 과거 근거가 최신 외부 문서에 의해 바뀌지 않도록 각 문서에 의도적으로 내장합니다.
- v2의 출처 우선순위는 `source-policy.json`이 소유합니다. 직접 결정 → 현재 와이어프레임 화면 → 와이어프레임 내부 문서 → Notion → 기타 순이며, `pending`·`historical`·`unknown` 근거는 승인 규칙을 정당화할 수 없습니다.
- 충돌한 근거는 `conflictsWith`로 연결하고 `review.resolvedConflicts`에 채택 근거·대체 근거·영향 항목과 이유를 남깁니다.
- 각 제품 항목의 `origin.kind`는 `source_extracted`, `owner_stated`, `spec_projection` 중 하나입니다. `ai_inferred`는 허용하지 않습니다.
- AI가 답을 모르면 사실처럼 채우지 않고 `review.openQuestions`에 기록합니다. 대안이 있으면 `candidateChanges[].questionRef`로 해당 질문에 연결합니다.
- 차단 질문이나 검토 후보가 남아 있으면 승인할 수 없습니다. 외부 의존처럼 의도적으로 유보한 비차단 질문은 영향받는 행동을 금지하거나 영향 없는 범위만 허용해야 합니다.

## AI가 읽는 범위

작업할 때 전체 제품 문서를 한 번에 넣지 않습니다. 제품 검토는 관련 승인 도메인 한 개와 플로우 한 개만 읽고, 실행 계약·구현 작업은 해당 플로우의 승인 목표 동작 설계 한 개를 추가로 읽습니다. 초안은 검토 작업에만 사용하고 구현 기준선으로 사용하지 않습니다.

검증 명령:

```powershell
pnpm test:product-specs
pnpm validate:product-specs
```

검증기는 스키마 구조뿐 아니라 안정 ID 중복, 출처·항목 참조, 질문·후보 연결, 완료 시나리오 추적성, 설계 영역과 검증 의도, 승인 기준선, 리비전 계보, 파일·폴더 이름까지 확인합니다.
